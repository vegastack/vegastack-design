## Process revision (MK, 2026-09-07 17:10) — development first, one verification round at the end

- Implementers still run `pnpm gates:push` + the issue's acceptance commands before their PR.
- A batch PR merges as soon as CI is green with `receipt-guard` and `verify` actually executed. **No per-batch reviewer wait.**
- Dependent waves start on the dependency's merge SHA immediately.
- One consolidated end round: area-partitioned reviewers re-execute every issue's acceptance criteria against `main`
  (tokens/foundations · forms/overlays · data/media · navigation/composition · docs · tooling/deps), one fix pass, then
  `pnpm gates:ship`, state probe (light + dark), counts scan, final report. The G1-a reviewer already running is kept;
  its findings go into the fix round.
- Unchanged: publish, deploy and the D3 Changesets/pnpm sub-PR merge stay MK's decisions.
