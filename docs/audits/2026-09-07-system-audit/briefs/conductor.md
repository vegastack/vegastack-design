# Merge-train conductor

You serialise the landing of finished audit batch PRs on `main` for epic #31. Read `_common.md` (remote runner, HUSKY=0 rule, PR/commit conventions) and `finish-after-f2.md` (incl. the Merge-chain rule). The train file is `scratchpad/merge-chain.md`; the orchestrator edits it (marks `agent-done`, appends new PRs). Re-read it before every step.

Loop until the file's remaining lines are all merged:

1. Take the topmost unmerged PR whose line says `agent-done`. If none, poll the file every 60 s.
2. `gh pr view <n> --json mergeable,statusCheckRollup`. If MERGEABLE and both `receipt-guard` and `verify` COMPLETED/SUCCESS → `gh pr merge <n> --squash --delete-branch` (ignore the "failed to delete local branch" warning), `git fetch origin`, record the merge sha in the file, continue.
3. If CONFLICTING: in that branch's worktree (the path in the file), `git fetch origin` then `git rebase --onto origin/main <first-own-commit>^` where the first own commit is the first commit after `git merge-base origin/main HEAD` — check with `git log --oneline origin/main..HEAD` first (the base is usually 8ce8de4d; T1's is d5c960a3 and two cherry-picked commits already in main should drop as empty). Conflict policy: `.gates/receipt.json` → take theirs (it is re-minted); generated files (`AGENTS.md` §Numbers block, `apps/docs/components/*.generated.tsx`, `apps/docs/lib/*.generated.ts`, `apps/docs/vrt/contract-routes.generated.ts`, `apps/docs/public/r/integrity-manifest.json`, `docs/ledger/component-matrix.md`, `docs/research/design-md-audit/**`, `apps/docs/content/docs/changelog.mdx`, `apps/docs/public/design.md`) → take either side, then regenerate: `pnpm registry:build`, `pnpm design:derived`, `pnpm design:sync`, `node tooling/sync-changelog.mjs`; `CHANGELOG.md`, `docs/ledger/bugs.md`, `docs/ledger/operator-review.md` → keep BOTH sides (main's entries first), run `node tooling/changelog-lint.mjs`. Then `pnpm typecheck && pnpm lint`, idempotency (`pnpm registry:build && git status --porcelain` clean; `pnpm design:derived && git status --porcelain` clean). Commit fixes as `chore(rebase): …`.
4. Sweep: `node tooling/verify-gate-receipt.mjs` — if it already covers the tree (it will not after a rebase that changed generated files), skip; else ONE remote sweep: `bash scratchpad/remote-gates-v3.sh <worktree> -- pnpm gates:push` (queues on a free lane; never two runs in one worktree). If a gate fails on something the batch owns, fix at the root and re-sweep once; if it fails on the known `relative-time` race or another pre-existing flake, record it in the PR body and re-sweep once. Commit `.gates/receipt.json` (`chore(gates): receipt …`).
5. Push: `HUSKY=0 git push --force-with-lease=<branch>:<old-remote-sha> origin <branch>` (the worktrees' fetch refspec is main-only, so the explicit lease form is required). Post a one-line PR comment: rebased onto <sha>, sweep result, CI run id. Wait for CI (`gh run list --branch <branch>` / `gh run view <id> --json jobs`) and merge per step 2.
6. STACKING to avoid a re-sweep per merge: while PR A's CI runs, you may already rebase the NEXT `agent-done` PR B onto A's head (not main), sweep it, and push it; when A merges, `git rebase --onto origin/main <A-head>` in B yields the identical tree, so B's receipt stays valid — verify with `node tooling/verify-gate-receipt.mjs`, push, wait for CI, merge. Never merge B while it still contains A's commits.
7. After each merge, append `merged <sha>` to that PR's line in the train file and re-read the file for new lines.

Never touch #56, #53, #22. Never run browser lanes on the Mac. Never `--no-verify` a commit. If a rebase is not mechanical (real source conflicts in component code), stop on that PR, write what you found into the train file line, and move to the next `agent-done` PR. Final message when the file has no unmerged `agent-done` lines for 30 minutes: list of merged PRs with shas, and anything skipped.
