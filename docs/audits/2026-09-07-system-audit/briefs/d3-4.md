## The real scope

1. **`@changesets/cli` `^2.31.1` → 3**, with a `@changesets/changelog-github` version compatible
   with it (currently `^0.5.1`).
2. **`.changeset/config.json`** — the `$schema` currently pins `@changesets/config@3.1.1`. Move it
   to whatever v3 expects, and handle **`privatePackages`**: the config today uses
   `ignore: ["@vegastack/docs"]`, and v3's private-package handling is the item the audit flagged.
   `linked: [["@vegastack/design-tokens", "@vegastack/design"]]` and `access: "public"` must survive.
3. **`changesets/action` v1.9.0 → v2** in `.github/workflows/release.yml` (line ~162, pinned by
   commit sha — keep it sha-pinned, and `tooling/verify-workflow-security.mjs` must stay green,
   along with its negative harness).
4. **pnpm 11.7.0 → 12**: `packageManager` in the root `package.json`, and every place that consumes
   it. **This is the risky half — read it before touching anything:**
   - The **Linux CI job runs `corepack enable` inside the pinned Playwright container** and gets
     pnpm from `packageManager`. Bumping the field changes what all five Linux runners execute.
   - The job installs with `--store-dir /pnpm-store`, a **persistent host store** bind-mounted from
     `/opt/vsk-runner/pnpm-store` on each box. A major pnpm bump may write a new store version
     directory; the first run then pays a full download on every box. That is recoverable (the
     runbook says the store is safe to delete) but it must be expected, not discovered.
   - The **mac minis** use `pnpm/action-setup@v6` plus `setup-node`, which also read
     `packageManager`. They additionally have the shared-store race of issue **#94** — do not
     confuse that failure with a pnpm 12 problem.
   - `devEngines.runtime` pins **Node 24.20.0** with `onFail: "download"`; confirm pnpm 12 is happy
     with it and does not change how that pin behaves.
5. **Re-verify `pnpm run version-packages` end to end.** WP5 made it
   `changelog-assemble.mjs && changeset version && version-sync.mjs && sync-changelog.mjs`, and the
   assemble step runs **before** `changeset version` deliberately. Changesets 3 must not break that
   ordering or the assembled `/CHANGELOG.md` entry. Prove it: `node tooling/changelog-assemble.mjs
--check` and `--dry-run` against the real pending set (150+ changesets today), and a dry version
   run on the branch.
