## Merge-chain rule (added 17:05 IST, 2026-09-08) — read before step 1

Squash-merging one sibling PR usually makes the next one CONFLICTING (changelog, contracts.json, AGENTS.md numbers), and a rebase moves the tree hash, which voids the receipt and costs another sweep. Avoid that by STACKING: before your final sweep, check `scratchpad/merge-chain.md` (orchestrator-maintained, ordered list of "PR → branch head"). Rebase onto the LAST unmerged head in that chain instead of origin/main (`git rebase --onto <chain-head> <your-first-own-commit>^`), resolve, sweep once, then append your own line to the chain file. When the predecessor squash-merges, `git rebase --onto origin/main <predecessor-head>` reproduces the SAME tree content, so your receipt stays valid and CI passes without a second sweep. Never open a PR that still contains a predecessor's commits — wait for its merge, do the `--onto origin/main` rebase (no re-sweep needed if the tree is identical: `node tooling/verify-gate-receipt.mjs` proves it), then open.
