# Common Findings

## Findings

| ID     | Priority | Finding                                                                            | Evidence                                                                                                                                                                                                                       | Impact                                                                                                                | Suggested fix                                                                                                                                  |
| ------ | -------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| CF-001 | P1       | Docs app shadcn config resolves as Radix, not Base UI.                             | `apps/docs/components.json:3` has `"style": "new-york"` and no Base marker. `shadcn info -c apps/docs --json` reports `"base": "radix"`. `shadcn add button --dry-run -c apps/docs` proposes `radix-ui`.                       | Maintenance commands can overwrite Base/native components with Radix baselines.                                       | Update config to current shadcn Base UI style/preset so `info` reports `"base": "base"`, then add a CI guard.                                  |
| CF-002 | P1       | Base UI target is true in source, but not in all project metadata.                 | Canonical components import `@base-ui/react/*`; docs package also declares `radix-ui` at `apps/docs/package.json:36`.                                                                                                          | Dependency graph still advertises Radix and invites accidental reintroduction.                                        | Remove direct `radix-ui` if no direct import needs it; document `cmdk` transitive Radix exception separately.                                  |
| CF-003 | P1       | `Button` does not use Base UI Button semantics.                                    | `button.tsx:7` imports `useRender`, `button.tsx:97` always passes `type`, `button.tsx:103` always passes `disabled`; docs/tests use `render={<a />}`. Base UI Button docs call out `nativeButton` and `focusableWhenDisabled`. | Invalid attributes on polymorphic renders, loading focus loss, and docs that conflict with Base UI link guidance.     | Rebase on `@base-ui/react/button`, expose/handle `nativeButton` and `focusableWhenDisabled`, and document anchor styling via `buttonVariants`. |
| CF-004 | P1       | `Field` has an undeclared registry dependency on `Input`.                          | `field.tsx:9` imports `@/components/ui/input`; `field.tsx:88` renders `Input`; field registry item has empty `registryDependencies`.                                                                                           | `shadcn add @vegastack/field` can leave unresolved imports in a clean consumer.                                       | Add `@vegastack/input` registryDependency or remove the hidden Input dependency from `FieldControl`.                                           |
| CF-005 | P1       | Package Toaster and registry Toaster diverge.                                      | `packages/ui/src/provider/toaster.tsx:64` uses `text-success` icons and no Sonner CSS-var bridge; `packages/ui/registry/ui/sonner.tsx:69` wires CSS vars and uses `text-success-text`.                                         | Docs exercise registry copy, while npm consumers get different toast styling.                                         | Generate/mirror package Toaster from canonical registry source or make one shared source.                                                      |
| CF-006 | P2       | Focus affordance lint gate fails.                                                  | Node 24 `pnpm run lint` fails with seven `outline-none` violations in `alert-dialog`, `dialog`, `hover-card`, `otp-input`, `popover`, `sheet`, `textarea`.                                                                     | CI/lint is not green; docs promise visible focus indicators that are not consistently local to components.            | Add tokenized `focus-visible` styles or adjust docs/lint rules where global outline is the approved contract.                                  |
| CF-007 | P2       | Docs focus wording claims `ring-ring/50`, but showcase uses global `outline-ring`. | `apps/docs/app/global.css:49`; repeated MDX claims in button/dialog/select/etc.                                                                                                                                                | Consumers and auditors chase the wrong focus implementation.                                                          | Standardize MDX wording: visible focus indicator via global `outline-ring`, except where a component owns a specific ring.                     |
| CF-008 | P2       | Compound API docs are incomplete.                                                  | `command.mdx` documents only `CommandDialogProps`; `table.mdx` documents only `TableProps`; `sidebar.mdx` documents a subset of many public prop interfaces.                                                                   | Consumers see parts in examples but cannot rely on API sections as complete.                                          | Generate tables from exported prop types or mark trivial native parts intentionally omitted.                                                   |
| CF-009 | P2       | Consumer registry setup is under-documented.                                       | Per-component install snippets show direct `@vegastack/<name>` add commands; docs do not explain namespace registration, auth/service token, or production registry URL.                                                       | Copy-paste install fails unless the downstream project already has hidden config.                                     | Add a top-level install workflow and a reusable callout before component install snippets.                                                     |
| CF-010 | P2       | Client boundaries are broader than necessary in several components.                | Static or mostly-static components such as `breadcrumb`, `pagination`, `alert`, `page-header`, `kbd` are `'use client'` because of optional interactive behavior.                                                              | More hydration and less RSC friendliness than required by the project rule.                                           | Split interactive leaves or explicitly document client-only components.                                                                        |
| CF-011 | P2       | Some Base UI prop aliases create duplicate/conflicting APIs.                       | `Accordion` uses `openMultiple`; `ToggleGroup` uses `toggleMultiple` while still extending Base props.                                                                                                                         | Downstream consumers learn VegaStack aliases instead of Base UI names, and conflicts can be resolved by spread order. | Either fully own/narrow aliases or adopt Base UI names with migration notes.                                                                   |
| CF-012 | P2       | Overlay APIs hide advanced portal/positioner controls.                             | `PopoverContent` and `HoverCardContent` own Portal/Positioner; tooltip narrows `sideOffset` to `number`; menu positioner className can be overwritten.                                                                         | Shadow-root, custom-boundary, fixed positioning, and nested overlay needs force forks.                                | Add `portalProps`/`positionerProps` and merge className safely.                                                                                |
| CF-013 | P2       | Several docs/accessibility claims are stronger than tests.                         | Context menu keyboard open is documented but untested; dropdown/context submenu behavior is documented but lightly tested; range slider docs require per-thumb names but preview/test use one label.                           | Accessibility regressions can ship despite green axe tests.                                                           | Add keyboard/state tests that match docs claims.                                                                                               |
| CF-014 | P3       | VRT exists but has no committed baselines in this checkout.                        | `apps/docs/vrt/components.spec.ts` enumerates 68 routes; `test:vrt -- --list` reports 68 skipped.                                                                                                                              | Visual coverage is scaffolded but not active proof yet.                                                               | Generate and commit baselines through the documented CI bootstrap flow.                                                                        |
| CF-015 | P3       | Install snippets pin `shadcn@4.7.0` while live docs/CLI are newer.                 | Many MDX pages use `npx shadcn@4.7.0 add ...`; live `shadcn@latest` reported newer behavior.                                                                                                                                   | Snippets age and may hide CLI behavior changes.                                                                       | Centralize snippet generation and either intentionally pin with rationale or use `shadcn@latest`.                                              |

## Clean Common Signals

- Generated docs copy-in files are byte-for-byte synced from canonical source by the registry workflow.
- `meta.integrity` exists in generated registry items and header verification passes.
- Semantic token use is broadly strong; no first-party Radix import was found.
- Base UI portal isolation is present in the docs shell and token base CSS.
- View transitions are not used in low-level primitives, which is the right default.
