# Token-purity audit — `packages/ui/registry/ui/*.tsx`

Date: 2026-07-14
Scope: 68 canonical components in `packages/ui/registry/ui/*.tsx` (excludes `*.test.tsx`, `__screenshots__`, and the vendored `registry/ui/icons/**` mirror, which is exempted by `design-lint.mjs` itself). Method: read `packages/tokens/tokens/*.tokens.json`, the compiled `packages/tokens/dist/theme.css` (`@theme inline` bridge — the authoritative list of which Tailwind utilities are actually token-backed), `packages/tailwind-preset/preset.css`, and `tooling/design-lint.mjs`; then grepped every hardcoded-style category across all 68 files and read 13 components line-by-line in full (the 10 requested spot-checks plus button/image/badge/skeleton/tooltip, which surfaced findings during cross-referencing).

**Headline: zero hex/rgb/hsl color literals and zero raw Tailwind palette utilities anywhere in the 68 files.** The color contract (the part `design-lint.mjs` actively enforces) is genuinely clean. Every other category the mandate asked about — opacity, arbitrary values, durations/easings, z-index, shadows, ring/border widths, inline styles, JS magic numbers, and the typography scale — has real, uncaught violations, because `design-lint.mjs` doesn't check for any of them.

**Worst offenders (by violation density):**

1. **`button.tsx`** — 24 opacity-modifier hits in one CVA string (every status variant × hover/active state pair hand-writes `/5`, `/10`, `/20`, `/30`, `/50`, `/80`, `/90`, `/95`).
2. **`markdown-view.tsx`** — all six heading levels (`h1`–`h6`) use raw `text-2xl/xl/lg/base/sm` instead of the design system's own `text-h1`–`text-h4`/`text-label` typography tokens, which exist specifically for this.
3. **`select.tsx` / `input.tsx` / `checkbox.tsx` / `radio-group.tsx` / `textarea.tsx` / `toggle.tsx`** — the shared `border-ring/70`, `bg-input/30`, `border-destructive/70` opacity triplet is copy-pasted (not centralized) across 8+ form-control files.
4. **`sidebar.tsx`** — two hardcoded `rem` magic-number layout constants (`SIDEBAR_WIDTH`, `SIDEBAR_WIDTH_ICON`) with no corresponding token, plus `ease-linear` (not a design-system easing token).
5. **`message-scroller.tsx`** — a single class string mixes a literal `duration-200` (bypasses the `duration-base` token that has the identical value) with `duration-400` (no token has this value at all).

### Non-token raw typography sizes (`text-xs/sm/base/lg/xl/2xl`)

The token set defines a complete typography scale — `text-display`, `text-h1`–`text-h4`, `text-label`, `text-label-sm`, `text-code`, `text-code-sm` — each with matched line-height/weight/letter-spacing, wired through `@theme inline` in `packages/tokens/dist/theme.css:210-240`. None of `text-xs/sm/base/lg/xl/2xl/3xl` are token-backed; they're bare Tailwind defaults with no themeable line-height/weight pairing. Yet the vast majority of the 68 components use the raw Tailwind sizes instead of the typography tokens:

Right now the rule is implicit and unenforced either way.

## (c) `design-lint.mjs` gaps

Reading `tooling/design-lint.mjs` end to end, it enforces exactly six things: (1) hex-color literals, (2) raw Tailwind palette utilities, (3) `!important`, (4) non-sanctioned icon-library imports, (5) inline `<svg>` icons, (6) the `Omit<…, 'render'>` render-contract, (7) the §7.1 inline-style contract (custom-property-only keys + the one documented swatch-fill exception), (8) the §7.6 arbitrary-value contract (only `var(--token)` / token-`calc()` / layout primitives / CSS-wide keywords), and (9) the outline-none-needs-a-focus-affordance heuristic.

**What it explicitly, correctly catches (verified by testing the regexes against the codebase — zero hits, and the code IS clean here):**

- Hex/rgb literals anywhere in a line.
- `bg-neutral-900`-style raw palette utilities.
- Arbitrary-value classes carrying a hardcoded literal length/color (`h-[13px]`, `bg-[#fff]`) — the `ARB` regex + its 4-item allowlist is genuinely tight; every arbitrary value found in the codebase (`max-w-[calc(100dvh-var(--spacing)*8)]`, `max-w-[80%]`, `grid-cols-[repeat(var(--swatch-cols),…)]`, the Base UI runtime vars) legitimately passes its own documented exceptions.
- Inline `style={{}}` objects that assign a direct visual property or a literal hex/px/rem — `color-picker.tsx`'s two sanctioned exceptions and `sidebar.tsx`/`truncated-text.tsx`'s custom-property-only styles are the only inline styles in the codebase, and all correctly pass.

**What it completely misses (every category below produced real findings above, with zero lint coverage):**

1. **Opacity everywhere.** No rule for `/NN` alpha-channel suffixes (`bg-primary/50`) or the `opacity-*` utility. The file header comment even says "The token-only contract is strict: NO hardcoded visual literal anywhere… not even opacity" (line 10) — but no `RULES` entry, and no branch of the arbitrary-value or inline-style logic, checks for it. This is the single largest gap given ~125 combined instances found.
2. **Raw typography sizes.** No rule flags `text-xs/sm/base/lg/xl/2xl/3xl` as non-token, even though the design system ships a complete, purpose-built typography scale (`text-h1`–`text-h4`, `text-label`, `text-label-sm`, `text-code`, `text-code-sm`) that these bypass wholesale.
3. **`z-*` index literals.** No z-index scale exists in tokens and no lint rule flags raw `z-10`/`z-50` as needing one.
4. **Raw shadow/ring/border-width utilities.** `shadow-sm`, `ring-2`, `ring-3`, `border-2` are all invisible — the `COLOR_PROPS`/`LEN_PROPS` regexes only fire on _arbitrary-value_ (`-[...]`) forms of these properties, never on the named Tailwind scale forms (`shadow-sm`, `ring-2`).
5. **Hardcoded duration/easing utilities.** The file header's own prose (line 16) says "Motion durations use the `duration-fast`/`-base`/`-slow` token utilities… never `duration-[var(--…)]`" — but that sentence describes the _arbitrary-value_ form; it says nothing about (and the code enforces nothing against) `duration-200`/`duration-400`/`ease-linear`, i.e. non-arbitrary Tailwind utilities that also aren't tokens. `message-scroller.tsx`'s `duration-200`/`duration-400` and `sidebar.tsx`'s `ease-linear` sail through clean.
6. **Values assigned to CSS custom properties.** The §7.1 inline-style rule validates only that `style={}` object _keys_ are `--*` variables; it never inspects what's assigned to them. `sidebar.tsx`'s hardcoded `'15rem'`/`'3rem'` JS constants pass every existing check.
7. **JS-level magic numbers (timing, offsets).** The linter is a per-line/per-file regex pass over `className`-adjacent syntax; it has no way to see `timeout = 1500`, `debounceMs = 800`, `openDelay = 700`, or the `sideOffset`/`collisionPadding` inconsistency across floating-panel components, because none of these are className strings at all — they're plain numeric default parameters. This is a structurally different category the current tool can't address without new, bespoke logic (e.g. an AST pass over default-parameter values in files matching a "timing/offset" name allowlist).
8. **`SVG_GRAPHIC_ALLOWLIST` / icon exemptions are not re-verified.** `registry/ui/icons/**` is blanket-exempted from every rule (inline `<svg>`, inline-style, hex, raw-palette) on the stated assumption that `tooling/mirror-animated-icons.mjs` "asserts no hex/raw-palette itself" — this audit did not verify that assertion actually runs or is wired into CI; if it silently stopped running, hex colors could reappear in the icon mirror undetected by `design-lint`.

## (d) Recommended new tokens / lint rules

**New tokens to add to `packages/tokens/tokens/semantic.tokens.json`** (then thread through the `@theme inline` bridge in the Style Dictionary build so they become real Tailwind utilities):

1. **Opacity/alpha scale** — e.g. `opacity-subtle` (≈0.1), `opacity-soft` (≈0.2–0.3), `opacity-muted` (≈0.5), `opacity-strong` (≈0.7–0.8), `opacity-hover` (≈0.9). This alone would let `button.tsx`'s 24-instance CVA string, the 8-file form-control triplet, and the ~35 `opacity-NN` state hits all collapse onto a shared, named scale instead of picked-by-eye literals.
2. **Motion duration** — either add a `duration-slower` token (~400ms, to replace `message-scroller.tsx`'s bare `duration-400`) or confirm 400ms was a mistake and it should be `duration-slow` (300ms) — needs a design decision, not just a token add.
3. **Motion easing** — add `motion-ease-linear` (mapped to CSS `linear`) if linear easing for width/opacity transitions is an intentional, recurring pattern (used twice in `sidebar.tsx`), so it's declared rather than incidental.
4. **Z-index scale** — e.g. `z-overlay` (50) / `z-raised` (10), so every popover/dialog/sheet/scroll-arrow consistently references a named layer instead of Tailwind's bare numeric scale.
5. **Sidebar width tokens** — `sidebar-width` (15rem) / `sidebar-width-icon` (3rem) as real tokens (parallel to the existing `size-sm/md/lg` dimension tokens), replacing the two hardcoded JS string constants in `sidebar.tsx`.
6. **Interaction timing constants** — not necessarily DTCG tokens, but at minimum a single shared `@vegastack/utils` (or tokens package) export like `INTERACTION_DELAY = { instant: 0, short: 300, default: 700 }` / `COPY_FEEDBACK_MS` / `AUTOSAVE_DEBOUNCE_MS`, so `copy-button.tsx`'s `1500`, `auto-save-input.tsx`'s `800`, and `hover-card.tsx`'s `700`/`300` stop being independently-invented literals — and so the `sideOffset`/`collisionPadding` inconsistency across the six floating-panel components (4/6/8 and 8/16) gets resolved to one deliberate pair of values.
7. **Ring/border width scale** — if `ring-2`/`ring-3`/`border-2` are all intentional (they read as reasonable: 2px for decorative rings, thicker for the slider thumb), document them as the sanctioned exception set the way the color-picker swatch-fill is documented — otherwise fold them into the default `ring`/`border` (1px, from `base.css`'s `outline-ring/50`) usage.

**New `design-lint.mjs` rules** (in priority order, matching the size of the gap they close):

1. Flag any `(?:bg|text|border|ring|fill|stroke|outline|from|via|to|divide|accent|shadow)-[\w-]+\/\d{1,3}\b` (opacity-modifier suffix) and bare `opacity-\d+` outside an explicit, documented allowlist (disabled-state `opacity-50` is so universal it may deserve a blanket allow, but everything else should require a token or an inline justification comment).
2. Flag bare `text-(xs|sm|base|lg|xl|2xl|3xl|4xl)` in files whose surrounding context is a heading/label element (`h1`–`h6`, or anywhere `font-medium`/`font-semibold` co-occurs) as candidates for `text-h*`/`text-label*`; this needs a documented exception list for legitimate plain-body-copy usage rather than a blanket ban.
3. Flag `z-\d+` outside a small `z-overlay`/`z-raised` allowlist once those tokens exist.
4. Flag `shadow-(sm|md|lg|xl|2xl)` (only `shadow-overlay`/`shadow-none` are sanctioned).
5. Flag `duration-\d+` (non-arbitrary numeric Tailwind duration) and `ease-(linear|in|out|in-out)` the same way the file's own header comment already claims are banned — right now that's documentation, not code.
6. A lighter-weight, best-effort AST or regex pass over default-parameter values for names matching `/delay|timeout|debounce|duration|offset|padding/i` in files under `registry/ui/`, flagging unreviewed numeric literals for a human pass — full precision isn't achievable with a regex linter, but even a "these N defaults changed since last release, please confirm" diff-gate would catch drift.
