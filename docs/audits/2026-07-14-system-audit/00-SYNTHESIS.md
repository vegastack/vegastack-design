# System Audit Synthesis — 2026-07-14

Synthesizes the nine parallel audits in this directory (`01`–`09`) into one prioritized register.
Source audits were read-only; so is this document — no source files were modified in producing it.

Severity model used throughout (per the synthesis brief):
- **P0** — real functional/a11y bugs, pipeline-integrity issues.
- **P1** — violations of the repo's own written specs (`design.md`, `AGENTS.md`, `docs/ledger/*`), cross-component inconsistencies.
- **P2** — missing tokens/lint gaps, hygiene/debt.
- **P3** — nice-to-have opportunities.

That is a mechanical/enforcement gap (lint + review), not an architecture problem.

## 4. Decision items (owner's call, not mechanical)

These need MK's judgment before any agent should act — they're either genuine design-language calls, naming/rename decisions with consumer impact, or scope calls the audits deliberately left open.

1. **Overlay elevation strategy** — no immediate defect, but a design-system-level question: should `Dialog`/`Sheet` (heavier surfaces) get a slower transition duration than popover-weight overlays (P3-08)? Current flat `duration-fast` everywhere is defensible for "compact & sleek" but the differentiated-duration convention is the 2026 norm (Geist).
2. **Typography scale resolution** — pick direction: (a) cheaply remap raw `text-xs/sm/base/lg/xl/2xl` in the theme bridge to the system's real pixel/line-height/weight values so 122+ existing call sites become correct "for free," or (b) run the never-executed mechanical Phase-2 sweep from `docs/plans/design-token-overhaul.md` to rename every call site to the named tokens (XCUT-05 / P1-05).
3. **Card padding** — `design.md` disagrees with itself (20px prose vs. 16px recipe table); shipped code matches neither (16px default, 12px `sm`, no 20px/32px tier). Needs one canonical answer (P1-06).
4. **Destructive button** — does the system's actual "always soft/outline, never solid fill" destructive language become the documented spec (delete the solid recipe row), or does a genuine solid-fill variant get added for irreversible actions (P1-07)?
5. **`IconButton` deletion** — confirmed merge candidate (P1-21), but it's a breaking registry change requiring a changeset, migration note, and deprecation window — timing/rollout is an owner call.
6. **Semantic-color prop rename** (`variant`/`color`/`intent` → one name, likely `intent`) — a future-major-version, cross-cutting rename (P1-03). Needs sequencing against other breaking changes.
7. **`EmojiPicker.onSelect` → `onValueChange` rename** (P1-22) and **`empty-state` → `Empty` rename** (P2-10) — both breaking, both small in isolation; worth batching into one "breaking cleanup" release.
8. **`radius-xl`** — fold `bubble.tsx` onto `rounded-lg`, or formally re-admit a 5th `xl` radius token for large conversational surfaces (P1-09). This is a real design-language question (is chat visually "heavier" than the rest of the system?), not just a lint fix.
9. **Dark-mode form-control tint** (`dark:bg-input/30` applied only to form controls, not Card/Popover/Dialog/Sheet) — confirm intentional vs. legacy drift from a pre-"dark is co-primary" token generation (P1-24).
10. **Chevron icon for combobox-style triggers** — `ChevronDown` (Select's choice) vs. `ChevronsUpDown` (Country/State Select's choice) — pick one system-wide affordance (P1-23).
11. **`sidebar.tsx`'s `ease-linear`** — confirm whether linear easing is a deliberate choice for the collapse animation, or should move to `ease-standard` like everything else (P1-14 / XCUT-04).
12. **Button `xs` size tier** — formally document it in `design.md`'s control-height scale, or remove it (P2-17).
13. **`react-day-picker` v10 major bump** — needs a scoped audit of `date-picker.tsx` for removed props/grid-markup dependencies before scheduling (P1-20); not urgent, but a real breaking-change risk once undertaken.
14. **`@shadcn/react` chat-family scope** — if `Attachment`/`Item`/`Combobox` (P3-01) get built on the upstream `Bubble`/`Attachment`/`Marker` primitives, the `AGENTS.md` "ONLY non-Base-UI primitive" exception language needs to be reopened to cover the family, not just `message-scroller` (P2-44).
15. **TypeScript 7 adoption timing** — correctly deferred pending `typescript-eslint`/`ts-morph` ecosystem readiness at 7.1; needs a "when to revisit" trigger, not action now (P2-42).

- **Docs/registry pipeline is close to perfect.** 68/68 components have full 5-artifact coverage (MDX, preview, preview-export, registry.json entry, `public/r/*.json`); canonical↔copy-in are byte-identical for all 68; every provenance header matches its `meta.integrity` hash. Preview files (71) have zero hardcoded colors, zero non-semantic palette classes, zero inline styles, zero `!important`. (07)
