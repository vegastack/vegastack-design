VegaStack Design System

A warm, restrained, futuristic system for AI products — web & mobile. Subtle warm neutrals (paper, not parchment), crisp 400 headings under a whisper-light hero, tight rounded-rect geometry, and colour rationed to status + one brand accent. Light & dark are co-primary. Every value is a token; change a handful of variables and the whole system re-skins while components keep working.

1 · Colour

Warm neutral ramp subtle warm · OKLCH hue 75 · one ramp, shared by both themes

The change from pure grey: a whisper of warmth (chroma 0.003, toward paper) — identical methodology in both themes, just barely there. neutral-0 a warm-white #fefdfc; neutral-900 a near-neutral deep #131211 — dark is genuinely dark, not espresso. Contrast unchanged (fg/bg 18.4:1). The ElevenLabs "human/tactile" benefit, dialed right back so it stays futuristic.

Accent — three candidates full ramp each · subtle / fill / hover / active / text · hexes live per theme

Each candidate ships the same six tokens (constraint: identical structure, only the hue changes). Toggle the theme — subtle and text re-resolve per theme; fill / hover / active are theme-independent. The active one (indigo) is what --accent-* aliases to.

Accent — in use --accent-* · live alias of the chosen candidate

Status rationed — state only · full ramp each: subtle / fill / hover / active / text

Same six-token structure as the accent. fill carries white (--*-fg) and all three clear AA on it; hover / active darken for press states; subtle / text re-resolve per theme.

⚠ Rationed: chrome is achromatic warm neutrals. Info uses the accent (no separate info colour). Status appears only for genuine state — and never colour-alone (always an icon/label).

Data-viz · categorical qualitative · distinct series · series-1 = the live accent

A separate scale by design — categorical hues encode identity, not meaning, so they're never derived from status (would imply good/bad) or made of accent shades (would imply order). Series-1 is the accent, so single-series charts are automatically on-brand; series 2–8 fan out as an equiluminant ring (all L≈0.60, ~45° apart) and only appear when a chart truly needs many series.

Data-viz · sequential ordered low→high · accent-hued · theme-aware

For magnitude/intensity (heatmaps, density). One hue, even lightness steps — built by mixing the accent into the surface with color-mix(in oklch …), so it re-skins with the accent and the theme, with zero hand-picked values.

Data-viz · diverging two-ended · destructive ↔ neutral ↔ success

For signed deltas around a midpoint (±change, sentiment). Anchored on the status hues with a neutral muted centre — the one place reusing status is correct, because here the ends genuinely mean negative / positive.

Borders & overlays translucent ink — adapts to any surface

One rule: fills are solid (a known colour on a known surface), but lines & overlays are translucent ink — a border or the dim behind a modal is "X% black" in light, "X% white" in dark, so the same token reads correctly on a white card, a coloured panel, or an image. There is exactly one border token — border — used on every card, input, table, and overlay; plus scrim for the modal dim. That's the whole line system.

The other genuine use — the scrim. The dim layer behind a modal must be see-through (you still glimpse the page beneath). scrim is translucent ink over whatever happens to be on screen.

Do we need a separate "alpha scale"? No — removed. It only duplicated tokens. Translucent ink is needed in exactly two places: the one border (border — cards, inputs, tables, overlays) and the modal scrim (scrim). Everything else — fills, surfaces, hover washes — stays solid neutral.

2 · Typography 400 headings · light hero only · every property defined · Geist

The hero display whispers (weight 300) for one elegant marketing moment — but every functional heading settles at 400, because 300 reads too thin at h1–h2 in dense and dark UI. Small UI titles (h4) hold medium (500). Numbers use tabular figures (Geist Mono) so columns align. Every token below ships size · line-height · weight · tracking · family, so it tokenizes 1:1.

Weights: 300 light (display hero only) · 400 regular (h1, h2, h3, body) · 500 medium (labels, h4, buttons). Never bold (600+). Max two weights per view.

8 · Accessibility & contrast WCAG 2.1 AA · computed live · toggle the theme

Every ratio below is read from the rendered tokens with getComputedStyle and scored against WCAG — real numbers, not asserted, that re-compute when you switch theme or accent. Target is AA: 4.5:1 body text, 3:1 large text (≥18.66px) and UI/graphical objects; AAA (7:1) flagged where reached.

Focus — no rings · focus mirrors hover

Link · underline + colour

No focus rings anywhere. On keyboard :focus-visible, each control simply adopts its hover appearance — buttons darken within their own colour, inputs darken their border to the primary ink (matching, never a stray gray or accent), links underline. So a mouse click shows nothing extra, there's never a glow competing with the accent, and a keyboard user still always sees where they are (WCAG 2.4.7). The catch worth stating: hover alone is not enough — keyboard, screen-reader, switch and voice users can't hover, so this focus-visible state is the one cue they depend on. Here it simply is the hover look, so it costs nothing visually.

10 · Do's & Don'ts the rules, consolidated

Do use semantic tokens (bg-primary, text-muted-foreground).
Don't hardcode a colour — if it isn't a token, it doesn't ship.
Do ration colour: one accent + three status; everything else warm neutral.
Don't add a fourth status hue or a second accent "just this once".
Do keep functional headings at 400 (300 only for the hero display).
Don't go bold (600+) or use more than two weights in a view.
Do signal state with icon + text + colour together.
Don't rely on colour alone.
Do stay flat — hairline borders; one shadow for overlays only.
Don't stack shadows or shadow a button/inline card.
Do mirror the hover look on :focus-visible — no rings, but focus is still visible.
Don't rely on hover alone or add a glowing ring — keyboard users need the focus state; it just shouldn't shout.
Do use lucide at currentColor; tabular figures for numbers.
Don't mix icon libraries or inline ad-hoc SVG icons.
Do author light and dark together — both are primary.
Don't ship a token that only resolves in one theme.
