## v4 API notes / deviations from the reference

The task's reference file (`resizable-resizable.tsx`, shadcn new-york-v4) already used the **v4**
export names (`Group`/`Panel`/`Separator`, not the older `PanelGroup`/`Panel`/`PanelResizeHandle`),
so the exports matched. Everything else needed adjustment against the installed
`react-resizable-panels@4.12.2` `.d.ts`:

1. **`Group` sets its own layout inline** (`display:flex; flex-direction; flex-wrap:nowrap;
height:100%; width:100%; overflow:hidden` — the last four are documented as **not overridable**).
   The reference's `flex h-full w-full aria-[orientation=vertical]:flex-col` className is therefore
   dead weight in v4 — `ResizablePanelGroup` adds no layout classes at all.
2. **Ref prop is `elementRef`, not `ref`.** `Group`/`Panel`/`Separator` are plain functions (not
   `forwardRef`) that internally overwrite any `ref` passed in via `...rest` with their own DOM ref
   (merged with `elementRef`). Our wrappers accept `ref` (React 19 style, no `forwardRef`) and forward
   it to the primitive's `elementRef`.
3. **Sizes are unitless strings for percent, not numbers.** `defaultSize`/`minSize`/`maxSize`/
   `collapsedSize`: a JS **number** is pixels (`defaultSize={30}` = 30px); a **string** is percent
   unless suffixed (`"30"` = 30%, `"30%"` = 30%, `"30px"`/`"2rem"`/`"50vh"` etc. also work). This is
   flipped from the mental model most shadcn snippets assume and is **not** what the reference file
   implies. Documented prominently in the MDX ("Usage" section) and in `ResizablePanelGroup`'s JSDoc
   `@example` — this is the single easiest mistake for a consumer (or another agent) to make; my
   first test-file draft did exactly that and got nonsensical `aria-valuenow` values until I caught it.
4. **`Separator`'s `aria-orientation` is the axis PERPENDICULAR to the group's `orientation`** (ARIA
   separator convention — e.g. group `orientation="horizontal"` ⇒ handle `aria-orientation="vertical"`,
   a vertical bar between side-by-side panels). Styling keys off `aria-[orientation=…]`, matching the
   reference's convention, but I rebuilt the `after` hit-target math from scratch — the reference's
   `after:inset-y-0 … aria-[orientation=horizontal]:after:-translate-y-1/2` combination (no
   accompanying `top-1/2`/`inset-y-auto`) does not actually center the hit target for the horizontal
   case; verified by computing the box model, not copied.
5. **`data-separator` carries live interaction state** (`"inactive" | "hover" | "active" | "focus" |
"disabled"`, computed by the library), not a boolean. `ResizableHandle` uses
   `data-[separator=active]:bg-primary` for the drag state, plus real `hover:` and `focus-visible:`
   pseudo-classes for pointer-hover and keyboard-focus (both simpler/more standard than reading
   `data-separator` for those two cases).
6. **The group's `disabled` prop blocks the resize engine but does NOT set each handle's
   `aria-disabled`** — that's driven purely by `ResizableHandle`'s own `disabled` prop. Documented in
   the MDX Accessibility section and covered by two separate tests (functional block vs. ARIA state)
   so this doesn't get "fixed" into an incorrect assumption later.
7. **Keyboard resize (Arrow keys, Home/End) works with zero extra wiring** — the library attaches
   its own `keydown` listener to each separator element. No test/demo code needed to implement it.
8. **Icon:** grip glyph is `GripVertical` from `lucide-react` at `size-(--icon-compact)` (12px),
   rotated 90° for the horizontal-bar case via `group-aria-[orientation=horizontal]/handle:rotate-90`
   (the `group/handle` marker lives on the `Separator` itself, since the grip `<div>` is a child and
   has no `aria-orientation` of its own to key off directly).

modest for full-page VRT screenshots.

## Test results (scoped, from `packages/ui/`)

```
npx tsc --noEmit                                    → clean, no errors
node ../../tooling/design-lint.mjs registry          → ✓ design-lint: clean
npx vitest run registry/ui/resizable.test.tsx        → 18 passed (18), ~1.2s
```

18 tests cover: data-slot structure; horizontal-group ARIA (`aria-orientation="vertical"`,
`aria-valuenow`/`-min`/`-max`, `tabindex`); vertical-group ARIA (`aria-orientation="horizontal"`);
keyboard resize (`ArrowRight`/`ArrowLeft`/`Home`/`End` horizontal, `ArrowDown` vertical) including
`onLayoutChanged` payload + `isUserInteraction` meta; `withHandle` grip present/absent; handle-level
`disabled` (ARIA + tab order) vs. group-level `disabled` (functional block, no ARIA claim — see note
6 above); collapsible panel via imperative `panelRef` (`collapse()`/`expand()`/`isCollapsed()`);
nested groups (independent ARIA orientation + independent resize, structure count); axe a11y on
horizontal, vertical, and `withHandle` layouts; ref forwarding.

**Test-writing gotcha for whoever touches this file next:** the fast unit-test environment compiles
no Tailwind, so a `className="h-64 w-96"` container has **zero real height/width** and
percentage-based panel sizing computes garbage (`aria-valuenow` values like `16.667`/`4.167` instead
of `50`/`20`). Every top-level `ResizablePanelGroup` in the test file uses inline `style={{ height,
width }}` instead (see `GROUP_STYLE`), same convention as `message-scroller.test.tsx`.
