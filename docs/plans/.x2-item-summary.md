## Decisions / deviations from the shadcn reference

1. **`render` prop instead of `asChild`/Slot.** Matches the house pattern (`marker.tsx`, `bubble.tsx`, `badge.tsx`): `Item` calls `useRender({ render: render ?? <div />, defaultTagName: "div", ref, props: {...} })`. `ItemMedia`/`ItemContent`/etc. stay plain function components (React 19 ref-as-prop, no `forwardRef`).

2. **`role="listitem"` — dropped automatically on interactive rows.** The task spec said "ItemGroup role=list + Items role=listitem (per shadcn)" — but the actual upstream shadcn `Item` sets **no** role at all; the instruction's "per shadcn" framing doesn't hold up against the reference file. I implemented the spirit of the instruction (real `listitem` semantics for the common case) while fixing a real bug it would otherwise cause:
   - Forcing `role="listitem"` unconditionally onto a `render`-composed `<a>`/`<button>` **replaces** the anchor's native `link`/`button` role (ARIA has no dual-role concept) — this silently hides the interactive affordance from assistive tech, and broke `getByRole("link", …)` queries in my own tests until fixed.
   - Fix: `Item` sets `role="listitem"` **only when `render` is not passed** (default `<div>` tag). An interactive `Item` keeps its native role. Consumers can still force any `role` explicitly via a prop (spread after the default, so it always wins).
   - Corollary a11y finding: a `role="list"` `ItemGroup` containing **only** interactive (`render`-composed) `Item`s fails axe's `aria-required-children` (list requires `listitem`/`none`/`presentation` children). This is a structural ARIA limit, not a bug — documented in the MDX Accessibility section and in code comments. Interactive rows are meant to be composed standalone or alongside non-interactive rows, not as the sole content of a semantic list.

3. **`ItemSeparator` stays fully decorative.** It wraps `Separator` without overriding `decorative` (default `true` → `role="presentation"` + `aria-hidden`), so it never violates `ItemGroup`'s `role="list"` ARIA-owned-elements contract. Verified by an explicit test.

4. **Cross-component import via `@/components/ui/separator`** (not a relative `./separator` import) — confirmed this is the house convention by reading `sidebar.tsx` (`import { Separator } from '@/components/ui/separator'`) and `badge.tsx`/`icon-button.tsx` (same alias pattern for `Spinner`/`Button`). The `@/components/ui/*` alias resolves to `./registry/ui/*` inside `packages/ui/tsconfig.json`, so it type-checks and builds inside this package too — not just in the docs copy-in.

5. **Token mapping vs. shadcn's raw sizes**, per house control/icon scale:
   - `ItemMedia variant="icon"` chip: shadcn `size-8` (32px) → `size-(--size-md)`; inner icon shadcn `size-4` (16px) → `size-(--icon-default)`.
   - `ItemMedia variant="image"` tile: shadcn `size-10` (40px) → `size-(--size-lg)`.
   - `variant="muted"` background: shadcn `bg-muted/50` → `bg-muted/(--alpha-wash)` (the existing `--alpha-wash: 50%` token, documented for exactly this "neutral wash" use).
   - Interactive-row hover: shadcn `[a]:hover:bg-accent/50` (a _descendant_-selector, only matches a nested `<a>`, not `Item` itself if `Item` becomes the `<a>` via `asChild`) → rewritten as `[&:is(a,button)]:hover:bg-accent/(--alpha-wash)`, a _self_-selector arbitrary variant that correctly matches when `Item`'s own rendered tag is `a`/`button` (via `render`), with the alpha routed through the token.
   - No `outline-none` anywhere in the file — relies entirely on the centralized `base.css` `:focus-visible` outline (same pattern as `dropdown-menu.tsx`/`tabs.tsx`), avoiding the design-lint `outline-none`-without-focus-affordance check entirely.

6. **`ItemTitle`/`ItemHeader`/`ItemFooter` are `<div>`, not `<h3>`/heading elements** — matches the shadcn reference (`Item` is a row/list primitl, not a document-outline heading, unlike `EmptyTitle`'s `<h3>`). Documented in the Accessibility section that meaning lives in the text content, not an implicit heading landmark.
