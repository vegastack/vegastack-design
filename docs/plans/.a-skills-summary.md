## TASK 2 — `skills/design-audit/SKILL.md` (v0.1.0 → v0.2.0, full rewrite)

The checklist is now an explicit 1:1 mirror of `design-lint.mjs`'s actual rule set — **all 20
component-source rules + the 2 raw-CSS `!important` exceptions**, each cited by the same `id` the script
uses (`hex-color`, `raw-palette`, `important`, `icon-source`, `removed-radius-xl`, `raw-control-size`,
`raw-icon-size`, `raw-z-index`, `raw-alpha`, `raw-opacity`, `off-scale-text`, `inline-svg-icon`,
`render-contract`, `arbitrary-value`, `transition-pairing`, `flex-truncate-conflict`, `raw-motion`,
`outline-none`, `inline-style`, `icon-button-name`), plus 4 non-lint judgment rules (raw interactive
HTML, deprecated usage, docs completeness, naming-canon drift), registry integrity drift (header/hash/
manifest cross-check + `registryDependencies` cross-check), and a new **"VRT review discipline"** section
(individually-review-diffs, delete-then-regenerate for a suspect baseline — not `--update-snapshots`,
fresh-build requirement / `reuseExistingServer: false`, both-lanes coverage, no skipped/TODO VRT markers)
that the old skill didn't have at all.
**Stale-rule audit finding**: the PRE-overhaul skill did not actually contain any of the specifically-
flagged stale claims (old 5-step radius scale, old type scale, purple primary, focus rings, 45%
disabled-opacity) — it was written generically enough to not assert those specifics. Its real problem was
**incompleteness**, not staleness: it enumerated 6 broad rule categories where the lint script enforces
20+ specific, cite-able rules. The rewrite closes that gap rule-by-rule rather than removing anything.
