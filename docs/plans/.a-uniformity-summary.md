# Phase A — docs preview design-lint uniformity

`node ../../tooling/design-lint.mjs components/preview` went from **27 violations** to **0**, and the
invocation is now wired permanently into `apps/docs`'s `lint` script (zero-exception — every future
preview file is checked on every `pnpm lint` / CI run).

## Fixes by category

### raw-control-size (7)

The 28/32/40 control scale must route through `h-(--size-sm|md|lg)`, not raw `h-7/h-8/h-10`
(`--size-sm` = 1.75rem/28px, `--size-md` = 2rem/32px, `--size-lg` = 2.5rem/40px — `packages/tokens/src/tokens.ts`).

- `components/preview/emoji-picker.tsx:92` — `min-h-8` → `min-h-(--size-md)` (the regex also catches
  `min-h-8` because it contains the `h-8` substring; token-swapped rather than suppressed).
- `components/preview/separator.tsx:32` — `h-8` → `h-(--size-md)`.
- `components/preview/skeleton.tsx:120,121` — `h-8 w-20` → `h-(--size-md) w-20` (both footer-action
  skeletons).
- `components/preview/sidebar.tsx:185-187` — these were **descriptive label strings**
  (`'sm (h-7)'`, `'default (h-8)'`, `'lg (h-10)'`), not class names. Reworded to the pixel value per
  the task instruction instead of suppressing: `'sm (28px)'`, `'default (32px)'`, `'lg (40px)'`.

### transition-pairing (5, one file had 2)

Every `transition-*` utility now carries `duration-fast ease-standard` in the same string literal,
matching the pattern used throughout `packages/ui/registry/ui/*` (e.g. `breadcrumb.tsx`,
`accordion.tsx`, `bubble.tsx` canonical source).

- `components/preview/breadcrumb.tsx:117` — ellipsis-menu trigger.
- `components/preview/bubble.tsx:222` (both branches of the ternary) — collapsible chevron rotation.
- `components/preview/marker.tsx:215` — link-button revert marker.
- `components/preview/message-scroller.tsx:261` — visibility-outline turn button.

### hex-color (2 — both false positives from prose, not real hex)

Neither line contained an actual color literal; the regex (`#[0-9a-fA-F]{3,8}`) matched incidental
text that happened to look hex-shaped.

- `components/preview/dialog.tsx:91` — the prose used HTML entities `&#123;false&#125;` to render
  literal `{false}` inside a `<code>` tag; `&#123;` contains `#123` (valid hex digits). Replaced with
  a JS string expression `{'showCloseButton={false}'}` — identical rendered output, no entity.
- `components/preview/marker.tsx:161` — the demo text was `Merged <a>#482</a> into main`; `#482` is
  valid hex. Reworded to `Merged <a>PR 482</a> into main` (same meaning — a merged PR reference —
  without a `#`-prefixed hex-looking token). Minor visible text change, no geometry impact.

### arbitrary-value (13)

Tailwind v4's dynamic spacing scale (`--spacing: 0.25rem`, and any integer N × that unit is a valid
utility, e.g. `h-104` = 26rem) already has precedent in this codebase (`min-h-32` in
`playground.tsx`, `max-w-64` in `attachment.tsx`). All 12 hardcoded rem literals had an **exact**
scale step (no visual delta), converted 1:1:

| File                       | Before          | After      | Exact?                                                  |
| -------------------------- | --------------- | ---------- | ------------------------------------------------------- |
| `app-shell.tsx:51,118,160` | `h-[26rem]`     | `h-104`    | yes                                                     |
| `app-shell.tsx:201`        | `h-[22rem]`     | `h-88`     | yes                                                     |
| `card.tsx:29,41`           | `max-w-[16rem]` | `max-w-64` | yes                                                     |
| `dashboard-01.tsx:26,44`   | `h-[34rem]`     | `h-136`    | yes                                                     |
| `dashboard-01.tsx:35`      | `h-[26rem]`     | `h-104`    | yes                                                     |
| `scroll-area.tsx:53`       | `w-[40rem]`     | `w-160`    | yes                                                     |
| `scroll-area.tsx:104`      | `w-[28rem]`     | `w-112`    | yes                                                     |
| `wrapper.tsx:11`           | `min-h-[8rem]`  | `min-h-32` | yes (shared by every preview demo — no geometry change) |

The 13th case, `dialog.tsx:149`, was prose text (inside a `<code>` tag) describing
`max-h-[calc(100dvh-2rem)]` — a literal `2rem` offset inside `calc()`, which the lint rule bans even
in class strings (calc offsets must route through a token var). The _actual_ canonical component
(`packages/ui/registry/ui/dialog.tsx:29`) uses `max-h-[calc(100dvh-var(--spacing)*8)]`
(`var(--spacing)*8` = `0.25rem*8` = `2rem` — numerically identical). Updated the prose to describe
the real, token-correct value the component ships, rather than an approximation: no visual change
(it's text, not a class), and the docs now accurately describe the component's actual class.

## Files with a visible-geometry change (for VRT review)

All geometry conversions above landed on an **exact** Tailwind v4 scale step — the rendered pixel
dimensions are byte-identical to before. No visual diff is expected from the arbitrary-value or
raw-control-size fixes. Flagging these files anyway since their `className` literals changed and
they render demo chrome:

- `apps/docs/components/preview/app-shell.tsx` (4 `Wrapper` heights)
- `apps/docs/components/preview/card.tsx` (2 `Card` max-widths)

- `apps/docs/components/preview/scroll-area.tsx` (2 scroll-content widths)
- `apps/docs/components/preview/wrapper.tsx` (shared `Wrapper` min-height — affects every demo that
  doesn't override it, but the value is numerically identical: 8rem == 32×0.25rem)
- `apps/docs/components/preview/emoji-picker.tsx`, `separator.tsx`, `skeleton.tsx` (control-height
  token swaps — 32px in both the before and after)
- `apps/docs/components/preview/marker.tsx` (text content change on line 161: `#482` → `PR 482` —
  not a geometry change, but a visible text diff worth a VRT glance)

No visual change expected anywhere: `sidebar.tsx` (label text only, not rendered class), `dialog.tsx`
(prose text + one JSX-expression rewrite for identical rendered output), `breadcrumb.tsx`,
`bubble.tsx`, `message-scroller.tsx` (transition-pairing additions only affect animation curve/
duration, not layout).

## Lint-script wiring

exceptions) so every preview demo is checked on every future `pnpm lint` / CI run. Only the `"lint"`
script line was touched — no other `package.json` fields changed.
