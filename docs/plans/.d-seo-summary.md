# Phase D — SEO pack + registry headers + llms-route verification

Scope: `apps/docs/app/**` (metadata, sitemap, robots, OG images), `apps/docs/public/_headers` (new),
`apps/docs/lib/**` (helper modules). Did not touch `apps/docs/components/**` or
`apps/docs/content/**` (owned by the parallel component-polish agent).

## Canonical domain

`https://design.vegastack.com` — confirmed in `docs/plans/detail/04-registry-and-cloudflare.md`:
the registry `homepage` (line 11), the `VEGASTACK_REGISTRY` default (line 92), the registry item
`url` template (line 129), and the Cloudflare Access application domain for the human-docs app
(line 177). The docs app and the `/r/*` registry are served from the same Worker
(`apps/docs/wrangler.jsonc`), so this is also the docs site's own public URL. No other host
reference exists in wrangler/deploy configs. Set as `apps/docs/lib/metadata.ts:siteUrl`.

## 1. Metadata

- New `apps/docs/lib/metadata.ts`: `siteUrl`, `defaultDescription`, `createMetadata()` (merges
  openGraph/twitter defaults — adapted from the fumadocs.dev docs app's own `lib/metadata.ts`
  pattern, no third-party fetch involved).
- `apps/docs/app/layout.tsx`: added `export const metadata` (title template `%s · VegaStack
  Design`, `metadataBase: siteUrl`, default description) and `export const viewport` (theme-color
  meta, light/dark, literal hex values copied from `packages/tokens/dist/theme.css` since
  `<meta>` tags can't read CSS custom properties — flagged with `eslint-disable-next-line
  no-restricted-syntax` + an explanatory comment, no eslint config changes).
- Verified per-page titles already flow into the template: `apps/docs/app/docs/[[...slug]]/page.tsx`
  `generateMetadata` returns `title: page.data.title` (a plain string) from MDX frontmatter — Next
  merges a string child title into a parent `title.template` automatically. No change needed there
  beyond adding OG/Twitter images (see §3).

## 2. sitemap.ts + robots.ts

- `apps/docs/app/sitemap.ts` — enumerates `/` plus every page from `source.getPages()` (which
  already includes the `/docs` index page from `content/docs/index.mdx`, confirmed present so no
  separate manual entry). `revalidate = false`, no request-time APIs — static-export safe.
- `apps/docs/app/robots.ts` — allow-all plus `Disallow: /r/` (the registry is service-token-gated
  behind Cloudflare Access per `AGENTS.md` "Auth"; not meant for search indexing), links
  `sitemap.xml`. No pre-decided header/robots spec existed in
  `docs/plans/detail/04-registry-and-cloudflare.md` to follow — this is a from-scratch, sensible
  default.
- Both confirmed to statically prerender under `output: 'export'` in the real `pnpm build` (see
  build evidence below) — Next supports `sitemap.ts`/`robots.ts` as static-computed special files
  when they don't read request-time state, which is the case here.

## 3. OG images

Investigated `fumadocs-ui@16.10.5`'s `og` export (`node_modules/fumadocs-ui/dist/og.js`,
`generate`/`generateOGImage`) and the fumadocs monorepo's own `next-static` example app
(`/Users/kmanojkumar/code/references/fumadocs/examples/next-static/app/og/docs/[...slug]/route.tsx`)
— the exact pattern for a per-page `ImageResponse` route under `output: 'export'`
(`generateStaticParams` + `revalidate = false`). Confirmed compatible; implemented (not just a
single static fallback):

- `apps/docs/lib/og.tsx` — branded `OGImage` component (1200×630) built for `next/og`'s
  `ImageResponse` (Satori — no CSS custom properties available, so colors are literal hex copied
  from the dark-theme build in `packages/tokens/dist/theme.css`: background `#11100f`, foreground
  `#e6e5e3`, muted `#939290`, brand/phosphor accent `#56f57c` used only as a thin top stripe + a
  small live-dot next to the wordmark — per the `brand` token's own DTCG description, "marker
  roles only… never a fill, headline, or button").
- `apps/docs/lib/source.ts` — added `getPageImage(page)` (`/og/docs/<slug>/image.png`), mirroring
  `getPageMarkdownUrl`.
- `apps/docs/app/og/docs/[...slug]/route.tsx` — renders `OGImage` per docs page via
  `ImageResponse`, `generateStaticParams()` over all 91 docs pages.
- `apps/docs/app/(home)/opengraph-image.tsx` — Next's file-convention static OG image, scoped to
  the `(home)` route group so it applies only to `/` (avoids any ambiguity with the docs pages'
  explicit `generateMetadata` override).
- `apps/docs/app/docs/[[...slug]]/page.tsx` `generateMetadata` now sets
  `openGraph.images` / `twitter.images` to `getPageImage(page).url`.

No limitation to document — full per-page OG images work under static export, confirmed by build
(91 PNGs generated under `out/og/docs/**` + 1 at `out/opengraph-image-*` for the home page).

## 4. public/_headers

New `apps/docs/public/_headers` (Cloudflare Workers Static Assets header-rule format):
- `/r/*` → `Access-Control-Allow-Origin: *` + `Cache-Control: public, max-age=300, must-revalidate`
  (registry JSON is the update channel `vegastack-design check-updates` / `shadcn add --diff`
  poll — must revalidate quickly, not be immutable, per the task brief).
- `/_next/static/*` → `Cache-Control: public, max-age=31536000, immutable` (content-hashed, safe
  forever).
No pre-decided header spec existed in `docs/plans/detail/04-registry-and-cloudflare.md` to follow.
Confirmed copied into `out/_headers` verbatim by `next build` (Next copies `public/**` as-is).

## 5. llms.txt re-verification

Generator code: `apps/docs/app/llms.txt/route.ts` and `llms-full.txt/route.ts` call
`fumadocs-core`'s `llms(source).index()` / hand-rolled `getLLMText` over `source.getPages()` —
i.e. both are **fully derived from `content/docs/**` + `meta.json`**, not a hardcoded list. There
was no stale-string bug to fix in the generator itself; the source of truth (meta.json files) was
already correct post-rename.

Verified via `grep` on the rebuilt `out/`:
- `out/sitemap.xml` — 92 URLs (home + 91 docs pages), includes
  `/docs/components/{combobox,region-select,command,resizable,app-shell,item,chart,animated-number,empty,attachment}`
  and `/docs/blocks/dashboard-01`. Zero hits for `empty-state` or `state-select` as path segments.
- `out/llms.txt` — all 10 renamed/new pages present by name and correct link
  (`/docs/components/combobox`, `/docs/components/region-select`, `/docs/components/command`,
  `/docs/components/resizable`, `/docs/components/app-shell`, `/docs/components/item`,
  `/docs/components/chart`, `/docs/components/animated-number`, `/docs/components/empty`,
  `/docs/components/attachment`, `/docs/blocks/dashboard-01`).
- `out/llms-full.txt` — 7 hits for the strings `empty-state`/`state-select`, all inspected: every
  one is a prose/anchor coincidence (headings like "Full-page empty state", the generic UI concept
  "empty state", or a JSDoc-style prop description "Empty-state content shown when no items
  match") — none are stale route/component-name references. Confirmed clean.
- `out/llms.mdx/docs/components/{empty,region-select}/content.md` exist (renamed per-page raw
  routes present).
