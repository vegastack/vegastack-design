# C2 — React 19 ref-as-prop migration summary

## Scope

Migrated every `React.forwardRef` in the 24 assigned canonical component files
(`packages/ui/registry/ui/`) to React 19 ref-as-prop style, and added ref
forwarding to the 11 previously ref-less exports in `bubble.tsx`, `marker.tsx`,
and `message.tsx`. Canonical sources only — `apps/docs/components/ui/*` (the
generated copy-in) was never touched, per the single-source-of-truth rule.
`registry:build` was **not** run (not requested), and nothing was committed.

Every conversion followed the mandated pattern: `({ a, ...props }, ref) => …`
→ `function X({ a, ref, ...props }: XProps) { … }`, with every
`React.ComponentPropsWithoutRef<...>` (typed element tags or `typeof Base.Part`)
switched to `React.ComponentProps<...>` so the prop type carries `ref` in React
19, and every `X.displayName = '...'` line deleted (the named function
declaration now carries the name). No className, JSDoc content, variant logic,
or behavior changed. `image.tsx`'s internal `setImgRef` merge callback was
preserved as-is, just re-sourced from `ref` in the props object.

## Files given new ref forwarding (11 exports, previously plain functions)

- `bubble.tsx`: `Bubble`, `BubbleGroup`, `BubbleReactions` (`BubbleContent` was
  already `ComponentPropsWithRef`-based and untouched).
- `marker.tsx`: `MarkerIcon`, `MarkerContent` (`Marker` was already
  `ComponentPropsWithRef`-based and untouched).
- `message.tsx`: `MessageGroup`, `Message`, `MessageAvatar`, `MessageContent`,
  `MessageHeader`, `MessageFooter` (all 6 exports).

Each got a `ref` destructured from its (already-`ComponentProps<...>`) props
type and wired to the root element's `ref={ref}`.
