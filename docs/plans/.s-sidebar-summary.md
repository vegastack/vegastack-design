# Phase S — Sidebar overhaul (audit 11) — summary

Scope: `packages/ui/registry/ui/sidebar.tsx` (extended, not rewritten), new
`packages/ui/registry/ui/use-mobile.ts` hook, tests for both, and docs
(`apps/docs/components/preview/sidebar.tsx`, `apps/docs/content/docs/components/sidebar.mdx`).

## What changed / what's new

**New file `use-mobile.ts` (registry:hook)** — `useIsMobile(breakpoint = 768)`. SSR-safe
`matchMedia('(max-width: <breakpoint-1>px)')` hook, following `truncated-text.tsx`'s
`usePrefersNoHover` pattern exactly: initial state always `false` (desktop) so server/client
markup agree, real value lands in a client effect, live-updates via the media query's `change`
listener. `'use client'`, fully JSDoc'd.

**`sidebar.tsx` — every existing export and behavior preserved.** All 11 pre-existing exports
(`useSidebar`, `SidebarProvider`, `Sidebar`, `SidebarHeader`, `SidebarContent`, `SidebarFooter`,
`SidebarGroup`, `SidebarGroupLabel`, `SidebarMenu`, `SidebarMenuItem`,
`sidebarMenuButtonVariants`, `SidebarMenuButton`, `SidebarMenuBadge`, `SidebarSeparator`,
`SidebarTrigger`) keep their prior DOM shape, class output, and default behavior — the default
`collapsible="icon"` desktop path is untouched aside from additive `data-variant`.

Added:

1. **`SidebarContext`/`useSidebar()`** — new fields `isMobile`, `openMobile`, `setOpenMobile`.
   `toggleSidebar()` now branches: toggles `openMobile` when `isMobile`, else `open` (shadcn's
   split, re-expressed in our idiom).
2. **`SidebarProvider`** — new `mobileBreakpoint` prop (default 768, forwarded to
   `useIsMobile`); owns `openMobile` state; writes the `sidebar_state` cookie (`path=/`,
   `max-age=31536000`) inside `setOpen` on every desktop toggle. **Write-only** — never reads
   `document.cookie` at render (SSR-safe). The SSR restore pattern (server layout reads the
   cookie, passes `defaultOpen`) is documented in the provider's JSDoc and the mdx, not
   implemented in the component (that's inherently the consumer's server code).
3. **Mobile Sheet mode** — below the breakpoint, `Sidebar` renders its children inside
   `Sheet`/`SheetContent` (imported from `@/components/ui/sheet`) instead of the static `<nav>`.
   `SidebarTrigger`'s existing `toggleSidebar()` call opens it automatically (no separate mobile
   API). A visually-hidden `SheetHeader`/`SheetTitle`/`SheetDescription` gives the sheet an
   accessible name (axe-clean). The actual `<nav data-slot="sidebar">` landmark still renders
   _inside_ the sheet, so `ref`/`aria-label`/`data-state` etc. all resolve the same way
   regardless of mode.
4. **`collapsible` prop** on `Sidebar`: `'offcanvas' | 'icon' | 'none'`, default `'icon'`
   (=exact prior behavior). `data-collapsible` = `state === 'collapsed' ? collapsible : ''`
   (matches the pre-existing pattern exactly for the default case).
   - `'offcanvas'`: `data-[state=collapsed]:w-0` + `-translate-x-full`/`translate-x-full`
     (side-aware), `overflow-hidden` scoped to the collapsed state only (so a nested
     `SidebarRail` isn't clipped while expanded).
   - `'none'`: checked **first**, before the mobile branch — a rail that never collapses also
     never becomes a Sheet; always renders full-size in place.
5. **`SidebarRail`** — real focusable `<button>` (not `tabIndex={-1}`, deliberately more
   accessible than shadcn's mouse-only edge-drag handle), `aria-label`/`title="Toggle sidebar"`,
   positioned via `group-data-[side]/sidebar` (render it as a **child of `Sidebar`**, not a
   provider-level sibling — see "API deviations" below for why).
6. **`SidebarInset` + `variant` prop** (`'sidebar' | 'floating' | 'inset'`, default `'sidebar'`).
   `Sidebar` carries `peer` + `data-variant`; `SidebarInset` reads it via
   `md:peer-data-[variant=inset]:m-2 …rounded-lg border shadow-overlay` to become the panel only
   under `variant="inset"`. `'floating'` styles `Sidebar` itself (`m-2 rounded-lg border
shadow-overlay`, height adjusted via `calc(100svh-var(--spacing)*4)`).
7. **`SidebarMenuSkeleton`** — icon-circle + text-line, composes `Skeleton`. Width is
   `SIDEBAR_MENU_SKELETON_WIDTHS` (5-entry fixed cycle) selected via `index % length` — no
   `Math.random()`, deterministic for VRT.
8. **`SidebarTrigger` touch target** — added `relative` + `before:absolute before:-inset-2`
   (checkbox.tsx's pattern). 28px visible box + 2×8px = 44px effective hit area, universally
   (not breakpoint-conditional — 44px already covers the ≥24px desktop minimum too).
9. **Nav label truncation (point 8)** — left `[&>span:last-child]:truncate` as-is (DOM/API
   unchanged). **Decision: did NOT import `truncated-text.tsx` into `sidebar.tsx`.** Documented
   the composition pattern instead (`<span><TruncatedText>{label}</TruncatedText></span>`) in
   both `sidebarMenuButtonVariants`' comment and `SidebarMenuButton`'s JSDoc — importing it would
   force every `sidebar` consumer to also pull `@vegastack/truncated-text` →
   `@vegastack/tooltip`, and pay for its `ResizeObserver` + ARIA disclosure logic, even for the
   common case of short static labels.
10. Collapse motion — kept the token pairing (`duration-base ease-standard`), extended the
    transitioned-properties list to `transition-[width,transform]` (single literal, so the
    design-lint transition-pairing rule still sees one duration+ease per transition) since
    offcanvas now also needs a transform transition; the same one string covers both.

## API deviations from the spec / shadcn, with rationale

- **`--sidebar-width-mobile` is NOT a new design token** (packages/tokens is out of scope for
  this task — forbidden file). Routed the "same var+arbitrary-class way" as `--sidebar-width`,
  but the `18rem` default lives _inside_ the `var()` call as a fallback:
  `w-[var(--sidebar-width-mobile,18rem)]` — a design-lint-sanctioned arbitrary-value form (rule:
  any arbitrary value starting `var(--` passes, regardless of its fallback). A literal `18rem` in
  a `style={{...}}` object is explicitly banned by the lint's inline-style contract even for a
  `--*`-only key, so this was the only lint-clean way to ship a default without touching tokens.
  **Follow-up recommended:** promote `--sidebar-width-mobile: 18rem` into
  `packages/tokens/tokens/semantic.tokens.json` alongside `sidebar-width`/`sidebar-width-icon` in
  a separate, tokens-scoped change.
- **`SidebarRail` takes no `side` prop** and must be rendered as a **child of `Sidebar`** (not a
  `SidebarProvider`-level sibling, unlike shadcn's fixed-position two-div gap/container
  technique). Our `Sidebar` is a single real flex child (not `position: fixed`), so there's no
  separate "gap" element to hang a sibling rail off of; nesting it inside lets it read
  `group-data-[side]/sidebar` directly from its own ancestor with zero extra props to keep in
  sync. Documented in its JSDoc + the mdx composition example.
- **`SidebarInset` uses `peer`/`peer-data-[variant=inset]`**, matching shadcn's actual mechanism
  (verified against upstream), but `Sidebar` stays a normal flex sibling rather than
  `position: fixed` — so `SidebarInset` is a plain content column with `md:` breakpoint-scoped
  panel styling, not a full re-architecture of the layout model. Chose to extend the existing
  single-flex-child layout rather than introduce the fixed-position two-layer technique, per the
  "extend, not rewrite" mandate.
- **`SidebarProvider` gained `mobileBreakpoint`** (not in the spec's literal list) — a natural,
  low-risk extension so `useIsMobile`'s configurability isn't stranded; defaults to 768,
  zero behavior change for existing consumers.
- **Mobile-aware composition requires `SidebarTrigger` outside `Sidebar`.** This is a _real, load-bearing_
  usage change surfaced by adding mobile mode: below the breakpoint, `Sidebar`'s own children
  (Sheet content) only mount once `openMobile` is true — a trigger nested inside `SidebarHeader`
  (the pre-existing example composition) can never be reached to open it. The pre-existing
  desktop-only `Demo` test fixture is untouched (still valid for desktop-only assertions); a new
  `MobileDemo` fixture in the test file puts the trigger outside `Sidebar`, and the mdx's new
  "Mobile" section documents the composition explicitly with a code sample.

## registry.json additions needed (not applied — `registry.json` is a forbidden file for this task)

New `registry:hook` item (mirrors `use-animation-replay`'s shape):

```json
{
  "name": "use-mobile",
  "type": "registry:hook",
  "title": "useIsMobile",
  "description": "SSR-safe viewport-width hook — reports whether the viewport is below a breakpoint (default 768px), live across resizes.",
  "categories": ["hook"],
  "dependencies": [],
  "registryDependencies": [],
  "files": [
    {
      "path": "packages/ui/registry/ui/use-mobile.ts",
      "type": "registry:hook",
      "target": "@ui/use-mobile.ts"
    }
  ],
  "meta": {
    "whenToUse": "Switching a layout between desktop and mobile treatments (e.g. Sidebar's rail vs. Sheet mode) based on real viewport width.",
    "whenNotToUse": "CSS-only responsive layout — reach for a Tailwind breakpoint utility instead when no JS branching is needed.",
    "version": "0.1.0"
  }
}
```

`sidebar`'s existing item needs its `registryDependencies` array updated (currently just
`["@vegastack/separator"]`) — `sidebar.tsx` now also imports from `sheet.tsx`, `skeleton.tsx`,
and `use-mobile.ts`:

```json
"registryDependencies": [
  "@vegastack/separator",
  "@vegastack/sheet",
  "@vegastack/skeleton",
  "@vegastack/use-mobile"
]
```

(No new npm `dependencies` for `sidebar` itself — `sheet`/`skeleton` bring their own npm deps
via their own registry items.)

## Test evidence

`npx tsc --noEmit` (packages/ui): clean.

`npx vitest run registry/ui/sidebar.test.tsx registry/ui/use-mobile.test.tsx`: **34/34 passed**
(10 pre-existing sidebar tests untouched and still green + 19 new sidebar tests + 5 new
use-mobile tests... exact split: `sidebar.test.tsx` 29 tests, `use-mobile.test.tsx` 5 tests — see
below for what each new block covers).

New coverage added:

- `use-mobile.test.tsx`: desktop/mobile via mocked `matchMedia`, custom breakpoint, live
  `change`-event updates, SSR-safe fallback when `matchMedia` is absent.
- `sidebar.test.tsx`:
  - Mobile mode: closed by default (no `[role=dialog]`), trigger opens it (`MobileDemo` fixture,
    trigger outside `Sidebar`), Escape closes it, axe-clean while open.
  - `collapsible` modes: `'icon'` (default, unchanged), `'offcanvas'` (utility classes present +
    `data-collapsible` reflects the mode once collapsed), `'none'` (always expanded, trigger is a
    no-op for it).
  - `SidebarRail`: toggles open state on click, carries `aria-label`/`title`.
  - `SidebarInset`: renders `<main>`, forwards `className`.
  - `SidebarMenuSkeleton`: same `index` → identical width; different `index` → different width;
    the 5-wide cycle wraps (`index=5` matches `index=0`); `showIcon={false}` hides the circle;
    decorative (`aria-hidden`) like the `Skeleton` it composes.
  - Cookie: `sidebar_state=false`/`true` written to `document.cookie` on toggle.
  - `SidebarTrigger` touch target: `::before` resolves ≥44×44 (real Chromium-computed geometry
    via an injected CSS mirror, same technique as `checkbox.test.tsx`'s suite — note this mirror
    needed an extra `border: 0; padding: 0;` reset on the trigger's native `<button>` that
    `checkbox.test.tsx`'s `<span>`-rooted mirror didn't need, since this harness compiles no
    Tailwind Preflight to zero out the UA default button chrome); a point inside the expansion
    hits and toggles it; a point beyond it does not.

**Bug found + fixed while writing tests, worth flagging:** this suite's real Playwright browser
viewport is **414×896** (mobile-sized) with no explicit `browser.viewport` config — there is no
desktop-sized default. Since `useIsMobile`'s default breakpoint is 768px, EVERY test in
`sidebar.test.tsx` (including all pre-existing desktop tests) would otherwise mount `Sidebar` in
mobile-Sheet mode, closed by default, rendering nothing. Fixed with a file-scoped
`beforeEach`/`afterEach` that defaults `window.matchMedia` to "desktop" for every test in this
file; `withMobileViewport()` flips a single shared override for the tests that specifically
exercise mobile mode. This is scoped to `sidebar.test.tsx` only (did not touch the shared
`vitest.setup.ts`, which is out of scope for this task and affects every other component's
tests).

`node tooling/design-lint.mjs packages/ui/registry`: clean.
