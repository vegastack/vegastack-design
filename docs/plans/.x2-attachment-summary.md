## Deviations from the shadcn `new-york-v4` reference

Reference read from
`/private/tmp/.../scratchpad/x2-refs/attachment-attachment.tsx`. Kept the same
overall anatomy/prop shape (`state`, `size`, `orientation`, media/content/title/
description/actions/trigger/group) but adapted:

1. **Radix `Slot` → Base UI `useRender`** for `AttachmentTrigger`'s polymorphism
   (house rule), copying `marker.tsx`/`bubble.tsx`'s pattern exactly.
2. **No `ring` utilities.** The reference used `focus-within:ring-1 ring-ring/50`;
   per the locked v2 token decision ("one border, no rings"), focus is instead
   surfaced via `focus-within:border-ring/(--alpha-tint-border)` (the same idiom
   `button.tsx`/`bubble.tsx` use).
3. **Dropped the reference's `AttachmentAction`** (a `Button` wrapper defaulting to
   `variant="ghost" size="icon-xs"`). This system already has `IconButton`, whose
   whole job is a type-level `aria-label` guarantee for icon-only actions — adding
   a second wrapper around it would be pure duplication (DRY). Consumers compose
   `IconButton` directly inside `AttachmentActions`, the same way `message.tsx`'s
   preview composes bare `Button` inside `MessageFooter` with no `MessageAction`
   wrapper. **Caveat:** `IconButton` hardcodes `data-slot="icon-button"` internally
   (it spreads `...props` *before* setting `data-slot`, so a caller-supplied
   `data-slot` is clobbered) — so a composed remove action is queryable by
   `[data-slot="icon-button"]` or by role/accessible-name, not by a bespoke
   `attachment-action` slot. Documented in the component JSDoc and the mdx
   Accessibility section.
4. **Added `AttachmentProgress`** (not in the reference) — a thin `Progress`
   wrapper (`size="sm"`, requires `aria-label`) for the `uploading` lifecycle,
   composing the system's existing `Progress` component per the task brief.
5. **`AttachmentMedia` auto-shows an upload spinner overlay.** The reference has no
   equivalent — I composed `Spinner size="inherit"` directly inside
   `AttachmentMedia`, toggled by `group-data-[state=uploading]/attachment:flex`, so
   consumers don't have to conditionally render it themselves.
6. **Live-region announcements are opt-in via `AttachmentDescription`'s `live`
   prop** (`role="status" aria-live="polite" aria-atomic="true"`), mirroring
   `auto-save-input.tsx`'s status-suffix pattern and `copy-button.tsx`'s
   visually-live-but-usually-empty span — rather than the reference's silent
   `group-data-[state=error]:text-destructive/80` (color-only, no live region).
7. **`AttachmentGroup` is `flex-wrap`**, not the reference's horizontal
   scroll-snap row (`scroll-fade-x`/`scrollbar-none`/`snap-x`) — judgment call: a
   wrapping row reads better than a carousel for the handful of attachments a
   message-compose box typically holds. (Those utilities do exist in
   `packages/tokens/src/utilities.css` if a future revision wants the carousel
   back.)
8. **Size scale simplified to `default` | `sm`** (reference had `default` / `sm` /
   `xs`) — kept the surface smaller; `sm` already covers the compact
   message-compose case the task asked for. Media box sizes off the existing
   `--size-lg` (40px, default) / `--size-md` (32px, `sm`) tokens, not literal `w-10`/`w-8`.
9. **`state` values are `idle | uploading | error | complete | disabled`**
   (reference used `idle | uploading | processing | error | done`) — matches
   exactly the 5-state test matrix specified in the task brief; dropped
   `processing` (redundant with `uploading` for this system's needs) and renamed
   `done` → `complete` for clarity, added `disabled` as a first-class state
   (dims + `pointer-events-none` + `aria-disabled`, per the task's accessibility
   ask) rather than a separate boolean prop.

## Accessibility

- `AttachmentMedia` is `aria-hidden` — the file name (`AttachmentTitle`) carries
  identity, never the icon/thumbnail.
- Remove/download actions are composed `IconButton`s — `aria-label` is a **type
  error** if omitted, and both the preview demos and the mdx Accessibility
  section call out including the file name in it.
- `AttachmentDescription`'s `live` prop is the actual announcement mechanism for
  uploading/error text (a bare `role="progressbar"` on `AttachmentProgress` is not
  reliably announced on every value change — documented in its JSDoc).
- `state="disabled"` sets `aria-disabled` + `pointer-events-none` on the root, but
  — since the root can't reach into arbitrary children — consumers must also pass
  `disabled` to any nested `IconButton` for real keyboard inertness. Called out in
  `AttachmentProps.state` JSDoc and the mdx Accessibility section.
- axe (`expectNoA11yViolations`) passes for all 5 states individually and for a
  multi-attachment `AttachmentGroup`.
