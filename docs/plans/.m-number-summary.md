## Mechanism: JS `requestAnimationFrame` tween (not CSS `@property` + `counter()`)

Both were investigated. Verdict: **rAF tween**, and the deciding factor is not just the
documented a11y caveat — it's a hard functional blocker for the CSS route:

- `@property --n { syntax: '<integer>' }` itself is well supported in the installed Playwright
  Chromium (this repo's VRT browser) and in Safari 16.4+; Firefox shipped it later (128, mid-2024)
  — recent but not universal.
- But the _number itself_ would have to render via `content: counter(n)` generated content. CSS
  counters only support simple numbering **systems** (`decimal`, `cjk-decimal`, …) — they cannot
  produce `Intl.NumberFormat` output: no currency symbols, no percent signs, no `notation:
'compact'`, no locale-aware grouping/pluralization. Since the spec requires `format` to accept
  full `Intl.NumberFormatOptions` and apply identically to every animated intermediate frame, the
  CSS route cannot satisfy the formatting requirement at all — independent of its separately-true
  a11y caveats (generated content is inconsistently exposed to screen readers, and gating a
  `counter()` node to "announce settled value only" is awkward/unreliable).
- A JS tween sidesteps this cleanly: every frame — intermediate or settled — is produced by the
  _same_ `Intl.NumberFormat(locale, format)` call.

Full reasoning is written into the component's top-of-file doc comment in
`animated-number.tsx` (not just this summary).

**Duration + easing are read live from the motion tokens**, never hardcoded:
`getComputedStyle(node).getPropertyValue('--duration-fast|base|slow')` and
`--motion-ease-standard`, resolved off the rendered node (so a local token override that cascades
onto it is honored). A cubic-bezier is parsed out of the token string and evaluated with a
standard Newton-Raphson solve (the same technique browsers use for `transition-timing-function`)
— so the JS easing actually matches the CSS easing curve, not an approximation.

**Documented JS fallback constants** (`FALLBACK_DURATION_MS` = `{fast:150, base:200, slow:300}`,
`FALLBACK_EASE` = `cubic-bezier(0.2,0,0,1)`) fire only when `getComputedStyle` resolves empty —
which is exactly what happens in this package's fast unit-test harness (`vitest.config.ts`
compiles no Tailwind/token CSS for most test files). They mirror the shipped defaults in
`packages/tokens/dist/theme.css` and are never a substitute for the real tokens in a themed app.

## API surface

```ts
interface AnimatedNumberProps extends Omit<
  React.ComponentPropsWithRef<"span">,
  "children"
> {
  value: number; // required — re-render with a new value to trigger the tween
  format?: Intl.NumberFormatOptions; // currency/percent/compact/grouping — applied to every frame
  locale?: string | string[]; // BCP-47; defaults to runtime locale
  duration?: "fast" | "base" | "slow"; // motion-token name, default 'base' — never a raw ms value
}
```

- Flat export: `AnimatedNumber` + `AnimatedNumberProps`. No CVA — there are no genuine style
  variants (size follows text context, per the spec).
- React 19 ref-as-prop (`ref` destructured directly, no `forwardRef`), merged with an internal
  `setNode` callback so the tween can read live CSS off the actual rendered node.
- `data-slot="animated-number"` on the root `<span>`, plus `data-slot="animated-number-value"`
  (visible, `aria-hidden`) and `data-slot="animated-number-live"` (sr-only live region) on the two
  inner spans.
- `'use client'` — needs effects; server render / first paint is fully static (no flash).

## Behavior

- **Mount = static.** `displayValue` state is seeded with `value`; a `mountedRef` guard skips the
  tween effect on the very first run. Server and client render identically — no hydration
  mismatch.
- **Later `value` change = tween.** `from` is read off a ref (`displayValueRef`) that mirrors the
  _current_ rendered number, not the pre-effect value — this is what makes interruption correct.
- **Interruption.** Changing `value` again mid-tween cancels the in-flight rAF (via the effect's
  cleanup, which React runs before the next effect) and starts a fresh tween from wherever the
  visual number currently sits to the new target — no snap-back to an earlier value.
- **Reduced motion.** `usePrefersReducedMotion()` (SSR-safe `matchMedia` hook, same pattern as
  `truncated-text.tsx`'s `usePrefersNoHover` / `message-scroller.tsx`'s
  `usePrefersReducedMotion` — deliberately re-implemented per-component rather than shared, matching
  house convention of no shared `registry/hooks` file for this kind of local hook today) short-circuits
  straight to the target value with zero animation frames.

## Accessibility design

- Visible ticking text: `aria-hidden="true"` — a rapid stream of announcements while a number
  climbs would be noise.
- A second, visually-hidden span carries `role="status" aria-live="polite" aria-atomic="true"
className="sr-only"` and is updated **only** when a tween settles (or instantly, under reduced
  motion) — never on intermediate frames. This mirrors the `role="status"`+`aria-live="polite"`
  pairing already used in `data-list.tsx`/`table.tsx`/`attachment.tsx`.
- `tabular-nums` on the root — digits don't jitter horizontally as the character count changes
  mid-count (`99` → `100`).
- Verified with `expectNoA11yViolations` (axe, WCAG 2.1 A/AA) both at rest and after a settled
  value change.

Three exports, all stat-card style (`Card`/`CardHeader`/`CardDescription`/`CardTitle`/
`CardContent` + a `Button` that bumps state by a **fixed** amount — no `Math.random`, so the
resting/initial render is byte-identical every run for VRT):

  count, "Total signups", starts at `128`.
- `animatedNumberCurrency` — `format={{ style: 'currency', currency: 'USD' }}`, "Revenue this
  month", starts at `48250`.
- `animatedNumberCompact` — `format={{ notation: 'compact', maximumFractionDigits: 1 }}`,
  "Followers", starts at `12400`; the click increment (`+2100`) is sized to cross a compact-suffix
  boundary during the tween.

can't toggle the OS `prefers-reduced-motion` setting from a static docs page without faking
`matchMedia`, which would be a misleading demo — the real behavior is covered by the component
test suite instead).
