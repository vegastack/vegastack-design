Markdown in VegaStack has two surfaces and one typography. [`MarkdownView`](/docs/components/markdown-view)
renders a markdown string; [`TextEdit`](/docs/components/text-edit) with `format="markdown"` edits
one. Both wear the shared `prose` recipe from `@vegastack/design` (`proseClassName`), and `TextEdit`
resets ProseMirror's defaults, so a document sits at the same position whether it is being read or
edited. The recipe is the app's body text — `text-sm`, the body family and `foreground` ink for
paragraphs, lists, list markers, marks and quotes, headings on the app's type scale — so neither
surface has a separate "prose" look. Only inline code and code blocks are mono.

`TextEdit` is Notion-style: no border, no fill in any state, no focus ring and no view mode — the
caret is the focus cue. It rests looking exactly like `MarkdownView`; click anywhere and type. Leaving the editor calls `onCommit` with the
new markdown when it changed; <kbd>Esc</kbd> reverts.

```tsx
import { MarkdownView } from "@/components/ui/markdown-view";
import { TextEdit } from "@/components/ui/text-edit";

// Editable: the editor is the view.
<TextEdit
  format="markdown"
  defaultValue={summary}
  onCommit={save}
  aria-label="Summary"
/>;

// Read-only elsewhere:
<MarkdownView>{summary}</MarkdownView>;
```

## Every element, view and edit

The same document rendered by `MarkdownView` and edited by a `TextEdit`, stacked. Headings h1–h6, paragraphs, **bold**, _italic_, ~~strike~~, inline code, fenced
code blocks, links, bullet, ordered and task lists (nested), blockquotes, rules, tables, images and

## Slash menu

There is no toolbar. Type <kbd>/</kbd> at the start of a line or after a space to open the block
menu, then type to filter it. <kbd>↑</kbd> <kbd>↓</kbd> move, <kbd>Enter</kbd> inserts and

<kbd>Esc</kbd> closes it with the text left as typed.

| Command       | Inserts                        | Markdown shortcut           |
| ------------- | ------------------------------ | --------------------------- |
| Text          | a plain paragraph              |                             |
| Heading 1–4   | a heading                      | `# ` `## ` `### ` `#### `   |
| Bullet list   | a bullet list                  | `- `                        |
| Numbered list | an ordered list                | `1. `                       |
| Checklist     | a task list                    | `[ ] `                      |
| Quote         | a blockquote                   | `> `                        |
| Code block    | a fenced code block            | ` ```ts `                   |
| Table         | a 3×3 GFM table with a header  |                             |
| Image         | an image, from a URL and alt   | `![alt](url)`               |
| Divider       | a horizontal rule              | `---`                       |
| Link          | a link, through the link input | <kbd>Mod</kbd> <kbd>K</kbd> |

`slashCommands` limits and orders the menu, for example a comment composer that offers only lists,
code and links. `[]` turns the menu off. It limits the menu only: markdown typed or pasted for any
element still works, so every document round-trips.

## Bubble menu

Selecting text floats a small menu: **Turn into** (text, headings 1–4, the three lists, quote or
code block), bold, italic, strikethrough, inline code, link and **Clear formatting**. The link
button, and <kbd>Mod</kbd> <kbd>K</kbd>, turn the menu into an inline URL input: <kbd>Enter</kbd>
applies it, <kbd>Esc</kbd> closes it, and on an existing link **Open** and **Remove** sit beside it.
Pasting a URL over a selection links it directly. Links open in a new tab with
`rel="noopener noreferrer"`.

Every floating part — the bubble menu, the link and image inputs, the slash menu and the table
menu — renders in a portal on `<body>` with fixed positioning that flips and shifts to stay in the
viewport, so an `overflow: hidden` card, a comment box or a dialog never clips it.

## Tables

Tables are GFM tables: a header row, then body rows. With the caret in a cell, a table menu offers
insert row above or below, insert column left or right, move row up or down, move column left or
right, delete row, delete column and delete table. Hover a cell for its grips: drag the grip above a
column, or beside a row, to reorder it — a line shows where it lands — or click a grip to select the
whole column or row. <kbd>Tab</kbd> and <kbd>Shift</kbd> <kbd>Tab</kbd> move between cells, and

<kbd>Tab</kbd> in the last cell adds a row. Markdown has no header-less table,
so the header row stays first and has no toggle.

## Block handles

Hover any block — a paragraph, heading, quote, code block, table, or a single list item — for the
⋮⋮ handle at its left. Drag it to reorder; a line marks the drop slot, and a list item moves among
its own siblings. Click the handle to select the block, then <kbd>Backspace</kbd> deletes it and

<kbd>Mod</kbd> <kbd>C</kbd> copies it. <kbd>Mod</kbd> <kbd>Shift</kbd>
<kbd>↑</kbd> /<kbd>↓</kbd> moves the block the caret is in. A move is a move of
whole blocks, so the markdown is the same blocks in a new order.
`dragHandles=false` turns the handle and the table grips off; the comment
composer does.

## In-place editing

There is no mode to switch. The editor is transparent and borderless in every state, so it takes
the surface it sits on and its text lands exactly where `MarkdownView` would put it. Hover and focus
change nothing but the caret — there is no tint, border or ring — and an empty focused editor hints
"Type / for commands". There are no Save or Cancel buttons. Nothing inside it widens the page: long
words, URLs and inline code wrap, and code blocks and tables scroll inside their own box.

| Event                           | Result                                                                   |
| ------------------------------- | ------------------------------------------------------------------------ |
| Focus leaves the editor         | `onCommit(value)` — only when the document differs from when focus came. |
| <kbd>Esc</kbd>                  | Revert to the document focus found, blur, then `onRevert()`.             |
| <kbd>Mod</kbd> <kbd>Enter</kbd> | `onSubmit(value)` when set; otherwise commit and blur.                   |
| `autosave` idle gap             | `onCommit(value)` without leaving.                                       |

The page going hidden and the editor unmounting mid-edit commit through the same path, so a value is
never committed twice. A new `value` that arrives while the editor is focused waits for blur, so the
caret never jumps.

## Input rules

Type markdown and it becomes formatting as you go. Pasted plain-text markdown is parsed the same
way; pasted HTML is sanitized (scripts, styles, frames, event handlers and `javascript:` URLs are
dropped) before it is parsed.

| Type               | Becomes           |
| ------------------ | ----------------- |
| `# ` … `###### `   | Heading           |
| `- ` or `* `       | Bullet list       |
| `1. `              | Ordered list      |
| `[ ] ` or `[x] `   | Task item         |
| `> `               | Blockquote        |
| ` ```ts `          | Code block        |
| `---`              | Divider           |
| `**text**`         | **Bold**          |
| `*text*`, `_text_` | _Italic_          |
| `~~text~~`         | ~~Strikethrough~~ |
| `` `text` ``       | Inline code       |

Every rule works in every editor: `slashCommands` limits the menu, never the schema.
