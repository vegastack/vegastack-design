## Usage

```tsx
import { AutoSaveInput } from "@/components/ui/auto-save-input";

<AutoSaveInput
  aria-label="Workspace name"
  defaultValue={workspace.name}
  onSave={async (name) => {
    await updateWorkspace({ name });
  }}
  validate={(v) => v.trim().length > 0}
/>;
```

`AutoSaveInput` composes [`InputGroup`](/docs/components/input-group) around an
`InputGroupInput` — upstream's [`Input`](/docs/components/input) flattened into the
box — so the trailing status indicator sits in a real addon slot rather than on top
of a padded field. It owns its value as
local state from `defaultValue` (or follows `value` + `onValueChange` when
controlled), debounces keystrokes, and calls `onSave(value)` once the field
settles. A trailing indicator reflects the outcome: a spinner while saving, a
success check once saved, and an error cross on failure.

<Callout title="Presentational component">
  The component owns only the debounce timer and the inline status UI. **It does
  not persist anything itself** — `onSave` is yours, and so is everything around
  it (success/error toasts, optimistic cache updates, cross-field effects).
  There is no toast coupling; if you want a toast, fire it from `onSave` or
  `onStatusChange`. This split keeps the component reusable across apps while
  the app keeps the side effects.
</Callout>

### States

Status is owned by the component and only advances when the field is edited, so
this is a **live** example — type into each field and pause for the debounce to
watch the trailing indicator move. Each field is wired to a different outcome:

- **Saving** — a deliberately slow `onSave` holds the spinning `Loader` in
  flight.
- **Saved** — a fast `onSave` resolves to the `text-success-text` `Check`.
- **Error (rejecting onSave)** — a rejected promise flags the
  `text-destructive-text` `X` and sets `aria-invalid`.
- **Error (failed validate)** — clearing the field fails `validate`, which flags
  `error` _without_ ever calling `onSave`.

### Controlled value

Pass `value` + `onValueChange` to let the parent own the draft. External `value`
changes — like switching records — are treated as a **new saved baseline**, so
moving between records never auto-saves stale data and never re-flags a status.
Edit the field to save after the debounce, or switch records to reset the
baseline.

### Status indicator

`AutoSaveIndicator` is the same lifecycle as a line of text for an action row: a spinner and
"Saving…", a check and "Saved", and the `-text` ink with its own icon for "Couldn't save" and a
conflict ("Not saved"). It is a polite live region, empty while idle.

### Icon only

`variant="icon"` is the same status as one 16px icon for a field's trailing slot — an
`InputGroupAddon align="inline-end"` on an input or textarea, or beside a select: a muted
spinner while saving, a `text-success-text` check once saved, a `text-destructive-text`
warning triangle when the save failed (`text-warning-text` on a conflict). Each state pops in
(a fade and a 0.9 → 1 scale on the motion tokens), the check fades out over `duration-slow`
when the status returns to `idle`, and the box is always reserved, so nothing shifts. The
wording ("Saving", "Saved", "Couldn't save") stays as screen-reader text in the live region;
reduced motion swaps instantly.

### A whole form (useAutoSave)

`useAutoSave` saves a form object rather than one field: debounced (600ms), only the changed
fields, one save in flight at a time with the latest values sent next, a version carried for
optimistic concurrency (`isConflict` turns a stale-version error into the `conflict` status),
and a `flush()` to call before a step change or navigation. Pending changes are also saved on
unmount and when the tab closes.

## Accessibility

- Renders a native `<input>` — always associate a visible `<label>` (wrap it or
  use `htmlFor`/`id`); use `aria-label` only when a visible label is impossible.
- Status is conveyed by a **distinct icon per state** (spinner / check / cross)
  paired with a semantic color token, so it never depends on color alone.
- A single `role="status" aria-live="polite" aria-atomic="true"` slot announces
  `"Saving"`, `"Saved"`, or `"Save failed"` as hidden text while the visible icon
  remains decorative.
- The `error` status sets `aria-invalid` on the field, matching `Input`'s invalid
  styling and announcing the failure to screen readers.
- The spinner respects `prefers-reduced-motion` (`motion-reduce:animate-none`).
- On focus the underlying [`InputGroup`](/docs/components/input-group) darkens
  its border subtly (`border-ring/50`, easing in over 150ms) and paints no fill —
  text entry's exception to FOC-14 (MK 2026-09-27) — instead of removing the
  affordance; never `outline: none` with nothing in its place. The `error` status
  keeps its destructive border while focused.

| Key          | Action                                             |
| ------------ | -------------------------------------------------- |
| Any text key | Edits the value and (re)starts the debounce timer. |
| `Tab`        | Moves focus to/from the field as a normal input.   |
