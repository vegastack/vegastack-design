## Usage

```tsx
import { Label } from "@/components/ui/label";
import { RadioGroup, RadioGroupItem } from "@/components/ui/radio-group";

<RadioGroup defaultValue="option-one">
  <div className="flex items-center gap-3">
    <RadioGroupItem value="option-one" id="option-one" />
    <Label htmlFor="option-one">Option One</Label>
  </div>
</RadioGroup>;
```

radio dims on its own, inside a `Field` or not; add `data-disabled` to the `Field` so the label

## Accessibility

- Renders Base UI's Radio Group, which gives the group `role="radiogroup"` and each item
  `role="radio"` with `aria-checked`; <kbd>↑</kbd>/<kbd>↓</kbd> and <kbd>←</kbd>/<kbd>→</kbd> move
  the selection, and the group is one tab stop.
- The visible dot is 16px, so an `::after` pseudo-element extends the pointer target to at least
  24×24 (A11Y-2), verified by a real `elementFromPoint` probe.
- On `:focus-visible` the global 2px outline in `base.css` applies (FOC-1). The recipe carries no
  ring of its own and no `outline-none` (FOC-6).
- Bind every item to a `Label` or `FieldLabel` with `htmlFor`; a radio has no text of its own.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/radio-group.patch`. Every hunk:

- **FOC-1, FOC-6** — the `outline-none focus-visible:border-ring focus-visible:ring-3
focus-visible:ring-ring/50` glow is removed, along with the `aria-invalid` halo rings. `base.css`
  owns the single `:focus-visible` outline, and `outline-none` would suppress it.
- **FOC-5** — the invalid tint and its checked counterpart become
  `not-focus:aria-invalid:border-destructive` and
  `not-focus:aria-invalid:aria-checked:border-primary`, so focus outranks the error colour.
- **FOC-12** — upstream rings the whole choice card and cancels the control's own ring with two
  `group-has-[:focus-visible]/field-label:` rules. This system rings the control, so both are
  removed with the card ring they existed to serve.
- **FRM-15** — `disabled:cursor-not-allowed disabled:opacity-50` become `data-disabled:…`. Base UI
  renders each item as a `<span>`, which `:disabled` never matches, so upstream's radio dimmed only
  inside a disabled `Field`; keyed on the `data-disabled` Base UI sets, it dims everywhere.
- **API-26** — inside a `Field`, the `RadioGroup` is the control the Field names; each item keeps
  its own name (Base UI would otherwise hand the Field's label to every item). An item in a
  `Field` of its own still takes that Field's label.
- **DOC-2** — `cn` is imported from `@vegastack/design`.
