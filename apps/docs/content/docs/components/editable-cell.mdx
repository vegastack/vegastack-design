## Usage

```tsx
import { EditableCell } from "@/components/ui/editable-cell";

<EditableCell
  value={deal.name}
  label="Deal name"
  onSave={(name) => api.updateDeal({ name })}
/>;
```

**Edit looks like view.** There is no border, ring or background change when the cell edits: the
field inherits the font, size, weight, line height, tracking and colour of its surroundings, and
only the caret and the selection show it is being edited. The display and the field share one box —
a grid cell holding the value text with the field laid over it — so the field grows with its
content, wraps when the value wraps, and entering or leaving edit changes neither the width nor the
line box.

**Saving.** Blur or a click outside saves; <kbd>Enter</kbd> saves a single-line value and

<kbd>⌘</kbd>/<kbd>Ctrl</kbd>+<kbd>Enter</kbd> a multiline one; <kbd>Escape</kbd>
cancels and restores. Nothing is saved when the value is unchanged. When
`onSave` returns a promise the display updates at once; a subtle spinner trails
the value only if the save takes longer than 300ms; on failure the value rolls
back, the failure is announced and a toast offers Retry (the app mounts
`Toaster`). `onCommit` is the older name of `onSave` and still works.

**Affordance.** The only affordances are the hover tint, a text cursor and an optional `tooltip`.
Keyboard focus shows the same tint; <kbd>Tab</kbd> reaches the cell and <kbd>Enter</kbd> or

<kbd>F2</kbd> starts editing.

## Scope

| Behaviour                        | Where it lives                                                                                  |
| -------------------------------- | ----------------------------------------------------------------------------------------------- |
| Persistence, conflict check      | Host — `onSave` fires once per changed value; a rejected promise rolls back and offers Retry    |
| Debounced auto-save while typing | [`AutoSaveInput`](/docs/components/auto-save-input)                                             |
| The grid's roving focus model    | The grid host — `focusMode="managed"` removes this tab stop; `onNavigate` reports Enter and Tab |
| Date / actor / currency editors  | Apps, via the open `custom` editor contract                                                     |

## Examples

### Table cell

`variant="cell"` fills the table cell, so the field is as wide as the column and the column never
resizes. Only the text starts an edit: a click beside it goes to the row (a row link keeps
working). With `onNavigate`, <kbd>Enter</kbd> and <kbd>Tab</kbd> save and hand the host a
direction to move to the next cell (<kbd>Shift</kbd> goes back).

### Page title

`variant="heading"` keeps the heading's size and weight and wraps naturally, in view and in edit.
It has no box padding, so the title is edited exactly where it is rendered — idle and editing sit at
the same position, lined up with the lines below, and only the hover tint marks it editable. Put the
cell inside the heading element rather than restyling its parts.

```tsx
<h1 className="text-2xl font-semibold">
  <EditableCell
    variant="heading"
    required
    label="Meeting title"
    value={title}
    onSave={rename}
  />
</h1>
```

### Managed focus (grid hosts)

Inside a grid the grid's roving focus model owns reachability. `focusMode="managed"` removes the
cell's own tab stop, and the host opens the editor from its keyboard model through the controlled
`editing` / `onEditingChange` pair:

```tsx
<EditableCell
  variant="cell"
  value={cell.value}
  label={column.header}
  focusMode="managed"
  editing={isEditingThisCell}
  onEditingChange={(editing) => grid.setEditingCell(editing ? cellId : null)}
  onNavigate={(direction) => grid.moveEditor(direction)}
  status={grid.cellStatus(rowId, column.key)}
  onSave={(next) => grid.commitCell(rowId, column.key, next)}
/>
```

## Accessibility

- Read mode is a `role="button"` labelled `Edit {label}`, described by the value; edit mode is a
  text field labelled `label` (then `placeholder`, then a generic name).
- Saves and errors are announced through a visually hidden polite live region — "Saved",
  `Couldn't save {label} — value restored`, and the `required` message. The spinner is decorative.
- <kbd>Escape</kbd> cancels, restores the prior value and returns focus to the
  display.
- In `focusMode="managed"` the cell has no tab stop of its own — the host grid owns reachability.

| Key                                                 | Action                                                     |
| --------------------------------------------------- | ---------------------------------------------------------- |
| <kbd>Enter</kbd> / <kbd>F2</kbd> / <kbd>Space</kbd> | Start editing from the focused display.                    |
| <kbd>Enter</kbd>                                    | Save a single-line value (and move on, with `onNavigate`). |
| <kbd>⌘</kbd>/<kbd>Ctrl</kbd>+<kbd>Enter</kbd>       | Save a multiline value.                                    |
| <kbd>Tab</kbd>                                      | With `onNavigate`: save and move to the next cell.         |
| <kbd>Escape</kbd>                                   | Cancel and restore the prior value.                        |
