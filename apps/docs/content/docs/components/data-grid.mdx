## Usage

Virtualized keyboard navigation scrolls an offscreen target into view and transfers focus when its cell mounts.

```tsx
import { DataGrid } from "@/components/ui/data-grid";

<DataGrid
  aria-label="Deals"
  columns={[
    { key: "name", header: "Name", sortable: true, mobile: "visible" },
    {
      key: "stage",
      header: "Stage",
      editable: { type: "select", options: stages },
    },
    {
      key: "amount",
      header: "Amount",
      align: "end",
      mobile: "merge",
      render: (d) => <span className="tabular-nums">{d.amount}</span>,
    },
  ]}
  data={deals}
  getRowId={(d) => d.id}
  onCellCommit={(row, key, value) => api.patch(row.id, { [key]: value })}
  selectable
/>;
```

`DataGrid` is the commissioned full-parity sibling
[`DataList`](/docs/components/data-list) always pointed to. The sorted row
model comes from TanStack Table (the sanctioned engine); row and column
windowing from TanStack Virtual behind the `virtualize` and `virtualizeColumns`
flags; the APG grid keyboard layer — which no library ships — is the
component's own.

```tsx
// Spreadsheet scale: the host sorts and groups on the server; both axes are windowed.
<DataGrid
  aria-label="Sample requests"
  columns={fields} // { key, header, width, frozen, headerMenu, summaryOptions, … }
  data={rows}
  getRowId={(row) => row.id}
  sortMode="manual"
  sort={sort}
  onSortChange={setSort}
  onColumnResize={saveWidth}
  onColumnReorder={saveOrder}
  columnOrder={order}
  virtualize
  virtualizeColumns
  rowHeight="short"
  maxHeight="70dvh"
  ariaRowCount={total + 1}
  headerTrailing={(focus) => <AddFieldButton {...focus} />}
  summaryRow={{
    label: `${total} rows`,
    value: fns,
    onValueChange: setFn,
    results,
  }}
  cellMenu={(rowId, key) => <CellMenuItems rowId={rowId} field={key} />}
/>
```

**Two deliberate differences from `DataList`, for migrators:**

1. Cells render as component **elements**, so a `render` implementation may use
   hooks (`DataList` invokes `render` as a plain function and cannot allow
   that).
2. The grid **sorts its own data** — that is what the row-model engine is for.
   `sort`/`onSortChange` stay controllable for URL state.

## Scope

**Reversed in 0.25.69** (Regent Tables, R2): the grid used to leave out column resize, a reorder
affordance, aggregation footers, and grouped virtualization. It now hosts a 50,000-row,
150-column, server-sorted grid — so frozen and resizable columns, header drag-to-reorder, a summary
row, host-sorted rows, host groups and column windowing are in. It still computes nothing the host
should: summary values, server sort orders and group pages come in as props.

| Behaviour                           | Where it lives                                                                                                                                                      |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Data fetching, filters, saved views | Host — [`FilterBuilder`](/docs/components/filter-bar-managed) + the `toolbar` slot                                                                                  |
| The cell write + conflict handling  | Host — `onCellCommit` is a request; `cellStatus` is your word                                                                                                       |
| Pagination UI                       | The `footer` slot; `loadMore` covers the continuous case                                                                                                            |
| Simple presentational tables        | [`DataList`](/docs/components/data-list) — still the right default                                                                                                  |
| The shared table chrome             | `@vegastack/data-table-parts` — sort header, selection, async states; it arrives with this component ([shared internals](/docs/guides/components#shared-internals)) |

### Two layouts

| Layout         | Turns on when                                                                                            | Columns                                                                                                                                                                |
| -------------- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Auto (default) | —                                                                                                        | Fill and fit, like `DataList`; responsive revelation merges or drops columns on narrow screens.                                                                        |
| Fixed          | Any column has `width`, `frozen` or `resizable`, or the grid has `onColumnResize` or `virtualizeColumns` | `table-layout: fixed` from a `<colgroup>`; every cell one line (truncating); the grid scrolls sideways instead of revealing; frozen columns stick to the inline start. |

The grid renders its own `<table>` inside ONE scroll viewport (`data-slot="grid-viewport"`), so the
sticky header, the sticky summary row and the frozen columns all resolve against the same box.

### The toolbar

The toolbar row holds the host's `toolbar` slot on the leading edge and the grid's own controls on
the trailing edge: the hidden-columns hint, then the "Columns" picker.

The picker is on by default and turns off with `columnPicker={false}` — a fixed three-column grid
should not carry a column manager, and a host that drives visibility from its own settings surface
already has one. With no `toolbar`, no picker and nothing hidden, the toolbar row is not rendered at
all.

## Examples

### Grouping

One `group` column groups the rows by value on the client. Groups are **flattened into the one row
list**: a group header is a row of its own, followed by its rows, so grouping and `virtualize`
combine. The group header is the shared `SectionToggle` DataList's sections use: the row count sits
after the label in muted tabular numerals (no parentheses), and a screen reader hears it as "Open,
2 rows". The header rows are on the keyboard path: <kbd>↑</kbd>/<kbd>↓</kbd> stop on them and

<kbd>Enter</kbd> or <kbd>Space</kbd> toggles.

### Cells mode

`selectionMode="cells"` makes the grid a spreadsheet surface. A range is kept by row id and column
key (`use-grid-selection`), so it survives a refetch and windowing; it covers loaded rows only.

- **Select**: <kbd>Shift</kbd>+arrows, <kbd>Shift</kbd>+click or a drag extend the range;
  <kbd>Shift</kbd>+<kbd>Space</kbd> takes the row, <kbd>Ctrl</kbd>+
  <kbd>Space</kbd> the column,
  <kbd>⌘</kbd>/<kbd>Ctrl</kbd>+<kbd>A</kbd> everything; a plain move or
  <kbd>Escape</kbd>
  collapses it. A range of more than one cell is announced ("4 by 3 cells
  selected").
- **Copy, cut, paste** go through the `copy`, `cut` and `paste` events (never the async Clipboard
  API) as TSV plus a bare HTML table, read by `grid-clipboard`: Excel, Google Sheets (with its exact
  numbers), Numbers and Airtable. One pasted value fills the range; a pattern that divides it
  tiles. Each column's `parse(cell, row)` turns a pasted cell into its value and `format(row)`
  writes its copy text. A column with neither `parse` nor `editable` is read-only to paste, clear
  and fill. Rows that run past the last loaded row go to `onPasteOverflow` — the host asks "Add 38
  rows?". A paste into an open editor is the editor's.
- **Write**: a paste, a clear (<kbd>Delete</kbd>) or a cut is ONE `onCellsCommit(changes)` batch;
  the host answers per cell (`ok`, `conflict`, `invalid`, `stale_schema`) and the grid announces
  "Pasted 120 cells · 4 skipped".
- **Fill**: drag the handle on the range's corner up or down, or <kbd>⌘</kbd>/<kbd>Ctrl</kbd>+<kbd>D</kbd>
  to fill down; `onFill({ source, target, series })` — <kbd>Alt</kbd> while dragging asks for a
  series. The host computes the values.
- **Undo** <kbd>⌘</kbd>/<kbd>Ctrl</kbd>+<kbd>Z</kbd> and **redo** <kbd>⇧⌘Z</kbd> / <kbd>Ctrl</kbd>+<kbd>Y</kbd>
  reach `onUndo` / `onRedo`; the host owns the history.
- **Someone else's change**: `remoteChanges` (keyed by `gridCellKey(rowId, key)`) pulses the cell
  with the system's highlight-on-change ring (`motion-flash`, gone under reduced motion) and shows
  the author in its corner for 1.5s; only the focused cell's `announcement` is spoken.

### Inline editing

Editable columns open [`EditableCell`](/docs/components/editable-cell) in
`focusMode="managed"` — the grid owns reachability, the cell owns the editor
and its async status. <kbd>Enter</kbd>/<kbd>F2</kbd> edits keeping the value;
typing a character edits replacing it (text and number editors); <kbd>Enter</kbd>
commits and moves down, <kbd>Tab</kbd>/<kbd>Shift</kbd>+<kbd>Tab</kbd> commit and
move across; <kbd>Escape</kbd> restores grid navigation; a rejected commit
reverts and announces. While an IME is composing, no key commits or moves.

### Keyboard-continuous load-more

The next page loads as the grid's end nears the edge of its scroll viewport, and

<kbd>↓</kbd> past the last row fetches it too — paging never breaks the keyboard
flow, and the two share one guard, so a page is requested once. While it loads,
skeleton rows the height of real ones are appended to the body. The tail is the
shared [`LoadMore`](/docs/components/load-more): no button, _Try again_ after a
failed fetch (`loadMore.error`), and nothing once `hasMore` is false unless you
pass `loadMore.endLabel`.

### Responsive revelation

Columns declare a pixel budget (`minWidth`, default 120) and a posture for what happens when they no
longer fit. **Data is never silently lost when a viewport narrows**, so the default posture is
`merge`:

| `mobile`    | When the column no longer fits                                                    |
| ----------- | --------------------------------------------------------------------------------- |
| `"merge"`   | **Default.** Stacks into the primary (first) column's cell, under its main value. |
| `"visible"` | Never hides — the column is essential and the grid scrolls instead.               |
| `"hidden"`  | Drops the column, and the toolbar reports "N columns hidden".                     |

`"hidden"` is the only posture that actually removes a value, which is why it is opt-in and why it
announces itself. If you choose it, be sure the value is genuinely recoverable elsewhere.

**Fill and fit**, as in `DataList`: the primary (first) column takes the width the others leave
and its text wraps, anywhere when a single word is wider than the cell; every other column is sized
to its content and kept on one line, and a header never breaks.

A merged value **wraps** inside the primary cell — it does not inherit a `mono` or end-aligned
primary column's one-line posture, and it wears its own column's face. When a sorted column is
merged or hidden (or switched off in the column picker), its header and arrow go with it, so the
toolbar states the order instead — _Sorted by Stage, descending, then Amount, ascending_ — and the
grid is described by that line and by the hidden-columns count.

## Accessibility

- Real `role="grid"` semantics on a native table: `columnheader`/`gridcell`,
  the primary column's cells as `rowheader`, `aria-colcount` and
  `aria-rowcount` with TRUE totals (`ariaRowCount`/`ariaColCount` when only
  some rows or columns are loaded; −1 while more rows exist and no total is
  given), `aria-rowindex`/`aria-colindex` on every row and cell, and
  `aria-readonly` on non-editable cells.
- One roving tab stop for the whole grid, kept by **row id and column key**
  (never by index), so it survives a refetch that moves its row. It roves over
  the header row, the group rows, the body and the summary row; the sort
  buttons, menu chevrons, resize handles and checkboxes inside are not stops
  of their own. Arrows move the active cell (RTL-aware); a windowed-out target
  scrolls in and takes focus as it mounts.
- <kbd>Enter</kbd>/<kbd>F2</kbd> opens the cell editor and **suspends grid
  navigation**; <kbd>Escape</kbd> closes it and restores focus to the cell;
  edit-mode entry announces politely.
- Multi-key sort headers carry `aria-sort` and a visible ordinal per key;
  shift-click adds a secondary key. Each sort button is named _Sort by
  &lt;column&gt;_. Sorted columns always show ↑/↓; an unsorted sortable
  column's ⇅ stays transparent until the header is hovered (fine pointers only)
  or its button has keyboard focus, so touch shows only the active arrows and
  unsortable columns show nothing — the same header parts as
  [DataList](/docs/components/data-list#sorting).
- Responsive revelation never hides data silently: `merge` (the default) stacks
  the value into the primary cell with its header as a visually hidden prefix
  (_Stage: Open_), and the only posture that drops a column
  (`mobile: "hidden"`) reports the count in the toolbar. The grid's
  `aria-describedby` points at that count, and at the "Sorted by …" line
  when a sorted column has left the header row.
- The scroll viewport is keyboard-reachable exactly when it scrolls, and the
  roving cell's focus outline is pulled inside so the viewport cannot clip it.

| ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |

| <kbd>⌘</kbd>/<kbd>Ctrl</kbd>+<kbd>Home</kbd>/<kbd>End</kbd>                                                                   | First / last cell of the grid.                                                |

### Column resize handle

`ColumnResizeHandle` (in `data-table-parts`) is the header's trailing-edge grip: a `separator` with
`aria-orientation="vertical"` and its `aria-valuenow`/`min`/`max`, named _Resize Qty_. Standalone it
is a tab stop with <kbd>←</kbd>/<kbd>→</kbd> (8px, <kbd>Shift</kbd> 32px) and

<kbd>Home</kbd>/<kbd>End</kbd>; inside the grid the same steps run from the
focused header with
<kbd>Alt</kbd>. Its hit area is 24px wide.

### Summary row

`GridSummaryCell` (in `data-table-parts`) is one footer cell: a quiet `Select` of the column's
`summaryOptions` (with a built-in _None_) named _Sum of Qty_, and the host's result beside it. An
unsummarised cell shows _Summarize_ only on hover or focus. The summary row is sticky at the bottom
of the viewport and counts as a row in `aria-rowcount`. The primary column's cell shows
`summaryRow.label` ("412 rows") before its own picker. The cells rove like any row; <kbd>Enter</kbd>
or <kbd>Space</kbd> opens the picker, and closing it returns focus to the cell.

### Trailing header control

`headerTrailing` is a render function: spread the focus props it is handed onto its one control (an
"add field" button, or a `PopoverTrigger`'s `render` button), and the control joins the header row's
roving focus — <kbd>→</kbd> from the last header reaches it — instead of becoming a second tab stop.
