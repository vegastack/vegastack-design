## Usage

```tsx
import { Board } from "@/components/ui/board";
import { BoardCard } from "@/components/ui/board-card";

<Board
  aria-label="Tasks"
  columns={statuses.map((s) => ({
    id: s.id,
    title: s.label,
    items: tasksBy[s.id],
  }))}
  getItemId={(task) => task.id}
  getItemLabel={(task) => task.title}
  renderCard={(task) => (
    <BoardCard
      surface={false}
      title={task.title}
      due={task.dueAt}
      priority={task.priority}
    />
  )}
  onMove={({ id, to }) => api.moveTask(id, to.container, to.index)}
  onAdd={(status) => openCreate({ status })}
  addLabel="Add task"
/>;
```

The split is content/chrome: **you render card content only** — a
[`BoardCard`](/docs/components/board-card) with `surface={false}` is the standard content — and the
board owns the lanes, sticky headers, counts, the collapse strip, empty drop zones, skeletons,
paging, the add button, the lifted card and the gap it lands in. `onMove` is the single move
command for every input path: drag, keyboard and the card menu.

## Scope

| Behaviour              | Where it lives                                                        |
| ---------------------- | --------------------------------------------------------------------- |
| Ordering + persistence | Host — `onMove` is a request; reject its promise to refuse a move     |
| Card content           | Host, via `renderCard` (a `BoardCard`) — the board owns all chrome    |
| Creating a card        | Host — `onAdd(laneId)` opens the host's form with the lane pre-filled |
| Single-list reordering | [`SortableList`](/docs/components/sortable-list)                      |
| Lanes from a list      | [`DataList`](/docs/components/data-list) `view="board"` (sections)    |
| Virtualization         | Deliberately none — lanes page with `loadMore` instead                |

## Examples

### Task board

The full board: `BoardCard` content, "+ Add task" at each lane's foot (`onAdd` receives the lane's
id, so the host's create form opens with that status filled in), per-card actions with a submenu,
and an empty lane that reads "Nothing here" at rest and "Drop here" while a card is dragged.

Drag a card: it lifts with a shadow and a slight tilt, the cards around it slide to make room, and
it settles into its slot. Near a lane's top or bottom edge the lane scrolls; near the board's
side edges the board scrolls. On a touch screen, hold a card for a quarter of a second to pick it
up (the device buzzes where it can); a swipe still scrolls. Under reduced motion the card still
follows the pointer, without the tilt or the slides.

### Full height

`height="fill"` is the default: the board measures where it starts and runs its lanes to the
bottom of the viewport (less `fillOffset`, the page's bottom padding). Cards scroll inside each
lane and the page never scrolls. Lanes are 320px (`columnWidth`) with a 12px gap and grow to share
a wide screen; the board scrolls sideways with a hidden scrollbar and fades at the edges that have
more. Pass `height="auto"` to size lanes to their cards, or any CSS length.

<ComponentPreview name="boardFill" file="components/preview/board.tsx" />

### Collapsed lanes

Every lane header has a collapse icon button (tooltip "Collapse lane") left of its ⋯ menu; turn it
off with `collapsible={false}`. The ⋯ menu holds only the lane's own actions from
`getColumnActions` and hides when there are none. Lanes are transparent, like list view: only the
column spacing separates them, and cards keep their own surface. A collapsed lane is a slim dashed
strip with an expand icon and its count (tooltip "Expand lane"); activating it expands the lane. Control the set with `collapsedColumns` and
`onCollapsedChange` to remember it. A lane declared `defaultCollapsed` is a terminal lane: it
expands read-only.

Lanes keep their width (`columnWidth`, default `20rem`) however many are collapsed: the space a
collapsed lane frees stays empty instead of stretching the others, and a board with more lanes than
fit scrolls sideways. The preview starts with two lanes collapsed.

### Server-gated moves

Moves are optimistic: the card lands at once and shimmers while `onMove`'s promise is pending. A
rejection snaps it back, announces it, and raises an error toast (`moveErrorToast` sets its
title, or `false` turns it off; the app mounts [`Toaster`](/docs/components/toast)).

<ComponentPreview name="boardGated" file="components/preview/board.tsx" />

### Locked lanes and auto height

A lane with `droppable: false` is never a target; its `lockedReason` shows in the lane when it is
empty. `readOnly` turns every move off for the whole board. With
`height="auto"`, `columnMaxHeight` caps each lane's card list.

<ComponentPreview name="boardLanes" file="components/preview/board.tsx" />

### Lane and card labels

Every lane and card has a plain-text name, because the board speaks them. A string `title` names
its lane on its own; a lane whose `title` is a node passes `label` (the board warns in
development when it has to fall back to the id). `getItemLabel` names the cards — in their
accessible name, their menu control ("Actions for Token audit") and every announcement.

<ComponentPreview name="boardLabels" file="components/preview/board.tsx" />

### Lane states

`count` is the lane's total when it has loaded only some cards ("Open, 14 tasks", through
`countLabel`). `loading` shows skeleton cards and marks the lane `aria-busy`. An empty lane shows
the design-system `Empty` at rest: an Inbox icon and "Nothing here" (a locked lane adds its
`lockedReason`). Change its copy with `empty` (`icon`, `title`, `description`, `action`); `emptyState`
replaces it outright. While a card is dragged, an empty lane that accepts it shows "Drop here".

<ComponentPreview name="boardLaneStates" file="components/preview/board.tsx" />

### Cards as links

`getItemHref` makes each card a real link, rendered as `<a>` or as your router's link through
`itemLinkRender`. A click follows it and a modifier click opens a new tab; a drag never follows
it. Enter follows the link; Space still picks the card up.

<ComponentPreview name="boardLinks" file="components/preview/board.tsx" />

### Paged lanes and card actions

A lane with more cards than it has loaded takes `loadMore`: the next batch loads as the lane's
foot scrolls into view, and the shared [`LoadMore`](/docs/components/load-more) button stays as the
fallback and the retry after an error. `getItemActions(item)` lists the card's own actions in
its ⋯ menu (a card with none shows no ⋯); an action with `items` opens a submenu. The menu has no
Move items — moves are the drag and the keyboard (Space, the arrows, Space).

<ComponentPreview name="boardPagedLanes" file="components/preview/board.tsx" />

### On a phone

Below 768px the board shows one lane at a time at full width. Swipe to move between lanes, or tap
a lane in the strip above, which shows each lane's count. To move a card to another lane, hold it,
then drag it to the screen's edge: the board turns to the next lane.

## Accessibility

- **Every move has a keyboard path.** <kbd>Space</kbd> picks the focused card up, the arrows
  move it (<kbd>↑</kbd>/<kbd>↓</kbd> within its lane, <kbd>←</kbd>/<kbd>→</kbd> across lanes,
  RTL-aware), <kbd>Space</kbd> drops it and <kbd>Escape</kbd> puts it back. Nothing is committed
  until the drop, and each step is announced ("In review, position 2 of 3").
- <kbd>M</kbd> opens the card's ⋯ menu of its own actions (it lists no Move
  items).
- Cards form one roving tab stop per board: <kbd>↑</kbd>/<kbd>↓</kbd> within a lane,
  <kbd>←</kbd>/<kbd>→</kbd> across, <kbd>Home</kbd>/<kbd>End</kbd> within the
  lane.
- Each lane is a region named by its label and total ("Open, 14 tasks"); a loading lane is
  `aria-busy`. The card's activator (a button, or a link) is a sibling of its content, so a
  `BoardCard`'s done tick is its own control, never nested inside another.
- Moves, drops, cancels and rejections announce through one polite live region.
- No focus ring: the focused card takes the system's background tint (FOC-13).

| Key                                                 | Action                                         |
| --------------------------------------------------- | ---------------------------------------------- |
| <kbd>↑</kbd>/<kbd>↓</kbd>/<kbd>←</kbd>/<kbd>→</kbd> | Browse cards; while picked up, move the card.  |
| <kbd>Space</kbd>                                    | Pick the focused card up; drop it.             |
| <kbd>Escape</kbd>                                   | Cancel the move and put the card back.         |
| <kbd>Enter</kbd>                                    | Activate the focused card, or follow its link. |
| <kbd>M</kbd>                                        | Open the focused card's menu.                  |

## Do / Don't

<DoDont
  do="Keep onMove the single move command and refuse a bad move by rejecting its promise — the card snaps back, the rejection is announced and a toast says so."
  dont="Re-sort the lane yourself while the promise is pending — the board already shows the move optimistically."
/>

<DoDont
  do="Render a BoardCard with surface={false} and put the card's actions in getItemActions."
  dont="Pass actions to the BoardCard as well — the card would show two ⋯ menus."
/>
