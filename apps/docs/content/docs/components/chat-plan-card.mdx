## Usage

```tsx
import { ChatPlanCard } from "@/components/ui/chat-plan-card";

<ChatPlanCard
  data={plan}
  onApprove={(mode) => approve(plan.id, mode)}
  onKeepPlanning={(note) => revise(plan.id, note)}
  onReject={(note) => reject(plan.id, note)}
/>;
```

Meta is only "Plan · v2". Under the title and goal come numbered steps (eight show, the rest open)
and three quiet rows: Will change, Won't, and Needs your OK — the steps the permission engine says
will still ask. No colour pills, no risk dot. Approve and run is primary, Approve, ask before
changes is outline, and Keep planning ▾ holds a note and Reject. When no step needs an OK there is
nothing to allow, so the card shows one Approve (`onApprove("ask_before_changes")`). A reader
who can't decide gets the plan read-only: pass no handlers, and the meta reads "Plan · v2 ·
Waiting for approval". Once settled (approved, rejected, replaced, changes asked for or expired),
the card becomes a `PlanLine` that can show the plan again.

## Accessibility

| Key      | Does                                                     |
| -------- | -------------------------------------------------------- |
| `Tab`    | Moves through steps with detail, Changed and the actions |
| `Enter`  | Opens a step's detail; in the note field, sends          |
| `Escape` | Closes the Keep planning menu, or leaves the note field  |

- Steps are an ordered list; each reads "Step 2: …" to a screen reader.
- Changed and Show report their state with `aria-expanded`.
