## Examples

### Composition

`NavigationMenu` renders the portal, the positioner, the popup and the viewport itself, so the call
site is the nav row alone: a list of items, each holding a trigger and its content, or a plain link.
`align` on `NavigationMenu` decides which edge of the row the shared panel hangs from.

```text
NavigationMenu
├── NavigationMenuList
│   ├── NavigationMenuItem
│   │   ├── NavigationMenuTrigger
│   │   │   └── NavigationMenuIndicator
│   │   └── NavigationMenuContent
│   │       ├── NavigationMenuLink
│   │       └── NavigationMenuLink
│   └── NavigationMenuItem
│       └── NavigationMenuLink
└── (portal · positioner · popup · viewport — rendered by NavigationMenu)
```

### Link Component

`render` on `NavigationMenuLink` replaces the element it renders, which is how a routing library's
link gets the menu's styling, its `data-slot` and its keyboard behaviour. In a Next.js app that is
`render={<Link href="/docs" />}`. Adding `navigationMenuTriggerStyle()` makes a top-level link sit
flush with the triggers beside it.

### RTL

Wrap the subtree in `DirectionProvider direction="rtl"` so Base UI resolves the logical sides, set
`align="end"` so the panel hangs from the right edge of the nav row, and put `dir` on
`NavigationMenuContent` — the panel portals out of the `dir="rtl"` subtree, so the attribute has to
travel with it.

## Accessibility

- Renders Base UI's Navigation Menu: the row is a `nav`, each trigger is a button with
  `aria-expanded` and `aria-controls`, and the panel is a labelled region. <kbd>Esc</kbd> closes the
  open panel and returns focus to its trigger.
- Arrow keys move between the triggers in the row and into the open panel, <kbd>Home</kbd> and
  <kbd>End</kbd> jump to the ends, and <kbd>Tab</kbd> leaves the menu entirely —
  the row is one tab stop, not one per link.
- A disabled trigger keeps its pointer events (FRM-4), so a tooltip can explain why it is
  unavailable; it is still `aria-disabled` and still cannot be activated.
- The panel portals out of the nav's subtree, so `NavigationMenuPositioner` re-applies the theme
  scope on the positioner inside the portal (OVL-13) — a dark or scoped surface survives the portal.
- Focus is the global 2px `:focus-visible` outline from `base.css`. Upstream suppressed the outline
  for every link inside the panel; that suppression is removed here (FOC-1, FOC-6), because the
  panel is where this menu's keyboard navigation actually lives.

## Do / Don't

  do="Use a Navigation Menu for site or product navigation whose sections need a panel of links, and give each panel real anchors so it works without JavaScript."

## Deviations

Upstream's file plus `packages/ui/upstream/patches/navigation-menu.patch`. Every hunk:

- **FOC-1, FOC-6** — `outline-none focus-visible:ring-3 focus-visible:ring-ring/50
focus-visible:outline-1` goes from `navigationMenuTriggerStyle` and from `NavigationMenuLink`, and
  the pair
  `**:data-[slot=navigation-menu-link]:focus:ring-0 **:data-[slot=navigation-menu-link]:focus:outline-none`
  goes from `NavigationMenuContent` — it suppressed the outline for every link inside the popup,
  which is where this menu's keyboard navigation actually lives.
- **FRM-4** — `disabled:pointer-events-none` is dropped from the trigger recipe; the opacity stays.
- **OVL-13** — `NavigationMenuPositioner` reads `useInternalThemeScope()` and attaches it to the
  Positioner INSIDE `NavigationMenuPrimitive.Portal` — the same host shape `popover`, `select`,
  `combobox` and `tooltip` carry. `tooling/verify-portal-theme-scope.mjs` inventories this host.
- **API-16** — the file gains `'use client'`. Upstream ships none because it calls no hook of its
  own; OVL-13's `useInternalThemeScope()` is a hook, and this file is the lowest leaf that needs the
  boundary.
- **DOC-2** — `import { cn } from "cn"` becomes `@vegastack/design`; our npm layer owns `cn`.
- **DOC-1** — prettier reflow plus the `registry-stamp.mjs` provenance header the three-copy model
  needs; no decision of its own.
