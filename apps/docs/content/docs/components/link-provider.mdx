## Usage

Mount it **once**, near the app root, in a client component that owns the router. Pass the router's
`push` and the app's own origin — the same value on the server and the client, so server-rendered
links hydrate unchanged:

```tsx
"use client";
import { useRouter } from "next/navigation";
import { LinkProvider } from "@/components/ui/link-provider";

export function AppLinks({
  origin,
  children,
}: {
  origin: string;
  children: React.ReactNode;
}) {
  const router = useRouter();
  return (
    <LinkProvider navigate={router.push} origin={origin}>
      {children}
    </LinkProvider>
  );
}
```

Every VegaStack link below it then follows one rule:

| The link                                                    | A plain click                                             | ⌘/Ctrl/Shift/Alt or middle click    |
| ----------------------------------------------------------- | --------------------------------------------------------- | ----------------------------------- |
| An in-app path (`/tasks/42`), or a full address on `origin` | `navigate(path)` — only the page changes, in the same tab | The browser's (a new tab or window) |
| Another web origin                                          | A new tab, `rel="noopener noreferrer"`                    | The browser's                       |
| `mailto:`, a bare `#anchor`                                 | The browser's                                             | The browser's                       |

It is read by default by `MarkdownView` (every rendered rich text: chat answers, citations,
comments, summaries), `InlineChip` without an `onOpen`, `RecordChip`'s ↗, `DataList` rows, and
`TextEdit` (a read-only body's links and the link card's Open), and it is the default template of
every `linkRender`. A component's own prop (`linkRender`, `onNavigate`, `linkOrigin`, an
`InlineChipProvider`'s `onOpen`) still wins. `RecordList`'s ↗ keeps its new tab: it sits in a dialog
the reader has not answered.

## Anatomy

- `LinkProvider` — the context: the host router's `navigate` and the app's `origin`.
- `AppLink` — an `<a>` that follows the rule; the default `linkRender` template across the system.

### A link of your own

`AppLink` is an `<a>` that follows the rule. A full address on the app's origin renders as its path.

```tsx
<AppLink href="/tasks/42">TSK-42</AppLink>
<AppLink href="https://example.org/spec">The spec</AppLink> {/* a new tab */}
```

### An Open button

`useOpenLink` opens an address from a button or a key press: in place when it is in-app, in a new tab
when it is external or `newTab` is set.

```tsx
const openLink = useOpenLink();

<Button
  onClick={(event) =>
    openLink(href, { newTab: event.metaKey || event.ctrlKey })
  }
>
  Open
</Button>;
```

### Helpers

- `useLinkProvider()` — the nearest provider's `{ navigate, origin }`, or `{}`.
- `useOpenLink()` — `(href, { newTab }) => void`, for buttons and keys.
- `inAppPath(href, origin)` — the in-app path of `href`, or `null`.
- `linkAction(href, links)` — `navigate`, `browser` or `external`.
- `isPlainClick(event)` — a primary click with no modifier.

## Accessibility

`AppLink` is a native `<a>` with a real `href`, so it is announced as a link, reached with Tab, and
opened with Enter; a new tab, a copied address and a middle click all work, because only a plain
primary click is intercepted. An external link gets `rel="noopener noreferrer"`; `MarkdownView`
also says "(opens in new tab)" to screen readers.
