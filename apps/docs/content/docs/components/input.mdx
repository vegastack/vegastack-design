## Accessibility

- Renders Base UI's Input, which is a native `<input>` wired to the surrounding `Field`, so the
  platform owns selection, IME composition and autofill.
- Focus is a **border tint on `:focus`**, not a ring, and the global outline is suppressed with
  `outline-hidden` (FOC-3, FOC-8). The tint fires for mouse and keyboard alike, because a text field
  cannot tell them apart and both need the caret located.
- Under `forced-colors: active` the tint disappears with every authored colour, so `base.css` paints
  a 2px `Highlight` outline on `input:focus` instead (FOC-7).
- Give it a label: `FieldLabel` bound with `htmlFor`, or an `aria-label`.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/input.patch`. Every hunk:

- **FOC-1, FOC-3, FOC-6, FOC-8** — `outline-none focus-visible:border-ring focus-visible:ring-3
focus-visible:ring-ring/50` becomes `outline-hidden` plus `focus:border-ring/70`: a border tint on
  `:focus` and no glow. `outline-hidden` rather than `outline-none`, so the forced-colours fallback
  has something to repaint.
- **FOC-5** — the invalid tint becomes `not-focus:aria-invalid:border-destructive` (and its dark
  counterpart), so focus outranks it; the `aria-invalid` halo rings are removed with the rest.
- **FRM-4** — `disabled:pointer-events-none` is dropped, so a disabled input stays hoverable and a
  Tooltip can explain it. Base UI's Input has no `focusableWhenDisabled`, so the native `disabled`
  attribute stays: this is the pointer half of FRM-4 only.
- **API-26** — NO HUNK: Base UI's `Input` is `Field.Control`, so inside a `Field` it already takes
  its label, the rendered description and error ids, and `aria-invalid` from the Field.
- **DOC-2** — `cn` is imported from `@vegastack/design`.
