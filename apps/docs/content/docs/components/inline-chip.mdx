## Usage

```tsx
import { InlineChip, InlineChipProvider } from "@/components/ui/inline-chip";

<InlineChipProvider
  value={{
    href: (kind, id) => routes[kind]?.(id) ?? null,
    person: (id) => members.get(id),
    onOpen: (target) =>
      target.kind === "file" ? openViewer(target.href) : false,
  }}
>
  <InlineChip kind="task" targetId="T-42" label="Ship the checklist" />
</InlineChipProvider>;
```

Every `@` mention and file link in the system renders as this chip — in `TextEdit`'s editor, in
`MarkdownView` and in `Comments` — so one `InlineChipProvider` near the app root tells all of them
where a chip links, who a person is, what a hover card previews and what a click opens. A chip's
own props win over the provider.

## Scope

- Owns: the chip's look (icon, ground and baseline alignment), its link or button semantics, ⌘-click,
  and the hover card (a person's avatar, name and email, or the host's preview).
- Does not own: resolving ids, routing, or the file viewer — the host passes `href`, `person`,
  `preview` and `onOpen`, directly or through `InlineChipProvider`.
- Compose with: `MarkdownView` and `TextEdit` (both render mentions and file links as this chip),
  `FileViewer` (open a file chip in it from `onOpen`).

## Examples

### Headings, lists and wrapping

The chip is an inline-block, not an inline-flex one: its label is ordinary text on the line's
baseline, its icon a 1em glyph, so it takes the size of a heading or a list item. It is one unit
and never wraps: the whole chip moves to the next line, its icon always beside its label, and a
chip wider than its line ends in an ellipsis. Its box never makes the line taller.

### Photo and restricted

A person chip leads with their avatar: the photo, else their initials on their hue (also when the
photo fails to load). The avatar is `1.1em` and centred on the text, so it stays inside the chip in
a heading, a table cell or a comment alike. A person marked `inactive` shows the "Inactive" badge after the name and carries
`data-inactive`. An id starting with `restricted:` (or `restricted`) is a target the reader may not
open: muted, never a link.

### Kinds

A person is the one coloured chip, on the tag blue every person surface uses. Every record wears
the same neutral page chip and is told apart by its icon alone, so a paragraph of references
reads as text rather than a legend; state still shows (a done task's check, a closed task struck
through, a restricted target muted).

The design system knows three kinds; every other kind is the app's. The provider's
`kinds: { [id]: { icon?, noun } }` gives each app kind its glyph (set at 1em on the baseline) and
its noun (the hover card's kind word); a kind it does not name shows a link glyph and "Item".

| Kind     | Icon             | Ground              | Ink               | Click                     |
| -------- | ---------------- | ------------------- | ----------------- | ------------------------- |
| `user`   | photo, else user | `--tag-blue-subtle` | `--tag-blue-text` | none; hover card          |
| `agent`  | bot              | `--muted`           | `--foreground`    | none                      |
| `file`   | the file's type  | `--muted`           | `--foreground`    | `onOpen` (viewer), `href` |
| app kind | `kinds[id].icon` | `--muted`           | `--foreground`    | `onOpen`, else `href`     |
| unnamed  | link-2           | `--muted`           | `--foreground`    | `onOpen`, else `href`     |

### Done and closed targets

A chip shows its kind's glyph whatever its target's state, so an open task never reads as done;
`done` swaps it for a check named "Done" for screen readers once the target is finished, and the
chip carries `data-done`. `struck`
strikes the label through and `status` adds a small muted tag after it. Use them for a target that
was closed without being done, such as a canceled or duplicate task. The chip keeps its ground and
link and carries `data-struck`. `TextEdit` and `MarkdownView` set all three from their
`mentionStatus(kind, id)`. Without one of their own, every chip — a bare one, in a rendered body,
in an editor, in a comment — takes its state from the `InlineChipProvider`'s `state(kind, id)`, so
one answer shows a record alike on every surface.

## Accessibility

- A chip with an `href` is a link; one that only opens (`onOpen`) is a button (`role="button"`,
  <kbd>Enter</kbd> / <kbd>Space</kbd>). A person chip is a tab stop so its hover
  card opens on focus as well as hover. The icon is hidden from assistive
  technology — the label names the chip.
- ⌘/Ctrl-click (and middle-click) on a linked chip opens it in a new tab. Inside an editor
  (`openOn="modifier"`) a plain click places the caret and only ⌘/Ctrl-click opens.
- The hit area reaches 24px tall without changing the line's height.

| Key                                 | Action                         |
| ----------------------------------- | ------------------------------ |
| <kbd>Tab</kbd>                      | Focus the chip; opens its card |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Open the chip's target         |
