## Accessibility

- Renders Base UI's Switch, which is a native `<button role="switch">` carrying `aria-checked`;
  <kbd>Enter</kbd> and <kbd>Space</kbd> flip it.
- The visible track is 14–18px tall, so an `::after` pseudo-element extends the pointer target to
  at least 24×24 (A11Y-2), verified by a real `elementFromPoint` probe.
- On `:focus-visible` the global 2px outline in `base.css` applies (FOC-1). The recipe carries no
  ring of its own and no `outline-none` (FOC-6).
- A Switch has no visible text of its own — give it an `aria-label`, or a `FieldLabel` bound with
  `htmlFor`, as every example here does.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/switch.patch`. Every hunk:

- **FOC-1, FOC-6** — the `outline-none focus-visible:border-ring focus-visible:ring-3
focus-visible:ring-ring/50` glow is removed, along with the `aria-invalid` halo rings. `base.css`
  owns the single `:focus-visible` outline, and `outline-none` would suppress it.
- **FOC-14** — the invalid tint stays upstream's `aria-invalid:border-destructive`, held in
  every state, focused or not (FOC-14 retired FOC-5's `not-focus:` guard).
- **FOC-12** — upstream rings the whole choice card and cancels the control's own ring with
  `group-has-[:focus-visible]/field-label:border-transparent` and `:ring-0`. This system rings the
  control, so both counter-rules are removed with the card ring they existed to serve.
- **DOC-2** — `cn` is imported from `@vegastack/design`.
