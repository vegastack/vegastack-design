## Usage

```tsx
import { Bubble, BubbleContent, BubbleReactions } from "@/components/ui/bubble";

<Bubble>
  <BubbleContent>
    I checked the registry output and removed the stale route.
  </BubbleContent>
  <BubbleReactions>
    <span>👍</span>
  </BubbleReactions>
</Bubble>;
```

`Bubble` is scoped to the bubble surface: framed chat text, short structured output, quoted replies,
suggestions and reactions. Avatars, names, timestamps and message-level actions belong to
[`Message`](/docs/components/message), which owns the row around it.

## Examples

### Composition

`Bubble` is the container; `BubbleContent` is the surface that carries the text — the variant colours
the content element, so padding and the rounded corners stay put. `BubbleReactions` floats over the
bubble edge.

```text
Bubble
├── BubbleContent
└── BubbleReactions
```

`BubbleGroup` stacks consecutive bubbles from the same sender. The `align` prop stays on each
`Bubble`, not on the group.

```text
BubbleGroup
├── Bubble
│   └── BubbleContent
└── Bubble
    └── BubbleContent
```

### Features

- Seven visual variants, from a strong primary bubble to unframed ghost content
- Start and end alignment for sender and receiver bubbles
- Reactions that anchor to the bubble edge with configurable side and alignment
- Bubbles size to their content, up to 80% of the container width
- Polymorphic content via `render` for link and button bubbles
- Customizable styling through the `className` prop on every part

<ComponentPreview name="bubbleFeatures" file="components/preview/bubble.tsx" />

### Variants

Use `variant` to change the visual treatment of the bubble.

| Variant       | Description                                            |
| ------------- | ------------------------------------------------------ |
| `default`     | A strong primary bubble, usually for the current user. |
| `secondary`   | The standard neutral bubble for conversation content.  |
| `muted`       | A lower-emphasis bubble for quiet supporting content.  |
| `tinted`      | A subtle primary-tinted bubble.                        |
| `outline`     | A bordered bubble for secondary or rich content.       |
| `ghost`       | Unframed content for assistant text or rich content.   |
| `destructive` | A destructive bubble for error or failed actions.      |

A bubble sizes to its content, up to 80% of the container width. The `ghost` variant removes the
max-width so assistant text and rich content can span the full row.

### Alignment

Use `align` on `Bubble` to align the bubble to the start or end of the conversation.

| align   | Description                                        |
| ------- | -------------------------------------------------- |
| `start` | Align the bubble to the start of the conversation. |
| `end`   | Align the bubble to the end of the conversation.   |

When building a chat interface, put the alignment on [`Message`](/docs/components/message) instead —
the row's `data-align` reaches the bubble through `group-data-[align=end]/message:self-end`.

### Links and Buttons

Turn a bubble into a link or a button with the `render` prop on `BubbleContent`. It renders a real
`<button>` or `<a>`, so it is focusable, exposes the correct role, and takes the global 2px
`:focus-visible` outline from `base.css`.

```tsx
<Bubble variant="muted">
  <BubbleContent render={<button type="button" />}>Click here</BubbleContent>
</Bubble>
```

## API Reference

### Bubble

The root bubble wrapper. A `<div>`; every other `div` prop passes through.

| Prop        | Type                                                                                       | Default     | Description                                      |
| ----------- | ------------------------------------------------------------------------------------------ | ----------- | ------------------------------------------------ |
| `variant`   | `"default" \| "secondary" \| "muted" \| "tinted" \| "outline" \| "ghost" \| "destructive"` | `"default"` | The bubble visual treatment.                     |
| `align`     | `"start" \| "end"`                                                                         | `"start"`   | The inline alignment of the bubble.              |
| `className` | `string`                                                                                   | —           | Additional classes to apply to the root element. |

### BubbleContent

The bubble content wrapper, built on Base UI's `useRender`.

| Prop        | Type                       | Default | Description                                                      |
| ----------- | -------------------------- | ------- | ---------------------------------------------------------------- |
| `render`    | `ReactElement \| function` | —       | Render the content as another element, such as a link or button. |
| `className` | `string`                   | —       | Additional classes to apply to the content element.              |

### BubbleReactions

Displays overlapped reactions for a bubble. A `<div>`; every other `div` prop passes through.

| Prop        | Type                | Default    | Description                                      |
| ----------- | ------------------- | ---------- | ------------------------------------------------ |
| `side`      | `"top" \| "bottom"` | `"bottom"` | The side of the bubble to anchor the reactions.  |
| `align`     | `"start" \| "end"`  | `"end"`    | The inline alignment of the reactions.           |
| `className` | `string`            | —          | Additional classes to apply to the reaction row. |

### BubbleGroup

Groups consecutive bubbles from the same sender. It adds no props of its own — a `<div>` with
`data-slot="bubble-group"` and `className`.

## Accessibility

- `Bubble` renders the presentational message surface. Conversation-level semantics — the list, the
  live region, the message count — belong to the container around it.
- Reactions render as a row of emoji, and a screen reader reads each glyph with no context (`+8`
  announces as "plus eight"). Group the row as a single image with a descriptive `aria-label`:
  `role="img"` also hides the individual glyphs, so no `aria-hidden` is needed.
- When reactions are interactive, render real buttons instead, and give an icon-only button an
  `aria-label`.
- An interactive bubble is a real `<button>` or `<a>` through `render`, named by its own text. It
  takes the global 2px `:focus-visible` outline from `base.css` — there is no ring glow, and nothing
  suppresses the outline (FOC-1 / FOC-6).
- Variants signal role and tone with colour. Pair them with text, alignment or icons so meaning is
  never conveyed by colour alone — a `destructive` bubble keeps the error in the message text.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/bubble.patch`. Every hunk:

- **FOC-1, FOC-6** — `BubbleContent` drops `[button,a]:outline-none`,
  `[button,a]:focus-visible:border-ring`, `[button,a]:focus-visible:ring-3` and
  `[button,a]:focus-visible:ring-ring/50`. An interactive bubble takes `base.css`'s one 2px
  `:focus-visible` outline like every other control; upstream's `outline-none` would have suppressed
  it outright, which is why the glow had to exist.
- **FOC-6** — `bubbleReactionsVariants` swaps upstream's RESTING `ring-3 ring-card` for
  `outline-3 outline-card`. FOC-6 is "never a box-shadow ring or glow anywhere" and it names Bubble
  by name; a Tailwind `ring` IS a box-shadow. The outline paints the identical 3px band in the
  identical token, outside the border box and following the radius, and the chip is a non-focusable
  `<div>`, so it can never collide with the focus outline.
- **A11Y-2** — audited, NO HUNK. Nothing in this file is a pointer target of its own: `Bubble`,
  `BubbleGroup` and `BubbleReactions` are `<div>`s, and `BubbleContent` becomes a control only when
  the call site renders one into it, at which point the control's own size is the call site's.
  `bubble.test.tsx` measures the interactive-bubble fixture against the floor.
- **A11Y-13** — the `destructive` bubble's ink becomes the family's `-text` role. Upstream writes
  `text-destructive`, which on its own `/10` tint measures 3.987:1 in light — under the AA floor
  A11Y-1 enforces — where `text-destructive-text` reads 6.966:1 on the identical composite. The
  fill and every other part of the variant are untouched.
- **API-16** — `"use client"` is ADDED. Upstream ships none, and this file calls `useRender` from
  `@base-ui/react/use-render`, which calls `React.useRef` internally — under the `react-server`
  condition that hook is `undefined`, so a server component rendering it throws on import.
  `tooling/verify-rsc-safety.mjs` is what found it. API-16 puts the boundary at the lowest
  interactive leaf, and this file is it.
- **DOC-2** — `import { cn } from "cn"` becomes `@vegastack/design`; our npm layer owns `cn`.
- **DOC-1** — prettier reflow plus the `registry-stamp.mjs` provenance header the three-copy model
  needs; no decision of its own.
