## Usage

```tsx
import {
  Card,
  CardAction,
  CardContent,
  CardDescription,
  CardFooter,
  CardHeader,
  CardTitle,
} from "@/components/ui/card";

<Card>
  <CardHeader>
    <CardTitle>Card Title</CardTitle>
    <CardDescription>Card Description</CardDescription>
    <CardAction>Card Action</CardAction>
  </CardHeader>
  <CardContent>
    <p>Card Content</p>
  </CardContent>
  <CardFooter>
    <p>Card Footer</p>
  </CardFooter>
</Card>;
```

## Examples

### Composition

`CardHeader` holds the title, the description and the action; `CardContent` holds the body;
`CardFooter` holds what closes the card. `CardAction` places itself in the top corner of the header
grid, so it is written inside `CardHeader` rather than floated over the card.

<ComponentPreview name="cardComposition" file="components/preview/card.tsx" />

### Size

Use `size="sm"` to set the card to the small size, which uses smaller spacing throughout.

<ComponentPreview name="cardSize" file="components/preview/card.tsx" />

### Spacing

In addition to the `size` prop, the `--card-spacing` CSS variable controls the gap between sections
and the inset of every card part. Set it on the root and every part follows.

Use negative margins with `-mx-(--card-spacing)` to take content edge to edge while keeping it
aligned with the card inset. When that content sits above a footer, add `-mb-(--card-spacing)` to
`CardContent` to remove the section gap.

<ComponentPreview name="cardSpacing" file="components/preview/card.tsx" />

### Image

Add an image before the card header to create a card with an image. The root drops its top padding
and rounds the first and last image for you.

<ComponentPreview name="cardImage" file="components/preview/card.tsx" />

### RTL

The card is written in logical properties throughout, so a right-to-left document mirrors the
header grid, the action corner and the part insets without any extra work.

## Accessibility

- Every part renders a plain `div` with no implicit role, so a card adds nothing to the
  accessibility tree on its own. Give it the landmark or heading it deserves — pass `render` on a
  heading inside `CardTitle`, or wrap the card in a `section` with an accessible name.
- `CardTitle` is styled, not semantic. A page of cards still needs a real heading level so the
  document outline reads correctly.
- Keep the reading order the visual order: `CardAction` sits in the top corner but is written
  inside `CardHeader`, after the title and description, which is where a keyboard reaches it.
- An image placed before the header is decorative in these examples and takes an empty `alt`. Give
  it a real description when it carries information the copy does not.
