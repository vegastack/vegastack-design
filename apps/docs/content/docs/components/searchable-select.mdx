## Usage

```tsx
import { SearchableSelect } from "@/components/ui/searchable-select";

const [project, setProject] = React.useState<Project | null>(null);

<SearchableSelect
  items={projects}
  value={project}
  onValueChange={setProject}
  itemToKey={(p) => p.id}
  itemToStringLabel={(p) => p.name}
  renderItem={(p) => p.name}
  searchLabel="Search projects"
  placeholder="Select project"
/>;
```

`SearchableSelect` is the one preset for _"a Select, but the list is too long to scroll"_. It is
controlled by the **item itself**, not by an id: pass the selected item as `value`, and
`onValueChange` hands you back an item (or `null` when the clear control is used). Give it
`isItemEqualToValue` when the value is not the same object reference as the entry in `items`.

Use it instead of restating the recipe: [CountrySelect](/docs/components/country-select) and
[RegionSelect](/docs/components/region-select) are both thin wrappers over it, and a third data-fed
picker should be too.

Reach for a plain [Select](/docs/components/select) when the option set is short and fixed, and for
[Combobox](/docs/components/combobox) directly when you need free text, suggestions, or
multi-select chips.

## Examples

### Anatomy

Three parts, and one rule that shapes the layout:

```tsx
<div className="relative w-full">   // the wrapper
  <Combobox.Trigger render={<Button variant="outline" className="w-full pe-9" />}>
    <ComboboxValue />               // the selected face, or the muted placeholder
  </Combobox.Trigger>
  <ComboboxContent className="w-(--anchor-width) p-0">
    <ComboboxInput showTrigger={false} /> // the panel-search row, inside the popup
    <ComboboxEmpty />
    <ComboboxList>{…ComboboxItem per item, check on the selected one…}</ComboboxList>
  </ComboboxContent>
  {/* chevron, OR the clear control when `clearable` and a value is set */}
</div>
```

The rule: an interactive control may not contain another one, so the clear control can never live
inside the trigger button. Both it and the chevron are siblings positioned inside the wrapper, and
they share **one** trailing reserve — so the trigger's text box does not move when a value is set.

The trigger is `w-full`, like every other form control. Constrain it with a parent
(`<div className="max-w-xs">`), never with a width of its own; the panel matches the trigger width
through `--anchor-width`.

Inside a [`Field`](/docs/components/field) the trigger is named by `FieldLabel` — not by its value —

### Server search

`remote` hands filtering to the server: the list shows `items` as given and never filters them
locally. `onSearchChange` reports the typed query, `loading` announces "Searching…" through the
panel's own status region while the rows already shown stay, `error` shows in the panel with a
_Try again_ button (`onRetry`, or `loadMore.onLoadMore`), and `loadMore` adds the shared Load more
footer under the rows. `useAsyncSearch` returns exactly these props — spread its result.
`leadingItems` are listed first and never filtered out ("Me", "Unassigned"). A `value` that is not
in the current page still shows its label.

### Several values and option details

`multiple` makes `value` an array: rows toggle, the panel stays open while you pick, the trigger
reads `{a}, {b}` or `{n} selected` (`countLabel`), each option reports `aria-selected`, and a form
posts every key under `name`. `itemToDescription` adds a second line read as the option's
description; `itemToDisabledReason` disables an option while keeping it reachable, with the reason
as its description. `groupBy` puts the rows under headings, in first-seen order; `groupOrder`
lists the headings that come first whatever the rows' order.

### People

`itemToSecondaryLabel={(p) => p.email}` turns each option into the standard person row — the name,
then a smaller muted email — and the local search matches both. The selected tick matches by
`itemToKey`, so options from a server search (fresh objects on each fetch) tick exactly as static
ones do.

```tsx
<SearchableSelect
  items={people}
  value={owner}
  onValueChange={setOwner}
  itemToKey={(p) => p.id}
  itemToStringLabel={(p) => p.name}
  itemToSecondaryLabel={(p) => p.email}
  renderItem={(p) => p.name}
  searchLabel="Search people"
/>
```

## Accessibility

- The trigger is `role="combobox"` with `aria-expanded` and `aria-haspopup="dialog"` — Base UI's
  pattern for a Select-style combobox whose input lives inside the panel. `role="combobox"`
  prohibits name-from-content, so the trigger is always named: by its `FieldLabel` inside a
  `Field`, by a `<label for>` pointing at `id`, or by `aria-label`. With none of these it falls
  back to the selected item's label, then the placeholder — never over a label it has.
- Outside a `Field`, `aria-invalid` and `aria-describedby` wire the trigger to an error message.
- The search field is named by `searchLabel` (default "Search"; name what it searches, "Search people") and focused when the panel opens. Inside a `Field`, the Field's label names the trigger only — the search field keeps its own name.
- The clear control is a `Button size="icon-xs"` **sibling** of the trigger with its own `aria-label`, so the
  trigger never nests one interactive control inside another.
- Selection is one code path for pointer and keyboard alike: both go through the Combobox root's
  `onValueChange`.

| Key                                 | Action                                    |
| ----------------------------------- | ----------------------------------------- |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Open the panel from the trigger.          |
| <kbd>↑</kbd> / <kbd>↓</kbd>         | Move the highlight between matching rows. |
| <kbd>Enter</kbd>                    | Select the highlighted row and close.     |
| <kbd>Esc</kbd>                      | Close without changing the selection.     |
