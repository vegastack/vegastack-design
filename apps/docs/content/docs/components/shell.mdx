## Usage

```tsx
import { GlobalBar, GlobalBarLeading } from "@/components/ui/global-bar";
import { NavTree, NavTreeItem } from "@/components/ui/nav-tree";
import { Rail, RailItem } from "@/components/ui/rail";
import {
  Shell,
  ShellColumn,
  ShellColumnHeader,
  ShellColumnToggle,
  ShellMain,
  ShellPage,
  ShellTopBar,
  ShellTopBarMore,
  ShellTopBarTitle,
} from "@/components/ui/shell";

<Shell
  globalBar={
    <GlobalBar>
      <GlobalBarLeading>
        <ShellColumnToggle />
      </GlobalBarLeading>
      …
    </GlobalBar>
  }
  rail={
    <Rail>
      <RailItem
        icon={<Home />}
        label="Home"
        render={<Link href="/" />}
        active
      />
    </Rail>
  }
  column={
    <ShellColumn label="Home">
      <ShellColumnHeader title="Home" />
      <NavTree>
        <NavTreeItem label="Tasks" render={<Link href="/tasks" />} active />
      </NavTree>
    </ShellColumn>
  }
  pageMin={640}
>
  <ShellTopBar>
    <ShellTopBarTitle>My tasks</ShellTopBarTitle>
    <ShellTopBarMore>
      <MoreMenu />
    </ShellTopBarMore>
  </ShellTopBar>
  <ShellMain>
    <ShellPage>…</ShellPage>
  </ShellMain>
</Shell>;
```

Put `ShellStateScript` in the root layout's `<head>`, from its own module so public pages carry no
client code:

```tsx
import {
  ShellStateScript,
  TimeZoneScript,
} from "@/components/ui/shell-scripts";

<head>
  <ShellStateScript />
  <TimeZoneScript />
</head>;
```

## Examples

### The layout rule

One rule places the column and the panel, at every width ([Shell layout](/docs/foundations/shell)):

| Width                   | Global bar | Rail    | Column                                     | Panel                                    |
| ----------------------- | ---------- | ------- | ------------------------------------------ | ---------------------------------------- |
| Phone (under 640)       | Hidden     | Tab bar | A sheet, from the page title               | Full screen                              |
| Tablet (640–1024)       | 44px       | 64px    | Slides over from ▤, an edge swipe or hover | Beside the page if it fits, else over it |
| Laptop and wide (1024+) | 44px       | 64px    | 240px in the flow while kept open          | Beside the page; the column folds first  |

The panel docks beside the page while the page keeps its minimum (`pageMin`: a list 640, a
document 560, a chat 520). When it would not, the column folds by itself; when even that is not
enough, the panel slides over the page and the column comes back. `resolveShellLayout` in
`@/lib/shell-layout` gives the same answer without a DOM.

The rule runs in CSS — container queries on the shell, over the data attributes it renders — so
the server's HTML is already laid out. Nothing measures after hydration.

The page makes room for a docking panel on the open motion (`duration-panel`, 120ms) only when a
person opened it: `ShellPanelToggle`'s click marks itself, and the app calls
`requestShellPanelOpen(element)` where someone opens a tab (a row, a link, ⌘.). The first paint
and opens the app makes by itself — a restored tab, an automatic Details tab — dock at once.

### The global bar

`globalBar` takes a [`GlobalBar`](/docs/components/global-bar): 44px across the whole window,
above the rail, the column, the page and the panel. It holds the app's own controls: ▤
(`ShellColumnToggle`, ⌘\\, hidden on a screen with no column), back and forward in the desktop app,
the workspace switcher, search (⌘K), Ask (⌘J), Help and the account. In the desktop app it is the
window's title row: it drags the window and clears the window's own buttons, so nothing below it
does.

### The column

A column is a `ShellColumn` (the navigation landmark) that starts with a 48px
`ShellColumnHeader`, the module's name and one or two actions, level with the page's top bar and
fixed while the column scrolls. Its places are a [`NavTree`](/docs/components/nav-tree).

### The top bar's order

The page's top bar keeps one order whatever order its slots are written in: the title, then at the
end **presence · icon tools · primary · Share · ☆ · ⋯**, with ⋯ always last and ☆ right before
it.

| Slot                  | Holds                                               |
| --------------------- | --------------------------------------------------- |
| `ShellTopBarTitle`    | The breadcrumb and the page's `<h1>`                |
| `ShellTopBarPresence` | Who else is here: one `AvatarGroup`, always first   |
| `ShellTopBarTools`    | The page's icon tools                               |
| `ShellTopBarPrimary`  | The one primary action, if the page has one         |
| `ShellTopBarShare`    | Share, an outline button                            |
| `ShellTopBarFavorite` | ☆                                                   |
| `ShellTopBarMore`     | ⋯, the page's menu; it also holds every folded tool |

The tools, Share, ☆ and ⋯ are one button shape: 28px, round, with the same hover. Narrow, Share
shows its icon alone (`ShellTopBarLabel`), presence leaves, and tools marked `data-shell-fold` go
to the ⋯ menu. There is no save status in the bar: saving is silent, and a failed save shows an
alert with a retry in the page.

### Phones

There is no rail or ▤ on a phone: the page title opens the module's column as a sheet
(`ShellColumnSwitch`, rendered by `ShellTopBarTitle` when the shell has a column; name it with
`switchLabel`), and picking a place closes the sheet. The sheet's rows are 44px targets.

The page scrolls the document, so Safari's and Chrome's own bars compact as you scroll. The bottom
bar sits above the home indicator, steps aside while you scroll down and returns when you scroll
up, and hides while the keyboard is open or a record is open full screen. Set
`viewport-fit=cover` and `interactive-widget=resizes-content` in the viewport meta, and a
`theme-color` that matches the background.

### Sections, bleeds and the gutter

`ShellPage` sets `--page-gutter` from the page's own width (`shellGutterClasses`: 16, 24 from
640px, 32 from 1024px, 48 from 1920px). Inside it, `ShellSection` gives one region its own
measure (`prose` 720, `default` 1200, `full`), so a `full` page can hold a list at `default`
beside a full-width grid; `ShellBleed` lets a grid or canvas reach the page's edges past the
gutter.

```tsx
<ShellPage size="full">
  <ShellSection measure="default">
    <DataList … />
  </ShellSection>
  <ShellBleed>
    <DataGrid fill … />
  </ShellBleed>
</ShellPage>
```

### Floating items

`ShellFloatingArea`, passed as `floating`, stacks the assistant pill, the audio player and upload
progress at the page's bottom-right. It never covers the panel, lifts over the phone bar and the
home indicator, and is left out of print. Toasts stay bottom-centre.

## Accessibility

- A skip link is the first stop; it moves focus to the page (`ShellMain`, the document's
  `<main>`). The global bar is the app's header, the rail and the column are named navigation
  landmarks, the top bar is the page's header, and the title is its `<h1>`, rendered with the page.
- The current module and view carry `aria-current="page"`; a count is part of the item's name
  ("Tasks, 17").
- The column's resize edge is a separator: drag it, or focus it and use the arrow keys.
- Everything that hovers has a key or button: the column's peek opens from ▤ and ⌘\ too.

| Key                                   | Action                                                             |
| ------------------------------------- | ------------------------------------------------------------------ |
| <kbd>F6</kbd> / <kbd>Shift+F6</kbd>   | Move between the global bar, rail, column, top bar, page and panel |
| <kbd>⌘</kbd> <kbd>\\</kbd>            | Fold or unfold the column (slide it over on a tablet)              |
| <kbd>Escape</kbd>                     | Put away a column that slid over the page                          |
| <kbd>←</kbd> <kbd>→</kbd> on the edge | Resize the column; Home and End for its ends                       |
