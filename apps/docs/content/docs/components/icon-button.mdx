## Installation

```npm
npx shadcn@latest add @vegastack/icon-button
```

## Usage

```tsx
import { IconButton } from "@/components/ui/icon-button";
import { Plus } from "lucide-react";

<IconButton aria-label="Add item">
  <Plus />
</IconButton>;
```

`IconButton` is a thin wrapper over [`Button`](/docs/components/button): it forces icon-only
geometry and **requires** `aria-label`, since the icon carries no visible text. It is the only
sanctioned icon-only path — `Button` has no icon size tier — so an unlabeled icon control cannot
compile.

### Shape

`shape="round"` is the sanctioned way to get a circular control — a `rounded-full` override on a
Button is not. Reserve it for avatar-adjacent and media-transport chrome; product chrome stays
`square`.

### States

Idle, `disabled`, and `loading` — both flags inherited from `Button`. `disabled` renders
`aria-disabled` and keeps the control focusable and hoverable so a Tooltip can explain why it is
unavailable; `loading` stacks a spinner over the icon, sets `aria-busy`, and holds the square open.

## Accessibility

- An accessible name is **mandatory** — pass `aria-label`. The build fails to type-check without one,
  so an unlabeled icon button can never ship.
- Renders a native `<button type="button">`; keyboard <kbd>Enter</kbd> / <kbd>Space</kbd> activate it.
- `:focus-visible` shows a 2px ring (`outline-ring`) — never `outline: none`.
- `loading` sets `aria-busy="true"` and disables interaction; `disabled` sets `aria-disabled` and keeps the control focusable, so a Tooltip can say why.

| Key              | Action                          |
| ---------------- | ------------------------------- |
| <kbd>Enter</kbd> | Activate the button             |
| <kbd>Space</kbd> | Activate the button             |
| <kbd>Tab</kbd>   | Move focus to / from the button |
