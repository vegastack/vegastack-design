## Usage

```tsx
import { AssistantCard } from "@/components/ui/shell-assistant";

<Shell
  assistant={
    <AssistantCard
      id="assistant-card"
      aria-label="William chat"
      open={open}
      onOpenChange={setOpen}
    >
      <Chat onClose={() => setOpen(false)} />
    </AssistantCard>
  }
  …
/>;
```

The card opens from the global bar's Ask button and the ⌘J shortcut; opening is yours (set
`open`). Render it as [`Shell`](/docs/components/shell)'s `assistant` and, from 40rem, the shell
docks it beside the page as a second card, the split view (LAY-26): 400px wide (at most 45% of the
shell), with the page card's inset and corner, the page giving it the room. Outside a shell it
fills the container you put it in.

The card is the frame only: the chat inside draws its own header (with its Close), thread and
composer. Name the region with `aria-label`, or `aria-labelledby` pointing at the chat's heading.

It renders nothing until it first opens, so the chat you put in it costs nothing until asked for;
after that it stays mounted while closed, so a draft survives.

## Accessibility

| Key            | Does                                                            |
| -------------- | --------------------------------------------------------------- |
| <kbd>⌘J</kbd>  | The host's shortcut opens the card; set `aria-keyshortcuts`.    |
| <kbd>Esc</kbd> | Closes the card from anywhere inside it, unless a menu took it. |
| <kbd>Tab</kbd> | Moves through the chat inside the card.                         |

- The card is a `region` of the frame, named by `aria-label` or `aria-labelledby`, not a dialog: the page
  stays usable beside it. Opening it moves focus to its first text field; closing it returns focus
  to what opened it. While closed it is inert and hidden.
- Motion is the system's own and follows reduced motion.
