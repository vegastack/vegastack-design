## Usage

```tsx
import { Avatar, AvatarFallback, AvatarImage } from "@/components/ui/avatar";
import { Bubble, BubbleContent } from "@/components/ui/bubble";
import {
  Message,
  MessageAvatar,
  MessageContent,
} from "@/components/ui/message";

<Message>
  <MessageAvatar>
    <Avatar>
      <AvatarImage src="/avatars/01.png" alt="@shadcn" />
      <AvatarFallback>CN</AvatarFallback>
    </Avatar>
  </MessageAvatar>
  <MessageContent>
    <Bubble>
      <BubbleContent>How can I help you today?</BubbleContent>
    </Bubble>
  </MessageContent>
</Message>;
```

`Message` owns the row layout — avatar, alignment, header and footer. Render the visible message
surface inside it with [`Bubble`](/docs/components/bubble). For the scroll container around a whole
conversation, use [`MessageScroller`](/docs/components/message-scroller).

## Examples

### Composition

`MessageContent` is the column beside the avatar: the header sits above the message surface and the
footer below it.

```text
Message
├── MessageAvatar
└── MessageContent
    ├── MessageHeader
    ├── Bubble
    └── MessageFooter
```

`MessageGroup` stacks consecutive messages from the same sender.

```text
MessageGroup
├── Message
└── Message
```

### Features

- Start and end alignment for sender and receiver rows via the `align` prop
- Avatar slot that anchors to the bottom of the message and stays clear of the footer
- Header and footer slots for sender names, status, and message actions
- Footer follows the message side; actions stay aligned on `align="end"` rows
- Group wrapper for stacking consecutive messages from the same sender
- Customizable styling through the `className` prop on every part

### Avatar

Use `MessageAvatar` to render an avatar next to the message. Set `align="end"` on the message to move
the avatar to the end of the row.

| align   | Description                                         |
| ------- | --------------------------------------------------- |
| `start` | Align the message to the start of the conversation. |
| `end`   | Align the message to the end of the conversation.   |

## API Reference

### Message

The message row wrapper. A `<div>`; every other `div` prop passes through.

| Prop        | Type               | Default   | Description                                       |
| ----------- | ------------------ | --------- | ------------------------------------------------- |
| `align`     | `"start" \| "end"` | `"start"` | The alignment of the message in the conversation. |
| `className` | `string`           | —         | Additional classes to apply to the row.           |

### MessageGroup

Groups consecutive messages from the same sender. It adds no props of its own — a `<div>` with
`data-slot="message-group"` and `className`.

### MessageAvatar

The avatar slot, aligned to the bottom of the message. When the row has a `MessageFooter`, the avatar
shifts up so it stays level with the message surface instead of the footer. It adds no props of its
own — a `<div>` with `data-slot="message-avatar"` and `className`.

### MessageContent

Wraps the header, the message surface and the footer. It adds no props of its own — a `<div>` with
`data-slot="message-content"` and `className`.

### MessageHeader

Displays content above the message, such as a sender name; stays aligned to the start whatever
`align` says. It adds no props of its own — a `<div>` with `data-slot="message-header"` and
`className`.

### MessageFooter

Displays content below the message, such as status or actions; aligns to the message side. It adds no
props of its own — a `<div>` with `data-slot="message-footer"` and `className`.

## Accessibility

- `Message` is a presentational layout wrapper — six plain `<div>`s. Every accessible semantic comes
  from what you put inside it.
- Action buttons in `MessageFooter` are usually icon-only, so give each one an `aria-label`.
- For an in-progress message, use a [`Marker`](/docs/components/marker) with `role="status"` so
  assistive tech announces the update as it appears.
- The component renders no control, so it contributes no focus affordance: whatever you render inside
  it brings the global 2px `:focus-visible` outline from `base.css`.
- `MessageContent` is `min-w-0` and wraps on word boundaries, so a long unbroken string reflows
  instead of widening the row past the viewport.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/message.patch`. Every hunk:

- **NO STYLING HUNK AT ALL** — `Message` is six plain `<div>`s with a class each: no control, no
  focus affordance, no cursor, no disabled state, no live region and no portal, so not one row in
  the exception map reaches it. A11Y-2 is audited and not applicable — nothing here is a pointer
  target. `message.test.tsx` asserts the part list, the `align` switch and the avatar/footer offset,
  so a future upstream that adds a control to this file fails there.
- **DOC-2** — `import { cn } from "cn"` becomes `@vegastack/design`; our npm layer owns `cn`.
- **DOC-1** — prettier reflow plus the `registry-stamp.mjs` provenance header the three-copy model
  needs; no decision of its own.
