## Usage

```tsx
import { SortableList } from "@/components/ui/sortable-list";

<SortableList
  aria-label="Pipeline stages"
  items={stages}
  renderItem={(stage) => <span>{stage.label}</span>}
  onReorder={({ id, to }) => moveStage(id, to.index)}
/>;
```

`SortableList` is the single-list consumer of `use-drag-reorder` (the system's
one drag-engine seam). It is controlled: `items` arrive in display order,
`onReorder` requests a move, and the host applies — or refuses — it.

Each row has a drag handle, its content, optional inline actions
(`renderActions`), and a row menu named `Actions for {label}` (`actionsLabel`
renames it) that holds the Move items. A row with `disabled: true` is locked: it
keeps its place and its menu, and other rows move past it. `layout="grid"` wraps
the same list into image tiles.

## Scope

| Behaviour             | Where it lives                                                                                                                                         |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| The persisted order   | Host — `onReorder` is a request; the app owns storage                                                                                                  |
| Selection             | Not here, deliberately: reordering + multi-select on one surface makes drag intent ambiguous — [`DataList`](/docs/components/data-list) owns selection |
| Cross-container moves | [`Board`](/docs/components/board)                                                                                                                      |
| Virtualized ordering  | `data-grid` territory                                                                                                                                  |

(Space included) never lifts the row. `renderActions` puts a delete button beside

### With row actions

`menuItems(item)` returns the row's own `RowAction`s — rename, delete — listed first in its ⋯ menu,
above a separator and the Move items: one menu per row, named `Actions for {label}`. A disabled

### Locked rows

Set `disabled: true` on an item to lock it. Its handle becomes a spacer of the
same size, so the handles stay aligned. Its row menu stays, with the Move items
disabled, and `lockedReason` is their accessible description. Other rows still
move past a locked row: the lock fixes the row, not the positions around it.

### Image grid

`layout="grid"` wraps the list into tiles at least `--spacing(28)` wide, as many
per row as fit. The handle and the actions sit over the tile's top corners. A drop
lands left or right of a tile, and in keyboard move mode <kbd>←</kbd>/<kbd>→</kbd>
step one tile while <kbd>↑</kbd>/<kbd>↓</kbd> step a whole row. The column count
is measured, so the row step is right at any width.

### Server-gated moves

Return a promise from `onReorder`: the moved row shimmers while the write is in
flight; a rejection announces the snap-back — the host never applied the move,
so the order simply stays.

### The menu path

Every row carries an "Actions for …" menu — Move up / Move down / Move to top / Move to bottom — so
the whole ordering is reachable without a pointer and without entering keyboard move mode. It runs
the same `onReorder` callback as a drag, so the host cannot tell the paths apart.

The drop-edge hairline, the lift dim and the pending shimmer come from the shared `drag-item`
recipe — the same one `Board` uses, installed once as its own registry item.

### Drag handle

Only the handle starts a pointer drag — the rest of the row stays free for text selection and the
controls inside it. That holds even when the handle mounts after its row, such as a row that was
disabled and becomes editable: the row's drag source is rebuilt around the handle as it is now.

## Accessibility

- Every reorder is reachable three ways: pointer drag on the handle, the
  keyboard move mode (<kbd>Space</kbd> lifts, arrows commit one announced step
  at a time, <kbd>Escape</kbd> ends), and the row's Move menu — the required
  lossless path on touch and for AT.
- Each step announces through a polite live region ("Moved to position 2 of
  3"); a refused move announces "Move rejected — position restored".
- Handles and menu triggers are named per row ("Reorder Alpha", "Actions for
  Alpha"); drop position shows as a 2px indicator line, and a lifted row dims.
- A locked row has no handle, only a hidden spacer. Its Move items stay in the
  menu, disabled, with `lockedReason` as their description.

| Key                                 | Action                                                          |
| ----------------------------------- | --------------------------------------------------------------- |
| <kbd>Space</kbd> / <kbd>Enter</kbd> | Toggle move mode on the focused handle.                         |
| <kbd>↑</kbd> / <kbd>↓</kbd>         | Commit a one-step move (in move mode). In a grid, move one row. |
| <kbd>←</kbd> / <kbd>→</kbd>         | In a grid, move one tile (in move mode).                        |
| <kbd>Escape</kbd>                   | End move mode.                                                  |
