## Usage

```tsx
import { AvatarStack } from "@/components/ui/person-hover-card";

<AvatarStack people={participants} label="Participants" />;
```

`AvatarStack` stacks up to `max` (5) 24px avatars — overlapping, each ringed in the background
colour — with the rest counted in a "+N". Hovering an avatar previews that person: a compact 240px
card with a 32px avatar and, beside it, the name over a smaller muted email (always shown when
known). The stack is one button: click, tap or <kbd>Enter</kbd> lists everyone in the same format.
Someone without an account (a free-text participant such as "Northwind FM leads") has no email:
their avatar shows initials and the card just the name.

### Photo, hue and initials

`PersonAvatar` draws a person the one way every people surface does: their photo when `image` is
set; else their initials on their own `hue` (one of the ten tag hues, stored per member); else the
initials on the muted fallback, for someone without an account. Initials follow one rule: the first
letters of the first and last words, the first two letters of a single word, or the email's first
two characters when there is no name (`personInitials`, exported from `person-avatar`).

The photo is a plain `<img>` in the server HTML, layered over the initials, so the browser fetches
it straight from the markup and paints it the moment it decodes: a cached photo is there on first
paint, with no flash of initials and no wait for hydration. The initials stay underneath until the
photo loads, and a photo that fails (a broken or expired URL) falls back to them. The photo never
changes the box.

### Sizes

`size` is one of six steps: `2xs` 16px and `xs` 20px for rows, chips and meta lines; `sm` 24px (the
default), `default` 32px and `lg` 40px, which are Avatar's own tiers; and `xl` 64px for a profile or
an agent's header. The initials, the team and agent icons (about 60% of the shape) and an agent's
mark all scale with the step, so never resize an avatar with a `className`. That override is what
left a 16px glyph filling a 16px circle. The two row steps show one initial, because two letters
crowd a 16 or 20px circle. Initials stay `text-xs`. `data-size` names the step that is drawn.

### Agents

An agent (`kind: "agent"`) is a soft hexagon, pointy at the top and bottom. Only agents use that
shape: circles are people, and rounded squares are teams and workspaces. With no mark, an agent
shows the bot on its `hue` (purple when none is set), or its initials with
`agentFallback="initials"`. `mark` (on the `Person`, or as a prop) puts the agent's own mark inside
the hexagon. It can be an image `{ src, srcDark, small, alt, fit, tile }`, such as a provider's favicon or the
workspace's built-in assistant mark, or a node, such as an icon. The design system holds no
provider names or logos: the app passes them in. An `inset` mark (the default) sits with room on
every side, on a neutral tile. Use `tile: "light"` for a dark-ink logo that would vanish on a dark
tile. A `fill` mark covers the whole hexagon. Until the image decodes the bot shows, and an image
that fails falls back to it. An agent's `image`, with no `mark`, is treated as an inset mark.

The hexagon is a CSS mask over the same square box as a circle, so there is no layout shift between
people and agents. It carries the same 1px hairline as a person's avatar, in both themes. A `PersonHoverCard` or `AgentHoverCard` around an agent takes the
hexagon too, so its hover fill and focus tint follow the shape, never a circle.

### Marks across themes and sizes

An image mark can carry `srcDark`, the vendor's own dark-background variant, shown instead of `src`
under the dark theme. If either fails to load, the other stands in for both themes, and the bot
shows only when both fail. `small` is the vendor's small glyph for the two row steps (`2xs` 16px and
`xs` 20px), where a full logo turns to mush; `small: false` draws the agent's fallback (the bot on
its hue) at those steps instead. Check that a small glyph keeps 3:1 contrast on its tile in each
theme before passing it; a monochrome dark-ink logo takes `tile: "light"` so it never vanishes in
the dark theme.

### Acting for someone

`actingFor` draws the member an agent works for as a small circle (their photo, else their initials
on their hue) offset 2px past the hexagon's bottom-end corner, on a halo the colour of the surface
beneath. The agent leads and the person rides on it, as attribution reads: "Claude Code for Manoj".
It shows from `sm` up; the row steps leave it out, where it would cover the mark. With an
`indicator` too, the indicator moves to the top-end corner. It is decorative: `PersonName` names
the member in text.

`PersonName` writes an agent as "Claude Code for Manoj" in rows, feeds and comments. In a picker,
where names are scanned in a list beside people, `variant="compact"` writes "Claude Code · Manoj"
and `agentLabel` adds the purple "Agent" label. A screen reader hears "Claude Code for Manoj,
agent" in both forms.

### People and agents together

### Indicators and agent state

`indicator` puts a small presence dot or state icon at the bottom-end corner, sized to the step
with a background-coloured gap, on a circle or a hexagon. `AgentStateRing` follows the hexagon
around an agent. In a narrow row, `AgentStateBadge` gives way before the agent's name: its word
truncates, then drops out, leaving the icon. The name truncates only after that. For the densest
rows, `iconOnly` keeps only the state's icon, with the word in a tooltip and for screen readers.

### Teams

A person with `kind: "team"` is a team: `PersonAvatar` draws it as a rounded-square tile with the
team icon on its hue — never initials or a photo — and `AvatarStack`, its hover previews and its
list show teams beside people the same way. Use the muted line (`email`) for something like
"8 members".

A workspace (`kind: "workspace"`) is a rounded-square tile too: its logo is shown whole
(`object-contain` on the plain background), so a wide company logo is never cropped into a circle,
and without a logo its initials sit on its hue. Use it for workspace switchers and headers.

### Inactive member

`badge` on the person puts a status right after the name — a string such as "Inactive" is a small
muted outline badge. It shows in `PersonCard`, the hover card and the `AvatarStack` list. For a
table's person cell, compose `PersonAvatar` with the name and `PersonBadge`.

### Partial lists and a footer

When only the first page of people is loaded, pass `total`: "+N" and the list's "and N more" count
from it, so the stack never shows two avatars for fourteen members. `footer` ends the list popover
with an action such as "Manage access". The avatars overlap by 4px, so two initials are never cut.

### A host's card for some people

`PersonHoverCardProvider` lets the host draw the card behind some people — an agent's state, last
action and Open agent, say — in every `PersonHoverCard` below it, including a comment's author and
an activity's actor. Give the person an `id` and return a card for the ones you know; return `null`
for the standard `PersonCard`. The element you return renders only while its card is open, and
`close` shuts the card before you navigate away.

```tsx
<PersonHoverCardProvider
  value={{
    card: (person, close) =>
      person.kind === "agent" && person.id ? (
        <AgentCard
          agent={person}
          onOpenAgent={() => {
            close();
            openAgent(person.id);
          }}
        />
      ) : null,
  }}
>
  {app}
</PersonHoverCardProvider>
```

## Accessibility

- The stack is one button named `"{label}: {names}"`; it opens the full list, so keyboard and touch
  users reach every person without the hover previews.
- `PersonHoverCard` on its own is a round button named by the person (or, with `trigger="name"`,
  a text button whose name is the visible name); its card opens on hover and on keyboard focus, a
  tap toggles it, and <kbd>Esc</kbd> closes it.
- An agent is never told apart by shape alone: `PersonName` and `personAccessibleName` say
  "agent" in text. A mark image takes an `alt` only when no name is shown beside it, and an
  `indicator` is decorative, so say the state it shows in text too.

| Key                                 | Action                                  |
| ----------------------------------- | --------------------------------------- |
| <kbd>Tab</kbd>                      | Move to the stack                       |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | List everyone (or open a person's card) |
| <kbd>Esc</kbd>                      | Close the list or the card              |
