## Usage

Wrap the application in `SidebarProvider`, put the navigation in `Sidebar`, and put the page in
`SidebarInset`. `SidebarTrigger` toggles the panel from anywhere inside the provider.

```tsx title="app/layout.tsx"
import { SidebarProvider, SidebarTrigger } from "@/components/ui/sidebar";
import { AppSidebar } from "@/components/app-sidebar";

export default function Layout({ children }: { children: React.ReactNode }) {
  return (
    <SidebarProvider>
      <AppSidebar />
      <main>
        <SidebarTrigger />
        {children}
      </main>
    </SidebarProvider>
  );
}
```

```tsx title="components/app-sidebar.tsx"
import {
  Sidebar,
  SidebarContent,
  SidebarFooter,
  SidebarGroup,
  SidebarHeader,
} from "@/components/ui/sidebar";

export function AppSidebar() {
  return (
    <Sidebar>
      <SidebarHeader />
      <SidebarContent>
        <SidebarGroup />
        <SidebarGroup />
      </SidebarContent>
      <SidebarFooter />
    </Sidebar>
  );
}
```

The desktop panel is `position: fixed` and appears at the `md` breakpoint; below it the same
children mount inside a `Sheet`. Every demo on this page therefore renders in a frame that carries
`contain: paint`, which makes the frame the fixed-positioning containing block — an application
shell has the viewport for that, a documentation page does not.

### Structure

- **SidebarProvider** — holds the collapsible state and provides the sidebar context to every child.
- **Sidebar** — the collapsible panel itself.
- **SidebarHeader** — the top of the panel: branding, titles, workspace switchers.
- **SidebarFooter** — the bottom of the panel: user menus, settings, actions.
- **SidebarContent** — the scrollable region between the two.
- **SidebarGroup** — one labelled section, with an optional action and a content area.
- **SidebarMenu** / **SidebarMenuItem** — a real `ul`/`li` list for links, badges, actions and
  submenus.
- **SidebarRail** — the thin strip on the panel's outer edge that toggles it.
- **SidebarInset** — the `main` landmark that wraps the page beside the panel.
- **SidebarTrigger** — the button that toggles the panel.

### SidebarProvider

Always wrap the application in `SidebarProvider`. It owns `open`, writes the `sidebar_state` cookie
on every uncontrolled toggle, and binds <kbd>⌘</kbd>/<kbd>Ctrl</kbd> + <kbd>B</kbd> (see Keyboard
shortcut below to retune or turn it off).

For a single sidebar, the `SIDEBAR_WIDTH`, `SIDEBAR_WIDTH_ICON` and `SIDEBAR_WIDTH_MOBILE`
constants in `sidebar.tsx` set the widths. For more than one, set `--sidebar-width` and
`--sidebar-width-icon` in the provider's `style` — those are the two variables the provider
publishes on its wrapper, so a second sidebar can carry its own. The mobile sheet is not
overridable this way: it sets `--sidebar-width` to `SIDEBAR_WIDTH_MOBILE` on its own content, which
wins over anything inherited.

```tsx
<SidebarProvider
  style={
    {
      "--sidebar-width": "20rem",
      "--sidebar-width-icon": "3rem",
    } as React.CSSProperties
  }
>
  <Sidebar />
</SidebarProvider>
```

### Sidebar

`side` picks the edge, `variant` picks the surface treatment, and `collapsible` picks what collapsing
means: `offcanvas` slides the panel out, `icon` shrinks it to a rail of icons, and `none` renders a
plain, always-visible column. Each value lands on the panel as `data-side`, `data-variant` and
`data-collapsible`, which is what the `group-data-*` recipes below read.

With `variant="inset"`, wrap the page in `SidebarInset` — the provider paints the sidebar surface
behind an inset page, and the main content is the floating card on top of it.

```tsx
<SidebarProvider>
  <Sidebar variant="inset" />
  <SidebarInset>
    <main>{children}</main>
  </SidebarInset>
</SidebarProvider>
```

### useSidebar

`useSidebar` reads and drives the panel from anywhere inside the provider. It throws outside one, so
a custom trigger has to live in the tree the provider wraps.

| Property        | Type                      | Description                                   |
| --------------- | ------------------------- | --------------------------------------------- |
| `state`         | `expanded` or `collapsed` | The current state of the sidebar.             |
| `open`          | `boolean`                 | Whether the sidebar is open.                  |
| `setOpen`       | `(open: boolean) => void` | Sets the open state of the sidebar.           |
| `openMobile`    | `boolean`                 | Whether the sidebar is open on mobile.        |
| `setOpenMobile` | `(open: boolean) => void` | Sets the open state of the sidebar on mobile. |
| `isMobile`      | `boolean`                 | Whether the sidebar is on mobile.             |
| `toggleSidebar` | `() => void`              | Toggles the sidebar. Desktop and mobile.      |

### SidebarFooter

`SidebarFooter` is the sticky bottom of the panel — the account row, settings, a sign-out. The
standard account menu (the one the Regent app ships) is in
[app-shell-01](/docs/blocks/app-shell-01): the avatar row opens a menu with Profile and Settings, a
**Theme** submenu (Light · Dark · System), Keyboard shortcuts and Sign out, every item with an icon.
Leading icons in menu buttons are muted until their row is hovered, focused or active — the
component does this, so add no colour classes (see [Icons](/docs/foundations/icons)).


### SidebarGroup

A group is one section of the panel: a `SidebarGroupLabel`, an optional `SidebarGroupAction`, and a
`SidebarGroupContent`.

```tsx
<SidebarGroup>
  <SidebarGroupLabel>Application</SidebarGroupLabel>
  <SidebarGroupAction>
    <Plus /> <span className="sr-only">Add Project</span>
  </SidebarGroupAction>
  <SidebarGroupContent></SidebarGroupContent>
</SidebarGroup>
```

To make a group collapsible, wrap it in a `Collapsible` and make the label the trigger with `render`.

```tsx
<Collapsible defaultOpen className="group/collapsible">
  <SidebarGroup>
    <SidebarGroupLabel render={<CollapsibleTrigger />}>
      Help
      <ChevronDown className="ms-auto group-data-open/collapsible:rotate-180" />
    </SidebarGroupLabel>
    <CollapsibleContent>
      <SidebarGroupContent />
    </CollapsibleContent>
  </SidebarGroup>
</Collapsible>
```

### SidebarMenuButton

`SidebarMenuButton` is the row itself. It renders a `button` by default; pass `render` to make it an
anchor or a framework `Link`. `isActive` marks the current route, `size` picks between a compact
row, the default and a two-line row, and `variant="outline"` gives it a hairline. On a link,
`isActive` also sets `aria-current="page"`; a button never gets it.

```tsx
<SidebarMenuButton render={<a href="#" />} isActive>
  Home
</SidebarMenuButton>
```

state: while its menu is open (`aria-expanded` / `data-popup-open`) it keeps the `sidebar-accent`
fill and ink, so the trigger needs no `className`.

### SidebarMenuAction

`SidebarMenuAction` is a second control on the same row — an overflow menu, an add button. It sits
inside the `SidebarMenuItem`, after the button, and `showOnHover` keeps it out of the way until the
row is hovered or something inside it takes focus.

```tsx
<SidebarMenuItem>
  <SidebarMenuButton render={<a href="#" />}>
    <Home />
    <span>Home</span>
  </SidebarMenuButton>
  <SidebarMenuAction>
    <Plus /> <span className="sr-only">Add Project</span>
```

### SidebarMenuBadge

A badge is a count pinned to the end of a row. It is `pointer-events: none`, so it never steals the
row's click, and it disappears in icon mode. It is also `aria-hidden`: the count a screen reader
hears is part of the row's own name, so give the button a `badgeLabel`. The simplest way is the
button's `badge` prop, which renders this part for you (see Counts below).

```tsx
<SidebarMenuItem>
  <SidebarMenuButton badgeLabel="24 unread" />
  <SidebarMenuBadge>24</SidebarMenuBadge>
</SidebarMenuItem>
```

### SidebarMenuSkeleton

`SidebarMenuSkeleton` stands in for a row while the navigation loads. `showIcon` adds the leading
square, and `index` picks the text width from a fixed cycle (70%, 55%, 85%, 60%, 75%), so a list of
rows looks varied and the server renders exactly what the client hydrates (LAY-16).

```tsx
<SidebarMenu>
```

### SidebarTrigger

`SidebarTrigger` is the toggle. It is an ordinary `Button` wired to `toggleSidebar`, so any button
can do the same job through `useSidebar`.

```tsx
import { useSidebar } from "@/components/ui/sidebar";

export function CustomTrigger() {
  const { toggleSidebar } = useSidebar();

  return <button onClick={toggleSidebar}>Toggle sidebar</button>;
}
```

Its accessible name is "Toggle sidebar"; pass `triggerLabel` to localise it.

### SidebarRail

`SidebarRail` is the thin strip along the panel's outer edge that toggles it on click. It is
deliberately outside the tab order — `SidebarTrigger` is the keyboard affordance and the rail is the
pointer one — so a sidebar that ships a rail still ships a trigger. Its `aria-label` and `title`
read "Toggle sidebar", and `triggerLabel` overrides both.

```tsx
<Sidebar>
  <SidebarHeader />
  <SidebarContent>
    <SidebarGroup />
  </SidebarContent>
  <SidebarFooter />
  <SidebarRail />
</Sidebar>
```

### Controlled Sidebar

Pass `open` and `onOpenChange` to drive the panel from your own state. A controlled provider writes
no `sidebar_state` cookie of its own — persistence becomes the host's decision, and
`useSidebarCookieOpen` (see Static shells below) is the ready-made one.

```tsx
export function AppSidebar() {
  const [open, setOpen] = React.useState(false);

  return (
    <SidebarProvider open={open} onOpenChange={setOpen}>
      <Sidebar />
    </SidebarProvider>
  );
}
```

### Styling

The panel publishes its state as data attributes, so a consumer styles against them rather than
against a prop. `group-data-[collapsible=icon]:` hides what icon mode cannot show:

```tsx
<Sidebar collapsible="icon">
  <SidebarContent>
    <SidebarGroup className="group-data-[collapsible=icon]:hidden" />
  </SidebarContent>
</Sidebar>
```

…and `peer-data-active/menu-button:` reaches an action from the state of the row beside it. Prefix it
with `md:` when the action also carries `showOnHover`: that recipe's own `md:opacity-0` compiles to
the same specificity as the override, so without the media prefix the hidden state wins on source
order.

```tsx
<SidebarMenuItem>
  <SidebarMenuButton />
  <SidebarMenuAction
    showOnHover
    className="md:peer-data-active/menu-button:opacity-100"
  />
</SidebarMenuItem>
```

### RTL

Wrap the subtree in `DirectionProvider direction="rtl"` and pass `dir="rtl"` to `Sidebar` — the `dir`
travels to the mobile `SheetContent`, which portals out of that subtree and would otherwise render
left to right. Every inset, border and margin in the panel is already logical, so `side="right"`
anchors it to the reading start and `SidebarTrigger`'s icon flips with it.

```tsx
<Sidebar dir="rtl" side="right">
  {/* ... */}
</Sidebar>
```

### Counts

Pass `badge` to `SidebarMenuButton` and it renders the visual `SidebarMenuBadge` beside the row,
while `badgeLabel` joins the row's accessible name: the link below is announced as "Inbox 12
unread". A string or number `badge` names itself when you leave `badgeLabel` out. The label
truncates before it reaches the count, and a count of three characters or more gets a wider
reserve. When the panel collapses to icons, the `tooltip` carries the count too.

```tsx
<SidebarMenuButton
  render={<a href="/inbox" />}
  isActive
  tooltip="Inbox"
  badge="12"
  badgeLabel="12 unread"
>
  <Inbox />
  <span>Inbox</span>
</SidebarMenuButton>
```

### Action row with shortcut

A row that opens a palette shows its shortcut with `Kbd`. Mark the keys `aria-hidden` and put the
chord on the button with `aria-keyshortcuts`, so the name stays "Search". Build the modifier with
`formatShortcutKey` from `use-platform`, so it reads ⌘ on a Mac and Ctrl everywhere else. A row with
a secondary action keeps it in `SidebarMenuAction`, a separate control.

```tsx
function SearchRow() {
  const { os } = usePlatform();
  return (
    <SidebarMenuButton variant="outline" aria-keyshortcuts="Meta+K Control+K">
      <Search />
      <span>Search</span>
      <KbdGroup aria-hidden="true" className="ms-auto">
        <Kbd>{formatShortcutKey("mod", os)}</Kbd>
        <Kbd>K</Kbd>
      </KbdGroup>
    </SidebarMenuButton>
  );
}
```

### Unavailable item

An item the user cannot open yet stays in the list with `aria-disabled="true"`. The row keeps its
pointer events (FRM-4), so a `Tooltip` can say why, and `aria-describedby` points at a visually
hidden copy of the same reason for a screen reader. A short `badge` marks the state at a glance;
`badgeLabel` gives it words, so the row is named "Agents Coming soon" rather than "Agents TBD".

```tsx
<SidebarMenuItem>
  <Tooltip>
    <TooltipTrigger
      render={
        <SidebarMenuButton
          aria-disabled="true"
          aria-describedby="agents-reason"
          badge="TBD"
          badgeLabel="Coming soon"
        />
      }
    >
      <Bot />
      <span>Agents</span>
    </TooltipTrigger>
    <TooltipContent side="right">Available on the Team plan</TooltipContent>
  </Tooltip>
  <span id="agents-reason" className="sr-only">
    Available on the Team plan
  </span>
</SidebarMenuItem>
```

### Keyboard shortcut

<kbd>⌘</kbd>/<kbd>Ctrl</kbd> + <kbd>B</kbd> toggles the sidebar from anywhere on
the page, except where the user is typing: the provider ignores the chord inside
an input, a textarea, a select or a `contenteditable` element
(`isEditableTarget` from `use-platform`), and ignores an event another handler
has already `preventDefault`ed. `keyboardShortcut` changes the key, and `false`
turns the binding off — for an editor that owns <kbd>⌘</kbd> + <kbd>B</kbd> for
bold, say.

```tsx
<SidebarProvider keyboardShortcut="j">{/* ⌘/Ctrl + J */}</SidebarProvider>
<SidebarProvider keyboardShortcut={false}>{/* no chord */}</SidebarProvider>
```

### Static shells

A shell that is prerendered or cached cannot read the `sidebar_state` cookie on the server, so it
renders the panel expanded and a collapsed sidebar would jump on hydration. Put
`SidebarStateScript` in the root layout's `<head>`: before first paint it reads the cookie, marks
`<html>` with `data-sidebar-state="collapsed"`, and gives the desktop panel the `data-state` and
`data-collapsible` its own recipes already read, so it paints collapsed. Pass it the same
`collapsible` as your `Sidebar`, and the request's `nonce` under a nonce-based Content Security
Policy. The provider starts from that mark, so hydration agrees with the screen and React warns
about nothing.

For a controlled provider, `useSidebarCookieOpen` returns `[open, setOpen]`: it starts from the
same mark, reads the cookie after hydration when there is no mark, and its setter writes the cookie
(`SameSite=Lax`). The controlled provider itself never writes one.

```tsx title="app/layout.tsx"
import { SidebarStateScript } from "@/components/ui/sidebar";

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en" suppressHydrationWarning>
      <head>
        <SidebarStateScript collapsible="icon" />
      </head>
      <body>{children}</body>
    </html>
  );
}
```

```tsx title="components/app-frame.tsx"
"use client";

import { SidebarProvider, useSidebarCookieOpen } from "@/components/ui/sidebar";

export function AppFrame({ children }: { children: React.ReactNode }) {
  const [open, setOpen] = useSidebarCookieOpen();
  return (
    <SidebarProvider open={open} onOpenChange={setOpen}>
      {children}
    </SidebarProvider>
  );
}
```

`suppressHydrationWarning` on `<html>` covers the `data-sidebar-state` attribute the script adds
there. The script is inline, so a strict Content Security Policy needs a nonce or hash for it.

## Accessibility

- `SidebarInset` is the `main` landmark; `Sidebar` itself is a styled `div`, so give the panel a
  landmark of your own when it is the page's navigation — an `aria-label`led `nav` inside
  `SidebarContent`, or `aria-label` on the element you pass through `render`.
- `SidebarMenu` and `SidebarMenuSub` are real `ul` lists of `li` rows, so the navigation is announced
  with a length and a position. Mark the current route with `isActive`: on a link it also sets
  `aria-current="page"` (A11Y-18), and a button never gets it. `SidebarMenuSubButton` does not do
  this for you, so add `aria-current="page"` to the active sub-link yourself.
- A count is part of the row's name, not loose text beside it: `badge` and `badgeLabel` on
  `SidebarMenuButton` make the link read "Inbox 12 unread", and the visual badge is `aria-hidden`
  (A11Y-17).
- Below the `md` breakpoint the panel mounts inside `Sheet`, which brings the focus trap, the scroll
  lock and <kbd>Esc</kbd> with it; `SidebarTrigger` opens it and focus returns to the trigger on
  close.
- `SidebarRail` is `tabIndex={-1}` by design. It is the pointer affordance; `SidebarTrigger` and
  <kbd>⌘</kbd>/<kbd>Ctrl</kbd> + <kbd>B</kbd> are the keyboard ones, so ship a
  trigger with every rail. The chord never fires while focus is in a text field
  or a `contenteditable` element (INT-11).
- `SidebarMenuAction` and `SidebarGroupAction` are 20px glyphs that an invisible
  `after:absolute after:-inset-2` grows to a 36px pointer target — at every width, not only on touch
  (A11Y-2). Give each one a real name too: an icon plus an `sr-only` label, as every example here
  does.
- An icon-only row needs the `tooltip` prop, which is what names it once the panel collapses to
  icons.
- Focus is the global 2px `:focus-visible` outline from `base.css`. Nothing in this component
  suppresses an outline or paints a ring glow.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/sidebar.patch`. Every hunk:

- **API-29** — `SidebarMenuButton` takes the `sidebar-accent` fill and ink on `aria-expanded` and
  `data-popup-open`, so a menu trigger shows its open state without a `className`.
- **A11Y-2** — `md:after:hidden` is dropped from `SidebarMenuAction` and `SidebarGroupAction`. Both
  are `w-5` (20px) squares, which is under the 24px floor, and upstream already solves that the way
  A11Y-2 asks — with an invisible `after:absolute after:-inset-2` hit area — and then switches the
  area OFF again at `md` and above. Measured with a real `document.elementFromPoint` probe over
  compiled Tailwind: 36×36 with 0/5 obstruction misses at 390px, and 20×20 at 1280px, i.e. 4px under
  the floor at every desktop width. The hit area is the only thing that changes: the visible 20px
  box, its position and its hover wash are upstream's. `sidebar.test.tsx` measures both controls at
  both widths.
- **A11Y-17** — `SidebarMenuButton` takes `badge` and `badgeLabel`. The count joins the row's
  accessible name through a comma-free `sr-only` suffix ("Inbox 12 unread"), the collapsed tooltip
  carries the same count, and the visual `SidebarMenuBadge` is `aria-hidden`. The button renders the
  badge as its upstream sibling, the label keeps its `truncate` while the suffix is the last child,
  and the row reserves `pe-8` for a badge (`pe-12` for one of three or more characters).
- **A11Y-18** — `SidebarMenuButton` sets `aria-current="page"` when `isActive` and `render` is a
  link. A button never gets it, and a caller's own `aria-current` wins.
- **BRD-1** — the floating variant's panel draws a real `border border-sidebar-border` instead of
  upstream's `ring-1 ring-sidebar-border` box-shadow outline. The floating sidebar is a floating
  surface, and MK extended BRD-1 to it on 23-09-2026; the edge now matches the docked variant's
  `border-e` and survives forced colours. The collapsed width already budgets `+2px` for it.
- **DOC-1** — registry layout: `@/hooks/use-mobile` becomes `@/components/ui/use-mobile`. Hooks are
  `registry:hook` items alongside the components in this registry, which is the path the three-copy
  model and `shadcn add @vegastack/use-mobile` both use. Plus the prettier reflow and the
  `registry-stamp.mjs` provenance header; those carry no decision of their own.
- **DOC-2** — `import { cn } from "cn"` becomes `@vegastack/design`; our npm layer owns `cn`.
- **FOC-1, FOC-6** — `outline-hidden` and `focus-visible:ring-2` are removed from all five controls
  that carry them: `SidebarGroupLabel`, `SidebarGroupAction`, `SidebarMenuButton`,
  `SidebarMenuAction` and `SidebarMenuSubButton`. `outline-hidden` is the v3 spelling of "no
  outline": upstream suppresses the browser's and paints its own 2px ring instead, and this system
  does the opposite. `ring-sidebar-ring` is left in place on each — it is a colour with no ring
  width behind it any more, it paints nothing, and removing it would take the `--sidebar-ring`
  token's only reference with it.
- **FRM-4** — `disabled:pointer-events-none` and `aria-disabled:pointer-events-none` are dropped
  from `SidebarMenuButton` and `SidebarMenuSubButton`, so a disabled nav row stays hoverable and a
  Tooltip can explain why. Both opacity halves stay.
- **INT-11** — the <kbd>⌘</kbd>/<kbd>Ctrl</kbd> + <kbd>B</kbd> handler returns early on an event
  that is already `defaultPrevented` or that started in an editable target (`isEditableTarget` from
  `use-platform`: input, textarea, select, `contenteditable`). `SidebarProvider` takes
  `keyboardShortcut` (default `"b"`; `false` removes the listener).
- **LAY-13** — static-shell state. New `SidebarStateScript` (a `<head>` script that reads the
  cookie, marks `<html>` with `data-sidebar-state` and sets the collapsed `data-state` and
  `data-collapsible` on the desktop panel as the parser inserts it) and `useSidebarCookieOpen`. The
  uncontrolled provider starts from that mark and keeps it in step; the cookie write gains
  `SameSite=Lax` and happens only when the provider is uncontrolled.
- **LAY-16** — `SidebarMenuSkeleton`'s `Math.random()` width becomes a fixed cycle (70%, 55%, 85%,
  60%, 75%) picked by a new `index` prop, so the server and the client render the same markup.
- **OVL-16** — the mobile panel's `SheetContent` restates `data-[side=left]:w-(--sidebar-width)` and
  `data-[side=right]:w-(--sidebar-width)`, so the sheet stays at the sidebar's own mobile width
  (18rem) whatever width the Sheet gives a side sheet, and the scrim beside it stays tappable.
- **VOI-1** — "Toggle Sidebar" becomes "Toggle sidebar" on `SidebarTrigger` and `SidebarRail`, and
  both take `triggerLabel` to override it.
