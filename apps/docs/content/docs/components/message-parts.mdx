## Usage

```tsx
import { Message, MessageContent } from "@/components/ui/message";
import { MarkdownView } from "@/components/ui/markdown-view";
import {
  MessageActions,
  MessageActivity,
  MessageActivityNote,
  MessageActivityResults,
  MessageActivityStep,
  MessageBubble,
  MessageTime,
} from "@/components/ui/message-parts";
import { SourceList } from "@/components/ui/source-list";

<Message align="end">
  <MessageContent className="gap-1">
    <MessageBubble>{question}</MessageBubble>
    <MessageTime date={question.createdAt} />
  </MessageContent>
</Message>
<Message>
  <MessageContent>
    <MessageActivity summary="Searched the web · 2 searches" ms={14000}>
      <MessageActivityNote>Planning a search for LM-80 and TM-21.</MessageActivityNote>
      <MessageActivityStep icon={<Search />} label="Searched the web" detail="TM-21 projection">
        <MessageActivityResults results={results} />
      </MessageActivityStep>
    </MessageActivity>
    <MarkdownView typeScale="reading" citation={cite}>{answer}</MarkdownView>
    <SourceList sources={sources} />
    <div className="flex items-center gap-2">
      <MessageActions>{/* Copy, Retry, 👍, 👎 */}</MessageActions>
      <MessageTime date={answer.createdAt} reveal="hover" />
    </div>
  </MessageContent>
</Message>;
```

Compose these inside [`MessageContent`](/docs/components/message), next to the text. The answer's
text is [`MarkdownView`](/docs/components/markdown-view) at `typeScale="reading"`; a person's
message is `MessageBubble`, which reads at the same size and leading. The AI disclaimer belongs once
near the composer (a [`ChatComposerNotice`](/docs/components/chat-composer) or the chat's header), not on every answer.

A site icon (`MessageSource.icon`) comes from the host: serve favicons through the app's own origin
so the reader's browser never calls the cited site. The pages an answer cites are
[`SourceList`](/docs/components/source-list). A missing or failing icon is a neutral globe,
never a letter.

`MessageSources` takes [`Citation`](/docs/components/cited-list) chips for records (a meeting, a
task), which it does not bring with it: install `cited-list` too. An item the reader can't open is a
`Citation` with `render={<span />}`.

### The whole conversation

```text
MessageScroller            role="log" aria-label="Messages"
├── Message                role="article", named "{author}, {time}"
│   └── MessageContent
│       ├── MessageStatus
│       ├── the text       aria-busy while it streams
│       └── the other parts
└── one useAnnouncer region, mounted for the conversation's life
```

Keep `aria-busy` on the text's own wrapper, never on `Message`: anything inside a busy subtree can go
unannounced, and the status and any failure sit next to the text. Announce the status and "replied"
through the one `useAnnouncer` region.

## Examples

### A person's message

`MessageBubble` is the person's side: the muted surface with foreground text, the line breaks they
typed kept, at the reading scale's 14/24 (16/26 on a coarse pointer). `MessageTime` under it is
always there; the full date is in its tooltip.

### Activity

`MessageActivity` is what the agent thought and did on the way to its answer, one quiet line above
the text. Done, the line is a summary and the time the turn took. Open, it is a timeline: notes in
muted text, and steps — a search, a page opened, a skill used, a memory saved — each with its icon.
A step with children is a button that opens them in place, a search's results here, and a failed
step says why under it.

While the turn runs, pass `running` and `startedAt`: the line is the current note or step with a
shimmer and a live timer. Open it for the person who asked and close it when the answer starts
(`open` / `onOpenChange`), so the answer is the first thing to read.

`MessageStatus` is the one line saying what the agent is doing now. Replace its text as the agent
moves on and remove it when the answer's text starts. The text below it is `aria-busy` until the

### Notices and failures

`MessageNotice` is a quiet line with one action. A failed turn is `MessageStatus` with
`status="error"` and a Retry. Neither is a live region, so reopening a chat stays silent; pass `live`
to the one that just appeared because of what the person did.

## Accessibility

- No part is a live region unless you pass `live`. A conversation is `role="log"`, so a part that
  also announced itself would be read twice.
- A step's status and a plan item's state are read out from `statusLabels` and `stateLabels`, since
  the icon alone shows them.
- `MessageActions` keeps its buttons in the Tab order while hidden: focus reveals them. It makes
  every button in it the 28px square of `Button size="icon-sm"` with a 16px icon, whatever size it
  was given and whether or not a `TooltipTrigger` or `PopoverTrigger` wraps it, so Copy, Retry, 👍
  and 👎 are always one style. Put only icon buttons in the row. `MessageTime reveal="hover"`
  reveals the same way.
- `MessageActivity` and each step with children are disclosures: buttons with
  `aria-expanded`, opened by Enter or Space, nested ones included. A step's status is read before it
  ("Failed: Opened ies.org"). The live timer is hidden from screen readers while it ticks; the
  host announces the answer.
- A warning on the closed line is part of the button's name, so it is heard before the timeline
  opens. A nested group is a list named by its `label` and described by its count line.
- A thinking note's Show more is a button with `aria-expanded` that controls the note's text.
- Source and result rows are links that say they open a new tab; site icons are decorative.

| Key                                 | Action                                                                          |
| ----------------------------------- | ------------------------------------------------------------------------------- |
| <kbd>Tab</kbd>                      | Move through the activity, steps, sources, links, actions and versions          |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Open the activity, a step, the sources; press an action, Show more or Show less |
