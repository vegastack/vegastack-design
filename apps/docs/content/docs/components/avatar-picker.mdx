## Usage

```tsx
import { AvatarPicker } from "@/components/ui/avatar-picker";

<AvatarPicker
  person={{ name: me.name, image: me.image, hue: me.color }}
  maxSize={10 * 1024 * 1024}
  onUpload={(file) => uploadPhoto(file)}
  onRemove={() => removePhoto()}
/>;
```

Inline, `AvatarPicker` is only the person's avatar — their photo, else their initials on their
colour — as a round button named "Upload photo" or "Change photo". Hover or keyboard focus lays a
soft scrim with a white pencil over it (the initials fade out under it); a device without hover
shows a small pencil badge on the edge instead. A click opens the "Profile photo" dialog:

- A 128px circle that is itself the file button and a drop target, with the accepted formats and
  size under it ("JPEG, PNG or WebP · up to 10 MB"). On a phone the browser offers the camera and
  the gallery.
- A chosen or dropped file is only **staged**: it shows in the circle, nothing is saved. Closing
  the dialog discards it.
- **Update** (disabled until a file is staged) awaits `onUpload(file)`; **Remove** (only while
  there is a photo) clears a staged file, else awaits `onRemove()`. While a call is pending the
  button that started it shows a spinner (it keeps its width), the other button and the circle
  are disabled, and the dialog cannot be dismissed. It
  closes when the call resolves; when it rejects it stays open, keeps the staged photo, and shows
  the error's `message` under the circle.
- A refused file — the wrong type (an iPhone HEIC photo is told to export it as JPEG) or over
  `maxSize` — shows on the same line.

The component owns the dialog, the staging and the pending state; the app only does the work in
its callbacks (and shows its own toasts around them), then passes the new `person.image` back.

## Accessibility

- The inline circle is a button named "Upload photo" or "Change photo" that opens a dialog
  (`aria-haspopup="dialog"`). Focus moves into the dialog and returns to the circle when it closes.
- In the dialog the big circle is the file button, described by the format hint and any message;
  the file input behind it is hidden and never takes focus.
- Keyboard focus shows the same scrim and pencil as hover — the circle's focus cue, with no ring.
- One polite live region announces every refused file and every failed call, once each, with the
  same words shown under the circle.
- While a call is pending, the button that started it is `aria-busy` with a spinner, the other
  button and the circle are disabled, and <kbd>Esc</kbd> does not close the dialog.

| Key                                 | Action                                                          |
| ----------------------------------- | --------------------------------------------------------------- |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Open the dialog; in it, open the file browser or press a button |
| <kbd>Tab</kbd>                      | Move between the circle, Remove, Update and Close               |
| <kbd>Esc</kbd>                      | Close the dialog and discard a staged photo                     |
