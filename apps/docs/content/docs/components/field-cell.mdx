## Usage

```tsx
import {
  FieldCellDisplay,
  FieldCellEditor,
  FieldInput,
} from "@/components/ui/field-cell";

// Show a value
<FieldCellDisplay type="currency" value={1240.5} config={{ currency: "EUR" }} />

// Edit it in a grid cell: the column's render is the display, the custom editor gets the row
render: (row) => <FieldCellDisplay type="single_choice" value={row.status} config={{ options }} />,
editable: {
  type: "custom",
  render: ({ row, value, seed, commit, cancel }) => (
    // The editor commits a TYPED value: save it, then leave the slot (and move, with the key).
    <FieldCellEditor type="single_choice" label="Status" value={row.status}
      config={{ options }} seed={seed}
      onCommit={(v, move) => { save(row.id, "status", v); commit(value, move); }}
      onCancel={cancel} />
  ),
}

// Edit it in a panel or a form
<FieldInput type="date" aria-label="Due" value={due} onChange={setDue} />;
```

`field-cell` is one display and one editor per field **type**, so a table's cells, a row panel and
a record page's custom fields agree. `FieldCellDisplay` shows a value on one line; `FieldCellEditor`
is what a grid cell opens and commits a **typed** value (not a string); `FieldInput` is the same
editor as a plain form control.

| Type                                   | Display                                                      | Editor                                                      |
| -------------------------------------- | ------------------------------------------------------------ | ----------------------------------------------------------- |
| `text`                                 | One line, truncated (full value on hover and keyboard focus) | Text field (`maxLength`, 10,000 by default)                 |
| `long_text`                            | The first line                                               | The `TextEdit` editor (Markdown)                            |
| `number`, `currency`, `percent`        | End-aligned tabular figures in the reader's locale           | `NumberField` — "1,5" is 1.5 where the comma is the decimal |
| `date`                                 | A calendar day that never shifts with the zone               | `DatePicker`                                                |
| `datetime`                             | Date and time in the reader's zone                           | `DatePicker` and a time field                               |
| `single_choice`, `multi_choice`        | `FieldChoiceBadge`s in the option's hue, "+N" past two       | The option list, Add option with `onCreateOption`           |
| `checkbox`                             | A checkbox that toggles in place (`onToggle`)                | A checkbox                                                  |
| `person`                               | Avatar and name; several as avatars                          | `PeoplePicker`                                              |
| `link`                                 | `InlineChip`s in four states, "+N" past three                | An async record search (`searchRecords`)                    |
| `file`                                 | Kind tiles, "+N" past three                                  | Uploads live where files are added                          |
| `url`, `email`, `phone`                | A link out (http(s), mailto, tel)                            | A checked text field                                        |
| `calculated`                           | The value, or "—" with the missing inputs on hover           | —                                                           |
| `autonumber`, `created_*`, `updated_*` | Read-only                                                    | —                                                           |

Field types are data types. Everything a host knows — the options, the people, how records are
found, a link kind's icon and noun (the host's `InlineChip` kinds) — comes in through `config` and
the host's providers. Locale and time zone come from the reader (`TimeZoneProvider`).

## Examples

### Choice values

A choice value is a [`Badge`](/docs/components/badge) filled in its option's hue — Badge's custom
colour route on the tag tokens, never an outlined pill — and `FieldChoiceBadge` is that badge, so
every surface draws an option the same way: a cell, a phone card, the editor's list, a form
trigger. Use it wherever the host shows an option outside a field cell (a board card, a filter
value). A cell shows two and "+N"; a cut name and the hidden ones show on hover and keyboard focus.

```tsx
import { FieldChoiceBadge } from "@/components/ui/field-cell";

<FieldChoiceBadge hue="green">
  <span className="min-w-0 truncate">Sent</span>
</FieldChoiceBadge>;
```

In a grid the choice editor puts no field in the cell: the cell keeps its badges where they were,
and the option list opens under it at once — the search field first, each option as its badge, a
check on the chosen ones, and "Add “…”" at the end when `config.onCreateOption` is given. A single
choice commits on the pick. A multiple choice toggles with the list open and commits on

<kbd>Tab</kbd>, on <kbd>Enter</kbd> with no option highlighted, or when the list
closes (a click away); <kbd>Escape</kbd> cancels. As a form control
(`FieldInput`, a record's property row) a choice is a `SearchableSelect` field
with the same badges in its list.

### A cell editor

A picker commits on choosing (chosen with <kbd>Enter</kbd>, it also moves down) — a multiple
choice when the edit ends, as above; text, numbers and date-times commit on <kbd>Enter</kbd> or when focus
leaves the editor (not into its own calendar); long text opens in a popover, with the `@` mention
menu when `config.mentions` is given (with `mentionHref` and `mentionImage`, as `TextEdit` takes
them; the row panel's `FieldInput` too); <kbd>Escape</kbd>
cancels. The editor takes focus as it opens — a picker's list or calendar opens with it, and long
text's editor takes the caret. In a grid it follows the spreadsheet keys:

<kbd>Enter</kbd> commits and moves down (<kbd>Shift</kbd>+<kbd>Enter</kbd> up),
<kbd>Tab</kbd> right and <kbd>Shift</kbd>+<kbd>Tab</kbd> left — through
`onCommit`'s `move` — and <kbd>Tab</kbd> first steps through a date-time's own
date and time. The key that opened it (`seed`) replaces a text, URL, email,
phone, number or long-text value (keys typed while long text's editor loads
follow it); a date opens as a field that takes a typed date ("12/3", "Mar 12",
"today") starting from it; and a choice, person or link picker opens searching
for it. A date-time opens as it is. While an IME is composing, no key commits or
moves.

### In a grid cell

`variant="cell"` on `FieldCellDisplay` and `FieldCellEditor` is the grid cell's own look, for a grid
whose cells are one clipped line and whose editor floats over the cell as the box itself. The
display is plain — a number or percent has no digit grouping (only a currency groups, so a year
reads 2026), a link shows without its scheme and without a trailing slash on a bare host, a date
is clipped on its line rather than ending in an ellipsis, and every person is their avatar and
name. The editor draws no border, fill or shadow of its own (an invalid draft turns its text
destructive, and a number's steppers go). A text field is one wrapping box that grows to
`max-h-60` then scrolls, its newlines typed or pasted becoming spaces; a number field is typed as
written — the reader's decimal mark, no grouping, no steppers, <kbd>↑</kbd> and <kbd>↓</kbd>
step by 1, and "-", "." and "1." are drafts on the way to a value (one that never becomes a number
cancels when focus leaves). The commit keys are the grid's, as above.

```tsx
<FieldCellDisplay variant="cell" type="url" value="https://example.com/" />
<FieldCellEditor variant="cell" type="number" label="Quantity" value={2026} onCommit={…} onCancel={…} />
```

### Type icon and labels

`FieldTypeIcon` draws the icon of a field type, and `FIELD_TYPE_LABELS` and `FIELD_TYPE_ICONS` are the
words and icons for every `FieldType`, so a column header, a type picker and a field menu show a type the
same way. The icon is decorative (`aria-hidden`); the label is what a screen reader reads.

```tsx
<FieldTypeIcon type="multi_choice" /> {FIELD_TYPE_LABELS.multi_choice}
```

### Property rows

`FieldProperty` is one field as a record's property row, inside a `PropertyList` — a row peek, a
row page, a customer's or project's custom fields. Its value is drawn exactly as the grid draws it
(`FieldCellDisplay`, with numbers at the start of the value — `align="start"` — rather than the
column's end), with no box at rest and a quiet wash on hover; a click, <kbd>Enter</kbd> or a
typed character opens the grid cell's own editor (`FieldCellEditor`) in place. A checkbox toggles
where it is. A value that is itself a link — a URL, email, phone or record chips — stays followable, so an
**Edit** pencil beside it (on hover and focus, always on touch) opens the editor. Files show and
never edit here. Long text shows its first line as typed (Markdown escapes undone, mentions by name) and edits in place, growing with its text, with the `@` menu when
`config.mentions` is given. With `focusMode="managed"`, nothing in the row is a tab stop and the host
opens the editor through `editing` / `onEditingChange`. Read-only types (calculated, auto number, created and updated at and by), `readOnly`
and `disabled` show the value with no hover. An open editor fills the value's width and keeps the row's height. `onSave` returns a promise: the value shows at once, a
spinner follows after 300ms, and a rejection rolls back with a Retry toast. `conflict` says
"Someone changed this field." under the value. An empty value reads "Empty". On a phone the value
goes full width under its label.

## Accessibility

- Every editor is named by its field (`aria-label` / `label`) and marks a value it refuses
  `aria-invalid` (an invalid URL, email or phone).
- Each link chip stays on one line and is never broken inside a name, even inside a host's prose;
  a cell that grows (`className="flex-wrap"`, a page's table block) wraps whole chips.
- A truncated text, number, date, tag or link name is revealed on hover and on keyboard focus; a
  link list's "+2" names what it hides on hover and on keyboard focus (an unreachable link only by
  its state); every overflowed list (links, people, files) is read in full by screen readers; the
  row panel shows every value whole.
- A restricted link is muted and never a link; an unavailable or deleted one says so.

| Key                                              | Action                                                         |
| ------------------------------------------------ | -------------------------------------------------------------- |
| <kbd>Enter</kbd>                                 | Commit a text, number, URL, email or phone editor; move down.  |
| <kbd>Enter</kbd> in a choice list                | Pick the highlighted option (a multiple choice toggles it).    |
| <kbd>Shift</kbd>+<kbd>Enter</kbd>                | Commit and move up.                                            |
| <kbd>Tab</kbd> / <kbd>Shift</kbd>+<kbd>Tab</kbd> | Commit and move right / left (past the editor's own controls). |
| <kbd>⌘</kbd>/<kbd>Ctrl</kbd>+<kbd>Enter</kbd>    | Commit long text.                                              |
| <kbd>Escape</kbd>                                | Cancel the edit.                                               |
