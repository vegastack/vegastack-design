## Usage

```tsx
import {
  CommentComposer,
  CommentList,
  type CommentData,
} from "@/components/ui/comments";

<CommentList
  comments={comments}
  count={total}
  hasEarlier={!!cursor}
  onLoadEarlier={loadEarlier}
  highlightedId={hashCommentId}
  onEdit={(id, body) => updateComment(id, body)}
  onDelete={(id) => deleteComment(id)}
  onCopyLink={(id) => copy(`${url}#comment-${id}`)}
  composer={<CommentComposer onSubmit={(body) => postComment(body)} />}
/>;
```

`CommentList` is a record's discussion: an `h2` "Comments" with the count and, when `onOrderChange`
is set, an "Oldest first" / "Newest first" toggle; "Load earlier" when older comments exist; the
comments; and the composer at the end. Pass `comments` oldest first; `order="newest"` reverses
them. With no comments, the composer sits right under the heading — no empty-state line (pass
`emptyText` for one).

`CommentComposer` is a light box — [`TextEdit`](/docs/components/text-edit)'s `boxed` variant on a
near-transparent fill, with a hairline border that darkens subtly with an ease while the editor
holds focus and no fill change — one line and 32px tall at rest — the `Input` height, radius (`rounded-lg`) and type size, whether focused or not — whose editor grows with its text to
about twelve lines and then scrolls inside. Its placeholder is "Add a comment…". A round ↑ send
button sits inline at the end of the box, pinned to the bottom line as the text grows (a quiet grey
disc while there is nothing to send; Cmd/Ctrl+Enter also sends); a muted round paperclip attach button sits
before it whenever `onImageUpload` or `onFileUpload` is set, opening the file picker (the files
upload through the editor's own flow), and the optional `attachments` slot before that. On a touch
screen both buttons get a 40px target. `replyingTo={{ name }}` shows "Replying to name ×" above the
box and the "Write a reply…" placeholder; × or Esc calls `onCancelReply` and keeps the text.
The `files` slot renders inside the box at its bottom, under the text — a draft's attached files (pending cards with progress and ×) are part of what Send posts. With `onAttachFiles`, files pasted or dropped on the box join that tray too, instead of going into the text. With `hasFiles` (the draft carries finished files), Send is enabled and posts
with no text; `CommentThread`'s `composer` takes it too. No
avatar sits beside it. Editing a comment uses the same box: a round ↑ Save (disabled while empty or unchanged) and a ghost × Cancel, both with
tooltips; Cmd/Ctrl+Enter saves and Esc cancels. The parts take data and
callbacks and keep only transient UI state. A callback that returns a promise drives the saving or
posting state. If the promise rejects, its message appears under the editor. Bodies are Markdown,
edited with `TextEdit` (no toolbar; a reduced slash menu; no drag handles) and rendered with
`MarkdownView`. The editor's bubble menu and link input float in a portal, so the box never clips
them. Times read in the compact form — "now", "19m ago", "3h ago" — with the exact time on hover.

Each comment sits in its own card — the composer's surface (`bg-muted/30`), a hairline
`border-border` and `rounded-xl` — and so do a deleted comment's placeholder and a comment being
edited (the editor sits straight in the card, with no box inside the box). Replies are rows inside
their comment's card, flush with it: the same 28px avatar and name column, the body under the name.
A long name truncates. The card's border never
changes on hover or focus. Its hover actions sit at the card's top-right: the add-reaction button
and the ⋯ button, identical ghost `icon-sm` buttons, shown on hover or focus inside the comment,
kept while their popup is open, and always shown on touch screens.

Each comment is anchored at `#comment-<id>`. Pass that id as `highlightedId` to tint it and scroll
it into view. The ⋯ menu is sized to its content and shows Copy link (a link icon) when `onCopyLink`
is set, and Edit (a pencil) or Delete (a destructive trash can) when the comment's `canEdit` or
`canDelete` allows them. Delete calls `onDelete` at once, with no confirmation dialog: the host
removes the comment and offers Undo (a toast), which keeps a slip recoverable without a modal.

Reactions come from each comment's `reactions` and show as [`Reactions`](/docs/components/reactions)
pills under the body. With `onReactionToggle`, a pill click toggles and an "Add reaction" button
joins the hover actions, Slack style.

### Drafts

`defaultValue` restores text the viewer left behind. On `CommentComposer` the editor opens on it
with Send enabled, and after a successful post the box starts empty (`onValueChange("")` fires).
On `CommentThread`, `composer={{ defaultValue }}` opens the reply box on the draft;
`composer.onValueChange` reports every change and `""` once the reply posts, and
`composer.posting` holds the box busy — Send shows its spinner and neither it nor

<kbd>Cmd/Ctrl</kbd>+<kbd>Enter</kbd> sends — while the host finishes an upload
in the box. An edit draft is reported by `onEditValueChange(commentId, value)`
on `CommentItem`, `CommentList` and `CommentThread`: the text on every change,
then `null` when the edit is saved or cancelled. Together they let a host keep
drafts and warn before unsaved text is lost.

To bring an edit back after a remount (a route hidden and shown again), control which comment is
being edited with `editingId` and `onEditingIdChange` on `CommentList` or `CommentThread`, and hand
the saved text back through `editDefaultValue(commentId)`: that comment mounts in editing mode with
its box on the restored text, and Save is enabled while it differs from the body. On a single
`CommentItem` the same text is its `editDefaultValue`. Without `onEditingIdChange` each comment
keeps its own editing state, as before.

### Threads

`CommentThread` is one discussion about a piece of text, the way Google Docs shows it beside the
page: the quoted words (a button when `onQuoteClick` is set, to find the highlight), the first
comment, its replies, and the one-line "Write a reply…" box
(<kbd>Cmd/Ctrl</kbd>+<kbd>Enter</kbd> sends; the box clears when `onReply` resolves and keeps the
text when it rejects). ✓ in the header calls `onResolve`. Pass `composer` to give the reply box
`mentions`, `mentionHref` and uploads, and `renderAttachments` to show each comment's files.
`active` lifts the card beside its highlight. Lay threads beside the text with
[`CommentMargin`](/docs/components/comment-margin).

#### Resolved, orphaned and collapsed

A resolved thread says who resolved it and when, and offers Reopen (`onReopen`). An `orphaned`
thread — its text was deleted — says "Original text was removed" instead of the quote. `collapsed`
shows the first comment, "N replies" (a button with `onExpand`) and the last reply, with no reply
box.

### Mentions, uploads and attachments

`CommentComposer` passes `mentions`, `mentionHref`, `onImageUpload`, `onFileUpload` and
`onUploadError` to its editor, exactly as on [`TextEdit`](/docs/components/text-edit).
`CommentItem`'s `attachments` renders under the body — an `AttachmentGroup layout="list"` of the
comment's files — and its `mentionHref` links the mention chips in the body. Pass `mentionHref` to
`CommentList` and it reaches every comment in the list; without it the chips are plain labels.

## Accessibility

- The section is labelled by its heading. The comments are a list, and replies are a nested list
  named "Replies".
- Each comment's ⋯ trigger is named for its author ("Actions for comment by Asha Rao").
- The relative time shows the exact time on hover or focus. "edited" does the same with the edit
  time.
- Errors are announced with `role="alert"`.
- Reaction pills are toggle buttons (`aria-pressed`) named with the emoji and count.
- A thread is an `article` named for its first comment's author; its ✓ is a button named
  "Resolve", and the reply box is a textbox named "Reply".

| Key                               | Action                            |
| --------------------------------- | --------------------------------- |
| <kbd>Cmd</kbd> + <kbd>Enter</kbd> | Send the comment, or save an edit |
| <kbd>Esc</kbd>                    | Cancel an edit                    |
