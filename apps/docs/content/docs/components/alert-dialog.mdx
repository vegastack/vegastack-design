## Usage

```tsx
import {
  AlertDialog,
  AlertDialogAction,
  AlertDialogCancel,
  AlertDialogContent,
  AlertDialogDescription,
  AlertDialogFooter,
  AlertDialogHeader,
  AlertDialogTitle,
  AlertDialogTrigger,
} from "@/components/ui/alert-dialog";

<AlertDialog>
  <AlertDialogTrigger render={<Button variant="outline" />}>
    Show Dialog
  </AlertDialogTrigger>
  <AlertDialogContent>
    <AlertDialogHeader>
      <AlertDialogTitle>Are you absolutely sure?</AlertDialogTitle>
      <AlertDialogDescription>
        This action cannot be undone. This will permanently delete your account
        from our servers.
      </AlertDialogDescription>
    </AlertDialogHeader>
    <AlertDialogFooter>
      <AlertDialogCancel>Cancel</AlertDialogCancel>
      <AlertDialogAction>Continue</AlertDialogAction>
    </AlertDialogFooter>
  </AlertDialogContent>
</AlertDialog>;
```

## Examples

### Composition

`AlertDialogContent` renders the portal and the backdrop itself. `AlertDialogMedia` is optional and
sits first in the header; the footer carries exactly two controls, in that order.

```text
AlertDialog
├── AlertDialogTrigger
└── AlertDialogContent
    ├── AlertDialogHeader
    │   ├── AlertDialogMedia
    │   ├── AlertDialogTitle
    │   └── AlertDialogDescription
    └── AlertDialogFooter
        ├── AlertDialogCancel
        └── AlertDialogAction
```

### Basic

A title, a description, and the cancel/continue pair. `AlertDialogCancel` is a `Button` with the
`outline` variant that also closes the dialog; `AlertDialogAction` is a plain `Button`, so the

### Destructive

`AlertDialogAction` forwards every `Button` prop, so a destructive confirmation is
`variant="destructive"` on the action — never a colour written onto the footer. Tint the media tile
to match and keep the cancel control visually quieter.

### RTL

The header's `text-start` and the media tile's column are logical, and the centring translate
carries an explicit `rtl:` counterpart, so a right-to-left document mirrors the surface without a
second layout. Wrap the subtree in `DirectionProvider` so Base UI agrees with the document's `dir`,
and hand `dir` to `AlertDialogContent` — the popup portals to `<body>`, so a `dir` on an ancestor of
the trigger never reaches it.

## API Reference

`AlertDialog`, `AlertDialogTrigger`, `AlertDialogPortal`, `AlertDialogOverlay`,
`AlertDialogHeader`, `AlertDialogMedia`, `AlertDialogTitle` and `AlertDialogDescription` add no
props of their own. `AlertDialogAction` is a `Button` and accepts every `Button` prop, `variant`
and `size` included.

The root takes no `modal` prop: Base UI's AlertDialog omits it, so an alert dialog is always modal.

## Accessibility

- Renders Base UI's AlertDialog: the popup is `role="alertdialog"` with `aria-modal`, named by
  `AlertDialogTitle` through `aria-labelledby` and described by `AlertDialogDescription` through
  `aria-describedby`. Focus moves into the popup and returns to the trigger on close.
- Dismissal is deliberate: clicking the backdrop does not close an alert dialog. <kbd>Esc</kbd>
  still does, and it is treated as a cancel, so give it a real `AlertDialogCancel` to land on.
- The background is made natively inert while the popup is open (A11Y-9), not merely focus-trapped;
  the hook restores each element's previous value once the last modal releases it.
- The popup portals to `<body>`, so `AlertDialogPortal` re-applies the enclosing theme scope on a
  `display: contents` host inside the portal (OVL-13).
- The icon in `AlertDialogMedia` is decorative — the title and description carry the meaning, so
  the destructive intent is never signalled by the tile's colour alone.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/alert-dialog.patch`. Every hunk:

- **OVL-13** — `AlertDialogPortal` reads `useInternalThemeScope()` and wraps its children in a
  `display: contents` element carrying that class — the same host shape `dialog` uses.
- **A11Y-9** — `AlertDialogContent` mirrors Base UI's `data-base-ui-inert` markers onto native
  `inert` through `useModalInert`. No `modal` context here: Base UI's AlertDialog omits the `modal`
  prop from its root, so an alert dialog is always modal and the hook is always enabled.
- **DOC-2** — `import { cn } from "cn"` becomes `@vegastack/design`; our npm layer owns `cn`.
- **DOC-1** — prettier reflow plus the `registry-stamp.mjs` provenance header; no decision of their
  own.
