## Usage

For stable relative text from the first render, pass a request timestamp with the timezone:
`<TimeZoneProvider timeZone={zone} referenceNow={requestNow}>`. Serialize the same numeric
`requestNow` into the client tree. Uncontrolled timestamps then share one live clock; passing
`now` directly remains a controlled clock. Without a request reference, the server renders a
clock-free absolute date ("Sep 25", "Sep 25 · 2:30 PM", "Due Sep 30"), so crawlers and no-JS HTML
keep the date; the browser then switches to the relative words.

```tsx
import {
  DateTime,
  DueLabel,
  Duration,
  RelativeTime,
} from "@/components/ui/relative-time";
import { formatDate, formatRelative, groupByDay } from "@/lib/date-time";

<RelativeTime date={row.updatedAt} format="minimal" />; // "2m"
<DateTime date={task.createdAt} />; // "Sep 25"
<DueLabel date={task.dueAt} />; // "Overdue 2d"
formatRelative(row.updatedAt, { timeZone }); // plain string, server or client
```

The formatting functions live in `@/lib/date-time` and are plain — call them in server components,
route handlers, emails and client code alike. The components wrap them in a semantic `<time>` and
add the absolute time in a hover tooltip ("Sep 25, 2026 · 2:30 PM IST").

### Shared rules

- The year shows only when it is not the current year.
- 12-hour clock with no leading zero: "9:04 AM".
- Minimal units `s` `m` `h` `d` `w` `mo` `y`, no space before the unit.
- Calendar days use the viewer's time zone (`timeZone` option on every function).
- Anything under 45 seconds reads "now".
- Built on `Intl`, locale-ready; English for now.
- Set in the body font with proportional figures, like the text around them. Tabular figures are
  for live timers (the media player's clock), not for dates.

### Where to use what

| Surface                                  | Use                                                         | Reads                                               |
| ---------------------------------------- | ----------------------------------------------------------- | --------------------------------------------------- |
| Table columns (updated, last activity)   | `formatRelative` / `<RelativeTime format="minimal">`        | now · 2m · 3h · 5d                                  |
| Table columns (created, due, start date) | `formatDate` / `<DateTime>`                                 | Today · Mon · Sep 25                                |
| Detail pages, audit rows                 | `formatDateTime` / `<DateTime variant="datetime">`          | Sep 25 · 2:30 PM                                    |
| Hover tooltips                           | `formatTooltip` (built into every component)                | Sep 25, 2026 · 2:30 PM IST                          |
| Notifications, feeds                     | `formatRelative` + `groupByDay` headers                     | 2m under "Today"                                    |
| Sentences                                | `formatRelative({ style: "suffix" })`, `separator: "comma"` | 2m ago · Sep 25, 2:30 PM                            |
| Due chips                                | `formatDueLabel` / `<DueLabel>`                             | Overdue 2d · Due today · Due Sep 30                 |
| Durations (meetings, audio, SLAs)        | `formatDuration` / `<Duration>`; `clock` for players        | 1h 15m · 1:15:04                                    |
| Durations in sentences and emails        | `formatDuration({ style: "long" })`                         | 1 hour 15 minutes · 7 days                          |
| Page headers, greetings                  | `formatLongDate`; `hourOfDay` for the greeting              | Thursday, September 24                              |
| Schedules, events                        | `formatDateRange`, `formatTimeOfDay`                        | Sep 25 · 2–3:30 PM                                  |
| Grouped lists (inbox, activity)          | `groupByDay`                                                | Today / Yesterday / This week / Last week / Earlier |
| API / JSON                               | ISO strings — never formatted text                          | 2026-09-25T09:00:00.000Z                            |

### Time zone

Day boundaries follow the viewer. Write the browser zone to a `tz` cookie, read it on the server
with the org zone from app config as the fallback, and provide it to the tree:

```tsx
// app/layout.tsx (server)
import { cookies } from "next/headers";
import {
  TimeZoneProvider,
  TimeZoneScript,
} from "@/components/ui/relative-time";
import { TIME_ZONE_COOKIE, getTimeZone } from "@/lib/date-time";
import { config } from "@/config";

const timeZone = getTimeZone(
  (await cookies()).get(TIME_ZONE_COOKIE)?.value,
  config.orgTimeZone,
);

<body>
  <TimeZoneScript />
  <TimeZoneProvider timeZone={timeZone} referenceNow={Date.now()}>
    {children}
  </TimeZoneProvider>
</body>;
```

`TimeZoneScript` writes the cookie on load and again when the tab becomes visible, so a changed
zone reaches the next request. Client code reads the zone with `useTimeZone()`; server code passes
`timeZone` to each function.

`RelativeTime` renders a semantic `<time dateTime>` element and self-updates on a
timer while the date is recent, with the exact date and time in the hover. It uses the
platform-native `Intl` APIs — no `date-fns` or other date dependency.

### RelativeTime formats

Past and future instants, in the house compact form: `now` under a minute, then `19m ago`,
`3h ago`, `2d ago`, `3w ago`, `5mo ago`, `1y ago`; future dates read `in 2d`. No unit carries a
period — the old Intl short style (`19 min. ago`) is gone.

#### Format variants

`format` picks the form of the `ago` label: `suffix` (the default, `19m ago`), `minimal` for dense
tables and chips (`19m`), and `long` for sentences (`19 minutes ago`). The deprecated `unitStyle`
maps `long` to `format="long"` and everything else to the default.

### Localization

`locale` localizes what `Intl` words: the `mode="day"` labels and dates and `format="long"`. The
compact `ago` form (`2h ago`) is the house form everywhere, so a dense column reads the same in
every locale. Without `locale` it formats in `DEFAULT_LOCALE` (`en-US`), never the runtime's: a
server under another `LANG` then renders the same text as the browser, so the page hydrates
without a mismatch. Pass the reader's locale explicitly to localize.

### Live updates

When `now` is left unset, timestamps subscribe to one shared ten-second clock, and each one
re-renders only when its own label can change: every tick within an hour of now, once a minute
within a day, and on quarter-hour boundaries beyond that (every real zone offset is a multiple of
15 minutes, so day words still flip at the viewer's midnight). A time of day and an `absolute` date
never subscribe. No per-row timers are allocated. The example below is intentionally **live** — it seeds a timestamp
30s in the past and climbs as you watch. Pass `refresh={false}` to opt out.

Application groups, due badges and date-picker presets can share that same clock through
`useDateTimeNow()`, exported by this registry item. It returns epoch milliseconds, or `undefined`
until hydration when no request reference was provided. With `TimeZoneProvider.referenceNow`,
server output and the hydration render receive the same reference. Keep a placeholder for a
missing reference; do not replace it with a separate `Date.now()` during rendering.

```tsx
import { DateTime, useDateTimeNow } from "@/components/ui/relative-time";

export function CurrentTime() {
  const nowMs = useDateTimeNow();
  return nowMs === undefined ? (
    <span>…</span>
  ) : (
    <DateTime date={nowMs} variant="time" />
  );
}
```

instances share one timer; a `RelativeTime now={...}` remains controlled.

### Determinism

The displayed value depends on the current time. For tests, SSR snapshots, or
Storybook, pass a fixed `now` (epoch ms) to render deterministically — this also
disables the refresh timer.

```tsx
<RelativeTime date={ts} now={Date.UTC(2026, 0, 15, 12, 0, 0)} refresh={false} />
```

### Server rendering

Pass a serialized request timestamp as `TimeZoneProvider.referenceNow` to render relative text
identically on the server and the hydration render. The shared clock then updates live labels.
Without that reference, the server renders the clock-free absolute date and the browser
replaces it with the relative label. `now` remains a controlled clock, and `refresh={false}`
freezes at mount time, never at an older request reference.

`DateTime` and `DueLabel` use the same request/live reference, so calendar words and due tones
update across midnight in the effective zone. `DateTime.options.now` is an explicit controlled
reference; `absolute`, `relativeDay` and other formatting choices retain their meanings.
Without a request reference, they render the clock-free absolute date (a time of day and an
`absolute` date are exact on the server). These components do not suppress hydration mismatches; absolute tooltip labels retain their full date,
time and zone.

## Accessibility

- Renders a semantic `<time dateTime="…">` so the machine-readable ISO timestamp is
  always present for assistive tech, even as the visible text updates.
- When the absolute-date Tooltip is enabled, the `<time>` is made focusable
  (`tabindex="0"`) so keyboard users can reveal it; `:focus-visible` shows a 2px ring
  (`outline-ring`) — never `outline: none` alone.
- Color is inherited from context — the component never encodes meaning in color, so
  the relative string stands on its own.

| Key            | Action                                                     |
| -------------- | ---------------------------------------------------------- |
| <kbd>Tab</kbd> | Move focus to the timestamp (when the tooltip is enabled). |
| <kbd>Esc</kbd> | Dismiss the open absolute-date tooltip.                    |

`focusable` controls whether the timestamp takes a tab stop to open its absolute-date
Tooltip. It defaults to `true` standalone, and to whatever an enclosing
`TruncationFocusProvider` sets — `false` for a grid or list host, where 50 rows would
otherwise mean 50 extra tab stops on top of that host's own roving focus. The
machine-readable `dateTime` attribute is there either way.
