## Usage

```tsx
import { Marker, MarkerContent, MarkerIcon } from "@/components/ui/marker";

<Marker>
  <MarkerIcon>
    <CheckIcon />
  </MarkerIcon>
  <MarkerContent>Explored 4 files</MarkerContent>
</Marker>;
```

`Marker` is the inline annotation in a conversation — a status update, a system note, a bordered
row, or a labelled divider. Compose it with [`Message`](/docs/components/message) in a thread.

### Features

- Inline marker, bordered row and labelled separator variants
- A decorative icon slot that is hidden from assistive tech
- A polymorphic root through `render`, for link and button markers
- Pairs with the `shimmer` utility for streaming status text
- Customizable styling through the `className` prop on every part

### Variants

Use `variant` to switch between an inline marker, a bordered row and a labelled separator.

| Variant     | Description                                          |
| ----------- | ---------------------------------------------------- |
| `default`   | An inline marker for status, notes and actions.      |
| `border`    | A default marker with a bottom border under the row. |
| `separator` | A centred label with divider lines on each side.     |

## Accessibility

`Marker` is presentational by default, and the correct semantics depend on how you use it. Choose
the role from intent rather than relying on one default.

- **Status and progress.** For a streaming or progress marker — "Thinking…", a running tool — set
  `role="status"` so assistive tech announces the update as it appears. `Marker` forwards `role` to
  the underlying element.
- **Labelled separators.** A separator carrying text needs no role: the divider lines are
  decorative CSS pseudo-elements and the text is announced as ordinary content. Do **not** add
  `role="separator"` — a separator takes its name from `aria-label`, its contents are treated as
  presentational, and the visible label would stop being announced.
- **Bordered markers** keep the default marker's semantics. The bottom border is decorative, so
  pick `role="status"`, `render`, or no role from the marker's purpose.
- **Decorative icons.** `MarkerIcon` is `aria-hidden`, so `MarkerContent` carries the meaning. An
  icon-only marker needs a name of its own — put it on an element that can hold one (`role="img"`
  plus `aria-label`), because `aria-label` on a bare `<div>` is prohibited.
- **Interactive markers.** When a marker links or triggers an action, render it as a real `<a>` or
  `<button>` through `render`, so it is focusable and exposes the right role. The accessible name
  comes from the marker text — and the pointer target is grown to 24px by the hit area described
  under **Deviations**.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/marker.patch`. Every hunk:

- **A11Y-2** — `markerVariants`' base string gains an invisible `::after` hit area
  (`after:absolute after:inset-x-0 after:-inset-y-1 after:content-['']`), scoped to `[a,button]:`.
  Upstream's own **Links and Buttons** section renders the marker root as an `<a>` or a `<button>`
  through `render`; the row is then one line of 14px text over `min-h-4`, which measures 20px — 4px
  under SC 2.5.8 — and a marker row is a control rather than prose, so the inline-text exception
  does not reach it. The area grows the block axis only, so two stacked markers never fight for a
  pixel, and it is scoped to the interactive spellings, so a presentational marker is byte-identical
  to upstream. An `::after` with no background paints nothing. `marker.test.tsx` measures both
  shapes.
- **Nothing else.** Upstream's marker paints no focus glow, sets no cursor, disables nothing and
  opens no portal; `MarkerIcon` is already `aria-hidden`.
- **API-16** — `"use client"` is added. Upstream ships none, and this file calls `useRender`, which
  calls `React.useRef` internally; under the `react-server` condition that hook is `undefined`, so a
  server component rendering it throws on import. The boundary goes at the lowest interactive leaf,
  and this file is it.
- **DOC-2** — `import { cn } from "cn"` becomes `@vegastack/design`; our npm layer owns `cn`.
- **DOC-1** — prettier reflow plus the `registry-stamp.mjs` provenance header the three-copy model
  needs; no decision of its own.
