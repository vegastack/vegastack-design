## Usage

```tsx
import {
  Inbox,
  InboxEmphasis,
  InboxFilters,
  InboxGroup,
  InboxItem,
  InboxMarkAllRead,
} from "@/components/ui/inbox";

<Inbox
  onClose={close}
  actions={<InboxMarkAllRead onClick={markAllRead} />}
  filters={
    <InboxFilters
      value={tab}
      onValueChange={setTab}
      unreadOnly={unreadOnly}
      onUnreadOnlyChange={setUnreadOnly}
      unreadCount={3}
    />
  }
  activeId={peekId}
  onActiveChange={setPeekId}
  onOpen={setPeekId}
  onLoadMore={loadOlder}
  hasMore={hasMore}
  loadingMore={loadingOlder}
>
  <InboxGroup label="Today">
    <InboxItem
      value="task-39"
      unread
      icon={<SquareCheck />}
      title={<InboxEmphasis>#39 Agent link RCA test</InboxEmphasis>}
      actors={[sanjay, arjun]}
      count={9}
      events={latestEvents}
      meta="Sanjay commented"
      time={updatedAt}
      href="/tasks/39"
      onToggleRead={toggleRead}
      menu={rowMenu}
    />
  </InboxGroup>
</Inbox>;
```

### When to use

- **Use it** for the notifications panel: one row per record with its latest events (someone
  assigned, mentioned or asked you; an agent needs you; a meeting processed, an export finished),
  plus requests you answer inline, which the user reads, acts on, triages and marks read.
- `Inbox` fills its container. Dock it in a `Sheet`, a `Popover` or a panel beside the sidebar; on a
  phone give that container the whole screen. With `onOpen`, rows open in the host's peek beside it
  and the Inbox stays open.
- **Don't use it** for transient confirmations (Toast), a record's history (Activity Feed), or a bare
  unread count in the chrome (NotificationBell).

## Anatomy

<Anatomy name="inbox" />

- `Inbox` — the frame: title, header actions (`InboxMarkAllRead`, `InboxMenuAction`, any
  `InboxHeaderAction`), the ✕ when `onClose` is set, the `filters` row, a scrolling body and a `footer`
  — or, with `onLoadMore`, the infinite-scroll end. `activeId` / `onActiveChange` / `onOpen` drive
  triage.
- `InboxFilters` — tabs (For you · Updates · Archived unless you pass `tabs`, each with an optional
  count) and, at the end, an Unread toggle that filters whichever tab is open.
- `InboxGroup` — a label that sticks within the scroll area, with no divider above or below it
  (16px above, except on the first group; 6px below), over a list it names. `InboxList` is the ungrouped list.
- `InboxItem` — one row. Title 14px regular — foreground when unread, muted once read — with the actor and
  record (`InboxEmphasis`) in medium; a dot in the start gutter and the tint mark unread, a 2px start
  bar the active row. An optional `badge` glyph on the avatar's corner names the kind of event. Under
  the title, `meta` (12px muted — a grouped row's latest event), then a line with the stacked `actors`
  and the `count` ("9 updates", a disclosure for the `events` behind it), then the inline `actions`,
  or the `answeredLabel` once a request is answered. 16px sides and 12px vertical padding; a 1px divider between rows only, and a
  tint, reaching both edges. The ⋯ menu sizes to its content (224–320px).
- `InboxEmpty`, `InboxSkeleton`, `InboxError` — the empty, first-load and failed-load states.

## Examples

### Grouped rows, requests and triage

One row per record: give it the record's `icon`, its latest event as `meta`, everyone involved as
`actors` (three avatars, then "+n") and how many events it stands for as `count`. Pass the `events`
themselves and the count becomes a disclosure that lists them under the row. A request carries
`status`: `pending` shows its inline Allow / Decline (`actions`), `answered` replaces them with the
`answeredLabel` line ("Granted by Sanjay · 5d"). The ⋯ `menu` holds the host's items — Archive,
Mark unread, Unwatch, Mute this type. Give each row a `value`, then J / K (or ↓ / ↑) walk the rows:
the active row gets a start bar, focus follows and `onActiveChange` reports it; Enter or a click calls
`onOpen` without navigating, so the host's peek opens beside the Inbox.

### Grouped events

you 3 tasks").

### Infinite scroll

Pass `onLoadMore`, `hasMore` and `loadingMore`: a sentinel under the last row calls `onLoadMore` as
it nears the viewport (page 15 rows at a time). While a page loads, three skeleton rows stand in —
no spinner. Set `loadMoreError` after a failure to show a ghost **Try again**, and `hasMore={false}`
ends the list on "You’re all caught up".

### Tabs and the Unread toggle

`tabs` replaces For you · Updates · Archived with your own — each `{ value, label, count? }` — and
`onValueChange` receives the tab's `value`. Unread is a separate toggle (`unreadOnly`,
`onUnreadOnlyChange`, `unreadCount`), so it filters any tab; it shows only when
`onUnreadOnlyChange` is set. Filtering the rows stays with the app.

```tsx
<InboxFilters
  value={tab}
  onValueChange={setTab}
  tabs={[
    { value: "for-you", label: "For you", count: 4 },
    { value: "mentions", label: "Mentions", count: 2 },
    { value: "updates", label: "Updates" },
  ]}
  unreadOnly={unreadOnly}
  onUnreadOnlyChange={setUnreadOnly}
  unreadCount={3}
/>
```

## Accessibility

| Key          | Action                                                                            |
| ------------ | --------------------------------------------------------------------------------- |
| J / ↓        | The next row: focus moves to it, it becomes active and `onActiveChange` fires     |
| K / ↑        | The previous row (K with none active starts from the last)                        |
| Enter        | Opens the focused row (`onOpen`, or its link when there is no `onOpen`)           |
| Tab          | Each row's link, its count disclosure, its chips and its hover controls, in order |
| ← / → (tabs) | Move between the filter tabs                                                      |

- Each group is a list named by its label; the whole row is one link (`href`, or your router link
  through `linkRender`), and the chips, the count disclosure and the hover controls sit above it.
- A row without `href` but with `onOpen` gets its title as a button (Enter or Space opens it). The
  active row's link or button (or the row itself, when it has neither) carries `aria-current="true"`.
  J / K also work inside a `Sheet` holding the Inbox. J / K are
  ignored while typing in a field or inside a menu; ↓ / ↑ walk only from inside the list.
- The count is a button with `aria-expanded` and `aria-controls` naming the events list; the stacked
  avatars are decorative, and an sr-only line reads everyone's names.
- The hover controls are always in the tab order and show on `focus-within`; on touch screens they
  are always visible.
- An unread row carries a dot, a soft tint and an sr-only "Unread:" before its title; the dot and the `badge` are decorative (`aria-hidden`), so the title must say what happened.
- The header icon buttons are named by their tooltips; the tabs are a named tab list and Unread a
  pressed-state toggle.

## Do / Don't

<DoDont
  do="Group one record's events into one row — its latest event as meta, the actors stacked, the count expanding to the events."
  dont="Show one row per event, so one busy record fills the panel with near-identical rows."

<DoDont
  do="Open rows in a peek beside the Inbox with onOpen, so J / K triage keeps going."
  dont="Put more than three action chips on a row, or leave an answered request's Allow / Decline in place — set status to answered."
/>
