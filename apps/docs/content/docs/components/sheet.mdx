## Usage

```tsx
import {
  Sheet,
  SheetClose,
  SheetContent,
  SheetDescription,
  SheetFooter,
  SheetHeader,
  SheetTitle,
  SheetTrigger,
} from "@/components/ui/sheet";

<Sheet>
  <SheetTrigger>Open</SheetTrigger>
  <SheetContent>
    <SheetHeader>
      <SheetTitle>Are you absolutely sure?</SheetTitle>
      <SheetDescription>This action cannot be undone.</SheetDescription>
    </SheetHeader>
  </SheetContent>
</Sheet>;
```

## Examples

### Composition

A Sheet is Base UI's Dialog with edge-anchored positioning, so the tree is the Dialog tree.
`SheetContent` is a flex column and `SheetFooter` carries `mt-auto`, which is what pins the footer
to the bottom of the panel however little content sits above it.

```text
Sheet
├── SheetTrigger
└── SheetContent
    ├── SheetHeader
    │   ├── SheetTitle
    │   └── SheetDescription
    └── SheetFooter
```

<ComponentPreview name="sheetComposition" file="components/preview/sheet.tsx" />

### Side

`side` on `SheetContent` — `top`, `right` (the default), `bottom` or `left` — picks the edge. It is
published as `data-side` and every inset, border, width cap and slide offset is a
`data-[side=…]` branch on that one attribute, so there is no second class list to keep in step. The
left and right panels cap at `sm:max-w-sm`; top and bottom size to their content unless you cap
them.

<ComponentPreview name="sheetSide" file="components/preview/sheet.tsx" />

### No Close Button

`showCloseButton={false}` on `SheetContent` removes the corner close control. Nothing else replaces
it, so give the panel its own way out — a `SheetClose` in the footer.

  name="sheetNoCloseButton"

### RTL

The panel's borders and its close button are written in logical properties, and each slide offset
carries an explicit `rtl:` counterpart, so a right-to-left document mirrors the motion as well as
the layout. Mirror the anchor too: a panel that opens from `right` in a left-to-right document opens
from `left` in a right-to-left one. And hand `dir` to `SheetContent` — the panel portals to
`<body>`, so a `dir` on an ancestor of the trigger never reaches it.

`SheetTrigger`, `SheetClose`, `SheetHeader`, `SheetFooter`, `SheetTitle` and `SheetDescription` add
no props of their own — each accepts everything its Base UI part or its `div` accepts. The portal
and the backdrop are internal to `SheetContent` and are not exported.

## Accessibility

- Renders Base UI's Dialog: the panel is `role="dialog"` with `aria-modal`, named by `SheetTitle`
  through `aria-labelledby` and described by `SheetDescription` through `aria-describedby`.
  <kbd>Esc</kbd> closes, focus is trapped in the panel and returned to the
  trigger.
- Give every sheet a `SheetTitle`. Without one the panel has no accessible name; if it must not be
  seen, keep it and add `className="sr-only"`.
- The background is made natively inert while the panel is open (A11Y-9). With `modal={false}` on
  the root nothing is made inert, so the page behind stays interactive — that is the mode's point.
- The panel portals to `<body>`, so `SheetPortal` re-applies the enclosing theme scope on a
  `display: contents` host inside the portal (OVL-13).
- The corner close button is an icon-only `Button` carrying a `sr-only` "Close" label.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/sheet.patch`. Every hunk:

- **OVL-13** — `SheetPortal` reads `useInternalThemeScope()` and wraps its children in a
  `display: contents` element carrying that class.
- **A11Y-9** — `SheetContent` mirrors Base UI's `data-base-ui-inert` markers onto native `inert`
  through `useModalInert`, gated on the root's `modal` prop published through a context — the same
  pair `dialog` carries, because upstream's Sheet is Base UI's Dialog.
- **DOC-2** — `import { cn } from "cn"` becomes `@vegastack/design`; our npm layer owns `cn`.
- **DOC-1** — prettier reflow plus the `registry-stamp.mjs` provenance header; no decision of their
  own.
