```tsx
  SheetContent,
  SheetDescription,
  SheetFooter,
  SheetHeader,

  </SheetContent>
</Sheet>;
```

## Examples

### Composition

A Sheet is Base UI's Dialog with edge-anchored positioning, so the tree is the Dialog tree.
`SheetContent` is a flex column and `SheetFooter` carries `mt-auto`, which is what pins the footer
to the bottom of the panel however little content sits above it.

```text
Sheet
├── SheetTrigger
└── SheetContent
    ├── SheetHeader
    │   ├── SheetTitle
    │   └── SheetDescription
    └── SheetFooter
```

<ComponentPreview name="sheetComposition" file="components/preview/sheet.tsx" />

### Side

`side` on `SheetContent` — `top`, `right` (the default), `bottom` or `left` — picks the edge. It is
published as `data-side` and every inset, border, width cap and slide offset is a
`data-[side=…]` branch on that one attribute, so there is no second class list to keep in step. The
left and right panels cap at `sm:max-w-sm`; top and bottom size to their content unless you cap
them.

### No Close Button

`showCloseButton={false}` on `SheetContent` removes the corner close control. Nothing else replaces
it, so give the panel its own way out — a `SheetClose` in the footer.

### RTL

The panel's borders and its close button are written in logical properties, and each slide offset
carries an explicit `rtl:` counterpart, so a right-to-left document mirrors the motion as well as
the layout. Mirror the anchor too: a panel that opens from `right` in a left-to-right document opens
from `left` in a right-to-left one. And hand `dir` to `SheetContent` — the panel portals to
`<body>`, so a `dir` on an ancestor of the trigger never reaches it.

<ComponentPreview name="sheetRtl" file="components/preview/sheet.tsx" />

### Sizes

`size` on `SheetContent` steps a left or right sheet through Dialog's own width scale (OVL-16), so
`size="lg"` is the same cap on either overlay: `sm` (`max-w-xs`), `default` (`max-w-sm`, upstream's
width), `lg` (`max-w-2xl`) and `xl` (`max-w-5xl`), from the `sm` breakpoint up. The value is
published as `data-size`. Below `sm` a side sheet is full width whatever its size, and from `sm` up
it is three quarters of the viewport under that cap, so a quarter of the page always shows beside
it and `xl` reaches its full 64rem only from a 1366px viewport (960px at 1280px). Top and bottom
sheets ignore the axis.

<ComponentPreview name="sheetSizes" file="components/preview/sheet.tsx" />

### Scrolling body

Put long content in `SheetBody`. It is the one scroller in the panel's flex column
(`min-h-0 flex-1 overflow-y-auto`), so the header stays at the top and the footer's actions stay on
screen however many fields sit between them. It carries the panel's `px-4` inset itself.

<ComponentPreview
  name="sheetScrollingBody"
  file="components/preview/sheet.tsx"
/>

### Header action

`SheetAction` seats one control at the end of `SheetHeader`, beside the title and description, and
reserves the corner close button's width so the two never meet. `closeLabel` on `SheetContent`
renames that close button — here "Close invoice" instead of the default "Close".

`SheetContent` adds `size` (`"sm" | "default" | "lg" | "xl"`, default `"default"`; side sheets
only), `closeLabel` (the corner close button's name, default `"Close"`) and `showOverlay`
(default `true`; `false` drops the dimmed backdrop for a non-modal panel docked beside the page).

`SheetTrigger`, `SheetClose`, `SheetHeader`, `SheetAction`, `SheetBody`, `SheetFooter`,
`SheetTitle` and `SheetDescription` add no props of their own — each accepts everything its Base UI part or its `div` accepts. The portal
and the backdrop are internal to `SheetContent` and are not exported.

## Accessibility

- Renders Base UI's Dialog: the panel is `role="dialog"` with `aria-modal`, named by `SheetTitle`
  through `aria-labelledby` and described by `SheetDescription` through `aria-describedby`.
  <kbd>Esc</kbd> closes, focus is trapped in the panel and returned to the
  trigger.
- Give every sheet a `SheetTitle`. Without one the panel has no accessible name; if it must not be
  seen, keep it and add `className="sr-only"`.
- The background is made natively inert while the panel is open (A11Y-9). With `modal={false}` on
  the root nothing is made inert, so the page behind stays interactive — that is the mode's point.
- The panel portals to `<body>`, so `SheetPortal` re-applies the enclosing theme scope on a
  `display: contents` host inside the portal (OVL-13).
- The corner close button is an icon-only `Button` carrying a `sr-only` label, "Close" unless
  `closeLabel` names it.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/sheet.patch`. Every hunk:

- **OVL-13** — `SheetPortal` reads `useInternalThemeScope()` and wraps its children in a
  `display: contents` element carrying that class.
- **A11Y-9** — `SheetContent` mirrors Base UI's `data-base-ui-inert` markers onto native `inert`
  through `useModalInert`, gated on the root's `modal` prop published through a context — the same
  pair `dialog` carries, because upstream's Sheet is Base UI's Dialog.
- **OVL-16** — `SheetContent` takes `size?: "sm" | "default" | "lg" | "xl"` and reflects it as
  `data-size`; a left or right sheet steps Dialog's scale (`sm:max-w-xs` · `sm:max-w-sm` ·
  `sm:max-w-2xl` · `sm:max-w-5xl`), top and bottom ignore it, and below `sm` a side sheet is full
  width. Widened from Dialog by MK 2026-09-24.
- **API-21** — `SheetBody` scrolls between the header and the footer; `SheetAction` is an end seat
  in `SheetHeader` that clears the close button; `closeLabel` renames the corner close control.
- **VOI-1** — the corner close's built-in string is the overridable `closeLabel`, default "Close".
- **DOC-2** — `import { cn } from "cn"` becomes `@vegastack/design`; our npm layer owns `cn`.
- **DOC-1** — prettier reflow plus the `registry-stamp.mjs` provenance header; no decision of their
  own.
