## Accessibility

- The group is a `role="group"`; the control inside it keeps every native semantic, so labelling is
  the control's job, exactly as for a bare `Input`.
- Clicking an addon focuses the control, unless the click landed on a button inside it.
- The **group** carries the focus affordance: while its input or textarea has focus, the group's
  border darkens subtly (`border-ring/40`, easing in over 150ms) — text entry's exception to FOC-14
  (MK 2026-09-27). No background changes, on the group or on the control inside it (which has no
  border and no fill), and there is no ring anywhere. An invalid group keeps its destructive border
  while focused. An addon button is a button: its own focus keeps the global background tint.
- Under `forced-colors: active` the group (`data-field-group`) carries the outline and the control
  inside stands down, so the two never paint a double ring (FOC-7).
- Give every icon-only `InputGroupButton` an `aria-label` or an `sr-only` label; the design lint
  fails a nameless one.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/input-group.patch`. Every hunk:

- **FOC-1, FOC-3, FOC-6** — the group's
  `has-[[data-slot=input-group-control]:focus-visible]:border-ring` plus `ring-3 ring-ring/50`
  is removed, and the group gains `data-field-group`, which the forced-colours fallback keys on.
  There is no ring and no glow.
- **FRM-16** — the `inline-start` and `inline-end` addons add
  `group-has-[>textarea]/input-group:self-start` and `pt-2.5`, so beside a textarea they sit
  level with the first line instead of the textarea's middle.
- **FOC-14** — the invalid border is `has-[[data-slot][aria-invalid=true]]:border-destructive`,
  held in every state, focused or not; the `has-aria-invalid` halo rings go with it.
- **FOC-14 text-entry exception (MK 2026-09-27)** — the group adds
  `has-[input:focus,textarea:focus]:not-has-aria-invalid:border-ring/40` with
  `transition-[color,background-color,border-color] duration-150 ease-out`: a subtle darker border
  on the GROUP that eases in while its control has focus — `[data-slot=command-input]` and the
  popup search rows included — and no fill anywhere (`base.css` excludes text inputs and `textarea`
  from the background tint). The `not-has-aria-invalid` guard keeps the destructive border; an addon
  button's focus keeps the tint.
- **FOC-6** — `InputGroupInput` and `InputGroupTextarea` drop `ring-0 focus-visible:ring-0
aria-invalid:ring-0`, which existed only to cancel the ring `Input` and `Textarea` no longer have.
- **API-26** — NO HUNK: `InputGroupInput` renders `Input` and `InputGroupTextarea` renders
  `Textarea`, both Base UI `Field.Control`s, so inside a `Field` they take their label, description
  and error ids and `aria-invalid` from it.
- **DOC-2** — `cn` is imported from `@vegastack/design`.
