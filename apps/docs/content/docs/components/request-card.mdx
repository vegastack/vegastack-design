## Usage

```tsx
import { RequestCard } from "@/components/ui/request-card";

<RequestCard
  spec={request.card}
  state={request.state}
  answeredBy={request.answeredBy}
  answeredVia={request.answeredVia}
  busy={pending}
  onAllowOnce={() => answer({ kind: "once" })}
  onAlways={(option) => answer({ kind: "always", scope: option.scope })}
  onDecline={(note) => answer({ kind: "decline", note })}
  onNever={() => answer({ kind: "never" })}
  onRevoke={() => revoke(request.permissionId)}
  onDoItNow={() => doItNow(request.id)}
/>;
```

The props are data only. `spec` is the `CardSpec` the server stores with each request
(`agent_requests.card`), the same JSON the Slack blocks and the phone's sheet draw, and `state` is
its `CardState`. Render times for the viewer before they reach the card ("From the 09:46 run ·
asked 2 min ago"). The host owns the request: it sets `busy` while an answer is on its way and
passes the new `state` back, with who answered (`answeredBy`: "you" or a name) and where
(`answeredVia`: `web`, `phone` or `slack`). A lost race shows its own words through `statusText`
("Already answered by Priya").

The agent's face is `spec.agent`: `avatar` is an image URL, and an agent without one passes its own
glyph and colour as `mark` and `hue` (the same fields as a `Person`; `mark` wins over `avatar`), so the card shows the face
every other surface does rather than the fallback bot. A glyph is a React node, so the host adds it
when it renders the stored spec.

## Scope

- **One card for every request**: posting, sending, sharing, opening a site, moving records. The
  same three answers everywhere: Allow once · Always allow ▾ · Decline ▾.
- **Always allow** saves the exact place from its main button ("Always allow in #ops"); its menu
  adds one step wider and, in a chat, "Allow for this chat". The options come from
  `spec.answers.always`, narrowest first; `null` offers no Always.
- **Decline** declines; its menu writes a note for the agent, or says "Never allow this" when
  `spec.answers.never` is set.
- **Neither Allow once nor Always is styled primary**, so a click-through is never the easy path.
- A **hard-rule** request (`spec.hard`) shows Allow once and Decline only, and the badge "Always
  asks".
- A **bundle** is a run's requests together: Allow all once · Always allow these · Review each ·
  Decline all.
- `compact` is one row for Home and Inbox: the title, where it came from and the buttons.
- `PermissionList` and `PermissionRow` are **What I've allowed**: each standing answer with how often
  it was used, why it's paused, and Revoke, or Undo for a Never.

| `CardState`      | The line                                      | Action    |
| ---------------- | --------------------------------------------- | --------- |
| `pending`        | the answers (or "Waiting for Manoj's answer") |           |
| `allowed_once`   | ✓ Allowed once by Priya from Slack            |           |
| `allowed_always` | ✓ Always allowed by you                       | Revoke    |
| `declined`       | Declined by Priya                             |           |
| `never`          | Never: set by you                             | Undo      |
| `skipped`        | Skipped: no answer in 24 h                    | Do it now |
| `expired`        | Expired: no answer in 7 days                  |           |
| `refused`        | Not allowed: a workspace rule blocks this     |           |
| `withdrawn`      | Withdrawn: a new message was sent             |           |
| `cancelled`      | Cancelled: the agent was archived             |           |

`CardPreview` is one of `quote` (text it would send), `recipients`, `items` (records, a move's linked
items included), `file`, or `from_to` (something it would make visible more widely).

## Accessibility

- The card is a region named by its title ("Inbox assistant wants to post in #ops"); every answer
  button is described by the same title.
- The menus are `DropdownMenu`s: their triggers are named "More ways to always allow" and "More ways
  to decline".
- An answer that settles while the card is on screen is announced politely; the first paint is not.
- Status is never colour alone: each settled line is a sentence with its icon.

| Key                                 | Action                                      |
| ----------------------------------- | ------------------------------------------- |
| <kbd>Tab</kbd>                      | Move through the answers and menu triggers. |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Answer, or open a menu.                     |
| <kbd>↑</kbd> / <kbd>↓</kbd>         | Move through a menu's options.              |
| <kbd>Esc</kbd>                      | Close a menu.                               |
