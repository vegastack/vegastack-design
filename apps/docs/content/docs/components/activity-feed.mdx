## Usage

```tsx
import {
  ActivityEvent,
  ActivityFeed,
  ActivityFeedItem,
  ActivityFeedList,
  ActivityJumpToLatest,
  ActivityKindIcon,
  ActivityUnreadDivider,
  ActivityValue,
  useActivityFeedKeyboard,
} from "@/components/ui/activity-feed";
import { CommentComposer, CommentThread } from "@/components/ui/comments";

const feedRef = useActivityFeedKeyboard();

<ActivityFeed
  ref={feedRef}
  count={threads.length}
  filter={filter}
  onFilterChange={setFilter}
  order={order}
  onOrderChange={setOrder}
>
  <ActivityFeedList>
    {items.map((item) =>
      item.type === "event" ? (
        <ActivityFeedItem key={item.id}>
          <ActivityEvent
            actor={item.actor}
            icon={<ActivityKindIcon kind={item.kind} />}
            date={item.at}
          >
            changed status to <ActivityValue>{item.to}</ActivityValue>
          </ActivityEvent>
        </ActivityFeedItem>
      ) : (
        <ActivityFeedItem key={item.id} kind="thread">
          <CommentThread thread={item.thread} viewer={me} onReply={reply} />
        </ActivityFeedItem>
      ),
    )}
  </ActivityFeedList>
  <CommentComposer onSubmit={post} />
  <ActivityJumpToLatest enabled={items.length > 3} />
</ActivityFeed>;
```

The parts are presentational and data-agnostic: the host merges its comment threads and its
change events into one list, applies the filter and the order, and pages them. Events sit 4px
apart; a thread card or a divider keeps 12px around it. Each event leads with a 20px node in the
same column as the comments' avatars — an `ActivityKindIcon`, the new value's `StatusIcon` or
`PriorityIcon`, or the actor's avatar (`icon="avatar"`) — then the actor, whose name opens their
person hover card, the sentence with its `ActivityValue`s, and the relative time.

Put `CommentDayDivider` (from `comments`) between items on different days, and one
`ActivityUnreadDivider` before the first item the viewer hasn't seen; its `onVisible` fires once,
when the line is half on screen — mark the record read there. Put `ActivityJumpToLatest` where the
latest items are — last oldest first, first newest first: while that spot is off screen (and the
viewer isn't scrolling away from it) a pill floats at the bottom of the view with an arrow
pointing there; it scrolls there and takes keyboard focus with it. An `agent` event says "Agent"
after the actor's name.

### Event groups

Pass pre-grouped `events` to `ActivityEventGroup` for one compact entry: the actor and latest
timestamp appear once, every change stays visible in chronological order, and the sentence wraps
under its text column. There is no expansion control. The host bounds a burst to two minutes,
keeps actor, comment/reply, calendar-day and unread boundaries, and groups before reversing the
entry order. Server comment-boundary markers let hidden replies separate edits too.
Supply each event's stable `id` so its position survives joining a group across cursor pages.

The children-based form remains available for explicitly folded rows (`visible` and `defaultOpen`).

### Cursor pagination

Pass `loadMore={{ hasMore, onLoadMore, loading, error }}` and a `paginationKey` containing
the filter, list generation and next cursor to `ActivityFeed`. The history edge loads automatically when it enters view: above the list
oldest first, below it newest first. Prepending older items preserves the visible item’s position.
Set `loadMore.error` after a failed read; automatic retries stop and a Retry button appears.
`loadingMoreLabel` and `retryMoreLabel` override the pagination copy. Keep an unread divider within the same timeline rather than paginating unread items separately.

### Agents and the system

`agent` on an event marks an agent's change; `agent: true` on a comment gives it a violet bar, a
bot avatar and an "Agent" label. An event with `actor={null}` is the system's.

## Accessibility

- The feed is a `section` labelled by its heading; the items are an ordered list named "Activity".
- The filter is a select named "Show"; the order toggle is a button whose label names the order
  shown.
- An event is one sentence: the event's icon is decorative, the actor's name is a button that
  opens their hover card, and the relative time shows the exact time on hover or focus.
- Combined event groups keep every change visible and announce the actor and time once.
  The children-based disclosure uses a button with `aria-expanded`.
- The unread line is a `separator` named "New".
- "Jump to latest" is hidden from assistive technology and out of the tab order while it is not
  shown; activating it moves focus to the "Latest activity" spot it scrolled to.
- J and K never fire while focus is in a field, a menu, a listbox or a dialog, with a modifier
  held, or when something else already handled the key. With several feeds on a page, the one
  holding focus answers (else the one mounted last); X ignores an item that has left the list.
- Scrolling (J/K, Jump to latest) is instant when the viewer prefers reduced motion.

| Key            | Action                                                    |
| -------------- | --------------------------------------------------------- |
| <kbd>J</kbd>   | Move to the next item (tinted and scrolled into view)     |
| <kbd>K</kbd>   | Move to the previous item                                 |
| <kbd>X</kbd>   | Toggle the focused item (`onToggle` — unfold its replies) |
| <kbd>Esc</kbd> | Clear the focused item                                    |
