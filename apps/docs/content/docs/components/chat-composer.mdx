## Usage

```tsx
import { ChatComposer } from "@/components/ui/chat-composer";

<ChatComposer
  placeholder="Ask anything, or @ an agent…"
  status={status}
  onSubmit={send}
  onStop={stop}
  hint="Only you can see this chat · AI can make mistakes. Verify important info."
/>;
```

The text is [`TextEdit`](/docs/components/text-edit), so a mention here is the same chip a comment
has. For a comment or a reply on a record, use
[`CommentComposer`](/docs/components/comments): this box is for a conversation, where Enter sends.

## Examples

### A notice on the box

`notice` attaches a `ChatComposerNotice` to the top of the box, sharing its border so the two read
as one: a usage limit, a send that is held, a paused agent. It carries an icon by `tone`, the
words, one optional action (a `secondary` xs button) and an optional ✕ through `onDismiss`. It is
silent by default; pass `live` when it appears because of what the person just did. The `hint` is
the one muted line under the box: who can see the chat and the AI disclaimer, wrapping on a phone.

### While the agent answers

With `status="streaming"` the send button is Stop, and the person can keep typing their next
message. Leave out `onStop` for someone who may not stop this answer: Send stays, held. With
`queues`, that next message sends anyway: the host holds it until the answer ends, and with text in
the box Send stands beside Stop.

  name="chatComposerStreaming"

/>

### Send held

`submitDisabled` holds Send and keeps the text, while a file uploads for example. The reason goes in
`submitDisabledReason`, a line under the box that also describes it.

<ComponentPreview
  name="chatComposerHeld"
  file="components/preview/chat-composer.tsx"
/>

### A failed send

The box clears as soon as the person sends, so they can start the next message; resolve `onSubmit`
when the send is accepted, not when the answer ends. If it rejects, the text comes back, ahead of
anything typed since, with `labels.sendFailed` under the box. Pass `error` to say more. Resolving
`false` puts the text back with no error, for a question first: "Send without the skill?".

### Turned off

`disabled` turns off the whole box, for an agent that is paused. The hint can say why.

### Filling it from outside

`handleRef` gives `setValue`, for a starter prompt that fills the box without sending, and `focus`.
`setValue(draft, { focus: false })` applies a draft that arrived after the box mounted. The text is
Markdown both ways: `onSubmit`, `onValueChange`, `defaultValue` and `setValue` all carry it, so a
line break arrives as `\\` and a new line.

```tsx
const composer = useRef<ChatComposerHandle>(null);

<Button onClick={() => composer.current?.setValue("Plan my day")}>
  Plan my day
</Button>;
<ChatComposer handleRef={composer} onSubmit={send} />;
```

## Accessibility

- The box is a textbox named by `labels.message`, described by the hint and the error.
- A failed send is `role="alert"`. It appears because of what the person did.
- Enter sends everywhere but a code block, so in a list it sends too; Shift+Enter continues the line.
- Send, Stop, 📎 and @ are named buttons in the Tab order, with a tooltip each.

| Key                                               | Action                                                       |
| ------------------------------------------------- | ------------------------------------------------------------ |
| <kbd>Enter</kbd>                                  | Send; on a phone, or in a code block, a new line             |
| <kbd>Shift</kbd> + <kbd>Enter</kbd>               | A new line                                                   |
| <kbd>⌘</kbd> / <kbd>Ctrl</kbd> + <kbd>Enter</kbd> | Send, from anywhere in the text                              |
| <kbd>↑</kbd>                                      | In the empty box, bring back the last message (`onEditLast`) |
| <kbd>Esc</kbd>                                    | Leave the box; the text stays                                |
