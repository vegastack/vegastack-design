## Usage

```tsx
import { ChatComposer } from "@/components/ui/chat-composer";
import { ComposerMeta } from "@/components/ui/composer-meta";

<ChatComposer
  placeholder="Ask William anything…"
  state={state}
  onSubmit={send}
  onStop={stop}
  addMenu={<ChatMenuItem onSelect={upload}>Upload files</ChatMenuItem>}
  meta={
    <ComposerMeta
      privacy="Private · AI can make mistakes"
      model={menu}
      context={ring}
    />
  }
/>;
```

One box, two lines tall at rest, 16px radius and one hairline that darkens a little while it has
focus. Inside are only **+** (attach and bring things in, from `addMenu`, a list of
[`ChatMenu`](/docs/components/chat-menu) items) and **Send**. Under the box, `meta` takes the quiet
line — Plan, the model and effort, the memory ring — as a
[`ComposerMeta`](/docs/components/composer-meta). The text is [`TextEdit`](/docs/components/text-edit),
so a mention is the same chip a comment has; `handleRef.openMentionMenu()` opens the `@` list for a
"Mention a page or task" item. For a comment on a record use
[`CommentComposer`](/docs/components/comments): this box is for a conversation, where Enter sends.

## Examples

### Send, Stop and the states between

`state` drives the one button. `idle` with text is a primary ↑; an empty box is a quiet outline.
`sending` shows the braille [`TextSpinner`](/docs/components/text-spinner) inside the same button —
keep it for at most ~300ms, then move to `running` — and Send becomes Stop ■ with a crossfade and a
small scale. `stopping` holds Stop while the agent winds down; say "Stopping…" in the notice. A
double click on Send never lands on the Stop that replaces it. Under reduced motion the faces swap
at once and the spinner is a still `…`.

### Files and chips

`attachments` are one row above the text: an image with a `thumbUrl` is a 56px thumbnail, anything
else a one-line chip with its type icon and a middle-ellipsis name. Upload progress is a still ring
inside the chip's icon (`progress`, 0–1); a failed one shows ⚠, its reason and ↻
(`onRetryAttachment`). × (`onRemoveAttachment`) takes one off, and so does Backspace in the empty
box. The row scrolls sideways and fades at the edge it can scroll toward; the text grows under it.
`chips` adds other things that travel with the message, such as the page's chip, after the files.

### While the agent works: steers and a notice

While `running` the person can keep typing. With `queues`, Enter sends it and the host shows it in
`steers` above the box — `↳ "…" · read after this step ×` — until the agent reads it (`state:
"read"`); × (`onCancelSteer`) takes a queued one back. With text in the box a small Send stands
beside Stop, for a phone with no Enter. `notice` sits on the box's top edge, inside its hairline: a
`ChatComposerNotice` with `tone="progress"` leads with the braille loader ("⠹ Reconnecting — your
agent kept working [Reload]"). The box never turns red.

### Notices

`ChatComposerNotice` carries a lead by `tone` (`info` ⓘ, `warning` ⚠ in the warning ink,
`progress` the braille loader, the one moving thing), the words, one optional action (a ghost xs button) and an optional ✕
through `onDismiss`. It is silent by default; pass `live` when it appears because of what the person
just did, such as a held send (with `submitDisabled`).

### A failed send

The box clears as soon as the person sends. If `onSubmit` rejects, the text comes back, ahead of
anything typed since, with `labels.sendFailed` under the box; pass `error` to say more. Resolving
`false` puts the text back with no error, for a question first: "Send without the skill?".

### Filling it from outside

`handleRef` gives `setValue`, for a starter prompt that fills the box without sending, `focus`, and
`openMentionMenu`. `setValue(draft, { focus: false })` applies a draft that arrived after the box
mounted. The text is Markdown both ways: `onSubmit`, `onValueChange`, `defaultValue` and `setValue`
all carry it.

```tsx
const composer = useRef<ChatComposerHandle>(null);

<Button onClick={() => composer.current?.setValue("Plan my day")}>
  Plan my day
</Button>;
<ChatComposer handleRef={composer} onSubmit={send} />;
```

## Accessibility

- The box is a textbox named by `labels.message`, described by the error.
- A failed send is `role="alert"`. It appears because of what the person did.
- Send, Stop and + are named buttons in the Tab order with a tooltip each; Send's name follows its
  face ("Send", "Sending", "Stop", "Stopping").
- Each attachment's × is named "Remove q3-prices.pdf"; upload progress is also read as a percentage.
- Steers are a list named "Waiting to be read"; each × is named with its words.
- Enter sends everywhere but a code block, so in a list it sends too; Shift+Enter continues the line.

| Key                                               | Action                                                       |
| ------------------------------------------------- | ------------------------------------------------------------ |
| <kbd>Enter</kbd>                                  | Send (a steer while it runs); on a phone, a new line         |
| <kbd>Shift</kbd> + <kbd>Enter</kbd>               | A new line                                                   |
| <kbd>⌘</kbd> / <kbd>Ctrl</kbd> + <kbd>Enter</kbd> | Send, from anywhere in the text                              |
| <kbd>↑</kbd>                                      | In the empty box, bring back the last message (`onEditLast`) |
| <kbd>Backspace</kbd>                              | In the empty box, take the last attachment off               |
| <kbd>Esc</kbd>                                    | Leave the box; the text stays                                |
