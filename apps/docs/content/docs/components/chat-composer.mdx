## Usage

```tsx
import {
  ChatComposer,
  ChatComposerActions,
  ChatComposerActionsEnd,
  ChatComposerActionsStart,
  ChatComposerAddButton,
  ChatComposerAttachments,
  ChatComposerHeader,
  ChatComposerHeaderTrigger,
  ChatComposerInput,
  ChatComposerMentionButton,
  ChatComposerSubmit,
} from "@/components/ui/chat-composer";

<ChatComposer
  state={state}
  onSubmit={send}
  onStop={stop}
  attachments={files}
  onFiles={upload}
>
  <ChatComposerHeader>
    <ChatComposerHeaderTrigger
      media={<Asterisk />}
      description="Chief of staff"
    >
      Talking to William
    </ChatComposerHeaderTrigger>
    <ComposerChip pressed={plan} onPressedChange={setPlan}>
      Plan
    </ComposerChip>
  </ChatComposerHeader>
  <ChatComposerAttachments />
  <ChatComposerInput placeholder="Ask William anything…" mentions={mentions} />
  <ChatComposerActions>
    <ChatComposerActionsStart>
      <ChatComposerAddButton menu={addItems} />
      <ChatComposerMentionButton />
    </ChatComposerActionsStart>
    <ChatComposerActionsEnd>
      <ModelEffortMenu {...model} />
      <ChatComposerSubmit />
    </ChatComposerActionsEnd>
  </ChatComposerActions>
</ChatComposer>;
```

`ChatComposer` is the card, and it owns the turn: the text, the send, Stop, the files and the drop.
The parts only lay the card out, top to bottom: a `ChatComposerNotice` on the top edge, the context
strip (`ChatComposerHeader`), the files (`ChatComposerAttachments`), the text (`ChatComposerInput`)
and the actions row (`ChatComposerActions`). Leave out what a surface doesn't need: a desktop quick
ask has no strip.

The card has one radius, `rounded-3xl` (22px, 2.2 × `--radius`), and one hairline that darkens a
little while the text has focus. Everything inside is concentric with it: the strip and the actions
row sit 6px in with fully round 32px controls, and the file tiles sit 10px in with `rounded-lg`. The
text is [`TextEdit`](/docs/components/text-edit), so a mention is the same chip a comment has. For a
comment on a record use [`CommentComposer`](/docs/components/comments): this box is for a
conversation, where Enter sends.

### Send, Stop and the states between

`state` drives `ChatComposerSubmit`, a perfectly round button the size of + and @. `idle` with text
is a primary ↑; an empty box is a quiet outline. `sending` shows the braille
[`TextSpinner`](/docs/components/text-spinner) inside the same button — keep it for at most ~300ms,
then move to `running` — and Send becomes Stop ■ with a crossfade and a small scale (with the
root's `onStop`). `stopping` holds Stop while the agent winds down; say "Stopping…" in a notice. A
double click on Send never lands on the Stop that replaces it. Under reduced motion the faces swap at
once and the spinner is a still `…`.

### Files, chips and drag-over

The root's `attachments` draw in `ChatComposerAttachments`, one row above the text: an image with a
`thumbUrl` is a 56px thumbnail, anything else a chip with its type icon and a middle-ellipsis name.
Upload progress is a still ring (`progress`, 0–1); a failed one shows ⚠, its reason and ↻
(`onRetryAttachment`). × (`onRemoveAttachment`) takes one off, and so does Backspace in the empty
box. The row scrolls sideways and fades at the edge it can scroll toward. Its children follow the
files: the page's chip, a skill for this turn. Files dragged over the card show "Drop to add to
chat" across it and go to `onFiles`, as pasted files do; `dropTypes` and `onDropData` take other
things dragged in.

### While the agent works: steers and a notice

While `running` the person can keep typing. With `queues`, Enter sends it and the host shows it in
`steers` above the card — `↳ "…" · read after this step ×` — until the agent reads it (`state:
"read"`); × (`onCancelSteer`) takes a queued one back. With text in the box a small Send stands
beside Stop, for a phone with no Enter. A `ChatComposerNotice` with `tone="progress"` leads with the
braille loader ("⠹ Reconnecting — your agent kept working [Reload]"). The card never turns red.

### Notices

`ChatComposerNotice`, the card's first child, carries a lead by `tone` (`info` ⓘ, `warning` ⚠ in
the warning ink, `progress` the braille loader, the one moving thing), the words, one optional
action (a ghost xs button) and an optional ✕ through `onDismiss`. It is silent by default; pass
`live` when it appears because of what the person just did.

### A failed send

The box clears as soon as the person sends. If `onSubmit` rejects, the text comes back, ahead of
anything typed since, with `labels.sendFailed` under the card; pass `error` to say more. Resolving
`false` puts the text back with no error, for a question first: "Send without the skill?".

### Filling it from outside

`handleRef` gives `setValue`, for a starter prompt that fills the box without sending, `focus`, and
`openMentionMenu` (an add menu's "Mention a page or task"). `setValue(draft, { focus: false })`
applies a draft that arrived after the box mounted. The text is Markdown both ways: `onSubmit`,
`onValueChange`, `defaultValue` and `setValue` all carry it.

```tsx
const composer = useRef<ChatComposerHandle>(null);

<Button onClick={() => composer.current?.setValue("Plan my day")}>
  Plan my day
</Button>;
<ChatComposer handleRef={composer} onSubmit={send}>
  …
</ChatComposer>;
```

### Migrating from the meta line

`ComposerMeta` and the props `placeholder`, `mentions`, `addMenu`, `onAttach`, `chips`, `notice`,
`meta` and `maxHeightRatio` on `ChatComposer` are gone. Move each into its part: `placeholder`,
`mentions` and the `mention*` props to `ChatComposerInput` (`maxHeightRatio` becomes `maxRows`);
`addMenu` or `onAttach` to `ChatComposerAddButton`'s `menu` or `onClick`; `chips` to
`ChatComposerAttachments`' children; `notice` to a `ChatComposerNotice` child; the model and the
memory ring to `ChatComposerActionsEnd`; Plan to a `ComposerChip` in `ChatComposerHeader`. The
privacy note has no place in the card: say who can read the chat in its header.

## Accessibility

- The text is a textbox named by `labels.message`, described by the error.
- The context strip is one button, named by its words and its description ("Talking to William,
  Chief of staff"); its focus cue is the system's background tint, never a ring (FOC-13).
- A failed send is `role="alert"`. It appears because of what the person did.
- Send, Stop, + and @ are named buttons in the Tab order with a tooltip each; Send's name follows its
  face ("Send", "Sending", "Stop", "Stopping"), and Sending is `aria-busy`.
- Each attachment's × is named "Remove q3-prices.pdf"; upload progress is also read as a percentage.
- Steers are a list named "Waiting to be read"; each × is named with its words.
- Every part is a named child of the root; using one outside `ChatComposer` throws.

| Key                                               | Action                                                       |
| ------------------------------------------------- | ------------------------------------------------------------ |
| <kbd>Enter</kbd>                                  | Send (a steer while it runs); on a phone, a new line         |
| <kbd>Shift</kbd> + <kbd>Enter</kbd>               | A new line                                                   |
| <kbd>⌘</kbd> / <kbd>Ctrl</kbd> + <kbd>Enter</kbd> | Send, from anywhere in the text                              |
| <kbd>@</kbd>                                      | Open the mention list (`ChatComposerInput`'s `mentions`)     |
| <kbd>↑</kbd>                                      | In the empty box, bring back the last message (`onEditLast`) |
| <kbd>Backspace</kbd>                              | In the empty box, take the last attachment off               |
| <kbd>Esc</kbd>                                    | Leave the box; the text stays                                |
