## Usage

```tsx
import {
  ContextMenu,
  ContextMenuContent,
  ContextMenuItem,
  ContextMenuTrigger,
} from "@/components/ui/context-menu";

<ContextMenu>
  <ContextMenuTrigger>Right click here</ContextMenuTrigger>
  <ContextMenuContent>
    <ContextMenuItem>Profile</ContextMenuItem>
    <ContextMenuItem>Billing</ContextMenuItem>
    <ContextMenuItem>Team</ContextMenuItem>
    <ContextMenuItem>Subscription</ContextMenuItem>
  </ContextMenuContent>
</ContextMenu>;
```

`side` on `ContextMenuContent` fixes which edge of the pointer the popup grows from — `top`,
`right`, `bottom`, `left`, or the logical `inline-start`/`inline-end`. The positioner still flips

## Accessibility

- Renders Base UI's ContextMenu: the popup is a `role="menu"` of `menuitem`, `menuitemcheckbox`
  and `menuitemradio` rows with type-ahead, <kbd>↑</kbd>/<kbd>↓</kbd>,
  <kbd>Home</kbd>/<kbd>End</kbd>, <kbd>→</kbd>/<kbd>←</kbd> for submenus and
  <kbd>Esc</kbd> to close.
- A context menu is never the only path to a command: the same actions must be reachable from a
  visible control, because a right-click is not discoverable and not available on every input.
- The popup portals out of the trigger's subtree, so `ContextMenuContent` re-applies the theme
  scope on the positioner inside the portal and `ContextMenuPortal` re-applies it on a
  `display: contents` wrapper (OVL-13).
- Rows carry the hand cursor from the one global rule in `base.css` (INT-1).
- A disabled row keeps its pointer events (FRM-4), so a Tooltip can explain why it is unavailable.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/context-menu.patch`. Every hunk:

- **OVL-13** — the same two hosts `dropdown-menu` has: `ContextMenuContent`'s own portal is scoped
  on its Positioner, and the exported `ContextMenuPortal` scopes a `display: contents` wrapper.
- **INT-1** — `cursor-default` is removed from the item, the submenu trigger, the checkbox item
  and the radio item.
- **FRM-4** — `data-disabled:pointer-events-none` is dropped from the item, the checkbox item and
  the radio item, so a disabled row stays hoverable.
- **BRD-1** — `ContextMenuContent` draws a real 1px `border border-border` instead of upstream's
  `ring-1 ring-foreground/10` box-shadow outline. A border survives forced colours and matches
  [Elevation](/docs/foundations/elevation); nothing else about the surface moves.
- **A11Y-13** — a focused destructive `ContextMenuItem` reads `focus:text-destructive-text` on its
  `bg-destructive/10` wash. Upstream inks it with the fill (`focus:text-destructive`), which
  measures 3.99:1 on its own tint in light, under the AA floor; the resting ink and the icon
  ink stay upstream's.
- **DOC-2** — `import { cn } from "cn"` becomes `@vegastack/design`; our npm layer owns `cn`.
- **DOC-1** — prettier reflow plus the `registry-stamp.mjs` provenance header; no decision of
  their own.
