## Usage

```tsx
import { RecordPicker } from "@/components/ui/record-picker";

<PopoverContent size="lg" className="p-0">
  <RecordPicker
    kinds={[
      { id: "page", noun: "Pages", icon: <FileText /> },
      { id: "table", noun: "Tables", icon: <Table2 /> },
    ]}
    search={(q, { kind, cursor, signal }) =>
      api.search({ q, kind, cursor }, { signal })
    }
    recents={recent}
    onPick={(item) => link(item)}
  />
</PopoverContent>;
```

## Scope

One way to pick records, whatever their kind: a relation field, a block's source, a "Link to…"
dialog. The picker knows no kinds — the app passes them with their nouns and icons, and its own
`search` loader (debounced, abortable and paged through `useAsyncSearch`). With a `browse`
loader the picker also walks the app's folders, one folder at a time, so an "Add from…" dialog
can be browsed as well as searched. People have `PeoplePicker`; a place to move something — a
folder to choose, not records inside it — has `DestinationPicker`.

## Examples

### In a popover

Type to search; the kind filter narrows it ("All" by default); `recents` show while the box is
empty; results group by kind. A record with a `disabledReason` shows why and can't be picked.

### In a dialog, picking several

`RecordPickerDialog` with `multiple`: the dialog starts from `value` (the records picked before),
rows toggle with a check, and Done reports the whole set through `onConfirm` (`onValueChange`
follows each toggle). `value` holds records, not keys, so an earlier pick survives a search that
no longer shows it. While a new search is on its way, Enter can't pick a row from the last one.

### Browsing folders

Pass `browse` — the app's listing of one folder (`null` is the top), paged like `search` — and
mark folder rows with `folder: true`. While the search box is empty the list is the open folder's
contents in the app's order; choosing a folder opens it (it is never picked), and the breadcrumb
above the list, or Backspace in the empty box, climbs back. Typing searches everything through
`search`, wherever it lives; a folder found that way opens from the top of the trail. `recents`
show at the top only. With `multiple`, ticks survive moving between folders, and `selectAll` adds
a "Select all" for the rows on screen. `kindFilter={false}` hides the kind filter when the
loaders can't narrow by kind.

In a dialog, `confirmLabel` can count the picks ("Add 3"), `cancelLabel` adds a Cancel button, and
an async `onConfirm` keeps the dialog open and the button busy until it settles — `false` keeps it
open so the reader can try again. The confirm is off while nothing is picked.

## Accessibility

| Key                   | Does                                                |
| --------------------- | --------------------------------------------------- |
| Type                  | Searches the app's records, in every folder         |
| ↑ / ↓                 | Moves through the results or the folder             |
| Enter                 | Picks (or toggles, with `multiple`); opens a folder |
| Backspace (empty box) | With `browse`: climbs to the folder above           |
| Esc                   | Closes the popover or dialog                        |

- The search box drives a grouped listbox; a refused row is `aria-disabled` and reads its reason.
- A folder row reads "folder" after its name. Opening one announces it, and the breadcrumb is a
  `nav` named "Folder path" whose crumbs are buttons; the open folder is the current page.
- Loading, errors and "Load more" sit outside the listbox, in a status row.
