## Usage

```tsx
import { ScrollArea, ScrollBar } from "@/components/ui/scroll-area";

<ScrollArea className="h-[200px] w-[350px] rounded-md border p-4">
  Your scrollable content here.
</ScrollArea>;
```

`ScrollArea` renders the viewport, one vertical `ScrollBar` and the corner itself, so a vertical
scroll area is a single element. Give it a bounded height — a container that can grow never scrolls.

## Examples

### Composition

`ScrollBar` is the one part you compose, and only for the horizontal axis. Everything you pass as a
child lands inside the viewport, so the horizontal bar is written beside the content rather than
outside the component.

### Named region

`aria-label` or `aria-labelledby` on `ScrollArea` names the viewport — the part a keyboard user
tabs to — and makes it a `region` landmark, so a screen-reader user hears what it holds before
scrolling it. An unnamed scroll area stays a plain scroller.

```tsx
<h4 id="release-tags">Release tags</h4>
<ScrollArea aria-labelledby="release-tags" className="h-48">
  …
</ScrollArea>
```

### Programmatic scroll

`viewportRef` is a ref to the scrolling element itself, for jumping to an edge, restoring a saved
position or keeping a log pinned to its end.

```tsx
const viewportRef = React.useRef<HTMLDivElement>(null);

<ScrollArea
  viewportRef={viewportRef}
  aria-label="Release tags"
  className="h-48"
>
  …
</ScrollArea>;

viewportRef.current?.scrollTo({ top: 0 });
```

## API Reference

`ScrollArea` accepts everything the [Base UI Scroll Area](https://base-ui.com/react/components/scroll-area)
`Root` accepts, plus `className`, `ref` and `render`, and adds one prop of its own: `viewportRef`
(`React.Ref<HTMLDivElement>`), a ref to the scrolling viewport. `aria-label`, `aria-labelledby`
and `tabIndex` are forwarded to the viewport rather than the root. `ScrollBar` adds no props: it
accepts Base UI's `Scrollbar` props, and its `orientation` is `"vertical"` by default and takes
`"horizontal"` for the other axis.

## Accessibility

- The viewport is a tab stop exactly when it can scroll (A11Y-6). Base UI sets
  `tabIndex: hidden.x && hidden.y ? -1 : 0`, so a keyboard-only reader can reach overflowing content
  with arrow keys, and an area whose content fits adds no empty stop to the tab order.
- Give a scroll area an accessible name — `aria-label`, or `aria-labelledby` pointing at the heading
  above it. The name lands on the focusable viewport, which becomes `role="region"`, so a
  screen-reader user hears what the region holds before entering it (A11Y-6).
- Focus is the global 2px `:focus-visible` outline from `base.css`. Upstream's ring glow and its
  `outline-none` are removed (FOC-1, FOC-6): the viewport is the one focusable part of this
  component, so suppressing the outline would leave it with no affordance at all.
- The scrollbar and its thumb are pointer affordances; every scroll they perform is reachable from
  the keyboard through the viewport itself.
- Native scrolling is preserved throughout — wheel, trackpad, touch and the platform's own
  scroll-into-view all behave as they do on an ordinary overflow container.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/scroll-area.patch`. Every hunk:

- **FOC-1, FOC-6** — the viewport's focus glow and outline suppression go: `outline-none`,
  `focus-visible:ring-[3px]`, `focus-visible:ring-ring/50` and `focus-visible:outline-1`. The
  viewport IS a tab stop (see A11Y-6), so `outline-none` would leave the one focusable part of this
  component with no affordance.
- **A11Y-6** — the tab-stop half needs no hunk: Base UI's `ScrollArea.Viewport` sets
  `tabIndex: hiddenState.x && hiddenState.y ? -1 : 0`, which is exactly "a scroll viewport is a tab
  stop only when it can actually scroll", and `scroll-area.test.tsx` asserts both directions. The
  naming half is a hunk: `aria-label`, `aria-labelledby` and `tabIndex` go to the viewport instead
  of the non-focusable root, and a named viewport is `role="region"`.
- **A11Y-22** — `viewportRef` is forwarded to the viewport, for programmatic scrolling.
- **DOC-2** — `import { cn } from "cn"` becomes `@vegastack/design`; our npm layer owns `cn`.
- **DOC-1** — prettier reflow plus the `registry-stamp.mjs` provenance header the three-copy model
  needs; no decision of its own.
