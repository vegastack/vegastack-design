## Usage

```tsx
import {
  ResizableHandle,
  ResizablePanel,
  ResizablePanelGroup,
} from "@/components/ui/resizable";

<ResizablePanelGroup orientation="horizontal">
  <ResizablePanel>One</ResizablePanel>
  <ResizableHandle />
  <ResizablePanel>Two</ResizablePanel>
</ResizablePanelGroup>;
```

A group fills its parent at `100%`/`100%`, so the parent owns the height. Sizes are unitless strings
read as percentages — `defaultSize="50%"` and `defaultSize="50"` are the same thing, and a bare
number is pixels.

## Examples

### About

The `Resizable` component is built on top of
[react-resizable-panels](https://github.com/bvaughn/react-resizable-panels) by
[bvaughn](https://github.com/bvaughn). The engine owns the layout maths, the pointer drag and the
keyboard resize; the bar, the grip and the focus affordance are ours. We are on v4, whose API renamed
`PanelGroup` to `Group`, `PanelResizeHandle` to `Separator` and `direction` to `orientation` — the
three wrapper names on this page are unchanged by that.

### Composition

A group is panels with handles between them. Every handle is a `role="separator"` control that
resizes the two panels it sits between.

```text
ResizablePanelGroup
├── ResizablePanel
├── ResizableHandle
└── ResizablePanel
```

## API Reference

<ApiTable path="lib/api-props.ts" name="ResizableHandleProps" />

`ResizablePanelGroup` and `ResizablePanel` add no props of their own — each accepts everything the
corresponding `react-resizable-panels` v4 part accepts. On the group that is `orientation`,
`disabled`, `defaultLayout`, `onLayoutChange` / `onLayoutChanged`, `groupRef` and `id`; on a panel it
is `defaultSize`, `minSize`, `maxSize`, `collapsible`, `collapsedSize`, `disabled`, `onResize`,
`panelRef` and `id`. Both also take standard `div` attributes and a `ref`.

## Accessibility

- Each handle is a `role="separator"` with `aria-orientation`, `aria-controls` naming the panel it
  resizes, and `aria-valuenow` / `aria-valuemin` / `aria-valuemax` carrying that panel's current
  size — the ARIA window-splitter pattern.
- A handle is a tab stop, and the arrow keys resize it; <kbd>Home</kbd> and <kbd>End</kbd> jump to the
  bounds. A `disabled` handle drops out of the tab order and reports `aria-disabled`.
- Focus is the global 2px `:focus-visible` outline from `base.css`. Upstream suppressed it with
  `focus-visible:outline-hidden` and replaced it with a ring; both are removed (FOC-1, FOC-6), so a
  keyboard user can see which handle they are about to move.
- The grip rendered by `withHandle` is decoration; the accessible target is the bar itself, which is
  wider than its 1px line through an `after:` hit area.
- Give a handle an `aria-label` when a group has more than one, so the two separators are
  distinguishable when read out of context.

/>

## Deviations

Upstream's file plus `packages/ui/upstream/patches/resizable.patch`. Every hunk:

- **FOC-1, FOC-6** — `focus-visible:ring-1 focus-visible:ring-ring focus-visible:outline-hidden` goes
  from `ResizableHandle`. `outline-hidden` is the v3 spelling of "no outline", so upstream suppressed
  the one focus affordance this system has on a control that is keyboard-operable (arrow keys resize
  it). `ring-offset-background` is left alone: it paints nothing without a ring width and is
  upstream's own class.
- **DOC-2** — `import { cn } from "cn"` becomes `@vegastack/design`; our npm layer owns `cn`.
- **DOC-1** — prettier reflow plus the `registry-stamp.mjs` provenance header the three-copy model
  needs; no decision of its own.
