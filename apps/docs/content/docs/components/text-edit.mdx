## Usage

```tsx
import { TextEdit } from "@/components/ui/text-edit";

const [html, setHtml] = useState("<p>Hello</p>");

<TextEdit
  value={html}
  onValueChange={setHtml}
  placeholder="Write something…"
  aria-label="Body"
  aria-describedby="body-help"
/>;
```

`TextEdit` is **controlled** with `value` / `onValueChange` (HTML strings), or **uncontrolled** with
`defaultValue`. It is built on [Tiptap v3](https://tiptap.dev) `StarterKit`, which bundles undo/redo
history, the **bold / italic / strike / code** marks, **headings**, **bullet & ordered lists**,
**blockquote**, and markdown-ish input rules (type `**bold**`, `# Heading`, `- ` for a list,
`> ` for a quote, `` `code` ``).

```tsx
// Uncontrolled — seed initial content and read changes via onValueChange.
<TextEdit
  defaultValue="<p>Draft…</p>"
  onValueChange={(html) => save(html)}
  aria-label="Notes"
/>
```

## Scope

`TextEdit` is the **presentational base editor** — a controlled HTML value, the StarterKit
formatting set, the slash and bubble menus, the placeholder, read-only mode, a `Cmd/Ctrl+Enter` `onSubmit`
affordance, and `minHeight`/`maxHeight` sizing. Heavier, app-coupled capabilities are intentionally
**out of this core** (each needs app infrastructure or ships as a separate composed extension),
mirroring the system's presentational / app-coupled rule:

| Capability                                                  | Why it's out of the base                                         | Where it lives                            |
| ----------------------------------------------------------- | ---------------------------------------------------------------- | ----------------------------------------- |
| Image upload / paste-to-upload                              | Needs app storage (R2/CDN)                                       | App resolves URLs (same split as `Image`) |
| @mentions                                                   | Needs the app's user/entity data                                 | App-supplied data source + query          |
| Emoji, code-block language menus                            | Composed Tiptap extensions                                       | Future composed addons                    |
| Real-time collaboration (multi-cursor, awareness, Yjs CRDT) | Needs `@tiptap/extension-collaboration` + `yjs` + a sync backend | Separate `text-edit-collab` component     |

This base ships no `@tiptap/extension-collaboration` and no `yjs` dependency — it is a self-contained
single-user editor. For richer needs, compose the relevant extension on top or use the dedicated
follow-up component.

Prose styling is **not** this component's to own: the editor surface wears the shared `prose`
recipe from `@vegastack/design`, the same string `MarkdownView` puts on its root, so what a person
types here and what the app renders from markdown are one typography.

## Examples

### Slash menu, bubble menu and in-place editing

There is no toolbar. Type <kbd>/</kbd> for a filterable block menu (text, headings, lists, a
checklist, a quote, a code block, a divider, a link); `slashCommands` limits it. Select text for a
bubble menu with bold, italic, strikethrough, inline code and an inline link input. The editor has
no view mode: leaving it calls `onCommit` when the text changed, <kbd>Esc</kbd> reverts
(`onRevert`), and `autosave` commits after an idle gap. Every command, the shortcuts, the input rules
and a view/edit parity example are on the [Markdown guide](/docs/guides/markdown).

### Anatomy

`TextEdit` is a single self-contained component, but it composes these pieces internally:

```tsx
// data-slot="text-edit" — transparent root, no border, no ring
<TextEdit>
  // Tiptap contenteditable, role="textbox" aria-multiline
  <EditorContent />
  // data-slot="text-edit-bubble-menu" — role="toolbar", over a selection
  <BubbleMenu />
  // data-slot="text-edit-slash-menu" — role="listbox", while typing after /
  <SlashMenu />
</TextEdit>
```

- **Root** (`data-slot="text-edit"`) — transparent and borderless: it takes the surface it sits on.
  Carries `data-editable` and `data-invalid` when it wraps an
  `aria-invalid` control. Clicking its blank space focuses the end of the document.
- **Bubble menu** (`data-slot="text-edit-bubble-menu"`, `role="toolbar"`) — `Toggle` buttons for
  bold, italic, strikethrough, inline code and link over a selection; link swaps it for an inline
  URL input (`data-slot="text-edit-link"`).
- **Slash menu** (`data-slot="text-edit-slash-menu"`, `role="listbox"`) — the block menu, in the
  Command item style with muted icons. Focus stays in the editor; the caret never moves.
- **Editor surface** (`role="textbox"`, `aria-multiline`) — the Tiptap/ProseMirror contenteditable.
  Prose is styled entirely with semantic tokens (headings, lists, code, blockquote), so it tracks the
  active theme with no `@tailwindcss/typography` dependency. Hover and focus tint it faintly; there
  is no border and no ring.

### Markdown

`format="markdown"` makes `value`, `defaultValue`, `onValueChange` and `onSubmit` carry Markdown
instead of HTML, through Tiptap's own `@tiptap/markdown` extension: headings, bold, italic,
strikethrough, links, bullet and ordered lists, blockquotes and code round-trip unchanged. Loading a
document never fires `onValueChange`; only an edit does. Store what the editor emits and render it
elsewhere with [`MarkdownView`](/docs/components/markdown-view). The format is read once, when the
editor is created.

### Invalid

Pass `aria-invalid` to mark the editor invalid: it forwards to the contenteditable textbox and the
root carries `data-invalid`. The editor draws no border, so the error text is the visible cue.
Connect the error text with `aria-describedby` so it is announced with the region. `aria-invalid`
also accepts `"grammar"` and `"spelling"`.

### Inside a Field

Inside a [`Field`](/docs/components/field) the contenteditable takes its label, the rendered
description and error ids, and `aria-invalid` from the Field, so a `FieldLabel` names the editor
without an `id` or `aria-labelledby`. An explicit `aria-labelledby` still wins.

### Submit on Cmd/Ctrl+Enter

Set `onSubmit` to get a keyboard submit affordance — pressing <kbd>Cmd/Ctrl</kbd>+<kbd>Enter</kbd>
fires it with the current value. It's presentational only: the **host** decides what submitting means
(save, send, …), and plain <kbd>Enter</kbd> still inserts a newline. Omit `onSubmit` to disable it.

### Sized content area

`minHeight` sets a starting height and `maxHeight` caps it — content past the cap scrolls
(`overflow-y-auto`). A number is treated as `px`; a string (e.g.
`'8rem'`) is used verbatim. Both are fed to the `--te-min-h` / `--te-max-h` CSS variables.

## Accessibility

- The editable surface is a `role="textbox"` with `aria-multiline="true"`. Give it an `aria-label`
  (or associate a visible label) so the region is announced.
- Use `aria-invalid` and `aria-describedby` to connect validation state and helper/error text to the
  contenteditable textbox.
- The slash menu is a `listbox` of `option`s with `aria-selected`; focus stays in the textbox and
  <kbd>↑</kbd> <kbd>↓</kbd>, <kbd>Enter</kbd> and <kbd>Esc</kbd> drive it.
- The bubble menu is a Base UI `Toolbar` labelled “Selection formatting”: one tab stop, arrow keys
  between its `Toggle`s, each with an `aria-label` and `aria-pressed`.
- Editing keymaps come from Tiptap `StarterKit` — see the table below. Focus is shown by the
  system's background tint on the surface (FOC-13); there is no ring or border.
- An invalid control (`aria-invalid`) sets `data-invalid` on the root for downstream styling; pair
  it with visible error text through `aria-describedby`.
- `readOnly` marks the surface read-only.

| Key                                                   | Action                                                                                                                        |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| <kbd>Cmd/Ctrl</kbd> + <kbd>B</kbd>                    | Toggle **bold**.                                                                                                              |
| <kbd>Cmd/Ctrl</kbd> + <kbd>I</kbd>                    | Toggle _italic_.                                                                                                              |
| <kbd>Cmd/Ctrl</kbd> + <kbd>Z</kbd>                    | Undo.                                                                                                                         |
| <kbd>Cmd/Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>Z</kbd> | Redo.                                                                                                                         |
| <kbd>Enter</kbd>                                      | New paragraph (or new list item inside a list).                                                                               |
| <kbd>Cmd/Ctrl</kbd> + <kbd>Enter</kbd>                | Fire `onSubmit` with the current value (when set); otherwise commit and blur. Plain <kbd>Enter</kbd> still inserts a newline. |
| <kbd>Esc</kbd>                                        | Revert to the value focus found, blur, and fire `onRevert`.                                                                   |
| <kbd>Cmd/Ctrl</kbd> + <kbd>K</kbd>                    | Open the inline link input (add, edit or remove the link).                                                                    |
| <kbd>Tab</kbd>                                        | Move focus out of the editor to the next control.                                                                             |
| <kbd>/</kbd>                                          | Open the slash menu.                                                                                                          |
