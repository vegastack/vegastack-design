pass `aria-invalid` on a standalone textarea). The tint is scoped to `not-focus:`
(FOC-5), so a focused textarea shows its focus cue rather than the error colour.

## Accessibility

- Renders a native `<textarea>`, so the platform owns selection, IME composition and spellcheck.
- Focus is a **border tint on `:focus`**, not a ring, and the global outline is suppressed with
  `outline-hidden` (FOC-3, FOC-8). The tint fires for mouse and keyboard alike, because a text field
  cannot tell them apart and both need the caret located.
- Under `forced-colors: active` the tint disappears with every authored colour, so `base.css` paints
  a 2px `Highlight` outline on `textarea:focus` instead (FOC-7).
- `field-sizing: content` grows the box with the text, so nothing is hidden behind a scrollbar at
  small sizes.
- Give it a label: a `FieldLabel` in the same `Field` (wired automatically), or an `aria-label`.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/textarea.patch`. Every hunk:

- **FOC-1, FOC-3, FOC-6, FOC-8** — `outline-none focus-visible:border-ring focus-visible:ring-3
focus-visible:ring-ring/50` becomes `outline-hidden` plus `focus:border-ring/70`: a border tint on
  `:focus` and no glow. `outline-hidden` rather than `outline-none`, so the forced-colours
  fallback has something to repaint.
- **FOC-5** — the invalid tint becomes `not-focus:aria-invalid:border-destructive` (and its dark
  counterpart), so focus outranks it; the `aria-invalid` halo rings are removed with the rest.
- **API-26** — the `<textarea>` renders through Base UI `Field.Control`, so inside a `Field` it takes
  its label, the rendered description and error ids, and `aria-invalid` with no props, like `Input`.
  The file gains `"use client"`, because `Field.Control` is hook-backed.
- **DOC-2** — `cn` is imported from `@vegastack/design`.
