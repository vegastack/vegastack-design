## Usage

```tsx
import {
  Attachment,
  AttachmentAction,
  AttachmentActions,
  AttachmentContent,
  AttachmentDescription,
  AttachmentMedia,
  AttachmentTitle,
} from "@/components/ui/attachment";

<Attachment>
  <AttachmentMedia>
    <FileTextIcon />
  </AttachmentMedia>
  <AttachmentContent>
    <AttachmentTitle>sales-dashboard.pdf</AttachmentTitle>
    <AttachmentDescription>PDF · 2.4 MB</AttachmentDescription>
  </AttachmentContent>
  <AttachmentActions>
    <AttachmentAction aria-label="Remove sales-dashboard.pdf">
      <XIcon />
    </AttachmentAction>
  </AttachmentActions>
</Attachment>;
```

`Attachment` shows a file or image attachment — its media, its name, its metadata — with optional
actions and an upload state. Use it for files and images in chat composers, message threads and
upload lists. It renders that state; it owns no upload logic.

### Features

- Icon and image media through `AttachmentMedia`
- Upload states: `idle`, `uploading`, `processing`, `error` and `done`, with built-in styling and a
  shimmer while the upload is in progress
- Three sizes, and horizontal or vertical orientation
- A full-card `AttachmentTrigger` that opens a link or a dialog while the actions stay
  independently clickable above it
- A scrollable, snapping `AttachmentGroup` with an edge fade
- Customizable styling through the `className` prop on every part

### Record files grid

A record's files — a product's datasheets and photos, say — read better as a grid than as a
scrolling row. Set `layout="grid"` on `AttachmentGroup` to wrap the tiles into equal columns that
reflow down to one or two at a phone width. `AttachmentProgress` gives an upload a determinate bar
that announces its percentage, and `muted` dims the media of a file the record no longer uses —
say why in `AttachmentDescription`, so the state is never carried by opacity alone.

For the full upload flow — acquiring files, per-file progress, cancel, retry and discard — see the
[Upload queue](/docs/components/dropzone#upload-queue) example on Dropzone.

### Form tiles

In a form or a settings page, files sit beside fields. Set `layout="tiles"` on `AttachmentGroup`
for square tiles — at most `columns` a row (four by default), three and then two as the container
narrows, never below 8.5rem a tile. The count follows the group's own width, not the viewport's, so
the same grid fits a full page and a narrow form column. Pair it with
[`UploadDialog`](/docs/components/upload-dialog) for adding files.

### Tile overlay

On a vertical tile, `AttachmentActions` is an overlay slot instead of a row: the default
`side="end"` is the top-right corner — at most two icon actions, such as × remove, a ⋯ menu or
download — and `side="start"` the top-left one, where a drag handle goes (`SortableList`'s grid puts
its ⠿ there). Each slot is inset from the corner so its buttons sit on the image, shows on hover or
focus within the tile and always on a touch screen, and paints an `AttachmentAction` in
`scrim-foreground` on a blurred `scrim` wash (`bg-scrim/40`, `/60` on hover) — the same scrim
`AvatarPicker` lays over a photo, from the shared `tile-overlay` recipe. `--scrim` and
`--scrim-foreground` are theme-invariant tokens (black and white in both themes); retune them in
your theme to change every tile overlay at once. Leave a slot out and it is not there. A horizontal chip keeps its actions inline.

```tsx
<Attachment orientation="vertical" file={file}>
  {/* media, content */}
  <AttachmentActions side="start">{/* handle */}</AttachmentActions>
  <AttachmentActions>
    <DropdownMenu>
      <DropdownMenuTrigger
        render={
          <AttachmentAction aria-label="Actions for spec-sheet.pdf">
            <EllipsisVerticalIcon />
          </AttachmentAction>
        }
      />
      <DropdownMenuContent align="end">
        {/* Download, Replace, Remove */}
      </DropdownMenuContent>
    </DropdownMenu>
  </AttachmentActions>
</Attachment>
```

### Open on click

Give a tile its `file` (a `FileViewerItem`) and the whole tile becomes one `Open {name}` button: a
click or tap, or <kbd>Enter</kbd>/<kbd>Space</kbd> on it, opens the
[`FileViewer`](/docs/components/file-viewer) — an image to zoom and pan, a PDF page by page, a
download card for anything else. The viewer is its own chunk, loaded the first time a tile opens.
It pages through every tile in the same `AttachmentGroup`; wrap several groups (a record's file
sections) or a `SortableList` of tiles in `AttachmentPreview` to page across all of them. The
overlay actions sit above the open button, so a click on × never opens the viewer.

Preview is on by default. `preview={false}` on a tile or a group keeps plain cards, and `onOpen`
replaces the built-in viewer with your own handler.

## Accessibility

- **Label every icon-only action.** `AttachmentAction` is usually a bare icon, so give each one an
  `aria-label` naming the action and its target — "Remove sales-dashboard.pdf", not "Remove".
- **Label the trigger.** `AttachmentTrigger` covers the card and has no text of its own, so give it
  an `aria-label` for what activating it does. A tile given a `file` labels its own open button
  `Open {name}`, and <kbd>Enter</kbd> or <kbd>Space</kbd> on it opens the viewer.
- **Overlay slots reveal on focus too.** A tile's overlay actions show while anything in the tile
  has focus, so a keyboard user tabbing from the open button to × sees every control it reaches.
- The trigger sits behind the actions in the stacking order, so an `AttachmentAction` and the
  `AttachmentTrigger` never trap each other — both stay separately focusable and separately
  clickable.
- Focus is the global 2px `:focus-visible` outline from `base.css`, painted on the trigger itself
  and following the card's own corner. The card wears no ring on the trigger's behalf — see
  **Deviations**.
- **Keyboard scrolling.** An `AttachmentGroup` scrolls horizontally. When its attachments are
  interactive, keyboard users reach the off-screen ones by tabbing. For a row of _presentational_
  attachments, make the group itself the scroller with `tabIndex={0}`, `role="group"` and an
  `aria-label`.
- **Meaning beyond colour.** The `error` state uses a destructive colour; keep the failure reason
  in `AttachmentDescription` so the state is never carried by colour alone.
- `AttachmentAction` is `size="icon-xs"` — `size-6`, 24px, exactly on the WCAG 2.2 SC 2.5.8 floor.
  `attachment.test.tsx` measures it rather than assuming it.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/attachment.patch`. Every hunk:

- **FOC-1, FOC-6** — `attachmentVariants` drops `focus-within:ring-1 focus-within:ring-ring/50`, and
  `AttachmentTrigger` drops `outline-none`. Upstream's arrangement is the card wearing a ring on
  behalf of the invisible full-bleed trigger inside it, with the trigger's own affordance silenced;
  this system has one focus affordance and it belongs on the element that has focus.
  `rounded-[inherit]` on the trigger is part of the same hunk: the trigger is `absolute inset-0`
  inside a `rounded-xl` (or `rounded-lg` at `size="xs"`) card, so without it the outline would cut a
  rectangle across the card's corners.
- **A11Y-2** — audited, **no hunk**. Every control in this file is a `Button`: `AttachmentAction`
  defaults to `size="icon-xs"`, which is `size-6` — 24px, exactly on the SC 2.5.8 floor — and
  `AttachmentTrigger` is the full card. `attachment.test.tsx` measures both, so the day upstream
  shrinks the action tier below 24px it fails here rather than quietly shipping.
- **A11Y-13** — `AttachmentDescription`'s error ink becomes `text-destructive-text` in place of
  upstream's `text-destructive/80`. Rasterised on `card` with this system's tokens, upstream's pair
  measures 4.113:1 at 12px — a WCAG 1.4.3 failure, and the same pair A11Y-13 already moved onto the
  `-text` ink for Alert, Badge, Toast and the soft Button. It went unnoticed until Batch 6 because
  attachment's test lane ran unstyled and the cross-cutting contrast lane had no attachment
  subject; both gaps are closed. `AttachmentMedia`'s error _icon_ ink is deliberately left
  upstream-verbatim: measured against its own composited `/10` tint it is 3.973:1, over the 3:1
  floor for non-text UI.
- **API-16** — `"use client"` is added. Upstream ships none, and this file calls `useRender`, which
  calls `React.useRef` internally; under the `react-server` condition that hook is `undefined`, so a
  server component rendering it throws on import. The boundary goes at the lowest interactive leaf,
  and this file is it.
- **API-28** — Attachment's scope widens from chat to file and media tiles on any surface.
  `AttachmentGroup` takes `layout="scroll" | "grid" | "tiles"` (upstream's row stays the default), a new
  `AttachmentProgress` part composes `Progress`'s track and indicator and announces
  `aria-valuetext="{n}%"`, `Attachment` takes `muted` (`data-muted`, media at `opacity-50`), and
  image media styles a nested `<img>` with `[&_img]` in place of `*:[img]`, so the system `Image`
  and its fallback fill the slot. The tile overhaul (28-09-2026) adds `columns` (at most N tiles a
  row, container-responsive, and a sized `scroll` row), the `side="start" | "end"` overlay slots with
  the blurred scrim on a vertical tile, `file` / `preview` / `onOpen` and `AttachmentPreview` for the
  whole-tile open into `FileViewer`, and the full name as `AttachmentTitle`'s `title`.
- **DOC-2** — `import { cn } from "cn"` becomes `@vegastack/design`; our npm layer owns `cn`.
- **DOC-1** — prettier reflow plus the `registry-stamp.mjs` provenance header the three-copy model
  needs; no decision of its own.
