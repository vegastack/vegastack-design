## Usage

```tsx
import { FilterBar, FilterBarFacet } from "@/components/ui/filter-bar";
import { ToggleGroup, ToggleGroupItem } from "@/components/ui/toggle-group";

<FilterBar
  aria-label="Task toolbar"
  search={{
    value: query,
    onValueChange: setQuery,
    placeholder: "Search tasks",
  }}
  scope={
    <ToggleGroup
      aria-label="Scope"
      variant="outline"
      spacing={0}
      deselectable={false}
      value={[scope]}
      onValueChange={([v]) => v && setScope(v)}
    >
      {/* My tasks | Created by me | Team */}
    </ToggleGroup>
  }
  view={
    <ToggleGroup
      aria-label="View"
      variant="outline"
      spacing={0}
      deselectable={false}
      value={[view]}
      onValueChange={([v]) => v && setView(v)}
    >
      {/* List | Board */}
    </ToggleGroup>
  }
  facets={
    <>
      <FilterBarFacet label="Status" {...status} />
      <FilterBarFacet label="Due" {...due} />
      <FilterBarFacet label="Assignee" {...assignee} />
    </>
  }
  addFilters={[{ id: "priority", label: "Priority" }]}
  onAddFilter={showFacet}
  onClear={clearAll}
/>;
```

```
Row 1  [Search………………………]  [scope segmented]                 [view segmented] [actions]
Row 2  Status ▾   Due ▾   Assignee ▾   ⊕ More                               Clear
```

`FilterBar` is **presentational** — it never holds filter state. You own every value: the search
query, the scope and view, each facet's selection, the `filters` chips, what a "More" option adds,
and what "Clear" resets.

## Examples

### Anatomy

```tsx
<FilterBar
  search={{ value, onValueChange }} // row 1, first — a <SearchInput> that takes the free space
  scope={/* ToggleGroup */} //          row 1, after the search
  view={/* ToggleGroup */} //           row 1, pinned to the end
  actions={/* e.g. a Select Button */} // row 1, very end
  facets={/* FilterBarFacet… */} //     row 2, the primary filters
  filters={[/* … */]} //                row 2, one removable <FilterChip> per applied filter
  addFilters={[/* … */]} //             row 2, the "More" <DropdownMenu> of secondary filters
  onClear={clearAll} //                 row 2, "Clear" at the end while anything is applied
/>
```

- `FilterBar` — the container (`data-slot="filter-bar"`, `role="toolbar"`, named "List controls"
  by default; pass `aria-label` or `aria-labelledby` for a specific name like "Task toolbar"). It
  is a size container: its layout follows its own width, not the viewport's.
- **Row 1** (`filter-bar-primary`) — the search field, `scope` (`filter-bar-scope`), `view`
  (`filter-bar-view`) and `actions` (`filter-bar-actions`). Rendered when any of them is set.
- **Row 2** (`filter-bar-filters`, a `role="group"` named by `filtersLabel`, "Filters") — the facets,
  the chips, "More" (`filter-bar-add`), `trailing` and "Clear" (`filter-bar-clear`). Rendered only
  when there is something to filter.
- **One height.** Every control in both rows is h-8, the default size, with a 6px gap. Leave
  `ToggleGroup`, `Button` and `Select` at their default size inside the bar; one passed in at
  `size="sm"` is lifted to h-8.
- **Narrow bar** (below the bar's own `@3xl`, 768px): the scope takes its own full-width row
  (`filter-bar-scope-row`), the view shows icons only (wrap each option's text in a `<span>`; it
  stays the option's accessible name), and row 2 folds into one "Filters (n)" button
  (`filter-bar-sheet-trigger`) that opens a bottom sheet with the facets stacked, "Clear" and "Done".

### Committed search

Send the query from `search.onValueCommitted`, which fires with the settled value — after
`search.debounceMs` (300 ms by default) of quiet, and at once on Enter and on clear — while
`onValueChange` keeps the field instant. `searchPlacement` is deprecated and ignored: the search is
always first.

### Facets

`FilterBarFacet` is one filter on [`SearchableSelect`](/docs/components/searchable-select). Unset,
it is a quiet borderless trigger that reads just its label: _Status ▾_. Set, it becomes a filled
pill — _Status: Open_, _Status: Open, In progress_, then _Status (3)_ from three values — with a ×
named "Clear Status" that clears it. Use short, sentence-case labels ("Status", "Due date"); never
"Any", "All statuses" or "Select status". Its search box reads "Search status" and an empty result
reads "No matches" unless you pass `searchPlaceholder`, `searchLabel` or `emptyMessage`.

It takes SearchableSelect's item props — `multiple`, `remote` with `useAsyncSearch` for a
server-searched facet, `leadingItems`, `itemToDescription` — plus `pinSelected` (the chosen options
first, under "Selected") and `removable` with `onRemove` for a secondary facet added from "More":
clearing it also removes it, and while unset it carries a remove control beside it. `anyLabel` is
deprecated and ignored.

Put the primary facets in the bar's `facets` slot. A facet lives in the bar, never inside the
"More" menu — a combobox inside a menu is a trap. To offer one from the menu, show it in `facets`
once its option is chosen, `removable`. The bar counts the facets that hold a value (plus the
`filters` chips) for "Clear" and "Filters (n)"; pass `activeCount` to count differently.

### Editing a filter

Give a filter an `editor` and its chip's label and value become a button (`FilterChipTrigger`,
named `{label}: {value}`) that opens the editor in a popover; <kbd>Escape</kbd> closes it and returns
focus to the chip. The chip itself stays non-interactive and the remove control stays its own 24px
target. `onEditorOpenChange(id, open)` reports each open and close — commit on close, or live.

A "More" option can carry the same `editor`: choosing it opens the editor on the chip the
host adds with that option's `id`, so a filter is added and edited in one step.

### Scope (presentational core)

`FilterBar` is a **presentational** primitive (Model A — the component owns rendering; your app
owns the state). Stateful behaviour stays with the host, and each has a composition path:

- **Applied-filter state** — you hold the filter model and map it to `facets` and `filters`.
- **Clear** — pass `onClear`; the bar shows "Clear" while anything is applied.
- **Saved views, AI-suggested filters** — app concerns; put a control in `trailing` or `actions`.

The fully-stateful nested builder is [`FilterBuilder`](/docs/components/filter-bar-managed).

## Accessibility

- The bar is a named `role="toolbar"` ("List controls" by default; set `aria-label` or
  `aria-labelledby` for a specific name like "Task toolbar"), and its filter row is a
  `role="group"` named "Filters" (`filtersLabel`).
- Name the `scope` and `view` groups (`aria-label="Scope"`, `aria-label="View"`). On a narrow bar
  the view's text is visually hidden, not removed, so each option keeps its name.
- A set facet and every chip carry a round 24×24 × (WCAG 2.5.8) named `Clear {label}` — "Clear
  Status". Clearing a facet moves focus to its trigger; "Clear" moves focus to the filter row's
  first control, so focus never drops to the page.
- "More" is a labelled `Button` that opens a keyboard-navigable `DropdownMenu`.
- The narrow bar's "Filters (n)" button opens a modal bottom sheet titled "Filters"; <kbd>Esc</kbd>
  or "Done" closes it and returns focus to the button.
- The search field always has an accessible name — `search["aria-label"]`, then the placeholder,
  then "Search".

| Key                                 | Action                                                                 |
| ----------------------------------- | ---------------------------------------------------------------------- |
| <kbd>Tab</kbd>                      | Move through the search, scope, view, facets, chips, "More" and Clear. |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Open a facet or "More", press a segment, or clear the focused pill.    |
| <kbd>↑</kbd> / <kbd>↓</kbd>         | Move between options in an open facet or "More" menu.                  |
| <kbd>Esc</kbd>                      | Close the open facet, menu or filters sheet.                           |
