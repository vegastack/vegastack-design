## Accessibility

- Renders Base UI's Slider, which gives every thumb `role="slider"` with `aria-valuenow`,
  `aria-valuemin` and `aria-valuemax`; <kbd>←</kbd>/<kbd>→</kbd>, <kbd>Home</kbd>, <kbd>End</kbd> and
  <kbd>PageUp</kbd>/<kbd>PageDown</kbd> all move it.
- The thumb is 12px, so an `::after` pseudo-element extends its pointer target to 28×28 (A11Y-2),
  verified by a real `elementFromPoint` probe.
- On `:focus-visible` the global 2px outline in `base.css` applies (FOC-1) — upstream's
  `hover:ring-3 focus-visible:ring-3 active:ring-3` glow is gone (FOC-6).
- A slider has no visible text of its own — give it an `aria-label`. That label reaches the hidden
  `<input type="range">` that actually holds the role, which is what a screen reader announces. A
  `Label htmlFor` pointed at the Slider's `id` does **not** name it: the `id` lands on the root
  `<div>`, and the input keeps a generated one.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/slider.patch`. Every hunk:

- **FOC-1, FOC-6** — the thumb's `ring-ring/50` colour and its three glow triggers
  (`hover:ring-3`, `focus-visible:ring-3`, `active:ring-3`) are removed, along with
  `focus-visible:outline-hidden`, which would have suppressed the global outline.
- **FRM-4** — `disabled:pointer-events-none` is dropped, so a disabled slider stays hoverable and a
  Tooltip can explain it.
- **A11Y-16** — the root's `aria-label` is forwarded to every thumb through `getAriaLabel`. Base UI
  keeps the real control in a visually hidden `<input type="range">` inside the thumb, and a label
  on the root lands on a `<div>` with no role, so upstream's file ships a nameless `role="slider"`
  in every composition. A range slider gives both thumbs the group's name: upstream has no
  per-thumb label API.
- **DOC-2** — `cn` is imported from `@vegastack/design`.
