## Usage

```tsx
import {
  PropertyLabel,
  PropertyList,
  PropertyRow,
  PropertyValue,
} from "@/components/ui/property-list";
import {
  RecordLayout,
  RecordLayoutMain,
  RecordPanel,
  RecordPanelAction,
  RecordPanelItem,
  RecordPanelList,
  RecordPanelProvider,
  RecordPanelSection,
  RecordPanelToggle,
  RecordPanelTrigger,
} from "@/components/ui/record-layout";

<RecordPanelProvider
  open={open}
  onOpenChange={rememberOpen}
  sections={folds}
  onSectionOpenChange={rememberFold}
>
  <ShellTopBarPanel>
    <RecordPanelToggle />
  </ShellTopBarPanel>
  <RecordLayout>
    <RecordLayoutMain>
      <PageHeader title="Technical Datasheet design format" />
      <RecordPanelTrigger />
      {/* description, subtasks, activity and comments, in reading order */}
    </RecordLayoutMain>
    <RecordPanel>
      <RecordPanelSection value="details" title="Details">
        <PropertyList variant="panel" aria-label="Task details">
          <PropertyRow>
            <PropertyLabel>Status</PropertyLabel>
            <PropertyValue>…</PropertyValue>
          </PropertyRow>
        </PropertyList>
      </RecordPanelSection>
      <RecordPanelSection
        value="files"
        title="Files"
        count={1}
        action={<RecordPanelAction label="Add file" onClick={add} />}
      >
        <RecordPanelList>
          <RecordPanelItem
            render={<a href={file.href} />}
            icon={<FileText />}
            detail="1.2 MB"
          >
            Strada-Urban-Road-90W.pdf
          </RecordPanelItem>
        </RecordPanelList>
      </RecordPanelSection>
    </RecordPanel>
  </RecordLayout>
</RecordPanelProvider>;
```

`RecordLayout` is a record page. The **main column** holds the work in reading order — title,
description, subtasks or decisions, activity and comments — centred in its reading width, and
nothing in it repeats a field the panel shows. The **side panel** (`RecordPanel`) holds the
reference: one 320px column of stacked sections (Details, Related, Files, Attendees, Versions…),
flush to the page's right edge with one full-height divider from the page bar to the page's
bottom. There is no strip of icons. Never on a list page: a list's rows open in
[`Peek`](/docs/components/peek).

## Open and closed

The page bar's **▥** (`RecordPanelToggle`) is its last control, after ⋯ and a divider
(`ShellTopBarPanel`), and **⌘.** (Ctrl+. elsewhere) does the same from anywhere on the page.

| Record width        | Panel                                                                                 | On load                        |
| ------------------- | ------------------------------------------------------------------------------------- | ------------------------------ |
| from 1200px (75rem) | docks beside the main column, which re-centres its content in the room left           | the person's remembered choice |
| 640–1200px          | ▥ floats it over the page, edge to edge under the bar, with a shadow on its left      | closed                         |
| under 640px         | the "Details" button (`RecordPanelTrigger`) opens the same sections as a bottom sheet | closed                         |

- The app owns the remembered choice (`open`, `onOpenChange` on `RecordPanelProvider`) and keeps
  it per person; only the docked panel is remembered. A floating panel and a phone sheet are
  never remembered and never open on their own.
- A docked panel that is open on load is drawn by the server, so nothing moves when the page
  hydrates. A person's open plays the motion once (`duration-panel`): docked, the panel grows
  from nothing and the work slides to stay centred; floating, it slides in from the edge.
  Reduced motion plays none.
- The breakpoints follow the record layout's own width (a container query), not the window's,
  so a collapsed column or a split window picks the right one.
- In the shell, `RecordLayout` reaches past the page gutter to the page's edges; the main column
  takes the gutter back as its padding and scrolls on its own, as the panel does.

## Sections

Each `RecordPanelSection` is a 40px header — fold chevron, title (14/600), a muted count and one
optional action (`RecordPanelAction`, "+" by default) that shows on hover or focus — over its
rows, 16px in from the panel's edges, with a hairline under it. The app keeps each section's fold
per record type (`sections`, `onSectionOpenChange` on `RecordPanelProvider`); `defaultOpen`
stands until the person folds it. `useRecordPanel()` gives the page around the panel its controls —
`shown`, `toggle` and `reveal(value)`, which shows the panel and opens that section scrolled into
view (a menu's "Versions"); it is null outside a provider, as in a peek. Fix the order per record type; never reorder sections per record.

Two row shapes, the same everywhere:

- **Key and value** — `PropertyList variant="panel"`: a 92px muted key, the value at the same
  size, rows at least 30px tall; a plain value truncates, an editable one is a quiet picker or a
  ghost Record Chip in place.
- **A list of records** — `RecordPanelList` of `RecordPanelItem`s (files, contacts, related
  records, transcript lines): an optional icon, the text truncating, a muted trailing detail
  (a size, a relation, a role, a time). A row that opens something takes `render` (a link or a
  button) and the hover layer, which runs 8px past the text with the item radius.
  `RecordPanelEmpty` is a section's one-line empty state.

The panel's surface is `bg-panel` ([Colors](/docs/foundations/colors), COL-26): a hair off the
page in both themes.

### Tabs, counts and loading

## Accessibility

- The panel is an `aside` (a complementary landmark) named by the provider's `label` ("Details").
  Each section is a `section` named by its title; the title is an `h3` holding the fold button,
  which carries `aria-expanded` and reads the count after the title ("Files 1").
- ▥ is a button named "Hide details" or "Show details", with `aria-expanded` and, while the panel
  shows, `aria-controls`; its tooltip names ⌘. too. The phone's Details button opens a modal bottom
  sheet named "Details", with its own close button.
- Docked beside the page, the panel stays put on Escape. Floating over the page, it takes focus
  when it opens; Escape or a click on the page closes it, and focus returns to ▥.

| Key          | Action                                                             |
| ------------ | ------------------------------------------------------------------ |
| ⌘. / Ctrl+.  | Shows or hides the panel (the sheet on a phone).                   |
| Enter, Space | On ▥: the same. On a section's header: folds or opens the section. |
| Escape       | Closes a floating panel (not a docked one); focus returns to ▥.    |
