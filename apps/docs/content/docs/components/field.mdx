## Usage

```tsx
import {
  Field,
  FieldDescription,
  FieldError,
  FieldGroup,
  FieldLabel,
  FieldLegend,
  FieldSet,
} from "@/components/ui/field";

<FieldSet>
  <FieldLegend>Profile</FieldLegend>
  <FieldGroup>
    <Field>
      <FieldLabel htmlFor="name">Full name</FieldLabel>
      <Input id="name" />
      <FieldDescription>This appears on invoices.</FieldDescription>
    </Field>
  </FieldGroup>
</FieldSet>;
```

## Anatomy

<Anatomy name="field" />

A field is a label, a control, optional helper text and an optional error, in that order.
`FieldContent` is the flex column that keeps a label and its description together when the control
sits beside them; it is not needed when there is no description.

### Responsive Layout

- **Vertical** — the default: label, control, helper text, stacked.
- **Horizontal** — `orientation="horizontal"` puts the label and the control on one row; pair it
  with `FieldContent` to keep descriptions aligned.
- **Responsive** — `orientation="responsive"` switches between the two on the `@md/field-group`
  container query, so the layout follows the form's own width rather than the viewport's.

### Validation and Errors

Put `data-invalid` on the `Field` to switch the whole block into its error state; the control inside
it is marked `aria-invalid` for you. `FieldError` takes children, or an `errors` array it
de-duplicates into a list.

### Automatic wiring

Inside a `Field`, the control needs no ids and no `aria-*` props. `Field` renders Base UI's Field
underneath, so the control is labelled by `FieldLabel`, described by the `FieldDescription` and
`FieldError` that are rendered right now, and marked `aria-invalid` when the `Field` carries
`data-invalid`. An explicit `id` or `htmlFor` still wins, and an explicit `aria-describedby` keeps
its ids first. A control outside a `Field` is unchanged.

## Accessibility

- `FieldSet` and `FieldLegend` render a real `<fieldset>`/`<legend>`, so a screen reader announces
  the group's name before every control inside it.
- `Field` is a `role="group"` on Base UI's Field, so the control inside it is labelled by
  `FieldLabel`, described by the rendered `FieldDescription` and `FieldError`, and marked
  `aria-invalid` from the Field's `data-invalid` — with no ids to keep in sync (API-26).
- `FieldError` is `role="alert"` and carries a leading icon, so an error is never signalled by
  colour alone (A11Y-8), and its ink is the `destructive` family's `-text` role, which clears AA on
  the page (A11Y-13).
- The choice card carries no focus ring: the control inside it wears the global 2px outline
  instead (FOC-12), so focus is always on the thing that actually takes it.
- Use `FieldSeparator` sparingly — each one is a section boundary a screen reader has to cross.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/field.patch`. Every hunk:

- **FOC-1, FOC-3, FOC-6, FOC-12** — the choice card's
  `has-[>[data-slot=field]]:has-[:focus-visible]:border-ring` plus `ring-3 ring-ring/50` is removed
  outright. Field restates no focus chrome of its own: a text control inside it owns the `:focus`
  border tint (FOC-3), and a checkbox, radio or switch inside it wears the global `:focus-visible`
  outline (FOC-12).
- **API-26** — `Field`, `FieldLabel`, `FieldDescription` and `FieldError` render Base UI's
  `Field.Root`, `Field.Label`, `Field.Description` and `Field.Error` inside a `Field`, and
  `data-invalid` also sets Base UI's `invalid`, so the control reads its label, description ids and
  invalid state from the Field. Outside a `Field` each part renders upstream's plain element.
- **A11Y-8, A11Y-13, COL-12** — `FieldError` gains a leading `CircleAlertIcon` so the error is not
  signalled by colour alone, and its ink becomes `text-destructive-text`, the `destructive`
  family's text role. Upstream's `text-destructive` is the fill, which measures under AA as ink.
  `Field`'s own `data-[invalid=true]:text-destructive` moves to the same role.
- **DOC-2** — `cn` is imported from `@vegastack/design`.
