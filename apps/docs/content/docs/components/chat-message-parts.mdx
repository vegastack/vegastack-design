## Usage

```tsx
import { MessageParts } from "@/components/ui/chat-message-parts";

<MessageParts
  message={message}
  detail={readerSetting}
  live={turnRunning}
  renderData={{
    "data-plan": (part) => <ChatPlanCard data={part.data as PlanData} />,
  }}
  onOpenSubagent={openBeside}
/>;
```

`message` is an AI SDK `UIMessage` (typed structurally, so the registry needs no `ai` dependency).
From the top: the task list when there is one (it **is** the turn's progress); the work line —
`LiveLine` while the turn runs, the only moving thing, then `WorkSummary`, the same 28px so the
swap never reflows — over the work log; then the Subagents block, the answer's text (never folded,
new prose fading in while it streams), files and the cards the app draws for data parts; last, an
error row. Every sentence comes from the server (`providerMetadata.vegastack`, `metadata.turn`).

The reader setting decides how much work shows: **Summary** (the default) keeps the log closed;
**Normal** opens it while the turn runs and folds it when the answer starts; **Verbose** also opens
the thinking notes and each call's input. A person's own toggle wins until the setting changes.

## Accessibility

- The live words are a polite status for screen readers; the ticking timer is hidden from them.
- The work line is a disclosure button (`aria-expanded`) for the log.
- A message renders at most one `TextSpinner`, whatever its parts (a tested invariant).
