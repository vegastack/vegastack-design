## Usage

```tsx
import { ValueChange } from "@/components/ui/value-change";

<ValueChange before="Draft" after="Published" />;
<ValueChange before={null} after="Asha Kumar" />; // added
<ValueChange before="25 Oct" after={null} />; // removed
```

## Examples

### Changed

Both sides present: the old value in a `<del>`, struck through in the destructive ink, a
muted arrow, and the new value in an `<ins>` in the success ink with no underline. It sits
inline in a sentence and inherits the surrounding text size.

### Added and removed

Only `after` is an addition and only `before` a removal — the absent side and the arrow are
not drawn. `null`, `undefined`, `false` and an empty string count as absent; `0` does not.
With neither side it renders nothing.

## Accessibility

- The values are real `<del>` and `<ins>` elements, so the edit survives copy, reader mode
  and assistive tech that announces insertions and deletions.
- The arrow is `aria-hidden`; visually hidden connectives make the spoken sentence
  "changed from Draft to Published", "added Asha Kumar" or "removed 25 Oct". Each value is
  rendered once.
- Colour is never the only cue: the removed value is also struck through, and the sentence
  says which side is which.
- The component is server-safe — no client boundary.
