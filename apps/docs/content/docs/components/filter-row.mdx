## Usage

```tsx
import { AddFilterMenu } from "@/components/ui/add-filter-menu";
import {
  FilterRow,
  ListFacet,
  useAiFilterApplied,
} from "@/components/ui/filter-row";

const onAiApplied = useAiFilterApplied();

<ListToolbar
  filterRow={
    <FilterRow
      addFilter={
        <AddFilterMenu
          fields={fields}
          onPick={addFilter}
          ai={{
            onSubmit: runAiFilter,
            onApplied: (result) =>
              onAiApplied({
                count: result.added,
                unmatched: result.unmatched,
                onUndo: undoAi,
              }),
          }}
        />
      }
      facets={
        <ListFacet
          label="Status"
          multiple
          items={statuses}
          value={status}
          onValueChange={setStatus}
        />
      }
      chips={chips}
      onClear={clearAll}
    />
  }
/>;
```

The order never changes, so chips never jump:

1. **Pinned facets** (`facets`), in the page's order. Unset, a facet is a dashed outline that reads
   as an offer (`+ Due`); set, it is a solid chip. A facet with a custom editor is an `unset`
   `FilterChip` (below).
2. **Other chips** (`chips`), in the order they were added — from + Filter, a preset or the AI.
   A preset resolves to ordinary chips; there is no separate preset chip.
3. **`+ Filter`** (`addFilter`), right after the last chip, inside the scrolling line.
4. **Clear**, right beside `+ Filter`, only while something is set.

Chips made by an AI filter (`source: "ai"`) lead with ✦ until the filter is edited. What a run did
is a toast, never a line under the row: `useAiFilterApplied()` returns `onAiApplied`, which shows
"2 filters added by AI" (and "Couldn't match “warehouse”") with **Undo**, which removes exactly that
run's chips. Call it from `AddFilterMenu`'s `ai.onApplied` and after the toolbar search's
suggestion. Unknown words are listed, never guessed.

The facets, chips, `+ Filter` and Clear are **one line at every width**: it scrolls sideways with an
edge fade and never wraps to a second line. When a chip's picker opens (or a chip takes focus), the
line scrolls that chip into view — only the row moves, never the page. Every control on the row — facets, chips, `+ Filter`, Clear — is the
toolbar's tool height: 32px, or 28px in a `size="compact"` toolbar. The row counts what is applied
(its chips plus its set facets) and tells the enclosing
[`ListToolbar`](/docs/components/list-toolbar), whose Filter tool shows the count.

### ListFacet

One filter on [`SearchableSelect`](/docs/components/searchable-select), in the row's one chip
shape: the row's height (32px; 28px compact), rounded-md, quiet type. Unset it reads just its label (_Status ▾_); set it is
tinted and reads _Status: Open_, then _Status: 2_ from two values (the values in the chip's tooltip
and ticked in the popover), with a × named "Clear Status" in the chevron's fixed slot. Use short,
sentence-case labels; never "Any" or "All statuses". The search box shows only when the list is
worth searching (more than 7 options, or a `remote` list); `searchable` forces it on or off.

It passes `SearchableSelect`'s props through (minus the trigger face it owns: `renderItem`,
`renderValue`, `renderTriggerValue`, `placeholder`, `variant`, `size`, `aria-label`, `groupBy`
and `groupOrder`) — `multiple`, `remote` with `useAsyncSearch`, `leadingItems`,
`itemToDescription` — and adds `pinSelected` (the chosen options first, under "Selected") and
`removable` with `onRemove`. The tick matches by `itemToKey`, so options from a server search tick
as static ones do. For people, pass `itemToSecondaryLabel={(p) => p.email}` (and `itemToAvatar`):
each option is one `PersonOption` ([the person contract](/docs/components/searchable-select#people)).

### DateRangeFilter

**The** date filter: every date facet on every list is one, so dates behave the same everywhere. A
chip in the same shape as a facet; its popover lists the page's `presets` as the menus' 28px rows —
Overdue · Today · Yesterday · Tomorrow · This week · Last week · Next week · Last 7 days · Next 7
days · Last 30 days · This month · Last month · No date — and "Custom range", which drills into a
calendar (two months, one on a phone) with Apply in the same popover. The default set looks back
(Today · Yesterday · Last 7 days · Last 30 days · This month · Last month · Custom range); a due date
passes `["overdue", "today", "thisWeek", "next7", "thisMonth", "none", "custom"]`. Set, it reads the
preset ("Due: This week") or the dates ("Due: Sep 1–25"). A value's `from` or `to` is `null` when
the range is open on that side ("Overdue" has no first day; "No date" has neither). Pass `now` in
the same calendar-date convention as the range endpoints; it drives both the presets and the
calendar's Today highlight. `dateRangeForPreset(preset, now, weekStartsOn)` returns the
`{ from, to }` a preset covers, for the query (weeks start on Monday unless `weekStartsOn` says
otherwise). The calendar loads lazily — fetched when the chip is hovered, focused or
opened — so a filter row never puts the calendar engine in the page's first bundle.

### FilterChip

The removable "Label: value" pill `FilterRow` draws for each of its `chips` — the
[`Chip`](/docs/components/chip) primitive in the row's chip shape — exported for a custom row.
Give it an `editor` and its label and value become a button (`filter-chip-trigger`) that opens the
editor in a popover; <kbd>Escape</kbd> closes it and returns focus to the chip, and the × stays its
own 24px target. `unset` draws a pinned facet with no value yet as a dashed `+ Label` offer.

## Accessibility

- The chips are a `group` named "Filters". Each chip's × is named "Clear" and the filter's label.
- An AI chip's ✦ is labelled "Added by AI", so the mark is read with the chip.
- What an AI run did is a toast (announced by the toaster's live region) with an Undo button.
- Clear hands focus back to the row's first control once it unmounts.
- A `ListFacet`, `PeopleFacet` or `DateRangeFilter` is a button named by what it reads ("Status",
  "Status: Open"); its × is named "Clear" and the label, and <kbd>Escape</kbd> closes its popover
  and returns focus to it.

| Key                                 | Action                              |
| ----------------------------------- | ----------------------------------- |
| <kbd>Tab</kbd>                      | Move through + Filter, chips, Clear |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Open a chip's editor, remove, clear |
