### Disabled

A disabled toggle keeps its pointer events (FRM-4), so a Tooltip can explain why it is unavailable.
Base UI's Toggle has no `focusableWhenDisabled`, so the native `disabled` attribute stays and the
control leaves the tab order — this is the pointer half of FRM-4 only.

<ComponentPreview name="toggleDisabled" file="components/preview/toggle.tsx" />

### RTL

Every size is written in logical properties, so a right-to-left document mirrors padding and icon
spacing without any extra work.

<ComponentPreview name="toggleRtl" file="components/preview/toggle.tsx" />

### Loading

`loading` is ours (API-5). It shows a spinner over the label, sets `aria-busy`, blocks activation,
and keeps the label's box at `opacity: 0` — so the toggle's width does not move and its accessible
name survives (A11Y-12).

## Accessibility

- Renders a native `<button>` through Base UI's Toggle, carrying `aria-pressed` for the on/off
  state; <kbd>Enter</kbd> and <kbd>Space</kbd> flip it.
- On `:focus-visible` the global 2px outline in `base.css` applies (FOC-1). The recipe carries no
  focus ring, no `ring-3` glow and no `outline-none` of its own (FOC-6).
- An icon-only toggle has no visible text — give it an `aria-label`, as every example here does.
- `loading` sets `aria-busy="true"` and keeps the label in the accessibility tree (A11Y-12).
- The pressed state is never carried by colour alone: the fill changes and `aria-pressed` changes
  with it.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/toggle.patch`. Every hunk:

- **FOC-1, FOC-6** — the `focus-visible:border-ring focus-visible:ring-[3px] focus-visible:ring-ring/50`
  glow and the `outline-none` that suppressed the global outline are removed, along with the
  `aria-invalid:ring-destructive/20` and `dark:aria-invalid:ring-destructive/40` halos.
- **FOC-5** — the invalid tint becomes `not-focus:aria-invalid:border-destructive`, so focus
  outranks it.
- **FRM-4** — `disabled:pointer-events-none` is dropped, so a disabled toggle stays hoverable and a
  Tooltip can explain it. Base UI's Toggle has no `focusableWhenDisabled`, so the native `disabled`
  attribute stays: this is the pointer half of FRM-4 only.
- **API-5, A11Y-12** — the `loading` prop, the out-of-flow spinner and the `opacity-0` label; the
  dim is scoped to `disabled:not-data-loading:opacity-50` so a loading toggle is not dimmed twice.
  This is why `toggle` depends on the `spinner` registry item.
- **DOC-2** — `cn` is imported from `@vegastack/design`.
