## Examples

### Basic

A single-line transport rendered statically on a card. Left to right: play/pause, rewind and
forward (±15s), the combined `elapsed / duration` readout, a flexible seek bar, and a tappable
speed control. Every transport control is a `ghost` Button, so the chrome stays quiet against the
card.
The docs preview uses a 90-second local audio fixture, so it can play without network access.

### Mobile layout

Below the `@sm` container width the transport reflows to two lines while staying compact. The top
line carries the seek bar with `elapsed` and `duration` pinned to either edge in a smaller font;
the bottom line centres play/pause with rewind and forward flanking it, a transcript control on the
leading edge, and the tappable speed on the trailing edge. The transcript control renders only when
`onTranscriptClick` is supplied — wire it to open your app's transcript. The example is width-limited
so the mobile layout is visible on a desktop screen.

### Waveform

Set `variant="waveform"` to render the decoded audio as the seek bar. The waveform is sampled
from the real audio via the Web Audio API — played bars fill as playback advances, and the bars
seek by click, drag, or keyboard just like the slider. Until decoding finishes (or if it fails),
flat placeholder bars render and the seek stays operable.

### Docked with close

Set `docked` to pin the player to the bottom of its scroll column. It is `position: sticky`, so it
sits at the end of the column's content and stays on its bottom edge while the column scrolls, with
a border, the popover surface and a shadow, padded clear of the bottom safe-area inset. A docked
player is a landmark `region` named by `label`, so a screen-reader user can jump to it.

Pass `open` and `onOpenChange` to make it closable. The close button (named by `closeLabel`,
"Close player" by default) pauses playback, calls `onOpenChange(false)` and hands focus back to the
control that opened the player. A hidden player stays mounted and `inert` and slides out with the
docked-control pair, so its playback position survives a hide. Escape does not close it: Escape
belongs to whatever overlay the page opens above it.

### Lazy source

`src` also takes a function that resolves a URL, for a short-lived signed URL you only want to
fetch when someone listens. It is called once, on the first play (or the first `actionsRef` seek),
and the result is kept. While it resolves the player shows its loading line. To load a different
recording, remount the player with a new `key`.

```tsx
<AudioPlayer
  src={() => getSignedUrl(recording.id)}
  label={`${recording.title} recording`}
/>
```

### Loading and error

`loading` shows a status line with `loadingLabel` ("Loading audio…") and announces it once.
`error` renders an alert in the destructive ink with a "Try again" button (`retryLabel`). The retry
reloads the source, resolves a lazy `src` again and calls `onRetry`, where you clear `error`.

### Seek from outside

To jump the player from a transcript line or a chapter list, attach `actionsRef`. Its `seek(seconds,
{ play })`, `play()` and `pause()` are the player's own: a seek made before the metadata loads is
queued and applied on `loadedmetadata`, and a lazy `src` is resolved first. `mediaRef` still
exposes the raw `<audio>` element for anything else, such as reading `currentTime`.

```tsx
const actions = React.useRef<AudioPlayerActions>(null);
const media = React.useRef<HTMLAudioElement>(null);

<AudioPlayer
  src={url}
  label="Call recording"
  actionsRef={actions}
  mediaRef={media}
/>;
<Button onClick={() => actions.current?.seek(line.start, { play: true })}>
  {line.text}
</Button>;
```

## Accessibility

| Key                                 | Action                                                               |
| ----------------------------------- | -------------------------------------------------------------------- |
| <kbd>Tab</kbd>                      | Move through close, play/pause, rewind, forward, seek, and speed     |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Activate the focused button                                          |
| <kbd>K</kbd>                        | Play or pause                                                        |
| <kbd>J</kbd>                        | Rewind 15 seconds                                                    |
| <kbd>L</kbd>                        | Forward 15 seconds                                                   |
| <kbd>M</kbd>                        | Toggle mute                                                          |
| <kbd>←</kbd> / <kbd>↓</kbd>         | Decrease the seek position by one second while the slider is focused |
| <kbd>→</kbd> / <kbd>↑</kbd>         | Increase the seek position by one second while the slider is focused |
| <kbd>Home</kbd>                     | Seek to the beginning                                                |
| <kbd>End</kbd>                      | Seek to the end                                                      |

- Pass a descriptive `label`; it names the media element and prefixes every custom control.
- The seek rail composes `Slider`, so keyboard and screen-reader slider semantics stay intact.
- Icon-only transport buttons are `Button size="icon"`, each carrying its own `aria-label`.
- Tooltips expose the primary keyboard shortcuts for pointer and keyboard users.
- Playback speed is a single tappable button that cycles the rates; its accessible name always
  announces the current speed.
- Rewind and forward are visible buttons on both layouts (inline on a wide player; flanking
  play/pause on the second line of a narrow, mobile-width player) and keyboard shortcuts anywhere
  inside the player (J / L).
- The transcript control appears only on the narrow layout and only when `onTranscriptClick` is
  supplied; it carries an accessible name derived from `label` and opens whatever the consumer wires.
- Mute and a volume rail are present in **both** layouts. The rail is a vertical `Slider` that
  opens from the mute button on hover or focus; mute also stays on the M key. (Before the
  2026-09-07 audit, audio had no volume control at all and mute was keyboard-only.)
- The seek thumb is hidden at rest only where a pointer can hover. On a touch device it stays
  visible — without it there is no scrub affordance at all.
- The native `<audio>` element is used as the media engine and does not expose browser-native
  controls; VegaStack renders the consistent control surface.
- A docked player is a `region` named by `label`, not a toolbar: every control keeps its own tab
  stop and the seek rail keeps its arrow keys. A hidden player is `inert`, so nothing invisible is
  focusable, and closing returns focus to the control that opened it. Escape does not close it.
- `loading` is announced once through a polite live region; `error` is a `role="alert"` line in
  the `-text` ink, with the retry as a separate button after it.

## Do / Don't

<DoDont
  do="Use AudioPlayer for a single audio asset that needs a compact, branded transport."
  dont="Use AudioPlayer for playlists, queue management, or waveform editing."
/>

<DoDont
  do="Dock the player at the bottom of the column that holds the recording's transcript or notes, so it stays in reach while they scroll."
  dont="Put playback in an ActionBar: that bar is a toolbar of bulk actions over a selection, parked at the viewport edge, and a transport is neither."
/>
