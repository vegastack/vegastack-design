## Usage

```tsx
import { AgentEditBanner } from "@/components/ui/agent-edit-banner";

<AgentEditBanner
  agent={{ name: "Claude", for: "Manoj" }}
  changeCount={group.writes}
  at={group.lastWriteAt}
  status={
    undoing ? "undoing" : approving ? "approving" : refused ? "refused" : "idle"
  }
  onViewChanges={group.canDiff ? () => openDiff(group) : undefined}
  onApprove={canEdit ? () => approve(group) : undefined}
  onUndo={canEdit && group.canUndo ? () => undo(group) : undefined}
  onOpenVersions={() => openVersions()}
  onDismiss={() => dismiss(group.runIds)}
/>;
```

The banner is presentational: the host owns the agent's runs, the undo, the approval, the refusal
and the dismiss memory, and passes the state back. `agent` is the agent as a `Person` reads it — `name`
("Claude") and `for` its owner ("Manoj") — so the line says "Claude for Manoj" and the refused
sentence uses the short name. **The callbacks decide which buttons show**: leave out `onUndo` and
`onViewChanges` when the agent's checkpoint is gone, and every callback but `onDismiss` for a
read-only viewer. When the undo succeeds, remove the banner and show a toast.

**Approve** says "these changes are fine": pass `onApprove` and Approve shows beside Undo. The
banner keeps no record of it — store the approval, set `status="approving"` while it saves, then
stop rendering the banner. Unlike ✕, which only hides it for this viewer, an approval is the
decision the host keeps. Both are outline buttons, like every action on the banner.

## Scope

Pin it under a document's header, above the text, and reserve its space only while it shows.
Render at most two; pass the rest to the second one's `moreAgents`, which ends its line with "+1
more agent" and lists each in a popover with its own Approve and Undo. Every string comes in through `labels`
(and `refusedReason` for the refused line), with the English defaults below.

### States

`approving` spins Approve and `undoing` spins Undo; either disables every action, so an approval
and an undo never race. `refused` adds the reason line and swaps Undo for
Open versions; pass `refusedReason` for another reason ("…because the page was restored since.").
Without `onUndo` and `onViewChanges` (too old), or any action (a read-only viewer), the banner is
words and the ✕ — or words alone without `onDismiss`. `kind="created"` reads "Created by Claude
for Manoj · 5m ago".

## Accessibility

- The banner is an `Alert` status region with `aria-live="polite"`, so a banner that changes
  while on screen is announced without interrupting; the relative time inside it ticks silently.
- The buttons are named for the agent: "View Claude for Manoj's changes", "Approve Claude for
  Manoj's changes" and "Undo Claude for Manoj's changes", so two stacked banners never offer two
  identical names.
- The purple bot is decoration (hidden from assistive tech); the words say it was an agent.
- While undoing or approving, that button is busy (`aria-busy`) and every action stays focusable
  but inert.

| Key                                 | Action                                                      |
| ----------------------------------- | ----------------------------------------------------------- |
| <kbd>Tab</kbd>                      | Move through the time, "+N more agents", the buttons and ✕. |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Activate a button, or open the list of the other agents.    |
| <kbd>Esc</kbd>                      | Close that list and return focus to "+N more agents".       |
