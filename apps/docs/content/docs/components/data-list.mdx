## Usage

```tsx
import { DataList, type DataListColumn } from "@/components/ui/data-list";

interface User {
  id: string;
  name: string;
  role: string;
}

const columns: DataListColumn<User>[] = [
  { key: "name", header: "Name", sortable: true },
  { key: "role", header: "Role" },
];

<DataList columns={columns} data={users} getRowId={(u) => u.id} />;
```

`DataList<T>` is generic over the row type, so `render`, `getRowId`, and the selection/sort callbacks
are all fully typed against your data.

## Anatomy

`DataList` is a single generic component composed on top of the design-system primitives — it renders a
[`Table`](/docs/components/table) using the shared `@vegastack/data-table-parts`
([a shared internal](/docs/guides/components#shared-internals), installed with this component):
the sort header, the selection cells, the skeleton rows, the empty row and the column class rules
it has in common with [`DataGrid`](/docs/components/data-grid).

<Anatomy name="data-list" />

```tsx
<DataList<T>
  columns={[
    { key, header, render?, sortable?, align?, mono?, nowrap?, minWidth?, mobile?, className?, headerClassName?, interactive? },
  ]}
  data={rows}
  getRowId={(row, index) => string}
  selectable
  selectedIds={selected}            // controlled selection (Set<string>)
  onSelectionChange={setSelected}
  sort={sort}                       // controlled sort ({ key, direction } | null)
  onSortChange={setSort}
  loading={false}
  emptyState={/* optional override */}
/>;
```

- **Root** — one `<div data-slot="data-list-root">` stack in every configuration, holding the
  optional toolbar, the table, the status lines and the optional footer, so nothing `DataList` adds
  lands as a stray child of your own layout. `ref`, `className` and every `<table>` attribute go to
  the `<table data-slot="data-list">` inside it, which sits in the shared scroll viewport.
- **Selection column** — when `selectable`, a leading checkbox column with a tri-state select-all in the
  header (`data-slot="checkbox"`); each body row carries `data-selected` when picked.
- **Sortable header** — sortable columns render a ghost `Button` (`data-slot="data-table-sort"`)
  inside `<th data-slot="data-list-head">`, which carries `aria-sort` on every sortable column
  (`"none"` included) and `data-sorted="asc|desc"`; clicking cycles **asc → desc → cleared**. Its
  label wears the plain header's own `text-sm font-medium` in `text-foreground`, so sortable and
  static headers read as one row.
- **Body** — one `<tr data-slot="data-list-row">` per row; cells use `column.render` or fall back to
  `row[column.key]`, and **wrap by default** (see Wrapping below). A selected row keeps a light
  `bg-muted/50` wash through hover and press — light enough that a `secondary` Badge inside it
  stays visible (the full `accent` is the badge's own fill).
- **Loading** — skeleton rows (`data-slot="data-list-skeleton-row"`) replace the body while
  `loading`; the table gets `aria-busy` and a live status while placeholder rows stay `aria-hidden`.
- **Empty** — a single full-width row (`data-slot="data-list-empty-row"`) hosting the `emptyState`.
- **Merged stack** — when the container is too narrow, overflow columns render inside the first
  cell as `<span data-slot="data-list-merged">`, the sorted one marked `data-sorted`.
- **Status lines** — under the table, in `<div data-slot="data-list-status">`: a column dropped with
  `mobile: "hidden"` is counted in `<p data-slot="data-list-hidden-hint">`, and a sort whose column
  is merged or hidden is stated in `<p data-slot="data-list-sort-hint">` (see Fitting the width).

## Examples

### Selection

Pass `selectable` to add the checkbox column. Selection is **controllable** — lift it with
`selectedIds` + `onSelectionChange`, or omit both for built-in uncontrolled state. The header checkbox is
indeterminate when only some rows are selected, checked when all are, and toggles every row on click.

### Sorting

Mark a column `sortable` to make its header interactive. Sorting is **controlled by intent**: `onSortChange`
fires with the next `{ key, direction }` (or `null` when cleared) and **you** re-order `data` — the same API
works for client-side and server-side sorting. The header reflects the active sort with an arrow icon,
`aria-sort`, and `data-sorted`.

```tsx
const [sort, setSort] = React.useState<SortState | null>(null);

<DataList
  columns={columns}
  data={sortRows(rows, sort)} // your comparator
  getRowId={(r) => r.id}
  sort={sort}
  onSortChange={setSort}
/>;
```

### Row activation

Pass `onRowClick` to make rows activatable — for navigating to a detail page, opening a drawer, and
so on. `DataList` stays presentational: it only _signals_ the activation; the host decides what it does.

```tsx
<DataList
  columns={columns}
  data={rows}
  getRowId={(r) => r.id}
  onRowClick={(row) => router.push(`/people/${row.id}`)}
/>
```

### Activation accessibility

Activatable rows are built to **preserve native table semantics**. The `<tr>` is **not** given
`role="button"` / `tabIndex` — overriding the implicit `role="row"` would make its `<td>`/`<th>`
children invalid cells for assistive tech and break row/column navigation. Instead:

- The `<tr>` keeps `role="row"` and gets a mouse-only `onClick` (a `<tr>` may carry `onClick` with no
  role — that's valid) plus `data-clickable` for styling.
- A real `<button data-slot="data-list-row-action">` is injected into the **first** cell as the
  keyboard / screen-reader activation control — it is focusable and fires on <kbd>Enter</kbd> /
  <kbd>Space</kbd>, with the global 2px `:focus-visible` outline, all inside a valid `<td>`.
- Clicks on the selection checkbox, the injected button, or any nested control are excluded from the
  row's `onClick`, so there's **no double-activation**.

If the **first column already renders its own interactive control** (a link or button), set
`column.interactive` on it so `DataList` skips the injected button (it never nests one interactive
element inside another) — keyboard activation then comes from your in-cell control.

```tsx
const columns: DataListColumn<Person>[] = [
  {
    key: "name",
    header: "Name",
    interactive: true, // first column owns its focusable control → skip injected button
    render: (p) => <a href={`/people/${p.id}`}>{p.name}</a>,
  },
  // …
];

<DataList
  columns={columns}
  data={rows}
  getRowId={(p) => p.id}
  onRowClick={open}
/>;
```

### Load more (keyset)

A list fetched by cursor has no total and no page numbers. Pass `loadMore` and `DataList` renders
the shared [`LoadMore`](/docs/components/load-more) footer below the table (above `footer`): an
outline _Load more_ button, a busy state that keeps the loaded rows, an error line with _Try again_,
and — only when you pass `endLabel` — a caption once `hasMore` is false. While `hasMore` is true
the table reports `aria-rowcount="-1"`, because the total is unknown.

`loadMore.loading` is a next-batch fetch; the list-level `loading` prop is the first-load skeleton.

### Row actions

`rowActionsColumn({ getRowLabel, actions })` adds a trailing column with one ⋯ menu per row, named
for the row (_Actions for Ada Lovelace_). It is end-aligned, stays visible on narrow widths, and is
`interactive`, so opening the menu never activates the row. Each `RowAction` runs `onSelect`, or
renders as a real link through `render={<a href="…" />}`; `destructive` paints it in the destructive
ink; `disabled` keeps it in the menu — still reachable by the arrow keys — and `disabledReason` is
read as its description. A row with exactly one action that has an `icon` gets an icon button with a
tooltip instead of a menu. The column header is _Actions_ for assistive tech only.

`data-table-parts`; Board cards and SortableList rows use the same parts.

### Sections

`sections` plus `getRowSection` split the rows into collapsible sections under the one header, in
the order you list them: each non-empty section is its own `<tbody>` headed by a `SectionRow` — a
`th scope="rowgroup"` with a disclosure button and the row count in muted tabular numerals (a
section's `count` wins, for a server total). Empty sections are omitted, rows in no listed section
follow without a header, and select-all covers every loaded row. The collapsed state is
`groupState` / `defaultGroupState` / `onGroupStateChange`, the same `GroupState` DataGrid's groups use.

### Fitting the width

`DataList` never forces a horizontal scroll. It measures its container and fits the columns into
it with the same **responsive column revelation** as [`DataGrid`](/docs/components/data-grid): every
column declares a pixel budget (`minWidth`, default `120`) and a posture for when it no longer fits
(`mobile`, default `"merge"`). Columns are kept left to right while their budgets fit; the first
column always stays, and once one column overflows every column after it overflows too, so a narrow
late column never survives a wide earlier one.

| `mobile`    | When the column no longer fits                                                                           |
| ----------- | -------------------------------------------------------------------------------------------------------- |
| `"merge"`   | **Default.** Stacks under the primary (first) column's value, with its header as a screen-reader prefix. |
| `"visible"` | Never hides — the column is essential; if the columns still do not fit, the table is squeezed (below).   |
| `"hidden"`  | Drops the column; "N columns hidden" appears under the table, and the table is described by that line.   |

```tsx
const columns: DataListColumn<Person>[] = [
  { key: "name", header: "Name", minWidth: 160 }, // primary: always shown
  { key: "email", header: "Email" }, // merges when it no longer fits
  { key: "amount", header: "Amount", align: "end", mobile: "visible" }, // never hides
  { key: "notes", header: "Notes", mobile: "hidden" }, // dropped and counted
];
```

A leading selection column is budgeted first (40px). `"hidden"` is the only posture that removes a
value, which is why it is opt-in and why it reports itself — use it only when the value is
recoverable elsewhere (a detail page, a drawer). The server render shows every column, because an
unmeasured table has no evidence that anything overflows; on the client the split is corrected in a
layout effect, before first paint.

If a value is still wider than its column once revelation has run — a long unbroken email, a
one-line mono identifier in the first column, several `"visible"` columns — the table is
**squeezed** (`data-squeezed` on the `<table>`): every cell and sort label may then break anywhere
instead of scrolling. The check runs before paint and is re-taken only when the width, the columns
or the data change.

The squeeze reaches inside a custom `render` too: the text in a cell wraps, whatever it says for
itself, so a `truncate` span or a `whitespace-nowrap` row breaks across lines instead of ellipsing
(an auto-layout table cannot truncate, so the ellipsis was never available there). Parts that are
text grow taller to hold a wrapped label: a `Badge` (and `badgeVariants()` on your own element, and
`ToolCallChip`), a `Chip` or `Tag`, a link-variant `Button` (or `buttonVariants({ variant: "link" })`)
and `EditableCell`'s value.

**Controls and fixed-size content are never wrapped by the squeeze**, because their height is fixed
and a label wrapped inside one would spill out of it. They are recognised by what reaches the DOM,
whatever element carries it:

- every other `Button`, and any element styled with `buttonVariants()`, `toggleVariants()`,
  `navigationMenuTriggerStyle()`, `tabsListVariants()` or `stepperNodeVariants()`;
- a native `button`, `input`, `select` or `textarea`, and an element with the role `button`,
  `checkbox`, `combobox`, `radio`, `slider`, `spinbutton`, `switch` or `tab`;
- an `Avatar` and a `Kbd`.

These keep the one-line posture they give themselves (every VegaStack control sets one), and an
`Avatar`, a `Kbd` and a stepper node are held on one line and at full width. An unstyled `button` or
`role="button"` element has no fixed box, so it simply wraps with its cell. The text around a kept
part breaks instead, and the row grows taller. An icon cannot shrink either.

**A kept part wider than the container is the one thing the squeeze cannot fit.** Controls are never
wrapped, so keep the controls and fixed-size parts of every always-shown column small enough to fit,
side by side on one line, in the narrowest container you support; an outline `Button` whose label
alone is wider than the table leaves it nothing to squeeze, and the table scrolls sideways. Put
long text in a link-variant `Button` or a plain `<a>`, which wrap.

**A merged value always wraps.** It does not inherit the first column's posture: under a `mono` or
`align: "end"` first column (both one line by default) every stacked value still breaks inside the
cell — at a space, or anywhere when a single word is wider than the cell — and wears its own
column's face, so prose under a mono invoice number is not set in mono. The first column's own
value keeps its one-line rule, so give a long mono identifier a `minWidth` that fits it.

**Dropped columns and the sort stay visible.** A `mobile: "hidden"` column is counted under the
table. And when the active sort's column is merged or hidden — so its header, arrow and `aria-sort`
are gone — a second line says what the order is (_Sorted by Amount, descending_). `DataList` states
the order rather than forcing the sorted column back into the header row, which would re-open the

### Scope

`DataList` is the **presentational data table** — columns, render functions, row selection,
sortable-header signalling, loading, and empty state. It deliberately does **not** own
data-fetching or app-coupled data management. To make host composition ergonomic it exposes
**presentational slots + callbacks** (no app logic of its own): a `toolbar` slot (above the table),
a `footer` slot (below it), and `onRowClick` (activatable, keyboard-accessible rows). The host drops
its own search/filter and pagination controls into the slots and passes the already-filtered /
already-paged rows:

| Behaviour                                            | Where it lives                                                                                           | Mount point                  |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ---------------------------- |
| Search / filtering                                   | Host owns the query + filtered `data`                                                                    | `toolbar` slot               |
| Pagination / page-size                               | Host owns paging + the current page; [`DataListPager`](/docs/components/data-list-pager) is the control  | `footer` slot                |
| Keyset load-more                                     | Host owns the cursor and the fetch; [`LoadMore`](/docs/components/load-more) is the control              | `loadMore` prop              |
| Row activation (navigate / open)                     | Host's handler                                                                                           | `onRowClick`                 |
| Drag-and-drop reordering                             | The persisted order stays app-coupled; the mechanism is [`SortableList`](/docs/components/sortable-list) | compose it beside this table |
| Board / Kanban layout, grouping & collapsible groups | [`Board`](/docs/components/board) for Kanban; [`DataGrid`](/docs/components/data-grid) for grouping      | shipped                      |
| View persistence (URL / saved views)                 | Host owns the persisted view state                                                                       | —                            |

```tsx
// Host composes search + paging around the primitive
<DataList
  columns={columns}
  data={pageRows} // already filtered + paged by the host
  toolbar={<SearchInput value={q} onValueChange={setQ} />}
  footer={
    <DataListPager
      page={page}
      pageSize={pageSize}
      total={total}
      onPageChange={setPage}
      onPageSizeChange={setPageSize}
    />
  }
  onRowClick={(row) => router.push(`/items/${row.id}`)}
/>
```

Here the host owns a search box (in `toolbar`) and a [`DataListPager`](/docs/components/data-list-pager)
(in `footer`), filtering and paging the data itself — `DataList` only renders the already-filtered,
already-paged rows and the two slots:

grouping, inline editing, multi-key sort, column management, virtualization — is
[`DataGrid`](/docs/components/data-grid), and the Kanban tier is
[`Board`](/docs/components/board); this primitive stays the presentational default.

### Column

`column.render` is **invoked as a plain function inside `DataList`'s own
render, not mounted as a component** — so hooks called directly in its body
become `DataList`'s hooks and corrupt hook order the moment the loading or
empty branch flips. When a cell needs hooks, return a component element and
put the hooks in that component:

```tsx
// ✅ hooks live in RelativeCell, mounted as an element
{ key: "updated", header: "Updated", render: (row) => <RelativeCell date={row.updatedAt} /> }

// ❌ a hook called directly here corrupts DataList's hook order
{ key: "updated", header: "Updated", render: (row) => useRelative(row.updatedAt) }
```

`render` also receives an optional third argument, `DataListCellContext` —
`{ rowId, columnKey, selected }` — so a cell can react to its own row's
selection without threading state through the row type. Existing two-argument
render functions keep working unchanged.

### Wrapping, numbers and the mono face

`DataList` cells wrap by default: a long value breaks inside its own column instead of forcing the
whole table to scroll. Upstream's `TableCell` is `whitespace-nowrap`, so `DataList` spells
`whitespace-normal` out per cell rather than relying on an inherited default. Two column shapes are
unreadable when broken, so they opt back out automatically:

- `align: "end"` — the numeric convention. Give a number column `className: "tabular-nums"` too,
  so its digits line up in the regular font.
- `mono: true` — for codes and IDs only (an order reference, a ticket key): renders values in the
  mono face (`font-mono text-sm tabular-nums`) and pins them to one line. `mono` styles body cells
  only: the header is a label and stays in the sans face. A count, a date or an amount is a number,
  not an identifier — use `align: "end"` with `tabular-nums` instead.

`nowrap` overrides the inference in either direction: `nowrap: true` pins a prose column, and
`nowrap: false` lets an end-aligned column wrap.

```tsx
const columns: DataListColumn<Invoice>[] = [
  { key: "ref", header: "Ref", mono: true }, // an identifier: one line, mono
  { key: "subject", header: "Subject" }, // wraps
  { key: "amount", header: "Amount", align: "end", className: "tabular-nums" }, // a number: one line
  { key: "note", header: "Note", align: "end", nowrap: false }, // end-aligned but wrapping
];
```

## Accessibility

- Renders a real semantic `<table>` with `<thead>`/`<tbody>` and `<th>` header cells, so screen readers
  announce row/column structure natively.
- Sortable headers expose `aria-sort` (`ascending` / `descending` / `none`) and are real `<button>`s —
  keyboard <kbd>Enter</kbd> / <kbd>Space</kbd> activate them, with the global 2px `:focus-visible` outline.
- The select-all and per-row checkboxes have explicit `aria-label`s (e.g. _Select all rows_, _Select row 1_)
  and are fully keyboard operable.
- While loading, the table has `aria-busy="true"` and is described by a polite `role="status"` node.
  Skeleton rows are decorative (`aria-hidden`); the empty state carries its meaning in the
  title/description text, never by icon or color alone.
- Columns merged into the first cell keep their header as a visually hidden prefix
  (_Email: ada@vega.dev_), so a value lifted out of its column is never read without context. A
  column dropped with `mobile: "hidden"` is counted in a visible line that the table's
  `aria-describedby` points at, so the loss is heard with the table. When the sorted column is
  merged or hidden, the "Sorted by …" line is announced the same way.
- Activatable rows (`onRowClick`) keep native table semantics: the `<tr>` is **never** given
  `role="button"`/`tabIndex` (which would invalidate its cells). A real `<button>` injected into the first
  cell is the focusable keyboard / screen-reader activation; the row's `onClick` is mouse-only convenience.

| Key                                 | Action                                                                                                           |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| <kbd>Tab</kbd>                      | Move focus between sortable headers, row checkboxes, and (when activatable) each row's first-cell action button. |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Activate the focused sort header, toggle the focused checkbox, or activate the focused row.                      |
