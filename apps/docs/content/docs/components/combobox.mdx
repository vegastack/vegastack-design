## Usage

```tsx
import {
  Combobox,
  ComboboxContent,
  ComboboxEmpty,
  ComboboxInput,
  ComboboxItem,
  ComboboxList,
} from "@/components/ui/combobox";

<Combobox items={frameworks}>
  <ComboboxInput placeholder="Select a framework" />
  <ComboboxContent>
    <ComboboxEmpty>No items found.</ComboboxEmpty>
    <ComboboxList>
      {(item) => (
        <ComboboxItem key={item} value={item}>
          {item}
        </ComboboxItem>
      )}
    </ComboboxList>
  </ComboboxContent>
</Combobox>;
```

### Two-line options

An option that needs a second line composes Item's parts: `ItemContent` › `ItemTitle` +
`ItemDescription`. `ComboboxItem` provides Item's description context, so the description's id lands
on the option's `aria-describedby` and a screen reader hears it as the option's description
(API-19). A one-line option links nothing.

### Async status

When the list comes from a server, pass `filter={null}` so the engine stops filtering locally, and
render `ComboboxStatus` as a sibling of `ComboboxList`. It is Base UI's own polite status region:
keep it mounted and change its children — "Searching…", then the result count — rather than
rendering it conditionally. It is screen-reader-only by default; `visible` shows the message as a
muted row above the list.

## Accessibility

- Renders Base UI's Combobox: the input is `role="combobox"` with `aria-expanded`,
  `aria-controls` and `aria-activedescendant`, and the popup is a `role="listbox"` with type-ahead,
  <kbd>↑</kbd>/<kbd>↓</kbd>, <kbd>Home</kbd>/<kbd>End</kbd> and <kbd>Esc</kbd>.
- `ComboboxEmpty` is the engine's own polite live region, so the filtered result is announced. It
  stays mounted with zero height rather than `display: none` (A11Y-3, A11Y-4) — a region the
  platform never observed is a region it never announces.
- Focus shows on the **group**: a border tint while the control has focus (FOC-3), and no ring.
- The popup portals out of the input's subtree, so `ComboboxContent` re-applies the theme scope on
  the positioner inside the portal (OVL-13).
- Rows carry the hand cursor from the one global rule in `base.css` (INT-1).
- While the popup is open Base UI marks the trailing addon `aria-hidden="true"`, so the toggle
  inside it is out of the tab sequence (A11Y-9) — it stays clickable, and the `role="combobox"`
  input beside it is the single tab stop that opens the list, exactly as APG's editable combobox
  asks. `combobox.test.tsx` audits the open state with no axe exemption and pins the engine's
  shape, so the day Base UI stops hiding the addon the test says so.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/combobox.patch`. Every hunk:

- **API-19** — `ComboboxItem` provides Item's `ItemDescriptionContext` and points `aria-describedby` at an
  `ItemDescription` once one registers inside the option, so a two-line option reads its second
  line as the option's accessible description ([Two-line options](#two-line-options)). A one-line
  option is unchanged.
- **FOC-1, FOC-3, FOC-6** — `ComboboxChips`' `focus-within:border-ring` plus `ring-3 ring-ring/50`
  becomes `focus-within:border-ring/70`, and `ComboboxChipsInput`'s `outline-none` becomes
  `outline-hidden` so the forced-colours fallback has something to repaint. The single-line field's
  own focus chrome comes from `InputGroup`.
- **FOC-5** — the chips field's invalid tint becomes
  `not-focus-within:has-aria-invalid:border-destructive` (and its dark counterpart), so focus
  outranks it; the `has-aria-invalid` halo rings are removed.
- **INT-1** — `cursor-default` is removed from `ComboboxItem`, so a row shows the hand cursor the
  one global rule gives every `[role="option"]`.
- **FRM-4** — `data-disabled:pointer-events-none` is dropped from `ComboboxItem`, and
  `has-disabled:pointer-events-none` from `ComboboxChip`, so a disabled row or chip stays hoverable
  and a Tooltip can explain it.
- **A11Y-3, A11Y-4** — `ComboboxEmpty` no longer uses `hidden` (`display: none`) to hide itself
  while the list has results. Base UI drives that element as a polite live region and documents
  that hiding it breaks the announcement, so it stays in the layout at `h-0 overflow-hidden` and
  expands when the list is empty.
- **A11Y-2** — `ComboboxChipsInput` gains `min-h-6`. Upstream's chips input measures 20px inside the
  32px chips field, under the 24px target floor; the input is transparent, so nothing visible moves.
- **A11Y-16** — the toggle inside `ComboboxInput`, the clear control and the chip's remove control
  each gain an `aria-label`. All three are icon-only `<button>`s upstream ships with no text, and
  Base UI names none of them.
- **A11Y-9** — the toggle inside `ComboboxInput` takes `tabIndex={-1}`. Base UI marks the whole
  trailing addon `aria-hidden="true"` while the popup is open, and nothing tabbable may sit inside
  an `aria-hidden` subtree (axe `aria-hidden-focus`, serious). The attribute is set at that one
  call site, so the standalone `ComboboxTrigger` of the Popup composition keeps its tab stop; the
  addon is not made `inert`, so the mouse still reaches the control.
- **OVL-13** — `ComboboxContent` reads `useInternalThemeScope()` and attaches it to the positioner
  inside the portal; `tooling/verify-portal-theme-scope.mjs` inventories this host.
- **BRD-1** — `ComboboxContent` draws a real 1px `border border-border` instead of upstream's
  `ring-1 ring-foreground/10` box-shadow outline. A border survives forced colours and matches
  [Elevation](/docs/foundations/elevation); nothing else about the surface moves.
- **API-26** — Base UI's `Combobox.Input` reads the `Field` context itself, so inside a `Field` it
  takes its label, the rendered description and error ids, and `aria-invalid`. The addon's "Show
  suggestions" toggle drops the Field label Base UI also hands `Combobox.Trigger`, so the input is
  the one element the Field names.
- **API-27** — a new `ComboboxStatus` part re-exports Base UI's `Combobox.Status`, the engine's own
  polite status region for an asynchronously loaded list. It carries `data-slot="combobox-status"`,
  is `sr-only` unless `visible`, and is never hidden with `display: none`, so it stays mounted as a
  sibling of `ComboboxList` and only its children change.
- **DOC-2** — `cn` is imported from `@vegastack/design`.
- **DOC-1** — prettier reflow plus the `registry-stamp.mjs` provenance header the three-copy model
  needs; no decision of its own.
