## Usage

```tsx
import {
  Dialog,
  DialogContent,
  DialogDescription,
  DialogHeader,
  DialogTitle,
  DialogTrigger,
} from "@/components/ui/dialog";

<Dialog>
  <DialogTrigger>Open</DialogTrigger>
  <DialogContent>
    <DialogHeader>
      <DialogTitle>Are you absolutely sure?</DialogTitle>
      <DialogDescription>
        This action cannot be undone. This will permanently delete your account
        and remove your data from our servers.
      </DialogDescription>
    </DialogHeader>
  </DialogContent>
</Dialog>;
```

### Composition

`DialogContent` renders the portal and the backdrop for you, so the tree below is the whole
component: a trigger beside a content, and inside it a header and a footer.

```text
Dialog
├── DialogTrigger
└── DialogContent
    ├── DialogHeader
    │   ├── DialogTitle
    │   └── DialogDescription
    └── DialogFooter
```

### No Close Button

`showCloseButton={false}` on `DialogContent` removes the corner close control. `DialogFooter` has
its own `showCloseButton`, off by default, which appends an outline **Close** button to the band —
so a dialog without the corner control still offers a visible way out.

### Sticky Footer

`DialogFooter` is a `bg-muted/50` band pulled to the popup's edges with negative margins, so it
reads as part of the frame rather than as content. Put the scroll container between the header and
the footer and the actions stay visible while the body scrolls.

### Scrollable Content

The popup itself does not scroll — it is a grid that grows with its children. Long content goes in
its own `overflow-y-auto` element so the header stays in view.

### RTL

The popup's position, its close button and its inner padding are written in logical properties, so
a right-to-left document mirrors the whole surface; the `-translate-x-1/2` that centres it is not
logical, so it carries an explicit `rtl:` counterpart. Two things the caller owns: wrap the subtree
in `DirectionProvider` so Base UI's own logic agrees with the document's `dir`, and hand `dir` to
`DialogContent` — the popup portals to `<body>`, so a `dir` on an ancestor of the trigger never
reaches it.

`DialogTrigger`, `DialogClose`, `DialogPortal`, `DialogOverlay`, `DialogHeader`, `DialogTitle` and
`DialogDescription` add no props of their own — each accepts everything its Base UI part or its

Size is a `className`, not a prop: `DialogContent` ships `sm:max-w-sm` and a wider dialog overrides
it (`className="sm:max-w-md"`).

## Accessibility

- Renders Base UI's Dialog: the popup is `role="dialog"` with `aria-modal`, wired to
  `DialogTitle` through `aria-labelledby` and to `DialogDescription` through `aria-describedby`.
  <kbd>Esc</kbd> closes, and focus is trapped inside the popup and returned to
  the trigger.
- Give every dialog a `DialogTitle`. Without one the popup has no accessible name; if the title
  must not be seen, keep it and add `className="sr-only"`.
- The background is made inert natively, not just focus-trapped (A11Y-9), so a focus guard that
  hands focus to `<body>` cannot tab back into the page behind. With `modal={false}` the background
  stays interactive and nothing is made inert, which is the point of that mode.
- The popup portals to `<body>`, so `DialogPortal` re-applies the enclosing theme scope on a
  `display: contents` host inside the portal (OVL-13) — a scoped or dark surface survives the jump.
- The corner close button is an icon-only `Button` carrying a `sr-only` "Close" label.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/dialog.patch`. Every hunk:

- **OVL-13** — `DialogPortal` reads `useInternalThemeScope()` and wraps its children in a
  `display: contents` element carrying that class, so a nested theme scope survives the jump to
  `<body>`. The wrapper generates no box, so nothing about the backdrop's or the popup's fixed
  positioning changes. `tooling/verify-portal-theme-scope.mjs` inventories this host.
- **A11Y-9** — `DialogContent` mirrors Base UI's live `data-base-ui-inert` markers onto the native
  `inert` property through `useModalInert`, so a focus guard that hands focus to `<body>` cannot tab
  back into the background. The root now publishes its `modal` prop through a context, which is
  exactly the shape upstream's own Drawer uses, because native inert would also block the outside
  POINTER interaction that `modal={false}` and `"trap-focus"` keep.
- **DOC-2** — `import { cn } from "cn"` becomes `@vegastack/design`; our npm layer owns `cn`.
- **DOC-1** — the repository formatter reflows the file and `registry-stamp.mjs` writes the
  provenance header the three-copy model needs; those hunks carry no decision of their own.
