## Usage

```tsx
import {
  Alert,
  AlertAction,
  AlertDescription,
  AlertTitle,
} from "@/components/ui/alert";

<Alert>
  <InfoIcon />
  <AlertTitle>Heads up!</AlertTitle>
  <AlertDescription>
    You can add components and dependencies to your app using the CLI.
  </AlertDescription>
</Alert>;
```

## Accessibility

- The root carries `role="alert"`, so assistive technology announces its content as soon as it
  enters the accessibility tree. Render it when the event happens, not on every page load.
- Status is never colour alone (A11Y-8): every variant takes an icon, and the title carries the
  words. The icon is decorative — the sentence is what gets read.
- Each variant takes its family's `-text` ink over the card surface (A11Y-13), which clears the AA
  contrast floor in both themes; the description sits at 90% opacity and still clears it.
- `AlertAction` holds a real control. Keep it a `Button` so it is reachable by keyboard in the
  reading order, immediately after the description.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/alert.patch`. Every hunk:

- **COL-12** — `success`, `warning` and `info` variants, written in upstream's own `destructive`
  shape: one ink on `bg-card`, with a dimmed description. The four status families exist in the
  token contract; Alert is where they surface as a banner.
- **A11Y-13** — every status variant takes the family's `-text` ink rather than the fill. Upstream's
  `text-destructive` on card measures 3.98:1 in light, under the AA floor A11Y-1 enforces.
- **A11Y-8** — status is never colour alone: the page and `alert.test.tsx` require an icon and a
  title beside the tint, and the class string reserves the icon column either way.
- **DOC-2** — `cn` is imported from `@vegastack/design`.
