### Live alerts

An Alert is a polite `role="status"` region by default, whatever its variant, so an alert that is
on the page when it loads is read in page order and interrupts nobody (A11Y-3). Pass `live` when
the alert appears after mount because of something the user just did — a failed save, a declined
card. With `live`, a `destructive` or `warning` alert becomes an assertive `role="alert"`; every
other variant stays a polite `status`.

To leave an alert out of every live region — a standing notice that is part of the page when it
loads — pass your own `role`, which always wins: `role="note"` makes it a static note
that no screen reader announces on its own. `live` stays off by default, so nothing changes for an
alert that does not pass one.

<ComponentPreview name="alertLive" file="components/preview/alert.tsx" />

### Action placement

`AlertAction` takes its own column beside the title and description, top-aligned with the title, so
a long label never reaches under the text (LAY-15). When the alert itself is narrower than 28rem —
a phone, a sidebar card — the action drops below the text instead. The switch follows the alert's
own width (a container query), not the viewport's.

## Accessibility

- The root is a polite `role="status"` region by default, so an alert present at page load is read
  in page order rather than interrupting (A11Y-3). With `live`, a `destructive` or `warning` alert
  is an assertive `role="alert"` instead: use it only for a message the user's own action just
  caused, and render it when that happens. A `role` you pass yourself still wins.
- Status is never colour alone (A11Y-8): every variant takes an icon, and the title carries the
  words. The icon is decorative — the sentence is what gets read.
- Each variant takes its family's `-text` ink over the card surface (A11Y-13), which clears the AA
  contrast floor in both themes; the description sits at 90% opacity and still clears it.
- `AlertAction` holds a real control. Keep it a `Button` so it is reachable by keyboard in the
  reading order, immediately after the description.

## Deviations

Upstream's file plus `packages/ui/upstream/patches/alert.patch`. Every hunk:

- **COL-12** — `success`, `warning` and `info` variants, written in upstream's own `destructive`
  shape: one ink on `bg-card`, with a dimmed description. The four status families exist in the
  token contract; Alert is where they surface as a banner.
- **A11Y-13** — every status variant takes the family's `-text` ink rather than the fill. Upstream's
  `text-destructive` on card measures 3.98:1 in light, under the AA floor A11Y-1 enforces.
- **A11Y-8** — status is never colour alone: the page and `alert.test.tsx` require an icon and a
  title beside the tint, and the class string reserves the icon column either way.
- **A11Y-3** — `Alert` takes `live?: boolean`. The root is a polite `role="status"` for every
  variant, and takes upstream's assertive `role="alert"` only with `live` on a `destructive` or
  `warning` alert; a caller's own `role` still wins.
- **LAY-15** — `AlertAction` is a grid item in its own top-aligned column beside the title and
  description, and drops below the text when the alert is narrower than `@md` (28rem). Upstream
  positions it `absolute top-2 end-2` and reserves only `pe-18` for it, so an `sm` label over seven
  characters reaches under the title ([Action placement](#action-placement)).
- **DOC-2** — `cn` is imported from `@vegastack/design`.
