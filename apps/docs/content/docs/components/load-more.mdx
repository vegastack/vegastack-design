## Usage

```tsx
import { LoadMore } from "@/components/ui/load-more";

<LoadMore
  hasMore={nextCursor != null}
  loading={isFetchingNextPage}
  error={fetchError ? "Couldn't load more tasks." : undefined}
  onLoadMore={fetchNextPage}
/>;
```

`LoadMore` is the tail of a **keyset** list — one fetched by cursor, with no total and no page
numbers. Nothing asks the reader to page: a sentinel at the end of the list is observed against its
nearest scrolling ancestor (the page when there is none) and calls `onLoadMore` as it comes within
`rootMargin` of the edge. While the page loads, skeleton rows hold the space the new rows will take.
A list shorter than its box keeps loading until it fills it or the cursor runs out.

It is controlled and owns no data: the host holds `hasMore`, `loading` and `error`, and
`onLoadMore` fetches the next batch (a retry is the same call). It requests **one page at a time**:
after a call it waits for the host — for `loading` to rise and fall when the host reports it, or for
the new rows to land when it reports neither — before it can fire again. Pass `loading`, or return a promise from `onLoadMore`.

`DataList`, `DataGrid`, board lanes, `SearchableSelect` and `VersionList` render it for you through
their `loadMore` prop, and `LoadMoreState` — the four paging fields on their own — is the shape those
props and `useAsyncSearch` pass around. Reach for the component directly only for another list.

## Examples

### States

- **Idle** — a 1px sentinel; nothing visible.
- **Loading** — skeleton rows (three 36px bars by default) where the next rows will land. Nothing
  else fires until the host answers.
- **Error** — the message above a _Try again_ button, which calls `onLoadMore` again. Rows already
  loaded stay, and loading pauses: a broken endpoint is never retried on scroll.
- **Done** — nothing, unless the host passes `endLabel`: a list that simply stops needs no caption.

### Skeleton rows

Pass `skeleton` with rows the height of the list's own, so nothing jumps when they are replaced.
A table that appends skeleton rows to its own body passes `skeleton={null}` and keeps only the
sentinel — `DataList` and `DataGrid` do.

```tsx
<LoadMore
  hasMore={hasMore}
  loading={loading}
  onLoadMore={fetchNextPage}
  skeleton={<MeetingRowSkeleton count={2} />}
  rootMargin="0px 0px 160px 0px"
  retryLabel="Retry"
  endLabel="That's every meeting"
/>
```

## Accessibility

- The tail is decoration (`aria-hidden`): the new rows arrive in the list itself, and the host's
  status region or the list's `aria-busy` is what a screen reader hears.
- Nothing takes or moves focus, and appending below the reader never moves the scroll position, so
  a keyboard reader's row cursor stays where it was. Arrowing toward the end scrolls the sentinel
  into view, which loads the next page; `DataGrid` also loads it on <kbd>↓</kbd> past the last row.
- A failed fetch renders its message as `role="alert"`, with a real _Try again_ button.
- `DataList` and `DataGrid` set `aria-rowcount="-1"` on the table while `hasMore` is true, because
  the total is unknown.

| Key                                 | Action                          |
| ----------------------------------- | ------------------------------- |
| <kbd>Tab</kbd>                      | Move to _Try again_ (on error). |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Retry the failed page.          |
