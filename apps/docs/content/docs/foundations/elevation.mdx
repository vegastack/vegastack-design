The system is **borders-only**. Surfaces are separated by a single hairline (`border-border`),
not by stacked shadows. There is **exactly one** sanctioned elevation token —
`--shadow-overlay`, defined in `@vegastack/design-tokens/theme.css` — and it is reserved for content that
floats *above* the page: popovers, dropdowns, dialogs, tooltips, menus.

<ShadowScale />

## The one shadow

`--shadow-overlay` is a soft, low-contrast two-layer shadow tuned to read as "this surface is
detached from the page" without looking heavy:

```css
--shadow-overlay:
  0 4px 14px -4px oklch(0.13 0.002 75 / 0.10),
  0 2px  4px -2px oklch(0.13 0.002 75 / 0.06);
```

It is bridged through `@theme inline` (`--shadow-overlay: var(--shadow-overlay)`) so it is
overridable in one place, and the shadow color is an OKLCH neutral at low alpha — it tints toward
the page rather than printing a hard grey halo. No `shadow-sm` / `shadow-md` / `shadow-lg` ramp
ships; floating components apply this one token (the `ShadowScale` specimen above renders it via
`box-shadow: var(--shadow-overlay)`).

## Why borders, not shadows

The aesthetic is **flat, dense, and developer-tool** — precision over depth. Shadow ramps exist to
fake physical layering, and that layering fights a high-density UI: every elevated card adds visual
weight, blurs edges, and makes a tight layout feel soft and cloudy. A one-pixel `border-border`
separates surfaces just as clearly, costs nothing in contrast, and keeps the page crisp at any
density. So a `Card` is `border border-border` on `bg-card` — never a drop shadow.

The single exception is genuine *floating* UI. A popover or dialog is literally rendered on top of
the page in a portal, and the shadow is the affordance that says so — it is depth that maps to real
stacking, not decoration. That, and only that, earns `--shadow-overlay`.

## When NOT to add a shadow

- **Cards, panels, list rows, table containers** — use `border-border`. A resting surface on the
  page is never elevated.
- **Buttons, inputs, badges, chips** — flat fills and borders only; no `shadow-*` to imply press
  depth. Use `data-*` state styling and the focus ring instead.
- **Hover / active states** — change the fill (`hover:bg-primary-hover`), not the elevation. Never
  introduce a shadow on hover.
- **Sticky headers and sidebars** — separate them with a `border-border` edge, not a scroll shadow.

A shadow is justified **only** when a surface is portaled above the page (popover, dropdown,
tooltip, dialog, menu). If the element lives in normal document flow, it gets a border.

## Stacking — the portal contract

Z-index is **two token bands, not a ladder** (`@vegastack/design-tokens`):

| Band | Token | Value | Use |
|---|---|---|---|
| Raised | `--z-raised` | 10 | A local raise **inside** a component's own stacking context — the focused OTP slot, a segmented item's focus edge, a floating label, chat-bubble reactions, select scroll arrows. |
| Overlay | `--z-overlay` | 50 | Every **portaled** floating surface — dialog, sheet, popover, menu, select, tooltip, hover-card. |

Apply them as `z-(--z-raised)` / `z-(--z-overlay)`; raw `z-N` literals are lint-banned.

**Why one overlay band works.** Base UI portals append to `<body>` (and `base.css` sets
`isolate` on `body`, so the page below can never leak above). Two overlays in the same band
resolve by **DOM order**: a Select opened inside a Dialog mounts its portal *after* the
Dialog's, so it stacks above — no `z-index` arithmetic, no per-component ladder, and nesting
works to any depth (dialog → popover → select → tooltip). This is asserted by real-browser
nested-overlay tests (`stacking.test.tsx`).

**The toast exemption.** Sonner's toaster container manages its own z-index (the library's
top-layer value). This is deliberate and documented rather than banded: the toaster mounts once
at app boot — *before* any dialog portal — so DOM order would put a modal opened later above
it, and a toast fired mid-dialog must still be visible. Toasts therefore sit conceptually in a
`toast` band **above** `--z-overlay`, implemented by the vendored library.
