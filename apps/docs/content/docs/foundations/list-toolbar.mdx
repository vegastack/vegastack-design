Every list gets the same rows under its title: the **tab row** when the page has a scope (scope
tabs or a table's saved views), then one **toolbar row** — the search on the left, a tight cluster
of icon tools on the right — and, only while Filters is open, the **filter row** of chips. The
page's main button is not in any of them: it sits at the right end of the app's top bar. The parts
are [`ListToolbar`](/docs/components/list-toolbar), [`FilterRow`](/docs/components/filter-row),
[`AddFilterMenu`](/docs/components/add-filter-menu), [`SortMenu`](/docs/components/sort-menu) and
[`DisplayMenu`](/docs/components/display-menu).

## Principles

1. **One anatomy everywhere.** Every list has the same rows and zones in the same order. A page
   leaves parts out; it never re-orders them or adds its own. Only the collapse steps below change
   the row.
2. **A control appears only when it applies.** Sort is absent on a board, Layout where there is one
   layout, ⋯ when it would be empty, the whole toolbar where a list has no tools. Nothing is shown
   disabled as a placeholder.
3. **One place per concept.** Tabs say _which set_. Search matches text. Filter says _which rows_
   (and the AI writes there). Sort says _what order_. Display says _how rows look_ and _which
   lifecycle states are included_. ⋯ holds _actions on the view_. The same concept never has two
   controls: a column header's sort and the Sort tool write one value; Display's Columns is the
   only column picker.
4. **The collapse order is fixed and measured** on the toolbar's own width, not the viewport.
5. **One main button per page, in one place on every page type**: the right end of the app's top
   bar — list pages, record pages (a task, a page, a table, a project), module master pages,
   settings and the library alike. Never in the toolbar. A record page's other actions stay in the
   top bar's ⋯; a short list inside a record tab uses a compact toolbar and its record's top bar.
6. **State is visible without opening anything.** Filter shows a count; Sort and Display show a dot
   when they differ from the page's default; a changed saved view shows a dot on its tab and a
   "Save view" button. Nothing hides behind a lone count.
7. **Icons, not labels, on tools; tooltips always.** Every tool has a tooltip with its name and
   shortcut and an accessible name that includes its state. Layout is one button that shows the
   layout it switches to. Text appears only on "Save view", tabs, chips and the bulk bar.
8. **A popover is the menu's surface.** Every toolbar popover has the `DropdownMenu`'s rhythm — a
   4px inset, 28px rows at a 6px text inset, 24px muted section labels, hairlines edge to edge —
   with no filled rows, no control tracks and no card inside a card. A chosen option is a check or
   a pressed toggle. A search inside one is the people dropdown's quiet filled field, or a hairline
   row whose divider keeps the default border colour. On a phone every toolbar popover is a bottom
   sheet with the same content.

## Anatomy

```
top bar:  breadcrumb ……………………………………………………………………………………… [⋯] [+ New task]   ← app top bar
title (+ description)
↕ 16
[scope tabs | saved views (folds to a dropdown)]                                     ← tabs (own row)
↕ 8
[⌕ search]  …………………………………………  [Save view] [↶ ↷] │ ▽n ⇅• ▥ ⚙• ⋯                  ← ListToolbar (32)
↕ 8
[pinned facets…] [chips…] [✦ chips…] →scrolls→ ……………………………… [+ Filter] [Clear]     ← FilterRow (open)
✦ 2 filters added by AI · Undo · Couldn't match “warehouse”                         ← after an AI run
↕ 12
list · table · board · grid
```

- **Tab row:** scope `Tabs` (`TabsList overflow="menu"`), `RouteTabs` (`overflow="menu"`) or a
  table's `ViewTabs` — at most one, passed as `ListToolbar`'s `tabs`. Absent when the page has no
  scope. It folds into a dropdown by itself when it does not fit.
- **Toolbar row:** the search first (left), on every page and every DataList — one place for muscle
  memory. Then, at the far end, in order: a state button ("Save view", only while a view is
  changed), the edit group (undo, redo, a divider), and the tool cluster — Filter · Sort · Layout ·
  Display · ⋯. The most stable tools sit at the far end, so a tool that hides never moves them.
- **Filter row:** the facets and chips in one line that scrolls sideways and never wraps; `+ Filter`
  and, while anything is set, Clear beside it at the right end. Every control on it is the toolbar's
  tool height.
- **Sizes:** the row is 32px; tools are 32px borderless icon buttons 4px apart, 8px from the search;
  the search is 240px, giving way to 144px. Icons: Filter `ListFilter`, Sort `ArrowUpDown`, List
  `List`, Board `Columns3`, Grid `LayoutGrid`, Display `SlidersHorizontal`, More `Ellipsis`, AI
  `Sparkles`.
- **The toolbar touches its list.** Page content that is not the list (a "Recent" strip) sits above
  the tabs, never between the toolbar and the list. An empty list keeps its toolbar but drops its
  column header and its status line ("N columns hidden").

## Where each option lives

| Option                                                      | Control                                                  |
| ----------------------------------------------------------- | -------------------------------------------------------- |
| Whose items / which kind (Mine · Team · All)                | Tab row                                                  |
| A table's saved views                                       | Tab row `ViewTabs` (dot when changed)                    |
| Attribute predicates (status, due, owner, space…)           | Filter — top facets pinned, the rest in + Filter         |
| A plain-language request                                    | + Filter's input, or the search's ✦ row for a phrase     |
| An advanced condition set                                   | + Filter's foot → a builder dialog, one chip             |
| Order                                                       | Sort — `SortMenu` for one key, `SortBuilder` for several |
| List · Board · Grid                                         | The Layout button (→ Display › Layout when narrow)       |
| Row height, group by, columns or fields                     | Display › Rows                                           |
| Show archived · closed · disabled · subtasks · empty groups | Display › Show (one switch each)                         |
| Save view, reset, copy link, export, import, empty trash    | ⋯ (`ListToolbarMenu`)                                    |
| Rename, lock, delete a saved view                           | The view tab's own ⋯                                     |
| Undo · redo (tables)                                        | The edit group (→ ⋯ on a phone)                          |
| The page's create action                                    | The main button, right end of the app's top bar          |

A state hidden by default (closed, archived, disabled) is always a Display switch, never a default
filter chip. A preset resolves to ordinary chips.

## AI filter, fewest clicks

Two entries, one engine, both the page's own (the design system holds no AI), and neither calls it
while the person types:

- **The search box.** Once the query reads as a phrase (three words), one row appears under it —
  "✦ Filter with AI" (`search.suggestion`). Enter alone still searches; ↓ Enter or a click sends
  the phrase, and the filter row opens with the chips it made.
- **`+ Filter`.** Its one input ("Filter by…") narrows the fields; once the text reads as a phrase
  (two words, or a word no field matches) its first item is "✦ Filter with AI: “…”".

## Responsive

The toolbar measures the width it is given. Each step happens only if the previous was not enough:

1. The search shrinks from 240px to 144px.
2. Layout moves into Display.
3. Sort moves into Display, as a "Sort by" row — only if the page has Display; otherwise it stays.
4. The search becomes an icon that opens across the row.
5. A table's undo and redo (and its "Save view") move into ⋯.

Filter, Display and ⋯ never collapse. The tab row folds into one dropdown on its own — the active
tab and ▾, every tab in the menu — when the tabs do not fit, and unfolds only with 24px to spare,
so it never flickers. Scope tabs never scroll sideways; only chips do.

| Viewport            | Content ≈ | Tabs             | Search | Sort / Layout     | Filter row         | Popovers     |
| ------------------- | --------- | ---------------- | ------ | ----------------- | ------------------ | ------------ |
| Desktop 1440        | 1120px    | inline           | 240    | in the row        | one scrolling line | popover      |
| Laptop 1280         | 960px     | inline           | 240    | in the row        | one scrolling line | popover      |
| iPad landscape 1024 | 700px     | inline           | 240    | in the row        | one scrolling line | popover      |
| iPad portrait 768   | 640px     | fold when needed | 240    | in the row        | one scrolling line | popover      |
| Phone 390           | 358px     | fold when needed | 144    | Layout in Display | one scrolling line | bottom sheet |

**Bulk selection** does not change the toolbar: the header checkbox and the
[`ActionBar`](/docs/components/action-bar)'s count are the selection state. On a phone the bar docks
full width above the safe area with icon-only actions, and the list keeps a spacer the bar's height
so its last row is never covered.
