Every screen of the app sits in one frame, [`Shell`](/docs/components/shell). It has **five
regions**, each owned by one part, and **one rule** decides where they go at every width (LAY-22).

```
┌───────────────────────────────────────────────────────────────────┐
│ G  global bar (44): ▤ ‹ › workspace · search ⌘K · Ask ⌘J, Help, account │
├────┬───────────────┬──────────────────────────────────────────────┤
│ R  │ C  title (48) │ T  top bar (48)                              │
│ a  │ o             ├──────────────────────────────────────────────┤
│ i  │ l             │                                              │
│ l  │ u             │  W  the page                                 │
│    │ m             │     (a Peek opens over its right side;       │
│ 64 │ n  240        │      a record page has its own side panel)   │
└────┴───────────────┴──────────────────────────────────────────────┘
```

## The regions

| Region     | Part                      | Size                                       | Holds                                                              |
| ---------- | ------------------------- | ------------------------------------------ | ------------------------------------------------------------------ |
| Global bar | `GlobalBar`               | 44px, full width                           | ▤, ‹ › (desktop), the workspace · search · Ask, Help, the account  |
| Rail       | `Rail`                    | 64px                                       | The modules (icon and a short label), Settings at the foot         |
| Column     | `ShellColumn` › `NavTree` | 240px, 200–360, folds to 0                 | A 48px title row, then the module's places: views, folders, spaces |
| Top bar    | `ShellTopBar`             | 48px                                       | Title · presence, tools, primary, Share, ☆, ⋯ — in that order      |
| Page       | `ShellMain` › `ShellPage` | prose 720 · default 1200 · full · form 720 | The page                                                           |
| Phone bar  | `ShellBottomBar`          | 56px + the home indicator                  | Home, Inbox, Agents, Spaces, More                                  |

Every size is a token, never a literal: `--shell-globalbar-height`, `--shell-rail-width`,
`--shell-column-width` (`-min`, `-max`), `--shell-topbar-height`, `--shell-bottombar-height`, and
the desktop title row's `--shell-titlebar-mac-inset` and `--shell-titlebar-win-inset`. The top
bar's height is the height of every page-level title row: the column's title row, a peek's head
and a record panel's head. The global bar is the desktop app's window row.

There is no right panel in the frame. A record opens in [`Peek`](/docs/components/peek) over the
page area's right side, so the list keeps its place; its full page uses
[`RecordLayout`](/docs/components/record-layout), whose side panel is part of the page.

## Where the column goes

The tiers are the design system's own: phone under 40rem, tablet under 64rem, laptop under 90rem,
then wide — read on the shell's width with container queries, so a resized desktop window, iPad
split view and browser zoom all behave the same.

- **Phone.** No global bar or rail: the page's own top row and the bottom bar. The column is a
  sheet from the page's title.
- **Tablet.** The rail shows. The column never takes room: it slides over the page from ▤, an
  edge swipe, or a hover on the current module, and goes away once you pick something.
- **Laptop and wide.** The column sits in the flow while the person keeps it open (⌘\).
  Resizing the column stops where the page would get narrower than 560px.

## State before the first paint

The shell lays itself out in CSS from data attributes, so the server's HTML is already right.
`ShellStateScript`, in `<head>`, reads the person's column cookie (`open:240`) before the first
paint and marks `<html>`; a missing or stale cookie falls back to the defaults. Nothing moves when
the page hydrates.

## Motion

The shell reuses the motion tokens: the column folds in `duration-state` on `ease-emphasized`;
closing uses `duration-state-exit` on `ease-exit`. A peek and a record panel open in
`duration-panel`, and only when a person opens them. With reduced motion, all of it is instant.

## Layers

The floating area (the audio player, upload progress) is `z-10`, a column sliding over the page
and a peek sit above the page, menus and dialogs are `z-50`, toasts `z-60` at the bottom centre.
