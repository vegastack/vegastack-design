The type system is **Geist** (sans UI and prose) and **Geist Mono** (code, data, tabular figures),
on **Tailwind's stock size scale**. Hierarchy comes from size, weight and colour, and the utilities
mean exactly what they mean everywhere else: `text-sm` is 14px, `text-base` is 16px.

<TypeScale />

## One scale, everywhere

This used to be two scales. `text-xs`…`text-3xl` were re-pointed at a denser product ladder
(`text-base` = 14px) while the docs shell stayed on the classic 16px documentation ladder, and a
pair of CSS bindings moved a subtree between them. That is gone: a pasted shadcn snippet now
renders at the size shadcn drew it, and `text-sm` means 14px on a product surface, in a component
preview and in this sentence alike.

## Weight and roles

There are no named role tokens. `text-h1`…`text-h4`, `text-label`, `text-code`, `text-mono-label`
and the `text-display-*` tier were utilities that baked size, line-height, weight and tracking
together; they are replaced by the two or three stock utilities each one stood for — a section
title is `text-base font-medium`, a control label is `text-sm font-medium`, inline code is
`font-mono text-sm`.

The 400/500 weight ladder is gone with them: `font-semibold` and `font-bold` are ordinary
utilities again, and upstream uses `font-medium` for titles and `font-semibold` where a heading
earns it. What has not changed is the judgement — at most two weights in one view, and colour
does the rest of the hierarchy work.

| Role                | Utilities                                 |
| ------------------- | ----------------------------------------- |
| Page heading        | `text-3xl font-semibold`                  |
| Section heading     | `text-2xl font-semibold`                  |
| Card / dialog title | `text-base font-medium`                   |
| Control label       | `text-sm font-medium`                     |
| Compact label       | `text-xs font-medium`                     |
| Body                | `text-sm` (product) · `text-base` (prose) |
| Inline code         | `font-mono text-sm`                       |
| Compact numerals    | `font-mono text-xs`                       |

## Font tokens

- `--font-family-sans` → Geist (UI + prose)
- `--font-family-mono` → Geist Mono (numbers, code, currency)
- `--font-family-serif` → **Newsreader** serif accent (display emphasis and pull-quotes only, never running text)
- `--font-family-display` → Geist display tier (a split token so a display face can be retuned independently)

Use the `font-sans`, `font-mono`, `font-serif`, `font-heading` (bridged from `--font-family-sans`)
and `font-display` (bridged from `--font-family-display`) utilities. `--font-family-pixel` and the
Geist Pixel flourish were deleted with the marketing layer.

## Font loading

**The font-delivery contract:** Geist Sans / Geist Mono ship from the `geist` npm
package (`geist/font/sans`, `geist/font/mono`). **Newsreader** loads via
`next/font/google`, which self-hosts the subset woff2 at build time — so the static export
serves every face itself: no render-blocking external request, no layout shift, and the fonts
work offline. `app/global.css` binds the loaded faces onto the runtime font tokens (with system
fallbacks):

```css
:root {
  --font-family-sans:
    var(--font-geist-sans), ui-sans-serif, system-ui, sans-serif;
  --font-family-mono: var(--font-geist-mono), ui-monospace, monospace;
}
```

<Callout type="info">
  This is the **one-file override** point: a consuming app supplies its own
  faces by redefining `--font-family-sans` / `-mono` / `-serif`, and every
  `font-sans` / `font-mono` / `font-serif` utility repaints — the `@theme
  inline` bridge maps these tokens to Tailwind's font utilities.
</Callout>
