🔧 Text limits, counted like a server (`String.length`) and never cut mid-composition. `RecordHeader` `titleMaxLength`; `Transcript` `speakerNameMaxLength`; `ChipInput` `maxLength` per chip with `maxLengthLabel` (a longer entry stays in, or comes back into, the input); `ShareDialog` `messageMaxLength`; `AgentPanel` `instructionsMaxLength` and `replyMaxLength` (each with a `FieldCounter`); `CommentComposer`, `CommentItem`, `CommentList` and a `CommentThread`'s `composer` take `maxLength` and `maxLengthMessage` — a count near the limit, and past it the host's message with Send or Save refused (the rich editor is never cut); a long text's `FieldConfig.maxLength` and `maxLengthMessage` do the same in `FieldInput`, the cell editor and `FieldProperty`. `AddFilterMenu` takes `ai.maxLength`, and no longer swallows a failed request: a thrown `Error`'s message shows (`labels.unavailable` when it has none), or `AiFilterResult.error` shows the host's words. `DropdownMenuInput` gains an `error` slot under the field (`aria-invalid`, described by it) for a refused autosave. A value already past a limit (seeded, or a lowered limit) never commits: `EditableCell`'s text editor (and so the title and speaker renames), the agent boxes, the invite message and the filter request hold it until shorter. Every prop is optional; without them nothing changes.
