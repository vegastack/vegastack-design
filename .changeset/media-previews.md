🔧 `FileViewer` previews every file type an app stores: text and code files show their first 1 MB, a CSV or TSV is a table (a built-in `parseCsv`; the header row and at most 500 rows, "Showing first 500 rows"), Markdown and MDX render through `MarkdownView` (loaded lazily, JSX never run), and Office and other files are a card with the file's own picture (`thumb`), size, facts and a primary Download. A new `loadPreview(item, { signal })` lets the app hand back parsed `text`, `table`, `markdown`, `html` or `card` content (`FileViewerPreview`) so parsers stay app dependencies. Items gain `refreshSrc` (an expired video or audio URL) and `peaks` (a stored waveform); video letterboxes instead of cropping; `data-kind` now names the stage on screen, and the plain file card is `card` (was `other`). `VideoPlayer` no longer shows a Quality menu unless `qualityOptions` are passed, never autoplays, documents `poster`, shows "Can’t play this video here" with a Download button (`downloadHref`, `loadErrorLabel`, `downloadLabel`), and renews an expired signed URL with `onSourceExpired`, resuming where it stopped. `AudioPlayer` takes precomputed `peaks` and decodes a file for its waveform only up to `maxDecodeBytes` (20 MB), showing the plain seek slider above it; a renewal that returns the same URL now reloads it in both players. `fileKindOf` treats `text/plain` as generic (the extension decides) and maps `.mdx`, `.toml`, `.ini` and `.jsonc`. New lib `media-probe`: `probeVideo` (duration, size and a JPEG poster), `probeAudio` (duration and up to 200 peaks, skipped over 50 MB) and `extractPptxThumbnail` (an Office file's embedded preview picture), browser-only and dependency-free.
